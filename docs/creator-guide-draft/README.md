# PNDS Creator Guide(Diátaxis 试验版)

> **状态:草稿。** 本目录是对 [`PNDS_CREATOR_GUIDE.md`](../PNDS_CREATOR_GUIDE.md) 按 [Diátaxis](https://diataxis.fr/) 框架重构的试验版,用于对比评审——原版未改动,本目录未纳入文档索引。评审定稿后,原版将被本结构替换(或调整后再替换)。

## Diátaxis 是什么

Diátaxis 把文档按**读者的处境**分为四个象限,每种文体服务一种阅读模式:

| 象限                     | 文体     | 读者状态     | 内容形态               |
| ------------------------ | -------- | ------------ | ---------------------- |
| [教程](./tutorial.md)    | 学习导向 | 「教我」     | 一条保证成功的完整路径 |
| [任务指南](./how-to.md)  | 任务导向 | 「我要做 X」 | 针对具体问题的独立步骤 |
| [参考](./reference.md)   | 信息导向 | 「查一下 X」 | 干燥、准确、完整的资料 |
| [解析](./explanation.md) | 理解导向 | 「为什么」   | 背景与设计动机         |

## 本目录结构

```text
creator-guide-draft/
├── README.md        本页:导航 + 与原版的映射
├── tutorial.md      教程:从模板创建第一个工程,到打出自己的 .pnds
├── how-to.md        任务指南:端口 / 编译 / 打包分发 / 发新版 / 演出机音频链路
├── reference.md     参考:环境 / 目录 / manifest / 契约 / 端口速查
└── explanation.md   解析:分工哲学 / .pnds / 版本号 / node_modules / 采样率 / 命名契约
```

正式采用时,`how-to.md` 大概率应拆分为每任务一个文件;草稿阶段先合并在一个文件里,便于通读对比。

## 评审时建议关注

1. **教程是否真的「教程」**——每一步有动作、有「你应该看到」,不看解析也能走完;
2. **任务指南是否各自独立**——从任何一节进来都不需要顺序阅读;
3. **参考是否可查**——找一条规则的时间是否比原版短;
4. **解析是否敢删**——原版把「为什么」混在操作里,拆出来后操作部分是否更干净;
5. 重复内容是否已被收敛到唯一位置(规范四件套仍是唯一权威,本目录只做创作者视角的摘编)。

标点沿用原版指南的半角风格;定稿时若统一为全角,脚本转换即可。
