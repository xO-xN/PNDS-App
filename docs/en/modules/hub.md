# hub Connection and Remote Nodes

`hub` optionally connects to an existing relay and is not a Blank default. Confirmed Work chat adopts the module, any missing exact Socket.IO Node client and production declaration, then completes wiring and checks in the same task. Discussion only proposes. Manual module addition copies source/provenance and records an unwired handoff.

## Configuration and objects

After the project declares internet capability, the Host injects node, hub URL, token and room configuration. Fields and scope follow the [network contract](../reference/network.md). Credentials stay out of pages and logs.

A remote node is a running remote project instance; local phones still connect to their local performer service. Node count, performer count and work roles are distinct.

## Wiring and lifecycle

Read the project's `modules/pnds-hub/README.md` for complete interfaces. The work supplies events, node-summary display and any required work snapshot. The module handles connections, reconnection, heartbeats, summary expiry and echo filtering, releasing connections/timers on stop. Authors define work progress and sound synchronization.

Adoption adds the exact `socket.io-client` shared reference and production declaration, using the Host-verified `PNDS_SHARED_LIBRARIES` entry. Missing or mismatched resources fail without network installation. Existing same-version resources are reused and author customizations are not overwritten automatically.

## Verification and maintenance

Verify same-room events, room isolation, rejected authentication, summary freshness, recovery and shutdown, plus local performance with an unreachable hub. A connection does not establish correct sound.

Task undo preserves later independent edits. Unsaved drafts and disk conflicts follow project protections. Report module adoption, work wiring, loaded behavior and listening separately.
