# 1.7.0 创作工作台：布局与工作流原型

2026-10-15 用户确认当前布局与讨论内调参、直接编辑代码、临时预演和明确应用流程定稿，作为 [1.7.0 正式规格](../../plans/v1.7.0-creation-assistant-spec.md)的实现基线。定稿不表示 App 已实现，也不表示真实模型选参、工程适配或像素／原生窗口视觉已验收；交付要求见 [#172 创作工作流验收](../../acceptance/172-v1.7.0-creation-workflows.md)。保留 [1.6 桌面定稿](../desktop-1.6/README.md)作为视觉基线，不修改冻结文件。

直接打开 [index.html](./index.html)。相邻 CSS、JS、Performer 文件需要一起保留。也可通过用户已经启动的 Vite 访问 `/docs/prototypes/creation-1.7/index.html`。本轮没有启动 App dev server。

所有文件、AI 回复、检查、Git、共享包、模块添加与音频状态都在内存中模拟，重新载入即重置。不会读取工程磁盘、调用模型服务、写入真实版本、启动音频或操作端口。Performer 可打开独立浏览器窗口，仅传递模拟触摸坐标。

## 布局决定

- 左侧：工程菜单、讨论／交接／变化／版本导航、文件，以及常驻的“App 共享包”“标准技术模块”入口。
- 中间：默认创作讨论，代码和其他工作视图按需打开。返回讨论时保留输入和文件草稿。修改建议在讨论内提供参数／代码编辑；实际执行差异属于相应回复的只读记录，“当前文件”进入工程文件草稿编辑。
- 右侧：同一 Monitor 始终保留。拖动分隔线或聚焦后使用左右方向键调整宽度，双击或 Home 复位；展开／还原保持页面状态。打开代码不会自动缩小画面。
- 底部：设备、网络、控制台和设置；控制台只在中间区域下方展开。模式入口沿用 1.6 外观与两步触发，演出模式本身仍参考已定稿原型。
- 最底一行是原型评审工具，不进入产品：三条流程入口、演示状态、四主题和双语。

默认采用 Pond、macOS 系统字体和既有颜色。以中间约 60%、画面约 40% 为起点，不冻结最终像素比例。桌面布局面向 App 既有最小窗口 1000×700；真实 macOS 尺寸和外观仍需人工核对。

## 可以直接体验的流程

### 讨论、改码、体验

正式流程由助手根据当前创作意图与真实工程内容按需提供合适控件，不强制每条回复出现 fader；用户也可主动要求调节某项内容。参数来源、当前值、目标版本和工程限制需核对，模型推测的试调范围与工程硬限制分别表达。以下固定参数只是原型示例。

讨论中的参数卡提供滑块、数值输入、范围和 AI 建议值。调节密度或缓动后，右侧同一 Monitor 立即显示带标记的临时预演：圆环间距和呼吸速度随所选值变化。预演不修改保存版、文件草稿、Git 或实际运行参数；“结束预演”恢复临时覆盖前的参数状态，“恢复 AI 参数”重新试用建议数值并保留其他手写代码。

同一卡片的“代码”入口允许直接修改完整目标单文件的待应用代码，包括非数字的内容。可以将 `title: '潮汐'` 改为其他文字，再点击“预演修改”查看右侧标题。该内容与工程文件草稿分开，切换工作视图仍保留，输入时不写入工程也不执行代码，并结束此前的预演。“预演修改”只呈现当前示例支持的映射；无法预演的代码仍可编辑和明确应用，再手动刷新／测试。参数与代码只在能够准确对应时同步；手改为表达式或其他结构后，无法对应的控件停用并说明原因，保留用户代码。

点击“应用到工程”才把当前参数／代码共同形成的最终建议保存到一个已有文本文件，并生成当次真实差异。可以继续调参后再次应用，每次差异独立保留，历史记录不随滑块变化。原型中应用后预演可继续，正式实现须在本次明确应用后重新核验并保留临时标记；实际运行采用保存版仍待手动刷新／重启。外部或未经核验的来源变化使旧预演失效。手动刷新会退出预演并采用保存值。未保存草稿、外部修改和不合法参数会阻止应用；旧目标需明确从当前文件重载。停止测试、新建工程会结束旧预演，不自动启动或重启。

应用代码同样核对单文件目标、现有草稿和保存版本，冲突时保留待应用内容。实际差异包含保存前后文本，涵盖非数字改动；继续修改产生下一条记录，不编辑或重写之前的执行结果。完整文件编辑器继续作为查看上下文与较长编辑的入口。

从“当前文件”进入编辑器，可以选中代码问助手、查找替换、跳行、缩进、撤销和保存。普通文件保存仍不自动刷新画面。修改 manifest、共享包引用、服务端或 SCD 后，刷新不能消除待重启提示，需手动停止再启动。

本轮仅模拟已知参数与文本的受限映射，不执行输入的任意 JavaScript。已确认的正式方案按具体参数与工程能力判断，不按画面／声音或固定工程类型划界；不注入任意模型生成代码，也不暗中启动或重启音频、服务或工程。[#231](https://github.com/xO-xN/PNDS-App/issues/231) 须提供可审查的参数绑定、版本校验、受限预演与恢复方式，并用真实模型与不同工程验证何时显示控件、如何选参；固定示例不能作为助手已具备该能力的证据。没有适配的修改说明原因，继续采用明确应用与手动测试；复杂或多文件适配进入创作交接单。结束预演不承诺回退工程时间或完整运行状态；恢复失败明确尚未恢复，不自动重启。

“读取当前工程”关闭时，含代码片段的问题不能发送；输入与附件保留。首次发送工程上下文显示范围与模型服务授权。聊天回复是固定演示内容，不能用于评估真实模型质量。

基础编辑器只演示可见交互，不替代生产编辑器验收：语法着色是简化实现；括号配对、全语言语义、外部磁盘版本校验等以正式规格为准。

### 添加 App 共享包与模块

“App 共享包”展示七项实际随附版本。选择后检查用途、运行类型、来源和引用状态，填写新的工程版本再采用。有 manifest 草稿时阻止采用。只保存引用与工程版本，不拷贝包、不改源码接线。

“标准技术模块”展示六项实际 0.2.0 模块，包括可选 Hub。详情展示文件、兼容、接线和验证要点；添加后文件树及交接任务更新，状态明确为文件已加入、待接线验证。已加入项可返回已有交接；目录冲突或相关草稿不被覆盖。原型加入的文件内容明确是占位素材，不能作为发行源码。

### 交接、比较与本地版本

打开“创作交接”，预览任务、文件与验收后确认。存在草稿时可选先保存或仅按保存版交接。保存版基线与 Git 版本分开；复制任务不更新起点。

在原型演示区域点击“模拟外部实现并提交”，外部改动已进入 Git 历史，但“交接后的变化”仍显示文本差异、新文件和资源指纹／大小摘要。查看当前文件、检查和验收入口独立存在。

“记录版本”先选择完整文件与说明，大资源默认不选。外部已暂存的选中文件会阻止记录。历史中单个现存文本只能载入编辑草稿，再明确保存；已有草稿先处理。

工程菜单提供 Blank / Classic 新建表单与初始版本范围预览。原型状态菜单可切换到“已有无 Git 工程”，再从版本页主动启用本地记录。邮箱选填，界面显示本机占位地址；不需要 GitHub 账号。

## 1.6 入口对照

| 入口                                                   | 本原型位置／演示深度                                                   |
| ------------------------------------------------------ | ---------------------------------------------------------------------- |
| 新建 Blank / Classic、打开工程、Finder、工程信息、打包 | 左上工程菜单；创建／范围与打包确认可点击；Finder、打开文件夹为说明演示 |
| 文件、README、manifest、SCD                            | 文件树；README 编辑／预览、manifest 表单入草稿、SCD 编译结果进入控制台 |
| 共享包和标准模块                                       | 左下常驻入口；完整目录→详情→添加状态                                   |
| 手动 None / Internal / External 测试                   | Monitor 下方；选择与实际运行配置分开，External 提供目标输入示意        |
| Performer 手机／平板与横竖                             | Monitor 下方添加独立窗口；支持鼠标模拟触摸、键盘与消息来源核对         |
| 静态检查与独立副本检查                                 | 中间顶栏盾牌；活动运行时仅允许静态检查，不自动停止 Monitor             |
| 主输出、设备、网络、HTTPS、Ports                       | 底栏与设置；仅可见状态示例，不连接真实服务                             |
| 模式切换                                               | 右下两步按钮；说明切换结果，不复制整个演出界面                         |

README 多语言同步、真实文件重命名冲突与完整配置校验等沿用 1.6 契约；此原型展示入口位置与主要关系，不取代既有功能验收。重命名复杂文件引用由交接示意承接。
