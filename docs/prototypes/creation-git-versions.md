# 创作模式工程版本：评估与原型

2026-10-19，七项产品决定已由创作者确认，见 [ADR-0011](../adr/0011-creator-git-version-navigation.md)。[打开 HTML 原型](./creation-git-versions.html)。

## 评估结论

适合采用。主动保存的版本可以成为尝试、比较与返回的明确起点，关系图能让从旧版本继续创作的分叉可见。版本来自 Git，聊天与助手任务恢复仍各自独立；不增加每次聊天复制工程的机制。

这项工作不能只替换现有历史列表。当前原生恢复只把历史内容写回工作文件，HEAD 和分支不移动，随后保存仍以旧 HEAD 为父节点。新方案必须让保存的父版本与界面标示的“当前工程版本”一致，并保留所有已有分支。

图的视觉可以呈树状，数据必须使用真实提交父子关系与分支引用。第一版不提供合并操作；读取已有 Git 历史时也不能捏造或忽略实际的合并关系。图中被选来查看的版本与当前工程版本分别标示。

## 实现边界

- 普通保存先写入全部草稿，再记录符合收录规则的修改。没有修改时不制造重复版本。名称为空时本地生成，不调用模型命名。
- 首次主动保存可以沿既有规则创建独立工程仓库；打开面板或聊天不初始化仓库。
- 从历史版本保存时建立新分支，保留原有分支。分支显示名称与 Git 引用标识需分开处理，避免把空格等命名规则带入日常创作。
- 切换前保存、停止运行和结束助手任务都必须完成后再切换。某一步失败不继续后续步骤；如果部分草稿已写盘但没有创建版本，反馈应如实说明，不暗示所有步骤均未发生。
- 复用原生文件新鲜度校验、一次性预览 token、运行租约、外部暂存保护、受保护路径规则与保存后同步。不能用前端按钮状态替代原生校验。
- 编辑器草稿保存与 Git 收录是两件事。被既有规则排除的内容不能因为“快速保存”而进入版本，也不能无提示地宣称整个工程都已被版本记录覆盖。
- 快速保存不附带模型请求或工程运行检查。文件扫描、草稿保存和资源量决定实际耗时，需要用真实工程验收；原型不证明保存速度。
- 版本图按需读取完整关系并支持受限分页，不能因为当前列表只显示 30 项就把它当成只有一条路线。长期历史仍消耗 Git 存储，需要另行评估整理与容量展示。

## 原型表现

沿用池塘主题的冷灰底、湖蓝操作色与系统字体；同时提供暖沙、暗场切换。本轮只评审 Git 窗口，其余工程栏、编辑器、预览和助手是定位用的示意，不作为 App 现状或整体改版提案。

2026-10-19 根据创作者的新反馈，工程版本改为中间栏的完整切换页，与编辑器、预览平级；取代原先底部展开面板的方案。打开原型默认显示“Git 版本”，左侧工程栏与右侧助手独立于中间页。页内以版本图与版本详情左右分区，窄屏上下排列；当前位置为实心圆，查看版本为外圈强调，未记录修改使用虚线。

切到编辑器或预览、再返回 Git 页，保留正在查看的版本、差异页签、缩放、名称输入和未保存代码，不触发保存、代码切换、运行停止或助手任务结束。点击工程文件进入编辑器；工程菜单中的“工程版本”和“当前修改与差异”进入 Git 页。中间页签支持左右方向键、Home 和 End。

示例工程名为 runes-pnds，内容完全是合成的页面与参数代码。所有状态只存在于页面内存；不访问真实工程、Git、模型、依赖资源或本地文件接口，刷新即可重置。

可从顶部“演示场景”选择：

1. 有未保存修改：选择旧版本，再保存当前修改后切换。
2. 所有修改已记录：直接切换，或先查看文件差异。
3. 工程运行中：明确停止并切换，完成后保持停止。
4. 助手任务未完成：明确结束任务，保留代码与聊天，再继续切换。
5. 文件保存冲突：保留草稿，阻止版本记录和切换。
6. 首次保存版本：创建起点，不对无变化的工程重复记录。

从起点或其他旧版本切换后，进入“预览”调整字号推子，再返回“Git 版本”保存当前版本，即可观察新的父子关系与分叉。可选填版本名称和新分支名称。
