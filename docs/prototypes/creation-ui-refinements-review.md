# 创作模式精简与助手工作流评审

2026-10-21，采用 grill-with-docs。七项产品选择已逐轮确认；第二轮 HTML 调整后，创作者已整体确认原型，并授权据此修改正式界面、助手工作流、Git 名称和双语 PNDS 文档。

[打开独立 HTML 原型](./creation-ui-refinements.html)。直接用本地浏览器打开，无需启动服务。底部深色条是原型控制，不属于产品界面；所有操作仅修改内存，刷新重置。现有工程、模型、Git 和偏好均不接入。

## 已确认的决定

| 问题               | 结论                                                                                                                              |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| Q1：助手与模式名称 | 助手栏名为“PNDS 创作助手”；中文模式名为“讨论 / 工作”。内部 edit 的技术标识不随中文改名改变。                                      |
| Q2：常态信息       | 收起“自动同步”“历史服务端用量”“估算 XX%”常驻文字；点击或键盘操作可查详情，异常继续明确显示。                                      |
| Q3：讨论收束       | 关键缺口谈清后，助手在当前回复提出写交接文件或交给内置助手实施；用户选择后继续，也允许自然语言触发。输入框下移除原三个固定操作。  |
| Q4：版本命名       | 所有本地已保存版本可改显示名，保持 Git 提交身份；默认沿当前工程版本所在名称系列递增，跳过已用序号。查看的历史版本不成为续号依据。 |
| Q5：开始工作       | 回复先说明已确认目标、范围与验收。点击“开始工作”立即创建新任务实施，同时将输入框下方模式切到“工作”。单独切换模式仍不启动任务。    |
| Q6：改名后续号     | 只改选中版本，不批量更名。当前版本改为“流动”后，下次默认“流动 1”；同名系列已有序号时取后续未占用序号。                            |
| Q7：自然语言整理   | 用户明确说“帮我整理一下工程代码库”即开始新工作并同步切模式；助手主动建议时等用户选择。补充规范通过文字或指定文档／资料表达。      |

用户原始要求同时确定：输入框与 PNDS 文档说明“想法 → 讨论实现方式 → 外部编程智能体或内置助手实施”。原型在新对话、讨论输入框和“创作指南”提供这段指引；工作模式输入框则提示描述明确任务，减少重复。

领域名称已记入 [CONTEXT.md](../../CONTEXT.md)。原型阶段未新增 ADR；正式实施后，讨论转工作边界记入 [ADR-0008](../adr/0008-creator-handoff-as-agent-seam.md)，本地版本显示名称的存储与对外互通记入 [ADR-0011](../adr/0011-creator-git-version-navigation.md)。

## 设计树与当前边界

- 信息层次 → 三项常态文字隐藏 → 同步／上下文图标与回复详情 → 异常继续直接显示。
- 讨论 → 关键问题与推荐 → 已确认方案 → 两条下一步路线。
  - 外部实现 → 可编辑交接草稿 → 正式记录与比较基线 → 用户交给外部编程智能体。
  - 内置实现 → “开始工作” → 模式同步选中“工作” → 新任务继承已确认目标、范围与验收。
- 整理工程 → 助手提议需选择；用户明确指令可直接开始 → 补充规范仍属于同一整理任务。
- Git → 查看与当前版本分开 → 紧凑方向栏与大代码区 → 显示名修改及当前系列续号。

保持讨论中的普通澄清只读；回答创作问题本身不会启动工作或写交接。Q7 新增的明确工作指令转交需要在正式实现中作为独立调度处理，不能让任意讨论工具获得写权限。

## 可点击核对

1. 默认“方案已确认”中点击“开始工作”，检查下方“工作”被选中，并出现工作中反馈。仅手动切换模式则仍等待任务。
2. 重新选择该场景，点击“写交接文件”，修改草稿；取消保持原状态，正式记录后才进入交接文档示例。
3. 在“讨论中”选疏密或速度，检查收束摘要及交接内容跟随选择；回答后仍停在讨论。
4. 在新对话输入“帮我整理一下工程代码库”，检查直接切到工作；“整理建议”场景则等用户选择。输入框下不再有三个固定操作。
5. 点击上下文圆环、回复右侧更多、侧栏右下同步图标，检查信息可查。切换“上下文超限”，检查警示直接可见。
6. 打开 Git，查看版本与“当前”位置各自独立。改名历史版本不影响下一版名称；改名当前版本后，下次名称按新系列递增。保存一次后，底部“模拟新改动”可准备下一次演示保存。
7. Git 的 A 为统一差异，B 为并排差异。工具栏保留完整修改方向；代码上方不再显示“前 / 后 / 代码差异”或“修改前 / 修改后”标题行。通过工具栏分段按钮、底部箭头或 `?variant=A` / `?variant=B` 切换布局。
8. 核对 1000 × 700、1280 × 800 下的密度及 Pond／Stage／Sand 主题。底部原型控制占位不代表正式 App 的底栏高度。

差异代码固定为界面示例，不是每个模拟版本的真实快照；不覆盖实际文件切换、分叉保护、磁盘冲突或运行验收。版本名称仅在原型内存中保存；没有修改 Git 历史。

## 第二轮原型调整

2026-10-21，创作者查看原型后提出五项调整，均仅修改本 HTML：

- 文件栏右下同步状态改为双向箭头，继续点击查看状态，不用对勾表达监听状态。
- 统一与并排差异都删除重复的列标题行，保留版本方向、文件名、行号与增删颜色；读屏标签继续区分修改前后。
- “统一 / 并排”改为两个直接可见的分段按钮，当前选择有明确高亮。
- 模型名称与右侧按钮间距为 16px。空输入时按钮弱化禁用；有内容时显示强调色发送箭头；回复中和工作中显示旋转加载环与居中的停止方块，点击停止本次演示，保留输入中的新草稿。工作状态同步选中“工作”，进行中禁用手动模式切换。
- 助手输入框移除手动缩放手柄；交接审阅窗口的文本编辑保持原有行为。

底部新增“助手回复中 / 助手工作中”场景，可直接核对持续加载状态；普通讨论发送也会短暂显示回复中状态。系统要求减少动态效果时加载环保持静止，状态和停止操作仍可用。

## 原型评审时的差异及正式文档位置

原型评审时，App 版本名写入 Git 提交消息，没有保存后更名入口，默认名来自时间戳；统一差异表头在窄行号列显示“修改前／后”，导致折行。正式实施已接入显示名修改与当前系列续号，名称元数据写入本地仓库配置，保持提交不变；重复表头已移除。见 [local-git.md](../developer/local-git.md) 与 `CreationGitDifference`。

正式修改时在既有双语语料更新推荐工作流、两模式用途、整理触发、补充规范、交接审阅与版本改名：
