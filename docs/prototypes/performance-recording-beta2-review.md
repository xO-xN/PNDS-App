# beta.2 演奏记录 UI／UX 原型

状态：2026-11-03 用户要求 Q16 先以 HTML 核对；Q17 自动保存收尾、Q18 断线期间时间继续均已确认。布局尚未定稿，未实施正式录制功能。

[打开独立 HTML](./performance-recording-beta2.html)。单文件可直接打开；本轮本机预览为 [A 底栏小面板](http://127.0.0.1:64268/performance-recording-beta2.html?variant=A&mode=creation&project=iii&theme=pond&lang=zh-CN&scene=library)。

## 这次核对什么

同一个底栏入口如何展开，才能方便录制与回放，同时保留乐谱画面。原型采用既有 PNDS 桌面系统字体、32px 顶栏、50px 底栏、四主题及当前创作／演出外框；主题颜色取自现有 `theme-variables.css`，不提出 App 整体改版。

| 方案                      | 结构与主要区别                                                             |
| ------------------------- | -------------------------------------------------------------------------- |
| A：底栏小面板（当前建议） | 底栏入口上方打开，列表进入单份详情；收起后继续，适合操作后把注意力放回乐谱 |
| B：右侧抽屉               | 非模态，列表在上、详情在下，同时保留；浏览更方便，占用的画面更持久         |
| C：居中对话框             | 左侧列表、右侧详情；焦点集中在记录，操作作品 START 前需要收起对话框        |

版式以 `?variant=A|B|C` 切换；下方独立评审条及左右方向键也可切换。输入框、下拉框编辑时不拦截方向键。三个布局共享同一份内存状态，切换布局本身不终止录制。

视觉计划：Pond 的桌面底色 `#dce4ec`、工作区 `#fcfdff`、面板 `#ffffff`、文字 `#293541`、强调墨色 `#285a8d` 与录制红 `#9d3043`，沿用既有主题的角色映射；系统字体以 11–13px 控件及 15–18px 标题保持桌面密度。录制经过时间使用等宽数位，不引入音频波形、轨道编辑器或准备流程。

## 可操作流程

- 打开记录列表、查看详情、从头回放；创作模式可叠加新演奏者、对已有演奏者整位重录。
- 记录中的演奏者用 A、B、C 区分，工程的乐谱序号另列；同序号可以出现多位记录演奏者。“同序号多人（Runes）”样例显示 A 和 B 都选择 3，新增叠加形成 C，重录 A 不覆盖 B。该信息只展示工程提供的记录属性，不增加编号准备检查。
- 首次录制直接起录，用户自行选择编号和准备；App 没有编号监控、准备确认或强制选择输入设备。
- 收起面板后状态与计时保留在底栏；重新打开继续当前操作。
- “停止并保存”保留本遍并更新合并记录；“放弃本遍”保留旧记录；到固定末尾自动保存，已有演奏者不重复追加。
- runes 的作品 START／暂停／进度条属于作品画面。首次录制可操作，并保存实际相对时刻；回放／叠加自动驱动同一指挥过程，作品控件锁定。记录计时与乐谱进度分别显示。
- 关闭／重启当前运行前自动保存本遍；模式切换按实际是否保留运行分别接续或收尾，不为记录额外增加确认。
- 断线场景继续计时，可模拟重连或自行停止、放弃。
- 演示未完成记录、当前工程内容变化后的明确选择、未接入工程的不可录制状态。

原型附带记录菜单、重命名、删除确认以及未完成记录回放已保存部分的呈现建议，仍待本次 UI 核对，不据此扩展已确认范围。导出／打开记录仅模拟结果，不读写实际记录文件。真实设备、工程、端口、声音和断线均未连接；艺术画面为示意，不用作作品视觉或声音等价证据。演出外框只展示池主场景，池客入口沿用独立的[角色原型](./performance-roles-1.7.1.html)。

## 评审控制条

底部“HTML 交互原型”区域在 App 外框之外，不属于产品。

`scene` 可取 `library`、`shared`、`empty`、`recording`、`replay`、`overdub`、`replace`、`incomplete`、`changed`、`offline`、`unsupported`。`shared` 载入 runes 的同序号双人创作样例。可切换 `mode=creation|performance`、`project=iii|runes`、`theme=pond|sand|stage|brutal`、`lang=zh-CN|en`。

“10×”与“推进到结束前”仅缩短演示等待，不是 App 的变速或定位功能。“查看演示状态”显示当前记录、经过时间、乐谱进度、已有演奏者、重录目标和指挥事件。切换场景／示例工程会载入新样例；刷新或重置页面清空内存修改。

双语文案源文件为 `locales/prototype-performance-recording.zh-CN.json`、`.en.json`；HTML 内嵌同份数据以支持离线打开。修改时同步内嵌副本，以解析后的键和值比较，保持两语键集合一致。所有图片、图标及示意谱面均在 HTML 内，不依赖网络或单独资源。

## 本轮验证

在内置浏览器的默认 1280×720 视口及 784×829 窄窗口核对布局；检查 Pond／Sand／Stage／Brutal、中文／英文、演出／创作以及三种布局。键盘焦点可见，Esc 收起并返回入口；C 与确认框约束键盘焦点。评审条高度变化时为 App 外框保留空间。

实际点击核对：首次录制无准备门槛；收起／重新打开时计时继续；两人叠加保存为三人；重录第二位时旧第二位不参与回放，放弃后原记录保留；末尾自动保存；关闭测试自动保存且没有新增确认；版本差异确认和断线状态。

本轮身份澄清后再次点击核对：A、B 都显示乐谱序号 3；重录 A 时已有回放只列 B→3；保存后再叠加，形成 A→3、B→3、C→5。该模拟只按记录身份选择和替换，不按乐谱序号合并。见[同序号示例截图](./performance-recording-shared-number-preview.jpg)；实际工程的多来源声音仍待正式适配验收。

runes 从空记录起录，首次在记录第 5 秒点击作品 START。状态区显示 `{ at: 5, playing: true, position: 0 }`；下一遍记录第 9 秒时乐谱进度为第 4 秒，且手动指挥控件禁用。这只证明原型时间模型，不证明实际工程协议、跨设备或声音同步。

最终 `npm run check:all` 全绿，双语内嵌数据与文案源文件解析后逐项一致，独立脚本语法检查通过，浏览器控制台未见警告或错误。外接缓存盘未挂载，本次检查临时使用已有本地 Rust 缓存，没有修改机器配置。可查看 [A 详情截图](./performance-recording-preview.jpg)及 [C 对话框截图](./performance-recording-dialog-preview.jpg)。

原型没有新增自动化测试，不将内存交互与 `check:all` 视为真实功能验收。正式实施仍须用户先确认完整方案，并按 [设计讨论](../plans/v1.7.0-beta.2-performance-recording-design.md)验证工程适配和实际声音。未 commit 或启动 App dev server。本机静态预览仅绑定 `127.0.0.1:64268`，只返回这一份 HTML，不提供源码目录。
