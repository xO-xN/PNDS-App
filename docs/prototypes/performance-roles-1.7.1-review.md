## 当前启动规则：默认池主与记忆角色（2026-11-03）

用户进一步决定：首次打开默认池主，之后每次打开 App 直接恢复上次使用的角色，覆盖此前“每次进入重新选角色”的启动选择；2026-11-04 已确认与 B 布局一起接入 App。正式记忆使用 `lastPerformanceRole` 偏好，缺省为 `host`，写入通过 `src/lib/preferences.ts` 串行队列。成功的显式角色选择才保存，打开菜单、当前项关闭、活动拒绝和取消均不记忆；保存失败需反馈，不宣称该选择已保存。恢复仅决定角色界面，不自动启动工程、加入演出或启用媒体，原生活动快照优先。Creation 的原生清理事务保持不变；成功进入后 `resetRole` 仅清当前角色和菜单、保留本次 `lastRole`，成功返回演出后，`enterPerformance` 仅在 `preferencesRestored=true` 时选择本次 `lastRole`；首次偏好未读完则保持 `role: null` 等待，不能在启动中创作往返时误用暂存默认池主。不自动启动／加入或恢复媒体，也不清除已保存偏好。

正式前端的 `restoreRolePreference` 只处理首次偏好装载，晚到结果不能覆盖原生活动或当前显式选择；初始 `role: null` 只表示启动准备中，`AppShell` 不展示旧选择卡片，偏好读取失败回落池主。显式选择通过 `commitRole` 同步更新界面及本次 `lastRole`，再排队保存；失败不回滚当前会话，须通知下次打开可能恢复原先保存的角色。以下浏览器专用记忆是原型演示机制，不能代替正式偏好队列。

`scene=launch` 或无场景参数按专用浏览器记忆启动；历史 `scene=entry` 也转到此入口，不再显示首次角色卡片。无有效记忆时默认池主；已记忆池客时只进入池客连接页，不恢复演出、旧谱面或媒体。未命名池主仍需原命名步骤，不以电脑名称回退。节点名不属于此次浏览器持久化范围，硬刷新重置命名示例不代表正式 App 的节点名偏好会丢失。

评审条「重新打开 App」取消旧页面示例、媒体意图、菜单／刷新确认与计时器，再从记忆进入对应空闲页；「模拟首次打开」仅删除本原型 `pnds-role-prototype:last-role` 这一项，不清除其他网页数据，也不会立刻把默认池主写回。读／写不可用时在评审状态中如实显示，合法角色只接受 `host`／`client`。只有成功的显式角色选择写入；活动锁定拒绝、打开菜单、当前项关闭或场景对照均不写。

启动流程始终保留 `scene=launch`，即使演示中已加入演出，硬刷新也只恢复角色并回空闲。用户明确选的 `host-live`／`client-live` 等参数仍是评审场景，不被误当成启动恢复。

本轮已用一次性 DOM 走查验证跨新页面恢复、非法值和存储异常、评审场景不污染记忆、仅清专用 key，以及加入／加载中重开取消旧计时器。实际浏览器核对了首次默认池主、选择池客后硬刷新仍进入未连接的池客页、模拟首次打开回到池主并保留命名门禁。`npm run check:all` 全绿；这些仅验证当时的 HTML，不能作为本次 App 启动记忆接入的验证结果。

`scene` 参数或评审条提供：

- `launch`：按角色记忆启动，首次默认池主；历史 `entry` 为此入口别名。`host-name`、`host-idle`、`host-live`：池主命名、准备、运行。
- `client-idle`、`client-opening`、`client-wait`、`client-live`、`client-lost`：准备、加载、待接纳、已加入与短时断线。
- `client-unknown`：谱面可用，但工程未提供接纳状态。
- `client-changed`：旧页面移除、媒体示例状态释放，明确加入后才展示新工程。
- `client-ended`：本次参与结束，检查并明确重新加入。
- `client-host-changed`：地址返回不同池主，保留原记录，确认后才进入新池主。
- `client-incompatible`：池主协议不兼容，提示升级，不打开工程页面。
- `host-auto-ports`：首选端口占用后的运行场景，突出可复制的实际地址，展开后区分局域网入口与工程的两个实际服务端口。
- `host-port-conflict`：旧工程未适配运行端口分配，冲突时不启动，可重试或选择其他工程。
- `client-project-incompatible`：池主协议可用，但工程实时连接使用固定地址，提示具体适配原因，不误报为池主需升级。
- `client-refresh-changed`：当前谱面正常；两击刷新后才发现演出变化，旧页面释放，明确确认后才加入新工程。
- `client-unreachable`：无法加载池主，保留输入／最近连接，提供重试或返回；断线后的主动刷新也可进入该状态。

池客刷新首击在同一个底栏按钮中显示「再次点击刷新谱面」，保留当前页面与媒体示例状态；Esc、外部点击或窗口失焦取消。第二击才移除旧页面并重新核验，刷新中继续拒绝角色切换；未知接纳工程刷新后仍显示未知。换场景、离开与切角色均清理旧确认／计时器，避免迟到回调重新加入。

本轮端口示例为局域网入口 `7340`／避让后的 `7341`，工程服务为 `6868`／`6869` 或 `52341`／`52342`；这些值只供视觉核对，不冻结正式默认端口。复制提示与显示地址使用同一实际值，原型不会改写真实剪贴板。最近连接只在明确加入成功后更新，不因为池主示例地址变化而自动改写。

用户已确认正在连接、待接纳、断线重连和退出清理均视作尚未退出，期间拒绝角色切换。已核实演出结束／变更并完成释放后的页面仅是通知，不继续持有旧演奏页面。

评审条属于原型，不进入产品。主题支持 Pond/Sand/Stage/Brutal；语言支持简体中文／English。「评审时固定侧栏」便于核对角色入口，取消后运行时通过左缘或按住 ⌘ 唤出。池客示例中的摄像头控件属于工程页面，不是 App 的通用传感器面板。
