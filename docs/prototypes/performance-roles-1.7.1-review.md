## 当前 A 方案

每次进入演出模式先在左侧选择角色。进入后不提供角色下拉菜单，改为同一个斜线按钮；它参考此前右下角按钮的斜面露角、半幅确认与填满切换。

| 状态                    | 按钮行为                                                 |
| ----------------------- | -------------------------------------------------------- |
| 空闲                    | 显示当前角色；悬停或键盘聚焦时显示目标角色。             |
| 首次点击                | 同一按钮显示「再次点击切换角色」，不替换按钮 DOM。       |
| 第二次点击              | 斜面填满后切换到另一角色；减少动态效果时立即完成。       |
| 演出中点击              | 拒绝切换，只在按钮内提示先退出演出；不关闭演出、不弹框。 |
| Esc、外部点击、窗口失焦 | 取消未提交的确认，保留角色和运行。                       |

本地演出、页面打开与工程接纳分别表达。池客侧栏显示当前池主名称和连接信息；最近连接列出池主节点名，工程名只显示在演出信息中。选择未命名的池主角色时，原型在侧栏展示节点名填写步骤；不采用电脑名回退，不要求 hub 地址或 token。

`scene` 参数或评审条提供：

- `entry`：未选角色；`host-name`、`host-idle`、`host-live`：池主命名、准备、运行。
- `client-idle`、`client-opening`、`client-wait`、`client-live`、`client-lost`：准备、加载、待接纳、已加入与短时断线。
- `client-unknown`：谱面可用，但工程未提供接纳状态。
- `client-changed`：旧页面移除、媒体示例状态释放，明确加入后才展示新工程。
- `client-ended`：本次参与结束，检查并明确重新加入。
- `client-host-changed`：地址返回不同池主，保留原记录，确认后才进入新池主。
- `client-incompatible`：池主协议不兼容，提示升级，不打开工程页面。
- `host-auto-ports`：首选端口占用后的运行场景，突出可复制的实际地址，展开后区分局域网入口与工程的两个实际服务端口。
- `host-port-conflict`：旧工程未适配运行端口分配，冲突时不启动，可重试或选择其他工程。
- `client-project-incompatible`：池主协议可用，但工程实时连接使用固定地址，提示具体适配原因，不误报为池主需升级。
- `client-refresh-changed`：当前谱面正常；两击刷新后才发现演出变化，旧页面释放，明确确认后才加入新工程。
- `client-unreachable`：无法加载池主，保留输入／最近连接，提供重试或返回；断线后的主动刷新也可进入该状态。

池客刷新首击在同一个底栏按钮中显示「再次点击刷新谱面」，保留当前页面与媒体示例状态；Esc、外部点击或窗口失焦取消。第二击才移除旧页面并重新核验，刷新中继续拒绝角色切换；未知接纳工程刷新后仍显示未知。换场景、离开与切角色均清理旧确认／计时器，避免迟到回调重新加入。

本轮端口示例为局域网入口 `7340`／避让后的 `7341`，工程服务为 `6868`／`6869` 或 `52341`／`52342`；这些值只供视觉核对，不冻结正式默认端口。复制提示与显示地址使用同一实际值，原型不会改写真实剪贴板。最近连接只在明确加入成功后更新，不因为池主示例地址变化而自动改写。

用户已确认正在连接、待接纳、断线重连和退出清理均视作尚未退出，期间拒绝角色切换。已核实演出结束／变更并完成释放后的页面仅是通知，不继续持有旧演奏页面。

评审条属于原型，不进入产品。主题支持 Pond/Sand/Stage/Brutal；语言支持简体中文／English。「评审时固定侧栏」便于核对角色入口，取消后运行时通过左缘或按住 ⌘ 唤出。池客示例中的摄像头控件属于工程页面，不是 App 的通用传感器面板。

界面文案源在 `locales/prototype-performance-roles.zh-CN.json` 与 `locales/prototype-performance-roles.en.json`；两份 JSON 同步内嵌以支持直接打开文件。所有状态仅存在内存中，刷新按显式评审场景重新开始；最近池主、节点名、地址、座位和摄像头均为示例，不读取真实偏好。

## 历史方案与决定

第一轮比较了 A（先选角色，进入后收拢）、B（常驻双角色分段）与 C（预览职责后进入）。用户选择 A，并否决角色下拉菜单与演出中通过弹框自动结束后切换的提案。当前 HTML 已收敛为 A；旧 B/C 不再作为可切换方案。

用户进一步明确：池客参与的是局域网内的本地演出，不能称为跨互联网或远程演出；最近连接按池主节点名显示；池主必须显式填写节点名。完整问答与实施前未决项见[设计讨论](../plans/v1.7.1-performance-roles-design.md)。

## 验证与边界

第一轮曾在 784×829 与 1280×820 视口核对三种布局和四主题，首次完整检查遇到既有 Rust fixture 的临时端口冲突，未修改该测试，重跑 `npm run check:all` 通过。该记录是第一轮证据，不代替本轮修订的验证。

第二轮已完成 HTML 脚本解析、双语文案源一致性与受控 DOM 操作：确认同一按钮存活、Esc 取消、空闲两次点击切换、运行中连续点击仍被拒绝、节点名阻止未命名池主启动、最近连接按池主名显示以及英文角色标签不混入中文。受控 DOM 不做布局测量，也不证明真实媒体或双机连接可用。

内置浏览器控制接口本轮暂不可用，已通过 Safari 核对同一 localhost 原型：中文首击确认、第二击进入池主命名步骤、英文演出中拒绝切换并保留在线状态。斜面按钮改用既有玻璃按钮墨色，四主题在动作底色上的文字对比分别约为 5.91、5.89、6.79、9.26，达到普通文字 4.5:1 要求。第二轮最终 `npm run check:all` 全绿；本轮没有修改正式 App 的业务实现。

第三至第五轮已确认：短时断线保留谱面并沿用工程逻辑；明确退出、池主结束或换工程后释放旧页面；新演出须明确加入。稳定池主身份用于最近连接，地址返回不同身份须先核对，退出后回到池客连接页。无工程接纳上报时只显示谱面已打开／状态未知。

受控 DOM 已走查新增场景：断线保留媒体开启意图，换工程后旧示例页面被移除，明确加入才显示另一工程；演出结束不自动加入；地址身份变化后原池主记录保留，新记录只在确认后写入；不兼容与无接纳状态分别显示。这里的页面移除和媒体释放仍为示例 DOM／状态，不是实体 WebView 或摄像头验收证据。Safari 已核对演出变化提示的实际布局，以及点击明确加入后才开始加载并显示新工程示例。扩展场景与规格草案完成后，`npm run check:all` 全绿。

当前 Host 的标准 HTTP 元信息尚不公开设置中的节点名，原型名称仅为合成数据。正式实施需增加名称公开路径与本地命名门禁，不能仅把工程名称换成节点名称。按钮、复制、设置、创作、加入与媒体控件均为内存演示，不请求真实网络、摄像头、麦克风或工程。

预览服务按用户明确授权启动，仅绑定 `127.0.0.1:64267`，只提供原型、主题 CSS 与品牌图标副本，不发布源码仓库。
