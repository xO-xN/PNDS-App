## 制作原型时的实现事实

- 目前文件侧栏采用类型分类，并非真实目录树；分类旁的新建位置由已有文件或默认目录推算。
- 左侧刷新只同步磁盘文件，后台已经每秒执行同一同步；底栏刷新重新加载运行中的保存版页面，不保存草稿，也不重启工程进程。
- 重命名位于文件编辑器的更多菜单，无文件列表快捷入口；现有重命名不自动改写代码引用。
- 顶部“检查”菜单包括静态诊断与临时副本运行检查，两者动作和执行条件不同。内置助手使用共享调度而保留各自策略。
- 当前 Git 具备本地分支和版本位置数据，但按版本切换的实现进入 detached HEAD。选择命名分支并继续推进其分支不是当前独立 API；原型须清楚区分分支位置和历史位置，不能把示例呈现当作已实现能力。
- 助手直接维护交接文档与手动确认交接的旧基线流程分别独立。本轮确认收拢 UI，不隐含删除历史基线或修改既有比较数据。

3. 文件区：真实目录树 → 新建文件/文件夹、统一资源入口、树内重命名，已确认。
4. 刷新：自动同步与底栏刷新页面已确认 → 原型体现二者职责。
5. 检查：调试栏菜单及问题数量已确认 → 原型体现静态检查与副本运行检查的区别。
6. Git：当前位置及分支列表已确认 → 原型演示分支位置、历史位置及受保护切换。

布局沿用本评审记录；命名分支切换的事务边界补充到 ADR-0011 与本地 Git 开发文档，不改变交接存储。领域名称继续沿用仓库 `CONTEXT.md` 的“创作交接单”“工程版本”“当前工程版本”，不把该评审文档当作术语表。

## 原型与评审方式

[交互原型](./creation-workspace-ui.html) 可直接作为本地 HTML 打开。沿用当前 App 的 Pond 配色、32px 顶栏、226px 文件栏和 50px 底栏；原型底部黑色评审条独立于产品界面，可切换三种主题、助手任务和检查问题场景。窄桌面适当收缩区域。

可依次评审：

1. 三页签切换，交接文档预览 → 编辑 → 切页 → 保存，确认正文和草稿保留。
2. 展开真实目录树，筛选、新建文件/文件夹，文件行右键或 F2 更名；遇同名目标应保留输入。
3. 从统一资源面板切换模块/共享包，观察加入模块后的示例目录和两类用途说明。
4. 调试栏更多菜单发起静态检查或副本运行检查；用评审条的问题场景查看数量提示与文件定位。
5. 模拟运行后分别刷新页面、重启测试，观察页面加载次数和进程启动次数的区别。
6. 顶部分支菜单和完整版本图分别选择分支或旧版本。单击图中节点只查看；真正切换展示保存、放弃、运行及未完成助手任务保护。历史位置保存会形成新路线。

文件正文、助手回复、检查结果、运行页面与 Git 数据均为明确的示例。Markdown 渲染器只为原型提供标题、列表、强调、代码和任务框的安全展示，不代表 App 已采用该实现；正式实现应复用现有安全 Markdown 组件。副本检查不验证原作视觉一致性。原型不安装依赖、不联系模型、不启动工程、不接触真实 Git 和文件。

本地 jsdom 点击回放用于核对交互脚本；它不能验证像素布局、原生窗口或真实分支切换。本次内置浏览器安全策略拒绝本地 `file://` 页面，未完成浏览器视觉验收；布局由创作者打开 HTML 后继续评审。
