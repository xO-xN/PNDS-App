## 建议核对的流程

1. 演出模式选择作品、加载，核对单一按钮的更改 / 关闭状态；离开侧栏看全窗口 Monitor，再移到左边缘显示侧栏。
2. 悬浮模式按钮，核对斜切色块、两次点击确认及取消，以及切换后指针停留时的新模式静止样式；文件夹工程直接进入同一工程创作，工程包进入创作首页。切回演出模式应回到开始界面。
3. 编辑源码或 README，保存后核对手动刷新 / 重启提示；添加多个 Performer 测试窗口，核对手机 / 平板、横屏 / 竖屏、各窗口状态和它对 Monitor 的互动；核对 Monitor 全屏预览及返回。
4. 悬浮工程标题并切换到另一文件夹，核对取消与未保存确认；查看 manifest 表单、音频素材的 Finder 入口、模块添加与交接任务、控制台第二页、测试音频切换、生成 `.pnds` 的保存位置。
5. 切换 v1.7，使用演示 API 配置，核对工程概况、第一次发送工程内容的确认、来源清单、建议转交外部 agent 的任务与聊天中的 Skills 提醒。
6. 新建演出文件夹，打开工程加入其中；核对编组成员独立、工具视图隐藏下拉及返回入口，以及列表切换不影响运行中的 Monitor。
7. 查看 SCD 工具栏编译入口与控制台结果，核对未保存保护和待重启提示；在设置查看 Ports 调试，使用外部占用演示核对释放确认，再在运行中核对端口保护。

所有工程、文件、运行、保存对话框和助手回复都是本地演示。原型不读写用户工程，不启动音频或工程服务器，不打开 Finder，不调用模型 API，不存储密钥。刷新浏览器会重置状态。

空间分配、信息层次与关键操作已经定稿；开发验收以正式版本规格为准，原型用于视觉和交互对照，不代表真实运行能力已经实现。
