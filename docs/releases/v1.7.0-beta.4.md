## 创作工作台与工程文件

- **新建工程与创作首页。** 从创作首页或工程菜单新建，也可从最近工程列表继续创作。新工程统一使用 Blank，自动初始化本地 Git 并记录初始版本。表单集中显示本机位置、GitHub 仓库目标及可见性，支持公开、私有或仅本机。模板包含独立工程身份、演奏者座位恢复、共享 monitor 状态和触控示例。已有 Classic 工程仍可打开并继续使用。
- **内置编辑器。** 用文件树或侧栏路径筛选打开文件，支持语法着色、括号匹配、当前文件查找替换、跳行和撤销重做。可新建、重命名文件和目录，拖到 Finder 可复制保存版。遇到外部保存与草稿冲突时，可比较后选择保留草稿或采用磁盘版。
- **保存和测试。** 可调整编辑区与 monitor 的宽度，在独立控制台窗口检查启动日志和编译结果，关闭控制台后保留工作台编辑状态。页面改动保存后可刷新，服务端改动需重启测试，SCD 改动需先编译 SynthDef。可用本机 SuperCollider 打开已保存的 SCD，并在 App 里保留未保存草稿。
- **收件箱与待处理资源。** 可新建、导入、编辑和保存代码或文本，旧创作资料可迁入；也可导入图片和音频，预览图片并通过所选输出试听音频。助手按需读取保存版文本及媒体元数据。在一次工作任务中可接入多份文档或媒体，审阅同名冲突并选择替换、并存或取消。接入失败时保留原文和资源，成功后可跨重启审阅和撤回最近一次接入。

## 创作助手、交接与工程诊断

- **自配模型服务。** 在设置里填入支持文本和工具调用的 OpenAI 兼容地址、模型名和密钥，可先测试连接。密钥保存在 macOS 钥匙串，工程聊天与资料放在私有创作数据中，随完整源工程目录携带。
- **讨论与工作。** 讨论用于读资料、逐题澄清和拟定方案，回复与方案随实际模型流显示。确认后进入工作模式，执行明确的多文件修改、检查和所需的 SynthDef 编译。可暂停和继续任务，审阅差异，并在文件版本允许时撤回。
- **来源、聊天和上下文。** 可审阅发送的保存版文件或显式附加的编辑器选区，查看回复引用的帮助来源和预计上下文用量。保存版文件可拖入助手，在消息中附加文件引用与 `@` 技能。每个工程可建多个聊天，支持历史搜索、改名和删除；重发旧问题会保留原聊天并创建分支。可审阅并采用长聊天摘要。
- **文件盘点与 README。** 新增只读文件盘点及双语 README 工作流，可按实际读取证据整理文件用途、引用和待核对项；动态引用仍需结合工程运行验证。
- **参数与代码建议。** 可在建议卡调整参数或编辑代码候选。适配预演的工程可临时查看画面或试听效果。确认应用后才写入工程，文件变化或已有草稿时先处理冲突。
- **手动交接。** 在讨论中审阅并记录交接文件和提示词，交给外部 agent。返回后用保存版基线对照文本差异及资源指纹，核对工程改动。
- **App 和 CLI 工程检查。** `pnds check` 可检查保存版 manifest、路径、依赖及产物，并输出 JSON。带 `--run` 时在临时副本检查 health 和页面 HTTP，可取消并清理。受控检查支持工程允许的 None，或明确选择 Internal。真实设备和音画可用实时测试核对。单文件修改也可先审阅差异，再保存或按版本保护撤销。

## 本地版本与 GitHub

- **内置本地 Git 与版本历史。** 可在无 Git 的文件夹工程中主动启用版本记录，预览纳入范围和署名。在版本历史内保存当前版本、改名，查看按实际父子关系绘制的版本树及常驻文件差异。可将历史文本载入草稿，在处理完草稿与运行状态后切换路线、恢复内容，或从旧版本继续并建立新路线。依赖缓存、构建产物和私有创作资料有独立排除规则，大型媒体默认不选。
- **审阅合并候选。** 本地路线合并先生成独立候选，可查看文本、图片和音频差异、处理冲突，并使用候选专属助手、检查与运行测试。明确完成后才写回工程；未完成的候选可保留并继续。合并后的编辑器同步保留较新输入，已删除文件的旧保存副本不会变成虚假冲突草稿。
- **GitHub 创建与同步。** 登录并授权 PNDS GitHub App 后，可从官方 Blank 模板创建公开或私有仓库，也可绑定空仓库或与工程共享 Git 历史的仓库。已有本机工程可核对目标、可见性、当前路线和已保存历史后首次上传。首次上传中断后可继续原操作，期间新保存的版本和草稿留在本机。可手动备份当前路线已保存的历史；完成该路线首次备份后，才可为它单独开启自动备份，新路线默认保存在本机。离线期间可继续保存本地版本，回到对应工程与路线后可续备份。远端同名分支可快进时可主动更新，远端历史分叉仍需先用外部 Git 工具处理。
- **换机接续与绑定管理。** 可从 GitHub 克隆公开仓库或获授权的私有仓库到新目录，打开后绑定来源仓库，默认手动备份。可在管理入口更换或解除绑定，旧队列随原绑定解除。首次向公开仓库备份、重建已删除的远端分支会提示确认。旧工程级自动备份设置升级为暂停，保留身份、历史、绑定与待传记录，再按路线重新确认。

## 模块、共享包与原生设备

- **离线资源。** 在创作工作台浏览模块和共享包。添加模块会把源码加入工程供作者维护。共享包通过 manifest Schema 2 引用 App 内固定版本，包括 p5、ml5、Express、qrcode、Socket.IO 和 osc-min。自带依赖的 Schema 1 工程仍可运行。采用共享包的 `.pnds` 携带版本引用，接收端需具备对应版本。资源确认卡会列出依赖和冲突，创作助手可在作者确认后接续采用与接线。
- **标准模块和 hub。** 模块手册覆盖演奏者身份、monitor 状态、语言和主题跟随、音频与 hub。适配 hub 的工程可查看远程节点，并将本机和跨站点连接纳入同一工程流程。作者可自愿在外部 agent 环境采用 PNDS Skills。
- **原生画面与声音。** 适配的 monitor 与演奏者窗口可分别授权和选择摄像头、麦克风，主 monitor 可将采集结果共享给投影。工程可按需接入设备倾斜和加速度、麦克风包络和频谱，以及离线 HandPose 的手部关键点与手势。设备与模型功能取决于工程接线、窗口角色和系统权限。
- **创作实时测试。** 可按工程声明选择音频模式，在展开的 monitor 中查看内部音频频谱与 DSP 负载，开多个独立 performer 测试窗口并选择手机或平板尺寸。鼠标可模拟单点触摸，实际多点触控可用真机核对。底栏网络弹层提供手机测试入口和二维码，也可选择 iPhone 或 iPad 的 USB 网络接口测试。

## 演出、联机与记录

- **池主与池客。** 演出模式新增池客角色，PNDS 记住上次选择。池客可输入局域网地址，或选择已发现或已核验的 PNDS 节点，审阅工程后在原生窗口加入演出。兼容工程的浏览器和原生池客共用一个入口，可将它保存为书签、主屏幕或 Dock 快捷方式。池客可按池主和工程恢复网页数据。
- **演出切换与断线。** 同一入口可发现下一场演出，演奏者明确确认后进入。暂时断线或新工程加载失败时保留已打开的谱面。已完成本地资源准备的兼容谱面可在断线后继续显示和使用。仍用旧入口的工程会提示兼容地址。ASBS 的适配流程会先准备演奏者所需谱页，再交接到可继续演奏的谱面。
- **导航与网络。** 底栏网络弹层集中显示完整地址、复制入口和二维码。演出主窗口可用 `⌘⌥↑`／`⌘⌥↓` 选择工程、用 `⌘⌥Enter` 加载；侧栏支持双指切换工程文件夹。适配自动运行端口的工程可避开端口冲突，并公布实际生效的 monitor 和 performer 地址。既有固定端口工程继续按原声明运行。修正了 DNS 服务状态显示及配置变更后的重启处理。
- **演奏记录。** 兼容工程可记录初始状态和演奏事件，一轮可含多个演奏者，回放时由工程生成声音。可叠加新轮、整轮重录、删除单轮或整份记录。Blank 自带基础触点录放。弹窗简化记录列表、轮次管理和导入操作，支持原生文件选择或拖入 `.pndsrecord` 及旧 JSON，并可导出记录。迁移记录时可单独导出，或备份完整工程目录。
- **内置工具。** 更新 Multichannel Signal Generator 至 1.4.0、Local Network Diagnostics 至 0.7.2、Telematic Network Diagnostics 至 0.8.1、Mobile Sensor Meter 至 0.4.5。工具采用统一入口。跨站诊断需要可达的公网 hub，浏览器传感器和媒体仍遵循设备权限与 HTTPS 条件。
- **界面、设置与帮助。** 调整了角色菜单、工程文件夹导航、音频与网络状态图标、演奏端连接提示和助手问答折叠。设置按用途重新整理，可逐项显示或隐藏底栏功能入口；加载与模式切换入口始终保留。更新了中英文内置帮助、模块手册和兼容性说明。

## 安装、兼容性与反馈

需要 macOS 13.5 或更新版本。Apple Silicon（M 系列）Mac 选择 `_aarch64.dmg`，Intel Mac 选择 `_x64.dmg`。安装包采用 ad hoc 签名，未使用 Developer ID 签名或 Apple 公证。beta 从 Releases 手动下载，App 的更新检查仍使用正式版通道。

安装前退出 PNDS，保留旧安装包，备份完整工程目录（含隐藏的 `.git`、`.pnds-creation` 等文件）及 `~/Library/Application Support/com.xo-xn.pnds-app/`。beta 与正式版共享数据目录。演出 `.pnds` 包和 Git 备份不包含全部私有创作数据；完整备份请复制工程目录。返回旧版前先保存 beta 期间的新内容，再使用测试前的副本恢复。

### Local versions and GitHub

- **Bundled local Git and version history.** Enable version recording for an existing folder project after reviewing the files and author identity. Save and rename project versions in Version History, inspect the tree of actual parent relationships, and keep file differences visible. Load earlier text into a draft. After resolving drafts and stopping a run, switch routes, restore content, or continue from an older version on a new route. Exclusion rules cover dependency caches, build artifacts, and private creation data. Large media are left out by default.
- **Review merge candidates.** Merging local routes first creates an isolated candidate. Review text, image, and audio differences, resolve conflicts, and use candidate-specific assistance, checks, and runtime tests. Only explicit completion writes the result back to the project. Retain and resume unfinished candidates. Post-merge editor synchronization preserves newer input and retires saved copies of deleted files without creating false conflict drafts.

Keep recording versions offline and resume pending backups when reopening the corresponding project and route. Apply fast-forward updates from the matching remote branch explicitly. Divergent remote histories still require external Git tools first.
- **Continue on another Mac and manage bindings.** Clone a public repository or an authorized private repository into a new folder, with its source repository bound and manual backup selected by default. Change or unlink the repository from management; the old queue is retired with its binding. PNDS asks for confirmation on the first backup to a public repository and before recreating a deleted remote branch. Earlier project-wide automatic backup settings migrate to paused, preserving identity, history, bindings, and pending records until backup is confirmed per route.

### Modules, shared packages, and native devices

- **Offline resources.** Browse modules and shared packages in the creation workspace. Module source is copied into the project for the author to maintain.
