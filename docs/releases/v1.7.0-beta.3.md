# PNDS v1.7.0-beta.3

这是 1.7.0 的预发行测试版。以下是自上次正式发行 v1.6.0 以来的完整用户可见更新，涵盖其后的 1.6.x 开发阶段及 beta.1、beta.2、beta.3 已纳入的改动。 [上次正式发行](https://github.com/xO-xN/PNDS-App/releases/tag/v1.6.0) · [完整代码变更](https://github.com/xO-xN/PNDS-App/compare/v1.6.0...v1.7.0-beta.3)

## 创作工作台与工程文件

- **离线新建。** 新工程统一从 Blank 开始，自动初始化本地 Git 并记录初始版本。模板包含独立工程身份、演奏者座位恢复、共享 monitor 状态和触控示例。已有 Classic 工程仍可打开并继续使用。
- **内置编辑器。** 用文件树或 `⌘P` 打开文件，支持语法着色、括号匹配、当前文件查找替换、跳行和撤销重做。可新建、重命名文件和目录，拖到 Finder 可复制保存版。遇到外部保存与草稿冲突时，可比较后选择保留草稿或采用磁盘版。
- **保存和测试。** 可调整编辑区与 monitor 的宽度，展开创作控制台检查启动和编译结果。页面改动保存后可刷新，服务端改动需重启测试，SCD 改动需先编译 SynthDef。可用本机 SuperCollider 打开已保存的 SCD，并在 App 里保留未保存草稿。
- **待处理文档。** 可新建、导入、编辑和保存代码或文本，旧创作资料可迁入。助手按需读取保存版。可在一次工作任务中接入多份文档，审阅同名冲突并选择替换、并存或取消。接入失败时保留原文，成功后可跨重启审阅和撤回最近一次接入。

## 创作助手、交接与工程诊断

- **自配模型服务。** 在设置里填入支持文本和工具调用的 OpenAI 兼容地址、模型名和密钥，可先测试连接。密钥保存在 macOS 钥匙串，工程聊天保存在本机。
- **讨论与工作。** 讨论用于读资料、逐题澄清和拟定方案。确认后进入工作模式，执行明确的多文件修改、检查和所需的 SynthDef 编译。可暂停和继续任务，审阅差异，并在文件版本允许时撤回。
- **来源、聊天和上下文。** 可审阅发送的保存版文件或显式附加的编辑器选区，查看回复引用的帮助来源和预计上下文用量。每个工程可建多个聊天，重发旧问题会保留原聊天并创建分支。可审阅并采用长聊天摘要。
- **参数与代码建议。** 可在建议卡调整参数或编辑代码候选。适配预演的工程可临时查看画面或试听效果。确认应用后才写入工程，文件变化或已有草稿时先处理冲突。
- **手动交接。** 在讨论中审阅并记录交接文件和提示词，交给外部 agent。返回后用保存版基线对照文本差异及资源指纹，核对工程改动。
- **App 和 CLI 工程检查。** `pnds check` 可检查保存版 manifest、路径、依赖及产物，并输出 JSON。带 `--run` 时在临时副本检查 health 和页面 HTTP，可取消并清理。受控检查支持工程允许的 None，或明确选择 Internal。真实设备和音画可用实时测试核对。单文件修改也可先审阅差异，再保存或按版本保护撤销。

## 本地版本与 GitHub

- **内置本地 Git。** 可在无 Git 的文件夹工程中主动启用版本记录，预览纳入范围和署名。可查看状态、差异和历史，给版本改名，将历史文本载入草稿，或在处理完草稿与运行状态后切换版本、恢复内容和建立新分支。依赖缓存、构建产物和私有创作资料有独立排除规则，大型媒体默认不选。
- **GitHub 同步。** 登录并授权 PNDS GitHub App 后，可绑定空仓库或与工程共享 Git 历史的仓库。可手动将已提交版本备份到同名分支，也可开启保存后自动备份。离线期间可继续保存本地版本，回到对应工程与分支后可续备份。远端同名分支可快进时可直接更新，历史分叉需先用外部 Git 工具处理。
- **换机接续。** 可从 GitHub 克隆公开仓库或获授权的私有仓库到新目录，打开后绑定来源仓库。可在备份设置中更换或解除绑定。首次向公开仓库备份、重建已删除的远端分支会提示确认。

## 模块、共享包与原生设备

- **离线资源。** 在创作工作台浏览模块和共享包。添加模块会把源码加入工程供作者维护。共享包通过 manifest Schema 2 引用 App 内固定版本，包括 p5、ml5、Express、qrcode、Socket.IO 和 osc-min。自带依赖的 Schema 1 工程仍可运行。采用共享包的 `.pnds` 携带版本引用，接收端需具备对应版本。资源确认卡会列出依赖和冲突，创作助手可在作者确认后接续采用与接线。
- **标准模块和 hub。** 模块手册覆盖演奏者身份、monitor 状态、语言和主题跟随、音频与 hub。适配 hub 的工程可查看远程节点，并将本机和跨站点连接纳入同一工程流程。作者可自愿在外部 agent 环境采用 PNDS Skills。
- **原生画面与声音。** 适配的 monitor 与演奏者窗口可分别授权和选择摄像头、麦克风，主 monitor 可将采集结果共享给投影。工程可按需接入设备倾斜和加速度、麦克风包络和频谱，以及离线 HandPose 的手部关键点与手势。设备与模型功能取决于工程接线、窗口角色和系统权限。
- **创作实时测试。** 可按工程声明选择音频模式，在展开的 monitor 中查看内部音频频谱与 DSP 负载，开多个独立 performer 测试窗口并选择手机或平板尺寸。鼠标可模拟单点触摸，实际多点触控可用真机核对。底栏网络弹层提供手机测试入口和二维码，也可选择 iPhone 或 iPad 的 USB 网络接口测试。

## 演出、联机与记录

- **池主与池客。** 演出模式新增池客角色，PNDS 记住上次选择。池客可输入局域网地址或选择最近池主，在原生窗口加入演出。兼容工程的浏览器和原生池客共用一个入口，可将它保存为书签、主屏幕或 Dock 快捷方式。池客可按池主和工程恢复网页数据。
- **演出切换与断线。** 同一入口可发现下一场演出，演奏者明确确认后进入。暂时断线或新工程加载失败时保留已打开的谱面。已完成本地资源准备的兼容谱面可在断线后继续显示和使用。仍用旧入口的工程会提示兼容地址。ASBS 的适配流程会先准备演奏者所需谱页，再交接到可继续演奏的谱面。
- **导航与网络。** 底栏网络弹层集中显示完整地址、复制入口和二维码。演出主窗口可用 `⌘⌥↑`／`⌘⌥↓` 选择工程、用 `⌘⌥Enter` 加载。适配自动运行端口的工程可避开端口冲突，并公布实际生效的 monitor 和 performer 地址。既有固定端口工程继续按原声明运行。修正了 DNS 服务状态显示及配置变更后的重启处理。
- **演奏记录。** 兼容工程可记录初始状态和演奏事件，一轮可含多个演奏者，回放时由工程生成声音。可叠加新轮、整轮重录、删除单轮或整份记录。Blank 自带基础触点录放。支持导入导出 `.pndsrecord` 和导入旧 JSON。迁移记录时可单独导出，或备份完整工程目录。
- **内置工具。** 更新 Multichannel Signal Generator 至 1.4.0、Local Network Diagnostics 至 0.7.2、Telematic Network Diagnostics 至 0.8.1、Mobile Sensor Meter 至 0.4.5。工具采用统一入口。跨站诊断需要可达的公网 hub，浏览器传感器和媒体仍遵循设备权限与 HTTPS 条件。
- **界面与帮助。** 调整了角色菜单、工程文件夹导航、音频与网络状态图标、演奏端连接提示和助手问答折叠。更新了中英文内置帮助、模块手册和兼容性说明。

## 安装、兼容性与反馈

需要 macOS 13.5 或更新版本。Apple Silicon（M 系列）Mac 选择 `_aarch64.dmg`，Intel Mac 选择 `_x64.dmg`。安装包采用 ad hoc 签名。后续 beta 从 Releases 手动下载，App 的更新检查使用正式版通道。

安装前退出 PNDS，保留旧安装包，备份完整工程目录（含隐藏的 `.git`、`.pnds-creation` 等文件）及 `~/Library/Application Support/com.xo-xn.pnds-app/`。beta 与正式版共享数据目录。普通演出 `.pnds` 包与 Git 备份的内容范围有限，完整备份请复制工程目录。恢复旧版前先保存 beta 期间的新内容，再用测试前的副本恢复。

## English

This 1.7.0 prerelease includes the user-facing changes since v1.6.0, the last stable release. It covers changes shipped in this candidate from the subsequent 1.6.x development and the beta.1, beta.2, and beta.3 milestones. ### Creation workspace and project files

- **Offline project creation.** New projects start from Blank with local Git and an initial version. The template includes an independent project identity, performer seat recovery, shared monitor state, and a touch example. Existing Classic projects can still be opened and used.
- **Built-in editor.** Open files from the tree or with `⌘P`. The editor supports syntax highlighting, bracket matching, find and replace in the current file, go to line, and undo and redo. Create and rename files or folders, and drag saved copies to Finder. When an external edit conflicts with a draft, compare the versions and choose which to keep.
- **Save and test.** Resize the editor and monitor areas and open the creation console for startup and compilation results. Reload pages after saving page changes, restart testing after server changes, and compile SynthDefs before restarting after SCD edits. Open a saved SCD in an installed copy of SuperCollider while keeping any unsaved PNDS draft.
- **Pending documents.** Create, import, edit, and save code and text independently, with migration for older materials. The assistant reads saved documents on demand. Adopt several documents in one work task, review name conflicts, and choose to replace, keep both, or cancel. Failed adoption preserves the source. You can review and undo the most recent adoption after restarting.

### Creation assistant, handoff, and project diagnostics

- **Model service configuration.** Set an OpenAI-compatible endpoint, model, and API key for text and tool calls, and test the connection in Settings. macOS Keychain stores the key. Project chats are saved locally.
- **Discussion and work.** Use Discussion to read relevant material, answer questions one at a time, and develop a plan. Once you approve the scope, Work can edit multiple files, run checks, and compile required SynthDefs. Pause and resume tasks, review changes, and undo when file versions still allow it.
- **Sources, chats, and context.** Review the saved files or explicitly attached editor selection that will be sent. See help sources and estimated context usage. Start multiple chats per project, branch from a previous question while preserving the original, and review summaries for long conversations.
- **Parameter and code suggestions.** Adjust parameters or edit a code candidate in a suggestion card. Projects with preview support can audition changes temporarily. Applying the candidate requires confirmation. Review intervening file changes or drafts before writing.
- **Manual handoff.** Review and save a handoff file and prompt for an external agent. Compare saved files against the handoff baseline when you return, with text diffs and fingerprints for changed assets.
- **Project checks in the app and CLI.** `pnds check` validates the saved manifest, paths, dependencies, and artifacts, with JSON output. Add `--run` to check health and page HTTP on a temporary copy. The run can be canceled and cleaned up, using None where supported or Internal when explicitly selected. Use live testing to check physical devices, sound, and visuals. Review single-file diffs before saving and undo saved changes subject to version checks.

### Local versions and GitHub

- **Bundled local Git.** Enable version recording for an existing folder project after reviewing the files and author identity. Inspect status, diffs, and history, name versions, or load earlier text into a draft. After resolving drafts and stopping a run, switch or restore versions and create branches. Exclusion rules cover dependency caches, build artifacts, and private creation data. Large media are left out by default.
- **GitHub sync.** Sign in and authorize the PNDS GitHub App to bind an empty repository or one with shared Git history. Back up committed versions to the branch of the same name manually or automatically after saving. Keep recording versions offline and resume pending backups when you reopen the corresponding project and branch. Fast-forward updates are available for the matching remote branch. Resolve divergent histories with external Git tools first.
- **Continue on another Mac.** Clone a public repository or an authorized private repository into a new folder, with its source repository already bound. Backup settings let you change or unlink the repository. PNDS asks for confirmation on the first backup to a public repository and before recreating a deleted remote branch.

### Modules, shared packages, and native devices

- **Offline resources.** Browse modules and shared packages in the creation workspace. Module source is copied into the project for the author to maintain. Manifest Schema 2 references specific app-bundled versions of packages such as p5, ml5, Express, qrcode, Socket.IO, and osc-min. Self-contained Schema 1 projects remain usable. A `.pnds` package that uses shared libraries carries version references, so the receiving app needs those versions. Resource confirmations show dependencies and conflicts before the assistant resumes adoption and wiring.
- **Standard modules and hub.** The module guide covers performer identity, monitor state, locale and theme following, audio, and hub connections. Hub-enabled projects can display remote nodes and work across local and remote sites. Authors may choose to use PNDS Skills in an external agent environment.
- **Native visuals and audio.** Compatible monitor and performer windows can grant access to and select their own cameras and microphones. The main monitor can share its results with projection. Projects can add device tilt and acceleration, microphone envelopes and spectra, and offline HandPose landmarks and gestures. Device and model features depend on project integration, window role, and system permissions.
- **Live creation testing.** Select a supported audio mode, view the internal audio spectrum and DSP load in the expanded monitor, and open independent performer test windows in phone or tablet sizes. The mouse can simulate a single touch, and physical devices can test multi-touch. The bottom network panel provides a phone test URL and QR code. You can also select the network interface of an iPhone or iPad connected over USB.

### Performance, connections, and recording

- **Host and Client.** Performance mode adds the Client role, and PNDS remembers the last selected role. A Client can enter a LAN URL or choose a recent Host and join from a native window. Compatible scores share one entry for browsers and native Clients, which can be saved as a bookmark, Home Screen icon, or Dock shortcut. Clients can restore webpage data for the same Host and project.
- **Switching and disconnections.** The same entry can discover the next performance. Performers explicitly confirm entry. A temporary disconnection or failed switch keeps the current score open. Compatible scores that have prepared their local resources can continue during a disconnection. Legacy projects show a compatible address. The ASBS integration prepares the performer's score pages before handing over to the playable score.
- **Navigation and networking.** Find the complete entry URL, copy control, and QR code in the bottom network panel. In the main performance window, use `⌘⌥↑` or `⌘⌥↓` to select a project and `⌘⌥Enter` to load it. Projects that opt into automatic runtime ports can avoid conflicts and advertise the active monitor and performer URLs. Existing fixed-port declarations remain usable. DNS status reporting and daemon restarts after configuration changes have been corrected.
- **Performance recordings.** Compatible projects capture initial state and performance events, with multiple performers in one take. The project generates sound during playback. Overdub, replace a take, or delete a take or the entire recording. Blank includes basic touch recording and playback. Import and export `.pndsrecord` and import legacy JSON. Move recordings using exports or a complete project folder backup.
- **Built-in utilities.** Updated Multichannel Signal Generator to 1.4.0, Local Network Diagnostics to 0.7.2, Telematic Network Diagnostics to 0.8.1, and Mobile Sensor Meter to 0.4.5. The utilities use the shared entry. Cross-site diagnostics require a reachable internet hub. Browser sensors and media still depend on device permissions and HTTPS requirements.
- **Interface and help.** Refined the role menu, project-folder navigation, audio and network indicators, performer connection feedback, and collapsed assistant Q&A. Updated the built-in help, module guides, and compatibility notes in both languages.
