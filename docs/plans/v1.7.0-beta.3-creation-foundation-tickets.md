## 并行与整合约束

- 可先同时推进 **6A、6B、6C**；具体首次可领取票为 **#316、#321、#322、#323**。实际并发数量按工具额度和代码归属安排，不必一次启动全部实现者。
- 优先由一个协调聊天按任务图调度后台实现者；各票在独立 worktree／分支工作，共用同一个 beta.3 整合分支，由统一整合者顺序回填或合入。
- 若分多次聊天运行，各组也必须使用不同工作目录；不要让几个聊天同时在同一 checkout 切分支、改 staging 或直接写入公共文件。6B／6C 的资源、命令与原生承载公共修改尤其需要串行整合。
- 建立任何隔离工作区前保留并核对当前已确认的 staged、unstaged、untracked 基线；只从旧 HEAD 派生会漏掉已确认但未提交的 beta.3 成果。不得覆盖无关修改。
- 每票开始前核对所需前置已进入同一整合基线，完成前同步整合分支最新成果；按 implement-spec 使用 TDD、适用检查和两轴复审。业务逻辑随实现带测试，App 完成标准为 `npm run check:all` 全绿。
- 遵守仓库“只在明确要求时 commit”。本次建票和说明不授权后续自动 commit、push、tag、PR 或正式发布；已有未提交工作按既定可核对增量方式整合，后续明确授权提交时再使用对应合并流程。
- 开发服务器由用户启动并回报；真实摄像头、麦克风、手机多点、模型、物理声音、签名权限、最低系统／双架构与双机结果分别记录，API 暴露、数据夹具或单票完成不替代最终实机验收。

### 01：新建唯一空白工程并运行默认依赖（#316）

**Issue：** [#316](https://github.com/xO-xN/PNDS-App/issues/316)

**Parent：** [#315](https://github.com/xO-xN/PNDS-App/issues/315)

**直接前置：** 无，可立即开始

**What to build：** 创作者从任何公开新建入口获得唯一 Blank 起点，生成工程离线使用 Express、Socket.IO、osc-min，可实际启动、连接并关停；既有 Classic 工程继续使用。

**Acceptance criteria：**

- [ ] 撤下 Classic 新建选项及相关推荐；不删除、覆盖或自动迁移既有 Classic、Template 衍生、自包含工程及作者定制源码，验证既有文件夹／工程包的适用打开、编辑、运行和分发兼容。
- [ ] 生成独立工程身份和初始工程版本，采用 App 当前确切共享版本；三库实际承担路由、实时连接和 OSC 编解码，无运行时 npm 安装、CDN 或缺失资源下载回退。
- [ ] 取消、缺少资源、版本不符或校验失败不留下半个工程；资源目录和助手读取只报告实际已采用事实。
- [ ] Express 改造保留角色页面、受限资源路由、正确 MIME、缓存策略、实际端口／监听器交接、启动报告、health、错误与关停行为。
- [ ] 音频基础保留 Internal／External／None 和静音占位，覆盖应答、超时、初始化失败及自有资源收尾；不引入 Classic 音色、座位、人数或声道艺术预设，不越过私有 bus 契约。
- [ ] 参数预演保留真实已加载源码快照和摘要；统一入口、模型／Worker 所需同源路径和长期数据作用域不回退。不删除 PNDS Template 维护源，不重开已完成的 #304。
- [ ] 新增业务测试随本票实现交付，优先从公开创建／聊天任务及真实工程观察外部行为；App 的 npm run check:all 全绿，涉及维护源时执行其适用检查。
- [ ] 同步对应开发规则、双语使用说明与助手资源资料，保留稳定装机帮助链接；分别记录自动化、适用实机结果和仍待实机项目，不以资源复制、API 暴露或模拟数据冒充完整验收。

### 02：空白工程跨重启恢复身份并接管旧连接（#317）

**Issue：** [#317](https://github.com/xO-xN/PNDS-App/issues/317)

**Parent：** [#315](https://github.com/xO-xN/PNDS-App/issues/315)

**直接前置：** [#316](https://github.com/xO-xN/PNDS-App/issues/316)

**What to build：** 在实际新建的空白工程中，演奏者断线、刷新或停止后重开仍恢复同一身份；同一 claim 的新连接接管后，旧连接停止控制工程。

**Acceptance criteria：**

- [ ] 默认接好通用 players 核心及无座位政策，不要求再次添加；演奏者身份与连接、乐谱选择、记录身份、声音及声道分别表达。
- [ ] 服务端实际停止并重新创建后仍能恢复身份；身份登记持久保存，上一场演奏参数、触点与声音状态每场重置，不能只靠同一服务进程内存通过测试。
- [ ] 同工程同 claim 新连接接管；旧控制、动作、重复加入和迟到断开不能影响新拥有者，也不能释放其逻辑资源。
- [ ] 沿既有 Host／工程作用域恢复，不用演出身份重置长期键；新演出仍需明确进入。逻辑接管不授权抢占另一页面的摄像头或麦克风。
- [ ] monitor 观察连接不分配演奏者身份；创作多个测试窗口保持各自身份及存储，不能因为来自同一台 Mac 合并成同一 claim。
- [ ] 存储拒绝、登记损坏或持久化失败有明确反馈，不伪报恢复成功；默认来源被目录／助手识别为已包含，不生成虚假待接线或交接任务。
- [ ] 新增业务测试随本票实现交付，优先从公开创建／聊天任务及真实工程观察外部行为；App 的 npm run check:all 全绿，涉及维护源时执行其适用检查。
- [ ] 同步对应开发规则、双语使用说明与助手资源资料，保留稳定装机帮助链接；分别记录自动化、适用实机结果和仍待实机项目，不以资源复制、API 暴露或模拟数据冒充完整验收。

### 05：空白工程默认输入形成录制回放与叠加闭环（#320）

**Parent：** [#315](https://github.com/xO-xN/PNDS-App/issues/315)

**直接前置：** [#319](https://github.com/xO-xN/PNDS-App/issues/319)

**What to build：** 创作者直接通过 App 现有演奏记录入口记录新工程交互、回放、叠加及整轮重录，无需选装录制模块；助手新增业务时同步维护真实接线。

**Acceptance criteria：**

- [ ] App 保留录制界面、存储、轮次管理和共同时间驱动；Blank 默认完成工程侧公共接线，既有 III／Runes 等定制适配不被自动替换。
