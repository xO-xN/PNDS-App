# v1.7.0-beta.3 单一空白工程、本地能力与原生媒体规格

状态：2026-11-09 用户已确认全部产品决定和公开工作流测试接缝，纳入现有 v1.7.0-beta.3。作为 #294 的同版增补规格，在 #313、#314 联合验收前完成实现与业务测试。本次仅发布规格及调整排期，尚未实施新增功能。

跟踪票：[#315](https://github.com/xO-xN/PNDS-App/issues/315)，标记 `ready-for-agent`；GitHub 原生前置为 #295／#300／#301，且 #313、#314 均已加入由 #315 阻塞的原生关系。

## Problem Statement

PNDS App 创作模式目前把新建工程、共享第三方库、可编辑技术模块、App 已有能力和作品业务接线分别呈现。创作者需要先理解这些实现分工，再决定添加哪些资源；助手也容易把“文件已加入”“引用已声明”误认为“能力已完成”。新工程已有本地网络与参数预演基础，却仍需重复补齐客户端身份、输入、演奏记录、运行生命周期等通用接线，增加首次创作负担。

二维码已归 App 提供，工程无需再实现加入入口；演奏记录的界面、存储、轮次管理和共同时间驱动也已由 App 提供。把这些能力重新包装为要求用户选装的模块，会让产品职责再次混淆。工程真正需要提供的是作品的输入、状态、画面、声音与回放之间的完整关系。

摄像头、麦克风和设备运动是明确的创作输入需求。现有原生 Client 已使用受管本地可信来源与第一方页面，为 HTTP 场地下的笔记本提供媒体 API 和权限处理基础；Host monitor 与创作 performer 测试窗口仍需获得一致能力。普通 LAN HTTP 浏览器、App 原生页面、权限声明、API 暴露、实际采集及模型推理必须分别验收。

本规格属于现有 v1.7.0-beta.3 的增补范围，需在 #313、#314 开始最终联合验收前完成，并与两票共同验收。规格发布不代表实现或实机验收已经完成。

## Solution

新建工程只保留 Blank 一种起点，撤下 Classic 的新建选择；既有 Classic、Template 衍生工程和已发行工程继续保留运行、编辑及兼容范围。Blank 表达“没有作品内容，但通用基础已经接好”，不表达“只有裸页面”。

Blank 默认采用 App 当前确切版本的 Socket.IO、Express 和 osc-min，并实际接入客户端连接与身份恢复、monitor 视图状态、鼠标单点与真实多点输入、演奏记录公共通道和现有参数预演基础。主题跟随、语言跟随和 hub 按需加入；hub 所需的 Socket.IO 客户端随该次采用自动完成引用与接线。工程自己的加入二维码从新建、资源推荐和助手工作流中撤下，App 继续负责入口二维码及必要的兼容资源。

身份恢复覆盖同一浏览器与入口、同一工程的断线、刷新、停止后重开；同一 claim 的新连接接管旧连接。持久身份与每场演奏参数分开：重开恢复身份，参数、触点和声音状态按工程初始值重置。monitor 视图状态默认为空；基础文件与接线位置存在，有真实声明键时再启用相应同步。

新增三类按需技术能力：摄像头手势传感、设备麦克风、设备运动传感。它们读取参与设备自己的输入，经同一演奏事件通道交给工程；不代替作者决定音乐映射。摄像头能力新增共享依赖只有 ml5，配合已选定的离线 HandPose 模型路线，输出关键点与捏合、张手等少量明确特征。该版本需要工程已具备 p5；缺失时说明原因，不自动加入 p5，也不偷偷切换到另一条模型路线。麦克风使用原生浏览器媒体与 Web Audio 能力，提供包络、峰值、波形和 FFT；设备运动使用浏览器原生能力，提供倾斜与加速度。

Host monitor 与创作 performer 测试窗口复用原生 Client 的可信第一方页面与权限处理机制。在主／投影两份 monitor 副本之间，由主 monitor 负责采集并向投影传递结果，投影不重复采集；这不禁止 performer、Client 在自己的参与设备上启用输入。多个测试窗口分别手动启用输入；硬件允许时共享使用，失败时明确反馈，不抢占或关闭另一个窗口的设备。

用户继续通过现有聊天确认创作任务。助手在同一个获准任务内完成资源采用、源码、模型、事件、状态、声音或画面、录制回放及验证接线；不让用户再选装“录制模块”，也不把安装资源当作任务完成。

## User Stories

1. **As a creator, I want one Blank starting point, so that I can begin without choosing a technical template.** 新建工程只展示 Blank；Classic 不再作为可选起点出现在相同入口或助手建议中。新 Blank 仍包含可运行结构和必要说明。

2. **As an existing project owner, I want my Classic and Template-derived projects preserved, so that this change does not invalidate my work.** 撤下新建选择不删除、重写或自动迁移现有工程，不禁止它们继续编辑、运行、打包或安装；已有定制源码继续由工程维护。

3. **As a creator, I want the default libraries already adopted, so that I do not assemble the basic network stack myself.** Blank 默认声明 App 当前确切版本的 Socket.IO、Express、osc-min；运行采用 App 现有离线资源，不要求用户安装 npm 依赖或额外下载。

4. **As a creator, I want the generated server to use its default libraries, so that the dependency list describes working behavior.** Express 实际承担路由组织，Socket.IO 实际服务页面连接，osc-min 实际用于音频传输所需编解码；不只添加未使用的引用。

5. **As a creator, I want the initial server to preserve the Host contract, so that a simpler authoring experience remains reliable.** 默认工程保留角色页面、资源范围、真实运行端口、监听器交接、启动报告、health、缓存、错误与关停语义；引入 Express 不削弱这些要求。

6. **As a creator, I want local performer and monitor communication ready, so that I can focus on the interaction I am composing.** 默认工程提供明确的双向事件接线与服务端角色识别；页面加载或传输连接不冒充工程已经接纳演奏者。

7. **As a creator, I want audio transport ready without an imposed instrument, so that I can define the work's sound.** 默认音频基础支持既有模式和资源收尾，保留静音占位；不预设 Classic 正弦声部、奇偶声道、乐手数量或 External 作品协议。

8. **As a creator, I want clients and identity recovery already wired, so that joining and reconnecting are ordinary behavior.** 默认接入 players 的通用连接核心与无座位政策；不要求用户先添加模块，不把数值座位或声道 helper 当作必要条件。

9. **As a creator, I want built-in resources recognized as already present, so that I am not asked to add them twice.** 新建结果、资源目录、工程概况与助手读取均反映实际已采用状态；已存在的默认模块不产生重复文件、引用或加入确认。

10. **As an existing project owner, I want new defaults to remain opt-in for my custom source, so that App updates do not overwrite my decisions.** 新 Blank 基础只自动用于新建工程；已有源码、模块来源与依赖声明不会因为版本较旧而被覆盖，迁移需属于明确的工程任务。

11. **As a performer, I want the same identity after reconnecting, refreshing, or reopening the same project, so that my device is recognizable.** 在同一浏览器和入口范围内，断线、刷新、停止后重开同一工程均恢复同一身份；身份恢复不能仅依赖服务端进程内存。

12. **As a performer, I want a fresh performance state when a project restarts, so that an old gesture does not unexpectedly resume.** 恢复身份不自动恢复上一场触点、推子、音符、声音或其他演奏参数；每场按工程初值开始，并明确区别于演奏记录回放。

13. **As a performer, I want my newest connection to own my claim, so that refreshes cannot leave two competing controllers.** 当前工程内同一 claim 的新连接接管旧连接；旧连接的控制、动作或迟到断开不能影响新拥有者或释放其逻辑资源。逻辑身份接管不授权抢占另一页面的硬件，也不复用新演出的旧进入确认。

14. **As a creator, I want monitor observers separated from performers, so that displaying a roster does not create a musician.** monitor 观察连接不参与演奏者加入、不占身份或声部；快照不泄露 claim 凭据，传输连接身份不能代替持久演奏者身份。

15. **As a creator, I want each test window to represent an independent performer, so that I can rehearse multiple participants.** 创作 performer 测试窗口保留独立身份与既有测试存储语义；不能因为多个窗口来自同一台 Mac 就误合并成一个 claim。

16. **As a performer, I want storage and admission failures explained, so that I know whether recovery is available.** 存储被拒绝、身份记录读取失败、工程拒绝加入或连接失败均有可行动反馈；只保存在内存时不得宣称停止重开后仍能恢复。

17. **As a creator, I want monitor synchronization ready without idle traffic, so that empty projects stay simple.** 默认提供 monitor-state 的源码、配置和接线位置；初始没有业务键时，不建立无实际用途的视图同步 namespace 或逻辑连接。

18. **As a creator, I want declared view choices synchronized, so that every monitor copy shows the same operator adjustment.** 对工程声明的低频视图键，当前副本、晚加入副本、刷新与重连副本均从服务端完整快照渲染；变更通过服务端校验和广播收敛。

19. **As a creator, I want view synchronization limited to its purpose, so that unrelated behavior is not coupled to it.** 乐谱进度、声音状态、高频演奏控制、claim、纯本地悬停，以及 App 自己的二维码和投影开演状态，不进入通用 monitor-state。

20. **As an operator, I want view state reset between performances, so that previous debugging choices do not silently carry over.** monitor-state 默认只活在本次工程运行中；停止重开回到声明初值，不与持久身份或工程版本记录混用。

21. **As a creator, I want synchronized fields validated, so that malformed updates do not corrupt the monitor.** 只接受已声明键和合法值；非法、未知或不满足工程限制的更新保持当前状态，并按工程界面规则给出反馈。

22. **As a performer, I want the default project to use the confirmed entry context, so that changing runtime ports does not break participation.** 页面资源、Socket.IO 和持久数据键沿既有受管入口接线；不从首选端口猜网址，不把当前演出身份拼进长期恢复键。

23. **As a performer, I want browser and native entry behavior retained, so that a better creation base does not change how I join a performance.** 普通浏览器与原生 Client 保留既有核对、明确进入、候选发现与成功后切换规则；新工程默认支持这些协议。

24. **As a performer, I want my loaded document retained during disconnection or performance changes, so that I can continue according to the work's rules.** 保留原页面与既有断线继续演奏契约；旧页面不能借新确认访问替换后的演出，失败切换不得先毁掉原页。

25. **As an operator, I want project pages isolated from App management, so that granting media access does not grant control of the Host.** 工程页面获得所需标准网页能力，不获得 Tauri 管理命令、任意文件或进程权限；原有来源与演出归属校验继续生效。

26. **As a performer, I want mouse input and real multitouch supported by default, so that I can use a laptop or touch device.** 鼠标默认提供单点交互；真实触屏提供实际多触点。鼠标单点不得被描述成真实多点硬件，也不新增固定虚拟触点的模拟交互。

27. **As a creator, I want input independent of a drawing library, so that I can choose how to render the score.** 默认输入基于标准网页事件，直接接入 players 与公共事件通道；不因输入能力自动加入 p5、ml5 或特定 canvas 渲染方式。

28. **As a performer, I want each gesture handled once, so that desktop simulation does not duplicate my input.** 原生 pointer、真实触摸与 App 既有鼠标单点模拟必须有清楚的统一入口；同一次手势不能同时作为 pointer 和合成 touch 重复触发业务或录制。

29. **As a creator, I want stable contact data, so that multiple touches can be mapped consistently.** 每个触点有本次手势内稳定标识及开始、移动、结束、取消语义；持续位置采用相对或归一化表示，窗口尺寸变化不固化旧坐标。

30. **As a performer, I want cancellation and ordinary controls to behave correctly, so that interaction does not become stuck.** 取消、失焦、捕获丢失、页面卸载与断线按明确规则释放相应接触；文本框、按钮、选择框等原生控件仍正常可用。

31. **As a creator, I want input transport separated from musical meaning, so that I can compose different instruments.** 通用输入层负责接触与数据交付，players 负责已接纳身份与连接；具体手势对应什么画面、声音、角色或声道由工程定义。

32. **As a creator, I want server acceptance before effects and recording, so that invalid input does not become part of a performance.** 工程校验载荷、连接拥有者和当前接纳资格后，才捕获并应用演奏事件；回放与真实输入不能绕过各自应有的限制。

33. **As a creator, I want input to survive layout changes, so that resizing is a normal operation.** 切换模拟设备尺寸、横竖方向、窗口尺寸或全屏不会靠重启工程修正输入；绘图和交互共同使用更新后的坐标映射。

34. **As a creator, I want recording infrastructure included, so that I never choose or install a recording module.** App 继续提供录制界面、存储、轮次与时间驱动；Blank 默认提供工程侧公共接线，现有已适配工程不重复安装或被替换。

35. **As a creator, I want live input and replay to use the same behavior, so that a recording reproduces the work.** 已接纳现场事件经捕获后进入业务应用；回放进入相同业务应用入口但不再次捕获，避免重录和双重执行。

36. **As a creator, I want real state recovery hooks, so that playback starts from the recorded musical state.** 工程提供实际状态快照、恢复、事件应用、释放与必要的时间推进；通用 helper 不伪造作品状态，不以空回调冒充完整音乐回放。

37. **As a performer, I want recorded identities kept distinct from device claims and score numbers, so that overdubs remain independent.** 同一设备同轮重连保持来源，跨轮形成独立记录演奏者；claim、持久身份、乐谱选择序号和记录身份不得混为一个编号。

38. **As a creator, I want replay admission and conducting rules enforced, so that live actions do not conflict with recorded sources.** 纯回放、叠加与整轮重录沿既有规则；工程在真实处理器中限制现场来源、角色冲突与手动指挥，不靠界面禁用代替服务端规则。

39. **As a creator, I want the assistant to extend recording when it adds behavior, so that new music remains part of the same workflow.** 助手新增交互、状态、画面或声音时，在同一任务内补齐事件、快照和回放关系；不能要求用户随后再添加“录制模块”。

40. **As a creator, I want recording support reported truthfully, so that I can rely on the controls.** 默认基础支持其实际接好的输入和状态；新增业务须验证真实结果。仅有资源文件、声明或管理端点不等于任意后来加入的音乐都会正确回放。

41. **As an existing project owner, I want my working recording adapter preserved, so that the new base does not break accepted behavior.** III、Runes 等已有适配继续使用其作品政策与真实接线；采用统一基础时不得自动替换定制快照、角色制度、声音或进度规则。

42. **As a creator, I want parameter preview retained, so that adjustable behavior stays available without another setup step.** Blank 继续包含现有预演基础和空声明；助手按任务提供真实参数、限制与 get/set，并保持实际已加载源码及声明摘要的核验，不制造展示用参数。

43. **As a creator, I want theme and locale following available on demand, so that the work can retain its own visual and language choices.** 主题和语言不列入 Blank 默认已启用能力；需要时采用对应模块并完成真实应用，工程名、作者与用户正文不自动翻译。

44. **As a creator, I want optional hub support adopted as one task, so that remote interaction has no hidden setup.** 采用 hub 时自动处理其确切 Socket.IO 客户端依赖、配置与工程事件接线；不把 App 的加入二维码代码重新加进工程，也不要求每个工程默认启用 hub。

45. **As a creator, I want three separate sensor choices, so that I can request only the input the work needs.** 摄像头手势传感、设备麦克风、设备运动传感各自按需采用，均指当前参与设备；不把池主的设备当成手机或 Client 的设备。

46. **As a creator, I want one supported camera inference route, so that offline behavior remains testable.** 摄像头模块只采用 App 当前确切版本的 ml5 与现有 HandPose 路线；本轮不同时引入另一套推理引擎、模型选择器或在线回退。

47. **As a creator, I want the camera prerequisite explained before adoption, so that I do not receive an unexpected drawing dependency.** 工程已有兼容且可信的自带或共享 p5 均可接线，不强制迁移已有版本；缺少时明确提示并暂不加入摄像头能力，不自动加入 p5，不留下 ml5、模型或模块的半加入残留，不无声替换路线或冒充已就绪。

48. **As a creator, I want camera models carried with the project, so that a venue does not need internet access.** 采用摄像头模块时，将选定离线模型及其所需资料纳入工程和分发工程包；资源缺失、版本不匹配或完整性失败明确报错，不在运行时下载修复。

49. **As a performer, I want to choose an available camera, so that the same work can run on phones and laptops.** 在权限及浏览器实际能力允许的范围内，支持手机前后摄像头、笔记本内置摄像头和浏览器可见外接摄像头；不伪造不可枚举或不可访问设备。

50. **As a creator, I want landmarks and a few defined hand features, so that I can map gestures without a large recognition system.** 默认手势传感输出 HandPose 关键点，以及捏合、张手等少量明确计算的特征；阈值、坐标和含义可查，不宣称识别任意手势或完整身体动作。

51. **As a creator, I want camera readiness measured in stages, so that loading a page is not mistaken for hand tracking.** 分别呈现媒体授权、实际图像、模型资源、模型就绪与真实推理结果；失败可重试，不以权限声明、API 暴露或假关键点替代成功。

52. **As a creator, I want the camera stream reused within its owner, so that features do not open the same device repeatedly.** 关键点与派生手势共享该已启用页面／模块实例内部的采集与模型结果；不为每项特征重复申请摄像头或重复启动同一推理链，不限制其他参与设备独立启用。

53. **As a performer, I want explicit sensor activation and recovery, so that selecting a project does not silently turn on hardware.** 摄像头、麦克风按用户动作启用；拒绝、不可用、系统设置变化与重试均有反馈。采用模块、打开详情或恢复角色不自动授权设备。

54. **As an operator, I want projection to use the main monitor's sensor result, so that one work does not capture twice on the Host.** 此约束限定主／投影两份 monitor 副本：主 monitor 持有采集与推理，投影消费结果，不重复打开同一摄像头或麦克风。performer、Client 和其他独立测试页面仍可分别手动启用自己的输入。

55. **As a creator, I want four microphone features, so that I can build sound-reactive behavior without another audio library.** 设备麦克风提供包络、峰值、波形和 FFT 数据；这些是本地分析输入，不等于生成音频录音、自动上传声音或默认开启扬声器监听。

56. **As a performer, I want to choose an available microphone, so that external and built-in devices are usable.** 在系统权限与浏览器可见范围内选择当前设备的内置或外接麦克风；选择失败或设备拔出明确反馈，不自动抢占其他页面的设备。

57. **As a creator, I want one microphone capture chain, so that several measurements do not consume several streams.** 每个已启用页面／模块实例内部复用一次媒体采集与分析链生成四类特征，不规定 App 全局只能有一份。切换、停用与关闭正确释放该实例原有流和分析资源，不关闭其他页面拥有的采集。

58. **As a creator, I want microphone analysis based on native browser facilities, so that it does not add p5 or ml5.** 使用标准媒体和 Web Audio 能力，不为包络、峰值、波形和 FFT 引入不必要的第三方依赖；数据单位、范围与采样约定由模块资料说明。

59. **As a creator, I want tilt and acceleration from the current device, so that movement can become a musical input.** 设备运动模块采用浏览器原生能力，无 p5、ml5 依赖；本轮覆盖倾斜和加速度，不承诺完整角速度、陀螺仪融合或所有设备提供相同字段。

60. **As a performer, I want unsupported motion inputs reported, so that missing hardware is not presented as a valid zero.** 按平台要求经用户动作请求运动权限；拒绝、没有传感器、字段不可用或浏览器不支持时明确区分，不用恒零、示例波形或模拟数据冒充真实输入。

61. **As a creator, I want clear sensor data conventions, so that mappings are consistent across rendering choices.** 模块说明坐标、单位、有效性与更新方式；归一化或平滑明确可见，不自行决定声音、乐谱角色、声道或节奏政策。

62. **As a creator, I want sensor results to enter the same accepted event channel, so that recordings can reproduce their musical effects.** 记录与回放工程真正使用的特征和动作，回放不自动重新启用摄像头或麦克风；不把原始媒体流或完整传感器录制作为默认分发内容。

63. **As a creator, I want sensor adoption to finish its actual wiring, so that a copied module is not called a finished feature.** 采用包含需要的共享引用、源码、离线模型、权限触发、输入、作品映射及验证；助手逐项说明已完成与尚未验证，不能停在文件复制。

64. **As a Host operator, I want camera and microphone access in the monitor on an HTTP venue network, so that laptop-based scores do not require venue HTTPS.** 主 monitor 使用复用 Client 思路的受管可信第一方来源和原生权限处理；不靠普通 LAN HTTP iframe 直接获得受限媒体能力。

65. **As a creator, I want camera and microphone access in performer test windows, so that I can test the same work inside the App.** 测试窗口获得对应的可信第一方媒体路径，同时保持独立身份、测试视口、页面交互、窗口生命周期和输入模拟；不把测试窗口变成 App 管理页面。

66. **As a performer, I want real native permission choices, so that media access remains under my control.** 只对当前有效页面和匹配来源处理媒体请求，使用真实 WebKit 与 macOS 权限选择；用途描述、拒绝与重新启用均受实际系统行为约束，不静默自动同意。

67. **As a creator, I want several test windows to use media without stealing from each other, so that multi-performer testing is predictable.** 每个窗口分别手动启用；底层允许时可使用同一物理设备，失败时说明共享限制，不为成功打开一个窗口而强行关闭或抢占另一个窗口。

68. **As a creator, I want an approved chat task to continue through adoption and wiring, so that I do not repeat the same confirmation.** 复用现有聊天确认与本任务内资源决定；确认后助手继续完成引用、模块、模型、源码与业务接线。已有资源不重复询问，缺 p5 的摄像头前置要求仍按明确限制反馈。

69. **As a creator, I want tests to exercise the created project rather than private helper internals, so that the result matches what I receive.** 从公开创建与聊天任务入口生成真实工程，检查实际文件、声明、路由、输入、身份、回放和故障恢复；既有工程采用和撤回也通过公开工作流验证。

70. **As a release reviewer, I want this increment completed before the final beta.3 acceptance, so that #313 and #314 assess the complete release.** 主测试 seam 为“公开创建／聊天 → 真实工程 → 原生媒体 → #313／#314 联合验收”；完成基础和原生媒体适配后再进行两票最终验收，保留稳定入口、切换与断网保页回归，不用模拟设备结果替代真机结果。

## Implementation Decisions

1. **发行与职责。** 作为 v1.7.0-beta.3 增补实施，不另开一个后续版本规避本轮范围。App 拥有工程生命周期、演奏入口、二维码、录制界面与存储、共同时间驱动及原生媒体承载。工程拥有作品状态、输入到画面／声音的映射、回放语义与工程资源；标准模块是加入后由工程维护的源码，共享包是 App 保存的第三方依赖。

2. **唯一创建起点。** 新建只保留 Blank，取消 Classic 新建选项与相关推荐；现有工程兼容继续成立。新建仍生成独立工程身份和初始版本，不继承示例作品身份或策略。不自动迁移、覆盖、删除已有定制工程。

3. **默认与可选。** Socket.IO、Express、osc-min 采用 App 当前确切版本并真实接线。players、monitor-state、公共输入、录制及已有预演基础属于 Blank 默认；主题、语言、hub、三种传感能力按需。模块具体标识和内部文件组织沿实现规范确定，不在规格阶段杜撰新约定。

4. **完整采用。** 资源目录、助手工具和概况能辨别默认已存在资源。采用 hub 在同一任务自动补齐所需 Socket.IO 客户端引用和导入，不把浏览器已有客户端混同 Node 依赖。缺少资源或不符合确切版本时明确失败，无运行时网络回退。

5. **身份政策。** 默认采用与座位、声道无关的随机 claim 和独立演奏者身份。服务端保存足以跨重启恢复的最小映射，演奏参数与之分离。同工程同 claim 新连接接管旧连接；控制、动作与释放均核对当前拥有者。接管只改变逻辑身份所有权，不授权抢占硬件或复用另一演出的进入确认。身份记录的具体存储组织属于实现决定，必须满足工程与来源范围、原子性、错误可见和分发边界。

6. **monitor 状态。** 声明键决定可同步状态及校验；初始为空时保持惰性，不增加空的视图通道。开启后从完整服务端快照渲染，只负责工程低频视图选择。身份、演奏记录和 App 显示调度不进入该状态层。

7. **公共输入。** 一个明确的标准输入入口接收鼠标单点和真实多点，并解决 pointer、touch 和原生模拟之间的重复交付。每个触点有明确生命周期，坐标随布局适配。普通表单、页面快捷键与既有保留输入规则不受破坏。

8. **公共录制闭环。** 默认生成现场输入校验、事件捕获、业务应用、快照／恢复、释放和需要时的时间推进基础。回放使用同一业务应用但不再次捕获。助手扩展作品行为时同步维护该闭环；不提供让用户选装的“录制模块”，不因只有声明就宣称全部业务可回放。

9. **音频分层。** 把稳定 OSC 传输、应答、超时、模式、资源归属与收尾集中在默认基础中。作品声部、音色、控制映射、路由与 External 协议保持可编辑且由工程定义。默认底层不得静默启动另一套声音引擎或越过 App 的私有音频 bus 契约。

10. **摄像头路线。** 使用现有确切 ml5 与 HandPose 资源；前提是工程已具备兼容且可信的自带或共享 p5，不强制迁移已有 p5 版本。采用前完成前置检查；缺前提提示并暂不加入，不自动采用 p5、不增加备用推理路线，也不留下 ml5、模型或模块的半加入残留。离线模型随模块采用进入工程及工程包；模型资源、关键点和少量特征的范围固定，媒体授权和推理结果分别处理。

11. **麦克风与设备运动。** 麦克风基于原生采集和 Web Audio，每个已启用页面／模块实例内部用一条流与分析链输出四类特征，不限制 App 全局只能采集一次，不默认录制或上传媒体。运动基于原生浏览器能力，限定倾斜与加速度。两者不引入 p5 或 ml5，不补造硬件缺席时的数据。

12. **原生媒体页面。** Host monitor 与创作 performer 测试窗口复用 Client 已有可信本地来源、第一方原生页面、来源隔离、受管代理和真实权限处理经验；具体可共享内部模块由实现确定。改变页面承载不得丢失原有揭示门、刷新 nonce、主题／语言推送、缩放、投影开演门、参数预演、App 命令与键位、焦点、侧栏、窗口及测试存储语义。模型、Worker、媒体及连接沿受管同源资源规则运行。

13. **采集归属。** 在主／投影两份 monitor 副本之间，主 monitor 持有采集与分析，投影消费结果；不限制 performer、Client 的参与设备或独立测试页面分别启用自己的输入。采集启停、错误恢复和页面明确释放按实际媒体所有权处理，网络暂停不得自行等同文档结束。多个测试窗口分别启用，设备共享失败不自动抢占。不得把 Client 已有 API 暴露证据直接作为新增页面的真实采集证明。

14. **聊天内完成。** 沿既有任务批准、资源确认、来源保护、撤回与故障恢复流程实施。一个已确认任务内复用已有决定，完成实际接线后再报告结果。工程缺少明确前置资源时，给具体阻碍和当前状态；不得跳过用户已定的“不自动加入 p5”规则。

15. **二维码与兼容。** 新工程及资源推荐不再要求工程提供加入 QR。App 仍拥有二维码编码与显示能力；隐藏工程推荐不能直接删除 App 自用或已发布工程需要解析的资源。历史模块来源和已发布帮助路径按现有契约保留。

16. **公开测试接缝。** 优先通过公开新建和聊天任务入口观察真实生成工程及原生行为。允许模块内部有测试接缝，但它们不能替代交付工程的集成结果；不为通过测试另造一套简化工程实现。

17. **目录与依赖规则。** 普通共享包新增界面及助手独立推荐撤下 socket.io-client 与 qrcode；底层资源、确切引用解析、已采用事实展示和外部自定义工程兼容继续保留。hub 自动依赖规则由资源系统确定，不依赖助手每次记住补包。默认已包含模块不得显示虚假待接线／交接任务；作者修改后的模块不自动覆盖。

18. **手势前置与资料。** p5 是本手势模块约定的产品前提，不把它说成 ml5 普遍的技术依赖；检查工程已有可信自带或共享来源，并完成目标页面实际接线。缺少时显示“本工程还没有 p5.js”，暂不添加模块及任何伴随资源。模型复制包含完整所需字节、来源、许可和完整性记录，仍归工程资源。普通用户在同一“添加并继续”卡片确认能力、必要依赖及影响，包名和技术详情可展开阅读；讨论保持只建议，工作模式执行写入。

## Testing Decisions

1. **创建和实际资源。** 从公开新建入口产生真实 Blank，核对唯一创建选择、独立身份、默认确切依赖、实际源码接线、无重复采用及失败不留下半个工程。以现有 Classic、Template 衍生和自包含工程覆盖兼容行为；不只快照一份固定文件清单。

2. **公共聊天工作流。** 通过现有批准任务与资源工具完成真实工程的采用和接线，验证已有资源复用、同任务不重复确认、完整恢复／撤回及自定义源码保护。覆盖可信自带／共享 p5 的采用、无强制版本迁移，以及缺 p5 时提示、无自动采用、无 ml5／模型／模块半加入残留；其他已获准独立工作不被虚假宣称完成。

3. **身份与多连接。** 使用真实工程的 HTTP／Socket.IO 和独立客户端验证刷新、传输断线、停止重启后的身份恢复；核对演奏参数每场重置。同 claim 新旧连接交错、旧控制、旧断开与重复加入不能释放或篡改新拥有者；多测试窗口仍是不同身份。包含存储拒绝、损坏和发布失败的真实反馈。

4. **视图与输入。** 空 monitor 状态不建立无用同步；有键时通过多份真实 monitor 校验完整快照、晚加入、重连、非法更新与运行重置。覆盖鼠标单点、真实多点数据路径、pointer／合成 touch 去重、取消、原生控件和 resize。真触摸与原生设备体验另留实机证据。

5. **录制闭环。** 在真实生成工程中接入可观察的状态和效果，从现场事件到记录、回放、叠加、整轮重录与释放验证同一业务入口。验证回放不再次捕获、跨轮身份独立、乐谱选择独立、时间推进和手动指挥门禁；空声明或仅管理端点不得被当作完整支持。

6. **默认运行契约。** 通过真实受管进程、监听器、HTTP、polling、WebSocket 和受控 OSC 核对动态端口、fd 交接、启动报告、health、资源限制、权限范围、音频初始化失败及关停。保持预演源码快照与来源摘要的真实验证，不能用启动后磁盘内容冒充已加载代码。

7. **离线模型和输入链。** 核对摄像头模型随工程及工程包携带，离线可加载，缺失与完整性失败无网络回退。验证关键点与捏合／张手特征的实际转换、单采集复用、麦克风四特征共享分析链、运动字段有效性及错误反馈。可控输入验证计算，真实设备验证采集与首次推理；二者分别记载。

8. **原生媒体。** 分别在 Client、Host 主 monitor、创作 performer 测试窗口验证可信第一方来源、媒体 API、真实授权／拒绝／重新启用、摄像头／麦克风实际采集与模型首次推理。核对当前设备的可选输入、切换、后台恢复和明确释放。主／投影 monitor 只由主副本采集，performer／Client 可独立启用；同一页面四类麦克风特征共用其采集链，多测试窗口成功共享或明确失败，不能抢占。

9. **入口与文档持续性。** 回归公开浏览器、原生 Client、Host monitor 和创作测试窗口的既有页面与网络所有权。覆盖断网保页、Stop／新演出后旧请求失效、明确重新进入、候选切换失败保原页、成功后交接，以及来源存储、模型／Worker 和 Socket.IO 资源路径。媒体支持不得反向要求整个场地迁移 HTTPS。

10. **统一完成标准。** 新业务逻辑随改动带测试；完成 App 必须通过 `npm run check:all` 全绿；各维护源执行其适用检查与构建。App 检查不替代独立维护源检查、真实原生设备、物理声音、手机触摸或签名安装验收。开发服务器由用户启动；不得借后台自动启用真实摄像头、麦克风或传感器制造验收结果。

11. **联合验收门。** 本规格的默认工程、聊天采用、原生媒体与回归先完成实现和自动化，再与 #313、#314 的最终场景联合验收。两票应覆盖同一组最终构建和真实工程，不先按旧底座通过，再把本规格留待后验。记录架构、系统、构建、工程版本、来源、步骤、预期／实际与未通过项。

12. **复用既有先例。** 扩展公开工程创建／启动和真实端口交接测试、聊天资源批准／重启恢复／整任务撤回测试、真实 Socket.IO 多客户端测试、现有 III／Runes 演奏记录公共适配测试、原生 Client 第一方来源／存储／媒体 API 夹具和浏览器切换保页测试。确定性关键点和音频数组仅用于特征计算断言，完整原生采集、设备选择、触摸及听音由实机证明。

## Out of Scope

- 不改变现有 beta.3 的浏览器／原生演奏入口、明确进入、稳定身份、断网保留文档和成功后切换的职责划分。
- 不删除既有 Classic、Template 衍生、旧共享引用或作者定制工程，不自动升级、合并或迁移其源码；取消的是新建 Classic 的选择。
- 不默认加入 p5、ml5、主题、语言、hub 或传感模块；不因摄像头前置条件缺失自动采用 p5。
- 不新增第二套摄像头推理路线、通用 AI 模型选择器、完整手势识别、身体姿态、面部识别或在线模型下载回退。
- 不承诺普通手机浏览器直接打开任意 LAN HTTP 页面即可取得受限媒体能力；本轮的 HTTP 场地支持基于 App 原生可信第一方承载，手机仍遵守实际浏览器条件。
- 不实现鼠标虚拟多点保持／编辑工具，不把桌面单点模拟视为真实多点、压力、传感器或移动浏览器验收。
- 不提供完整角速度／陀螺仪融合或保证所有设备具备运动传感器；缺数据不伪造结果。
- 不默认录制、保存、上传或分发原始摄像头／麦克风媒体，不提供自动音频监听、网络媒体流或远程硬件控制。
- 不规定作品音色、声部、座位、声道布局、人数、乐谱选择与 External 控制协议，不自动恢复上一场演奏参数。
- 不承诺任意后来添加、绕过公共事件与状态接口的业务都自动可录制回放；助手与作者仍须完成真实作品接线。
- 不凭资源复制、能力声明、API 暴露、假媒体或受控数据宣布完整原生采集、模型推理、声音或发行验收通过。
- 不要求用户离开已确认聊天任务再手工安装依赖或选装录制模块；系统实际权限选择和无法自动解决的硬件限制仍如实说明。
- 本规格发布及排期本身不实施产品代码，不自动启用硬件，也不表示版本已经可发行。

- 新增 VexFlow、Three.js、Tone.js 等共享库，以及另建资源预加载、共享时钟或同类可选模块；它们仍是后续候选，不扩大本轮已确认清单。
