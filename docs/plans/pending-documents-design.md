# 待处理文档：设计核实

状态：产品方案与工程文档收录规则已确认，并由本轮用户确认纳入 v1.7.0-beta.2；后续实施以[正式规格](./v1.7.0-beta.2-pending-documents-spec.md)（GitHub #260）为准。本文保留设计核实历史，不表示已实现。本轮只整理和发布规格。

## 已确认：第一轮

1. 用“待处理文档”整体替换“创作资料”入口，承接等待使用的代码和文本。
2. 点击“新建待处理文档”，左侧分组立即出现新条目并输入文件名；中央主编辑器打开空白内容。创作者粘贴后通过保存按钮或 `⌘S` 保存。
3. 用户发送消息时，助手获得已保存待处理文档的清单，结合任务按需读取正文。保存不启动助手。讨论可以指出相关文档，明确的工作任务可以使用文档。
4. 接入可安排文件位置、修改依赖路径、补充入口和加载引用，保留原代码的算法、声音、视觉及交互意图。需要实质改写这些行为时，先向创作者澄清。

术语定义见 [CONTEXT.md](../../CONTEXT.md)。这些目标取代现有“创作资料”的产品定位；实现前不改写现有使用教程和开发规则。

## 已确认：第二轮

5. 每份文档保存为独立文本文件，位于工程专用暂存目录；Finder 与外部编辑器可以读取，App 显示为“待处理文档”。
6. 暂存文档随完整工程目录复制、迁移；接入前不进入工程 Git 版本、默认演出 `.pnds` 包或工程运行检查。Git clone 不携带暂存文档。采用工程内私有目录边界，见 [ADR-0012](../adr/0012-pending-documents-private-files.md)。
7. 文档及必要入口、引用接入保存成功后，原条目从待处理区移出，后续编辑目标工程文件。接入未完成或失败时保留待处理文档；撤回接入时恢复它。保存成功与实际音画测试分别表达。
8. 接入相关文档有未保存修改时，提示“保存并继续／取消”；取消保留草稿，助手依据明确保存版工作。任务中再次变化时重新核对。
9. 已有资料自动迁入待处理区，保留原名称、正文和旧聊天来源关联。迁移失败保留原数据并允许重试；缺少可靠接入记录的旧资料先呈现为待处理。
10. 主操作为新建后粘贴；另保留次要“导入文本文件”，复制到待处理区并保留外部原文件。

## 已确认：第三轮

11. 点击新建后先出现编辑草稿，首次保存才创建真实文件。切换文档保留草稿；离开工程或退出 App 时提供“保存／放弃／取消”。保存工程版本也先保存这些草稿，但暂存文档仍不进入 Git。
12. 待处理区先使用一层列表，名称不包含目录路径；新建重名要求改名，导入重名提供可修改的建议名称并等待确认，旧同名资料全部保留。支持既有代码和文本类型，无扩展名按纯文本处理；单份上限 1 MiB，最多 64 份，正文合计上限 8 MiB。
13. 一个任务接入多份文档时，全部接入完成后再统一移出。中途失败保留所有待处理原文和已保存工程修改，列明完成与未完成部分，提供继续处理或撤回本次接入；部分成功不能表达为全部完成。
14. 保留最近一次接入任务的恢复记录，接入结果提供撤回入口，恢复该任务的工程改动及待处理原文。重启保留，下一次成功接入后替换。相关工程文件后续改变时阻止覆盖，可单独恢复原文到待处理区而保留当前工程文件。
15. 旧聊天保留当时实际读取的文本片段，另行提供当前文档或接入目标入口；不建立每次编辑的完整版本库。旧引用不重新解释为当前正文，助手再次使用时重新读取保存版。
16. 外部编辑后，未编辑文档更新；有未保存草稿时保留草稿并提示冲突。外部改名或删除后更新列表，保留已打开草稿并说明文件变化；助手使用前重新核对。

## 已确认：第四轮

17. 明确工作任务中，助手可阅读并选择相关文档接入，无需创作者逐份点名；有多个合理候选、用途不清或需改变艺术行为时询问。清单出现不意味着全部接入。
18. 参考文档与接入源按下一节已确认的工程文档收录规则区分。源码及需要长期维护的工程说明纳入工程后，在任务成功时移出；仅阅读的临时参考继续保留。
19. 可执行检查实际失败时保留原文并继续修复或暂停；检查能力不支持或被当前运行占用时，必要文件与引用均已保存后可以移出，但结果标记“已接入，尚未完成运行验证”并说明原因，保留恢复记录。必要文件或依赖仍缺失属于未完成，保留原文。
20. 助手按工程结构选择目标位置；目标内容完全相同可复用，不同时展示差异并等待“替换／并存／取消”，作答前不覆盖。目标有未保存草稿时先处理；确认后仍复核磁盘内容。
21. 用户可重命名、编辑、删除和在 Finder 定位。删除前确认，只删除暂存副本及对应草稿，不影响外部来源或已接入工程文件。助手读取原文，在目标工程副本中调整；成功后由系统移出原文。普通整理任务不顺带改写或清理待处理原文。

## 已确认：Q18 工程文档收录修订

2026-11-03 用户确认：在明确的工作任务中，将相关文档分成三类；助手可按第 17 项自行发现和选择，无需用户专门点名待处理区：

| 用途                                           | 处理方式                                                                             | 成功后是否移出 |
| ---------------------------------------------- | ------------------------------------------------------------------------------------ | -------------- |
| 源码                                           | 接入实际代码目录，补齐必要入口、依赖与引用                                           | 是             |
| 与当前任务相关、应长期维护的工程说明           | 收录到合适的工程文档，默认根 `docs/`；已有合适文档时优先更新，来源完整保留到任务成功 | 是             |
| 临时问答、未定草稿、外部参考全文或用途不明资料 | 按需阅读；用途不明确时询问                                                           | 否             |

“自动”发生在已授权工作任务中，添加、保存、讨论和单纯阅读不会触发文件收录。明确要长期维护的工程说明可按此默认规则收录，不逐份重复询问；无法确定长期用途时先询问。“按此说明实施”不能单独作为将整份外部参考全文写入工程的理由。普通工程整理仍遵循第 21 项，不自动扩大到待处理区。

PNDS 既有目录惯例是 `docs/`；根 `docs/` 默认参与工程 Git 版本，但不进入默认演出 `.pnds`。内部设计说明不自动写入面向演出准备者及投影观众的根 README。文档目标冲突、保存、批次完成和恢复使用与源码相同的规则。本修订补充第 18 项，术语中的接入同时包含工程代码与工程文档的收录。

## 完整实现方案（暂不实施）

### 文件区和编辑器

- 可编辑文件夹工程的文件区增加独立“待处理文档”分组，空分组仍保留新建入口。主操作为“新建待处理文档”，导入作为次要操作；不再打开旧资料管理弹窗输入正文。
- 新建立即生成带稳定草稿身份的条目，行内输入文件名，中央复用主文本编辑器；首次保存才发布真实文件。取消未填写的空白新建不产生磁盘文件。文件名、未保存标记、保存失败和外部冲突均在当前编辑流程表达。
- 保存、切换文档、退出、切换工程和保存工程版本共用草稿生命周期协调；任何保存失败或冲突阻止依赖它的离开或接入操作，保留内容。
- 将编辑对象明确区分为普通工程路径与待处理文档稳定 ID。复用现有文本缓冲、语法高亮及编辑器，不把私有路径伪装成普通工程文件路径。重命名保持文档身份，旧来源仍引用当时的名称和版本。

### 独立文件及原生边界

拟使用下列物理布局；路径是实施阶段的具体设计，界面只显示文档名和真实 Finder 定位：

```text
<project>/.pnds-creation/
  pending/
    index.json
    documents/<document-id>/<filename>
  integration-recovery/
    ...恢复元数据和必要原文／工程前后内容...
```

- 正文是独立 UTF-8 文件，索引只维护身份、名称、状态及关联目标等元数据。每份文档使用独立 ID 目录，允许保留旧资料中的同名文件，并在外部改名后保持来源身份。
- 原生提供专用列举、读取、新建／保存、重命名、删除、导入和 Finder 操作；以当前工程身份、文档 ID 和预期保存版本授权，不接收可逃逸的任意目标路径。
- 沿用现有受信目录句柄、路径隔离、不可跟随符号链接、保存版本复核和原子文件发布；文件与索引需要可恢复的发布顺序。发布前后中断均能重新判定真实状态；缺失或损坏时保留原数据并报告，不重建为空列表。
- 列举和使用前同步外部改名、删除和正文变化；正文版本以实际保存内容为准，外部保存不覆盖用户草稿。外部写入超过限制、无效编码或非文本内容时报告问题并保留可恢复草稿。
- 暂存正文、恢复记录和接入身份记录都留在私有目录；Git、默认演出包、普通助手文件工具和工程运行检查沿用私有目录排除边界。接入目标按普通工程文件规则处理。

### 助手发现和执行

1. 每次请求准备时获取当前工程已保存文档清单，只提供名称、身份和版本等必要元数据；列举不自动发送全部正文。
2. 助手结合当前任务按需读取实际保存内容。接入使用确切版本和完整实际读取证据；历史片段、摘要和文件名均不替代当前正文。
3. 明确本次参考文档、接入源和目标位置；用途有歧义时提问。接入源有未保存草稿则提供保存并继续或取消，目标草稿及同名冲突按已确认规则处理。
4. 沿现有工作工具准备目录、写入目标和调整必要引用；只调整工程副本，保留原文直到整批完成。每次写入记录实际前后内容及保存结果，继续现有同任务检查与修复路径。
5. 由显式接入完成步骤核对本次源版本、目标集合、必要引用处理和检查事实。模型一条“完成”回复或一次文件复制不能单独消费原文；语义接线质量依然需要助手真实阅读与后续人工音画验收。
6. 先持久化恢复记录和完成状态，再移出本次接入源，更新文件区与编辑器选择；任何中断都能区分未完成、部分写入和已完成状态。结果列出来源、目标、实际改动、检查通过／失败／未验证事项及恢复入口。

### 批次与恢复

- 同一工程同时只执行一个接入任务，沿用工作任务的归属和接续控制。未完成批次保留源文档、已写事实及恢复信息，继续与撤回均先核对当前保存版；取消执行不自动抹掉已保存改动。
- 整个包含接入的工作任务是恢复单位，涵盖它创建或修改的工程文件和引用；界面采用“撤回本次接入任务”，展示全部受影响文件。
- 完成后的恢复记录独立于会被清理的助手执行日志，保存最近一次成功接入；新成功批次的记录与原文移出均持久化后才替换旧记录。跨重启读取只展示恢复事实，不自动执行。
- 撤回先核对全部目标和源身份，相关工程文件已被后续修改时拒绝直接覆盖。仅恢复原文作为独立动作，不改当前工程；恢复沿用原文档 ID，目标暂存位置冲突时保护现有内容。
- 多文件写入或恢复中发生 I/O 中断时，通过持久化记录继续或报告实际部分结果，不假装整批已经恢复。Git 切换后重新核对恢复适用性，不自动重建待处理区。

### 旧资料与聊天迁移

- 首次打开旧资料时，将每个记录迁为独立文本文件，保持旧 ID、正文版本、名称和字节内容；同名由独立身份隔离，不覆盖任何条目。
- 新文件与索引完整发布并校验后才确认迁移完成，保留旧记录作为迁移恢复依据；重试复用原身份，不重复导入。独立持久化迁移完成状态，待处理区后来变空也不重新导入旧资料；索引损坏不能触发旧记录回退。损坏或部分迁移明确报告，保留已有文件和原记录。
- 旧聊天保留原来的读取快照、名称及来源身份。文档被编辑或移出时，历史展示当时片段，并将打开当前文档／目标文件作为另一个操作；新请求重新读当前文件，旧引用不授予新写入权限。

### 落地顺序与验收

1. 原生私有独立文件存储、稳定身份、迁移和中断恢复；补齐真实临时工程测试。
2. 文件区分组与主编辑器接入，打通新建、导入、保存、命名、外部变化及草稿离开流程。
3. 请求清单、按需读取、明确接入批次及目标冲突；验证历史与当前证据分别表达。
4. 批次完成、最近一次独立恢复记录、任务完成日志清理衔接及跨重启恢复。
5. 更新中英文 UI／帮助和对应开发规则，执行 `npm run check:all`；dev server 与原生交互由用户启动回报。

自动化重点包括：首次保存和取消、真实文件可访问、同名不丢失、容量与编码、外部保存和草稿冲突、跨工程迟到回复、清单不夹带正文、参考不误消费、同名目标显式确认、写入／迁移／整批完成中断、检查失败与不可执行的区别、跨重启恢复、后续编辑不被覆盖、原文单独恢复、旧聊天引用，以及私有数据在 Git／打包／运行检查中的排除。原生人工核对覆盖中文与英文的新建粘贴、Finder 外部编辑、助手实际摆放与接线、失败继续和恢复；自动化不代替真实模型及音画验收。

## 已确认决定的具体后果

- Git 版本不包含待处理区，因此切回接入前的工程版本不会自动重建待处理文档；应使用明确的原文恢复操作。切换版本后，整任务撤回仍须核对实际工程文件。
- 第 14 项以整个接入任务为撤回单位；若任务同时包含其他工程修改，撤回也涵盖这些修改，应在入口显示完整影响范围，不能仅删除复制出的文件而留下引用。
- 第 12 项将总量明确为正文总字节数；旧实现的 8 MiB 限制实际计算序列化 JSON 大小，新存储不能继续使用该表述。

## 现有事实

- 现有资料是 `.pnds-creation/materials.json` 内的不可变私有文本副本，支持添加、读取、移除，缺少编辑和重命名接口；见[私有文本资料](../developer/creation-workspace.md#private-text-creation-materials-241--248)。
- 普通工程文本已有主编辑器、草稿、保存及磁盘版本冲突处理，草稿当前以普通工程相对路径为身份；见[手动保存](../developer/creation-workspace.md#manual-save-rename-and-disk-conflicts-154)。待处理文档须有明确身份，避免名称与普通路径混淆。
- 助手已有清单、按版本分页读取、采用源码、同名冲突和任务撤回能力；见[资料接入](../developer/creation-assistant.md#adopt-private-source-into-an-edit-task-250)。新目标还要求每次请求主动提供待处理清单。
- 既有私有创作数据随完整工程目录迁移，工程 Git 版本和默认演出包排除该目录；见[工程结构](../zh-CN/reference/structure.md#工程内的私有创作数据)。第二轮已确认沿用该边界。现有普通文件 API 拒绝私有路径，独立文件仍须通过专用可信命令访问，不能直接把私有路径交给普通保存 API。
- 现有助手按文件逐次保存，尚无文档及其全部目标、引用的统一接入完成记录；已完成任务会清理恢复日志，当前没有长期任务撤回入口。因此第 7、13、14 项要求新增明确的接入完成与恢复能力，不能假设旧任务日志一直可用；见[任务日志生命周期](../developer/creation-assistant.md#task-snapshot-retention-2026-10-23)。独立接入恢复记录必须在清理任务日志之前持久化。
- 旧聊天来源绑定资料 ID 与内容版本，聊天内保存实际读取的正文快照；来源打开时版本不匹配会拒绝，不能把旧版本引用重新绑定到编辑后内容。第 15 项已确认沿用历史读取快照；接入恢复原文使用原稳定身份。
