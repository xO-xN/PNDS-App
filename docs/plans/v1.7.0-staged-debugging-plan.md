G2 的建议卡／比较接入、G3 的待应用建议选区、G5 的交接／版本视图与交接出口、G6 的候选与预演排除、G7 的候选与预演隔离，按对应责任票在 G5、G6 或 G8 补齐真实联调。早期阶段使用受控服务和测试入口时标记证据类型，不能替代真实模型、原生 App 或设备验收。

## 每组交付和结果记录

每次交给用户常规调试前，实施者须在本次交付源码上取得 `npm run check:all` 全绿，并提交下面的调试记录。未通过的构建可单独用于故障诊断，但必须标为“检查未通过／诊断用”，不能记作本组通过或常规交付。dev server 与真实 App 仍由用户启动并反馈。

| 字段           | 必须记录的内容                                                                                                          |
| -------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 源码与构建     | commit／分支、未提交差异标识（如有）、构建或安装包标识、自动检查时间与完整日志                                          |
| 环境与工程     | macOS、架构、App 版本、语言／主题／窗口尺寸、工程来源和版本；涉及模型时记服务及模型标识，涉及声音时记模式、设备与采样率 |
| 本轮可测范围   | 组号、issue、已接通检查点、尚未接入项；说明真实服务、受控替身和纯自动测试各覆盖哪部分                                   |
| 操作与预期     | 可复现的准备状态、输入、正常步骤、拒绝／失败步骤，以及每一步应观察到的结果                                              |
| 实际结果与证据 | 通过／失败／未测逐项填写；附截图、脱敏日志、真实文件／提交／运行状态核对和来源定位，不记录凭据或私人工程正文            |
| 失败复验       | 问题 issue、失败构建、修复源码、重复的原步骤和新证据；保留原失败，不以新截图覆盖失败记录                                |
| 下一次联调     | 未完成验收项、负责 issue 和应在哪一组复验；无证据不得改为通过                                                           |

以下每组的步骤是本轮最小人工调试脚本，完整票据验收与自动测试仍须全部满足。需要制造锁、断连、异常载荷或外部竞态时，使用可丢弃的工程副本、受控服务／进程或对应自动测试证据，不用真实无关工程和进程充当故障样本。

## G1：基础代码编辑

**直接依赖与顺序：** #224 依赖六项前序门控及 #154、#155。不等待模型配置或 G4；提供的文件／行定位和草稿能力供 G3、G5、G6、G7 接入。

**准备：** 可编辑源工程包含至少两种常用文本、长行、中文和需要内容校验的 manifest／README；另备只读工程包。记录一处可识别的 monitor 页面交互状态，启动与否由用户按既有流程选择。

**调试步骤：**

1. 从文件树和快速打开进入不同文件，使用行号、跳行、查找／替换定位一段代码；核对高亮、长行和搜索结果对应真实内容。
2. 用中文输入法、缩进、剪贴板及键盘编辑，在两个文件间切换并分别撤销／重做；返回时检查各自草稿、位置和内容，不保存便核对磁盘未变。
3. 明确保存其中一份合法草稿，核对实际磁盘变化、未保存提示和当前运行仍采用的版本；非法 manifest／README 修改按既有规则拒绝并保留可修正草稿。
4. 在外部修改已有草稿对应的文件，再尝试保存；检查冲突提示及双方内容可保留，取消、重新核对或明确重载均不能静默覆盖。
5. 打开只读工程包验证不可写；在源工程使用当前已有的文件阅读切换及 monitor 展开／还原，确认原页面状态保持，控制台仍在中间区域下方。#166 的分栏拖动、键盘调整和助手阅读入口在 G2 接通后补验，不作为 G1 独立编辑器的前置。

**通过标准与证据：** 对应文件内容和磁盘版本与操作一致，草稿与逐文件撤销隔离；保存成功和拒绝都有真实文件证据。只读及冲突保护不能只靠按钮禁用。原生录屏／截图与运行日志表明阅读和布局变化未重建、刷新或重启 monitor，输入法和快捷键在正确焦点生效。记录 G2 的新布局和 G3 等下游尚未接入的定位入口，不把入口占位算完整联调。

**调试步骤：**

1. 从未配置状态进入设置，保存、替换、移除并重新配置密钥；连接测试完成指定模型的文本和工具调用回环。观察鉴权、超时及不支持工具调用的不同反馈，核对请求未带工程内容。

4. 在讨论、文件和交接阅读区域间切换，调整左右宽度、monitor 展开状态和控制台；核对输入、回复、草稿、焦点与同一 monitor 交互状态保持。
5. 关闭并重开工程、重启 App、切到另一目录，再清理当前工程聊天；核对历史按工程隔离、来源可辨认，清理不影响另一工程或文件，旧发送与执行授权不恢复。
6. 移除配置或断网后继续编辑、保存和手动测试；G5／G6 就绪时补测讨论内建议卡、预演标记、真实 diff、整体比较与返回原回复，并重复历史恢复和视图切换。

**通过标准与证据：** 真实连接测试和来源导航可复现，脱敏载荷证明平台问答不发送工程。停止／切换后迟到回复、历史和授权均隔离；密钥存储及失败测试证明无明文回退或泄漏。原生布局证据与 G1 相同，配置失败不阻断本地编辑。#166 的问答／布局、卡片容器及阅读入口契约，#167 的历史格式、快照归属、持久化与旧授权不恢复，须实际实现并用受控消费者验证。建议卡真实接入由 #208、附件发送与历史恢复联调由 #225、比较视图真实接入由 #227 完成，#172 汇总；第 6 步的真实集成仍待验证，不反向阻止已满足自身全部职责的 #166／#167 关闭。

## G3：理解当前工程

**直接依赖与顺序：** #168 依赖 #166、#232、#233、#234、#235；#169、#170 各自只依赖 #168，二者可以并行；#225 依赖 #224、#167、#168。因此授权与受限读取先验证，概况、全工程阅读和附件各自接入；待应用建议选区在 G5 后补测。

**准备：** 两个可区分工程，包含已保存文本、未保存草稿、普通资源、应排除目录／敏感文件、超预算文件及受控越界路径样本；可观察脱敏请求载荷的测试服务与真实模型。记录本轮允许读取的来源和预算。

**调试步骤：**

1. 对当前工程提问，先取消授权，再确认明确工程、模型服务与读取范围；检查取消未发送、确认后只读取相关保存版，并从来源定位到实际文本。
2. 改动并保存一个来源文件，再在外部改动另一来源；查看概况刷新／过期提示及下一次实际读取版本。核对概况区分内容迹象、静态校验和最近测试，不能自行启动工程或请求模型。
3. 主动选择“阅读整个工程”，核对真实可读清单、排除原因和容量估算；分别取消、扩大范围、超出预算和确认前换工程／服务，验证旧确认失效，超限不会静默截断并声称读完。
4. 从保存文件和未保存草稿各选一段代码，预览路径、版本与保存状态后发送；核对实际附件只有所选内容，编辑、选择、加入输入框本身不发送，旧附件按发送时快照恢复。
5. 关闭工程读取后继续平台问答；实际载荷不含历史工程摘录、概况和附件。带附件的新问题应保留输入并要求明确处理，不能静默丢附件后发送。重复读取越界／排除文件的受控用例，核对服务端拒绝。
6. G5 就绪后从建议卡手写的非数字修改选择片段提问；附件明确“待应用建议”、候选修订和目标版本，仍遵守授权与预算，不混入其他手写内容、文件草稿或预演状态。

**通过标准与证据：** 载荷、来源和真实文件核对能解释模型实际看到什么；取消、关闭读取、身份变化、路径及预算边界均有拒绝证据。概况不把旧成功当当前结果，附件无隐式发送。#169 不等待 #170，反之亦然；第 6 步未完成时只记录 #225 当前文件／草稿附件检查点，不把候选选区验收勾为通过。

## G4：参数绑定与预演基础

**直接依赖与顺序：** #231 只依赖六项前序门控，不等待 #165、#166 或 #208。先验证本地描述／绑定，再验证实际适配、生命周期和失败恢复，供 G5 使用。

**准备：** 不同代码组织和参数类型的受控真实工程，覆盖连续数值、非数字值、有适配、无适配、不兼容适配及部分支持。通过该能力的测试入口或受控调用完成调试，不为本阶段新增永久开发者 UI。用户按需启动已适配工程；记录磁盘保存版、当前运行加载版和参数基准。

**调试步骤：**

1. 提交合法参数描述，核对真实文件／版本、定位、类型、当前值、工程硬限制和建议试调范围；再提交错误版本、错误工程、类型不符、重复或不可定位目标，观察确定性拒绝。
2. 在已适配运行中调整合法数值和非数字值，观察同一 monitor 或实际适配输出；连续快速调整并制造乱序回执，最后显示和实际效果须属于最新有效操作。
3. 用缺少／不兼容适配、需刷新／编译／重启及局部支持的工程尝试预演，核对支持范围和拒绝原因；消息发送成功不能当实际效果成功。无运行时不得自动启动服务或声音。
4. 结束预演，核对对应参数恢复到本次运行基准，磁盘、草稿、Git、交接基线不变；记录能力不承诺回退运行时间或已经发生的实际效果。
5. 分别触发断连、超时、恢复失败、外部文件变化、停止／重载／切换工程，核对旧预演失效、迟到消息隔离；恢复失败必须显示未恢复／状态未确认，不能自动重启掩盖。
6. 在受控保存流程后重新核验预演关联；仅有效时保留临时标记，结束仍恢复原运行参数。用户手动刷新／重启后才采用保存版，并使旧会话失效；核对没有任意脚本注入或进程控制副作用。

**通过标准与证据：** 真实可观察效果、能力消息、参数基准和文件状态前后对照一致；非法描述、过期事件和恢复失败均有确定性测试。非数字与不同组织结构不能仅由固定原型值改名覆盖。声音能力只有真实适配与设备证据才可记为通过。G4 通过仅证明工程接口和恢复边界成立，**不能证明 AI 知道何时选择参数或生成适合的控件**；该判断留给 G5／G8 的真实模型用例。

**通过标准与证据：** 三个检查点各有真实模型请求、候选修订、实际文件 diff、运行状态及失败恢复证据；确定性测试覆盖覆盖风险和授权边界。预演效果、磁盘保存、实际运行版本、只读执行差异、检查结果五者可区分。合法非数字编辑可应用，参数更新不抹去用户代码，当前磁盘已变化时撤销被拒绝。#209 的独立入口先通过不代表整个 G5 已通过；G5 也不替代 G6／G7 及发行验收。
