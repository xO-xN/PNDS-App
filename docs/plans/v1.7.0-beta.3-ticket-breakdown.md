## 用户最新范围调整

用户指定原草案 13 Template Preact、14 Orbital Fugue、16 Splash Ink、17 Co here-Co hear 不需要制作。本轮撤下这四张源码适配票，任务由 24 张收敛为 20 张；工程适配范围由原先十三个缩为九个，App Blank／Classic 对应资源仍在范围内。下表和正文均已重新编号。

范围按用户后续确认收敛为九个工程适配、共二十张子任务。Template Preact、Orbital Fugue、Splash Ink、Co here-Co hear 不做本轮源码适配，保留原方式兼容回归；不承诺它们已支持统一入口或 PNDS Client。该范围优先于父规格原有十三源清单。

这四个工程保留现有本机 Host／monitor 和原 performer 地址的兼容路径。当前源码均未声明完整 performer URL 或动态监听能力，页面仍自行拼接固定工程端口，因此不能将“不改源码仍保留原用法”写成“已支持新的统一入口、保存入口换工程或原生 PNDS Client”。本次核对是源码判断，不代替实机运行结果。

二十张子 issue 的 Parent 段均记录上述范围调整，避免只读父规格旧清单时扩大实施范围。父 issue 正文、标题、状态、标签及评论保持不变。建票不代表实现、提交或发布；调用分组见[implement-spec 运行安排](./v1.7.0-beta.3-implementation-runs.md)。

## 拆分原则与可并行范围

- 每票交付一条可演示或可验证的完整用户路径，随业务提供测试和文档；必要归属调整放在相应完整行为内。
- 01、02、03、06 可首先并行。01 沿用运行中 Host 已有的真实监听器验证接入契约；03 沿用现有元数据扩展入口持有时间；06 在现有原生协议上先保护文档；02 在现有 ASBS 中完成真实分谱准备。后三项不抢先定义新浏览器线协议。
- 浏览器保页与候选发现、浏览器成功后切换分成两票；原生同样分开。新协议与单击切换由 01 解锁，不因共享代码位置人为增加阻塞关系。
- 浏览器长期身份约定在 01 明确，各适配工程负责自己的实际凭据恢复、重置及拒绝验证，05 覆盖跨工程往返。08 仅负责可选保存入口与重开。
- 10–17 覆盖八个维护源，18 覆盖 ASBS，共九个：PNDS Template、Inarticulate III、Inarticulate IV、Runes、四个工具及 ASBS。02 是 ASBS 可独立先做的配套能力。App Blank 由 01 交付，Classic 与维护 Template 在 10 完成来源闭环。
- 四工具各票包含本工具固定发行物及对应 App 随包资源，不等待其他作品。提交、打标签和发布遵循明确授权，本地构建不能冒充远端可获取发行物。Telematic 另核对维护输入与当前 App 固定版本的差异，避免较旧快照覆盖较新能力。
- 每票自身验证适用的无 WAN 路径、HTTP 能力上限、业务回归和检查。19 汇集官方模板试点的真实平台证据，可在其他工程仍适配时开始；20 汇集本轮适配源与实际安装 App，并保留四个排除工程的原方式兼容回归。
- 文档归属随交付：01 负责已验证契约与中英参考，09 负责网络／扫码教程，18 负责 ASBS 准备说明，各工程负责自身迁移说明；20 核对装机帮助、资源与稳定链接。App 完成标准为 `npm run check:all` 全绿，其他维护源执行适用检查。开发服务器由用户启动并回报，自动化与实机证据分别记录。

### 01：贯通首个普通浏览器演奏接入与统一契约（#295）

**Issue：** [#295](https://github.com/xO-xN/PNDS-App/issues/295)

**Parent：** #294

范围按用户后续确认收敛为九个工程适配、共二十张子任务。Template Preact、Orbital Fugue、Splash Ink、Co here-Co hear 不做本轮源码适配，保留原方式兼容回归；不承诺它们已支持统一入口或 PNDS Client。该范围优先于父规格原有十三源清单。

**What to build：** 通过运行中的真实 PNDS Host，让普通浏览器和独立原生池客使用同一公开网址；用 App Blank 与真实受管集成夹具贯通第一条已确认演出的真实页面、资源及实时连接链路，形成后续工程可以采用的兼容契约。

**Acceptance criteria：**

- [ ] 由公开启动操作运行真实受管工程和实际绑定的 Host 入口；浏览器直接访问，不使用临时替代代理、浏览器扩展或测试手工注入原生私有身份头。
- [ ] 浏览器查看池主、工程及演出后明确进入；页面、脚本、资源查询、真实 Worker、Socket.IO polling 和 WebSocket 都使用同一已确认上下文。内部实际服务端口变化时仍可正确转发。 App Blank 验证创建路径，所需的真实 Worker／polling／WebSocket 由既有最高层受管集成夹具补齐覆盖。
- [ ] 在旧文档仍可本地运行时，停止或替换演出后，旧页面及 Worker 的 HTTP、polling、WebSocket 和旧确认均不能访问新演出；直接观察新工程实际收到的请求，覆盖 cookie 或端口复用。
- [ ] 确定并实证协议版本、兼容检查、工程适配方式及候选准备结果的表达；未知或不兼容工程明确说明需要适配，不静默跳到旧地址。不提前以未经验证的字段名作为对外契约。
- [ ] 工程能够分别取得稳定池主身份、工程身份和本次演出授权。长期浏览器数据按池主／工程区分，不用演出身份作恢复键；以真实页面读写验证分区和同工程再次进入的恢复边界，不宣称同源命名空间是安全隔离。
- [ ] App Blank 的创建来源采用已验证方式，新建工程实际可通过入口运行；已有原生首次检查／加入及私有来源不回退，Host 和 Client 使用独立 App 上下文。
- [ ] 链路必需资源不依赖 WAN。随业务提供真实外部行为测试，App 完整检查通过；将已验证契约、迁移要求和证据范围同步到开发文档及中英参考契约。

**Blocked by：** 无，可直接开始。

### 02：ASBS 完整准备本人分谱并在断主机后滚至结束（#296）

**Issue：** [#296](https://github.com/xO-xN/PNDS-App/issues/296)

**Parent：** #294

范围按用户后续确认收敛为九个工程适配、共二十张子任务。Template Preact、Orbital Fugue、Splash Ink、Co here-Co hear 不做本轮源码适配，保留原方式兼容回归；不承诺它们已支持统一入口或 PNDS Client。该范围优先于父规格原有十三源清单。

**What to build：** 在现有 ASBS 维护源中，提前持有本人完整分谱的必需资源，保留原页面、跟随引擎和滑动解码窗口；主机完全不可达时，已准备的页面仍能完整滚谱。

**Acceptance criteria：**

- [ ] 使用父规格核定的当前 ASBS 维护源及真实分谱，保留已有修改；本票可以沿用现有入口，不预先发明新的 Host 线协议或能力字段。
- [ ] 准备完整选定分谱的压缩谱图字节、结束页、几何及其他后续运行必需资源；结果绑定同一分谱和工程内容状态，不误用其他分谱或修订的缓存。
- [ ] 只有全部必需资源取得并可使用后才报告完整断主机准备完成；资源缺失、下载失败及切换分谱／修订期间不得虚报就绪，并提供可重试的准备反馈。
- [ ] 保留窗口解码和资源释放边界，不把所有谱图解码为常驻位图；保留原有自主推进、工程暂停、结束以及恢复对齐，不另写一套跟随引擎冒充原工程。
- [ ] 真实页面准备完成后停止受控 Host 或阻断全部 Host 请求，保持同一 Document 和运行循环，从此前未解码的中间页滚至结束页；不能只验预热的少数页面。
- [ ] 新增准备逻辑随改动测试，工程适用检查通过，记录资源量及真实续演证据；不承诺主机离线后的图标冷启动。

**Blocked by：** 无，可直接开始。

### 03：让空闲和跨模式池主持有稳定演奏入口（#297）
