# 浏览器演奏入口：规划讨论

状态：2026-11-09 用户要求通过 to-spec 定稿，纳入 v1.7.0-beta.3。以[正式规格](./v1.7.0-beta.3-browser-participation-spec.md) 和跟踪票 [#294](https://github.com/xO-xN/PNDS-App/issues/294) 为实施与验收依据，本文保留逐轮核对、来源基线与检查历史。尚未实施，不据本文宣称功能或实机验收完成。

## 已确认约束

2026-11-09，用户确定这个新接入方式不采用 HTTPS，原因是现场配置成本过高。规划以局域网 HTTP 入口评估，不要求用户配置域名证书或修改浏览器安全设置。

这项约束不表示删除 App 既有 HTTPS 功能，也不表示将需要安全上下文的工程静默改为 HTTP 运行。

用户随后在 Q5 确认：优先保证保存入口、稳定接入与跟随工程切换；独立窗口按平台提供，接受部分浏览器通过快捷方式打开普通网页。不将所有平台均具有独立应用窗口作为该方式的前提。

## 已确认的产品行为

用户已逐轮回答 Q1–Q10、Q12–Q22，确认以下方向；Q11 原提案由 Q14、Q15 的页面保留与简洁界面规则细化：

- **安装可选（Q1）。** 演奏者直接打开网页即可参与，也可以使用浏览器提供的主屏幕、Dock 或桌面快捷入口。
- **保留并改善原生池客（Q2、Q10）。** 桌面浏览器应正确运行演奏端，现有 PNDS Client 保留；原生池客也自动发现同一池主的新工程并显示名称，单击进入即可加载，不再重填地址或先点重新核对。保留原生网页数据隔离与新演出核验。
- **局域网优先、不依赖公网（Q3）。** 浏览器已安装、池主及所需本地资源已准备且局域网可达时，首次打开、保存快捷入口、再次打开和工程切换均以不要求公网为目标。不将完整 Android WebAPK 的在线打包作为必要路径。
- **网页换工程需点击进入（Q6、Q14）。** 池主切换工程后，网页自动发现新工程，并按简洁界面规则提供进入提示；演奏者点击进入后才加载新页面，无需手动刷新。此前已经打开的页面保持运行，声音仍按工程自身的启用流程处理。
- **每个入口对应一台池主（Q7）。** 保存的入口持续关注该池主的当前工程；连接其他池主使用另一条入口，首版不增加网页内多池主选择。
- **地址稳定的硬性范围（Q8）。** 同一池主 App 持续运行、所用局域网地址不变时，切工程不改变公共演奏入口；退出重开 App、换网络或 IP 变化后的恢复继续单独讨论。
- **空闲池主也提供入口（Q12）。** 节点名与局域网准备好后，尚未加载工程也可访问入口、保存图标或扫码，显示等待演出；开放入口本身不启动工程或音频。
- **跨 App 重启的端口复用（Q13）。** 优先复用上次入口端口；若被其他软件占用，允许重新分配，并明确提示需要更新已保存入口。App 在线期间换工程仍不换入口；IP 变化等其他恢复规则继续讨论。
- **演出二维码移入网络弹层（Q4、Q9）。** 移除演出底栏独立二维码按钮及演出投影二维码覆盖层；下栏显示完整演奏入口，网络弹层保留复制地址和首次接入二维码。创作模式的真机测试扫码先保留。
- **页面由演奏者明确操作才替换（Q14）。** 池主失联、明确停演或换工程均不自动刷新、卸载或停止设备上已经运行的工程页面；演奏者主动进入其他工程、刷新或关闭后才改变页面。接入层撤销旧演出的网络访问与本地页面继续运行分别管理，旧页面不能凭旧确认进入新的演出。工程自身的暂停、结束与断线处理仍由工程决定。此规则同时约束浏览器演奏端与原生池客。
- **正常演奏仅显示工程内容（Q15）。** 不设置常驻离开按钮或网络状态栏；有新工程时提供轻量提示。浏览器通过关闭页面离开，原生池客的退出／换池主操作保留在 App 侧栏。
- **ASBS 完整分谱预取纳入配套适配（Q16）。** 设备提前取得本人完整分谱所需资源，仍按窗口解码；以已经打开且准备完成的页面在主机断开后完整滚谱作为验收，保留原有断流自主与重连能力。具体准备门槛和失败呈现继续细化，不把该目标解释为 Host 离线时可从图标冷启动。
- **切换失败保留原页面实例（Q17）。** 演奏者主动进入新工程时，新页面加载失败不得销毁原页面；成功后才完成替换，失败反馈不能打断原工程继续演奏。不以销毁后重建旧页面充当恢复。
- **创作或池客期间保留公共入口（Q18）。** App 进入创作模式或切为 PNDS Client 后，演奏入口保持原地址可访问，只报告当前没有公开演出；创作测试不自动公开，仍通过其独立测试入口接入。已打开的工程页面按 Q14 保留。
- **旧工程提供明确的人工回退（Q19）。** 尚未适配稳定入口的工程，在新入口明确提示需要适配；操作者可从网络面板复制旧 performer 地址应急，标明该地址不保证换工程后继续使用。不自动把设备跳回旧地址。
- **浏览器与原生池客统一公开地址（Q20）。** 池主只提供一条公开演奏入口和对应二维码，浏览器与 PNDS Client 都从这里接入。原生池客仍可使用自己的私有页面来源，不将统一公开网址理解为放弃现有存储隔离。
- **浏览器数据恢复边界（Q21）。** 同一池主／工程按工程规则复用已保存身份，不同工程不混用；工程主动重置身份或拒绝凭据的规则继续有效。不保证不同浏览器或图标实例共享、同步或自动迁移数据。IP 或端口变化后，首版允许重新选择分谱／身份，不做跨地址自动迁移；原地址已有数据不因此被删除。该范围仅约束浏览器，不削弱原生池客现有稳定私有来源的恢复能力。
- **全部现有维护工程同步适配（Q22）。** 范围沿用已批准 QR 迁移清单中的 13 个维护源，并同步 App 对应资源，详见下节。未适配旧工程回退不是免除这 13 个维护源适配与验收的替代方案。本来依赖 HTTPS 的工程或功能保留原要求，不因迁移统一入口就宣称 LAN HTTP 具备受限 API 能力。
- **移除 Host 侧栏运行信息卡（后续增补）。** 用户希望撤下左侧栏“本机演出运行中”整个框，作为本轮网络区整合的一部分。侧栏保留角色／节点名、文件夹与工程列表；运行工程仍由既有标记与启停控件表达。完整公开地址、复制、QR、入口故障及必要诊断归下栏网络区，不新增替代的大卡片。

已确认的架构方向与二维码展示修订记录在 [ADR-0017](../adr/0017-stable-browser-performance-entry.md)。用户后续调用 to-spec 并指定 beta.3，正式规格已发布为 `ready-for-agent`；本次成文与建票没有自动开始功能编码、提交或 App 发布。

## 页面与接入行为矩阵

| 设备当前内容 | 池主事实或操作                     | 设备结果                                                      |
| ------------ | ---------------------------------- | ------------------------------------------------------------- |
| 尚未进入工程 | 池主空闲、创作模式或池客角色       | 显示没有公开演出，可保留该入口；不公开创作测试                |
| 已进入 A     | 失联、超时、入口或元数据故障       | 保留 A 的原页面实例，由工程按原规则继续运行；不自动刷新或遮挡 |
| 已进入 A     | 核实停演或池主切换模式／角色       | 保留 A；撤销旧网络接入，不向新工程传递旧确认                  |
| 已进入 A     | 恢复同一演出                       | 沿用工程自身的重连与对齐，不重新导航                          |
| 已进入 A     | 同一池主有新的演出 B               | 保留 A，仅轻量提示 B 可进入；同工程重开也不能自动加入         |
| 已进入 A     | 用户点进入 B，候选已变为 C         | 不把针对 B 的操作用于 C；更新候选并等待明确操作               |
| 已进入 A     | 用户点进入 B，但页面或资源准备失败 | 保留 A 原实例；失败反馈放在切换操作处，允许重试               |
| 已进入 A     | 用户点进入 B，B 加载成功           | 完成替换并收尾 A；避免新旧工程同时接受演奏输入                |
| 已进入 A     | 地址返回另一池主身份               | 保留 A，拒绝静默接纳另一池主                                  |
| 已进入工程   | 用户关闭页面、原生退出或主动刷新   | 按该明确操作处理页面与媒体；原生手动刷新沿用现有防误触规则    |

公开入口绑定稳定池主身份；工程长期恢复凭据按池主／工程区分，演出身份只用于当次接入，不将它作为长期身份键。浏览器同源内的工程命名空间用于避免正常工程的数据串用，不能表述为浏览器级安全隔离；原生池客现有每池主／工程私有来源保持。

### Host 侧栏卡移除的影响评估

当前 `HostClientAddress`（`PerformanceRoleButton.tsx`）只是 store 展示与复制动作，唯一挂载在 `Sidebar.tsx`；没有入口轮询、生命周期 effect、工程启停或角色门禁。移除展示不改变真实监听器、端口分配、演出身份或演奏设备的页面生命周期，不影响 ASBS 断线继续与原生池客自动发现规则。

| 原卡片内容                                       | 新位置或处理                                                        |
| ------------------------------------------------ | ------------------------------------------------------------------- |
| 完整池客地址、复制                               | 下栏网络区，改为浏览器与原生共用的实际公开入口，与 QR 使用同一来源  |
| 入口不可用、故障详情及本地演出继续的说明         | 网络按钮可发现的异常状态与弹层详情；不以本机 ready 代替对外入口就绪 |
| 入口端口、实际 performer／monitor 端口           | 网络弹层诊断折叠区；设置端口页继续保留                              |
| 重复的运行工程名、“选其他工程不结束演出”常驻提示 | 随大卡撤下，沿用工程列表运行标记与现有操作规则                      |

当前网络弹层尚未承担全部上述信息，不能只删卡片后视为迁移完成。新网络区也不能沿用旧卡片仅在 session ready 时显示的限制：Q12／Q18 要求空闲、创作和池客期间仍能访问既有公共入口。入口故障时保留实际地址供诊断，但不可把不可用入口继续当作邀请操作提供；故障反馈不能仅藏在从未打开的弹层里，亦不应新增常驻大框。

实施时把原卡的真实地址复制、运行事实不随选卡改变、端口不编造、入口故障不停止本地演出等回归断言迁到网络区；补充侧栏标题／滚动／选中与运行标记、弹层开关不启停工程／重绑入口／重建页面的验证。

### 为什么保存入口不应要求互联网

用户询问安装为何需要互联网。普通网页入口由浏览器保存，入口页面、图标和工程资源可全部由局域网池主提供。本方案不要求公网安装服务。

此前提到联网，仅来自 Android 可选的 WebAPK 路径：Google 文档说明 WebAPK 通常由云端打包签名服务生成；不可生成时可回退为网页快捷方式。这不是保存网址本身的必要条件，不能据此要求 PNDS 的首次接入联网。断开 WAN、保留 LAN 的首次创建入口与再次打开需纳入验收。依据：[Google WebAPK 说明](https://web.dev/learn/pwa/installation#webapks)、[Chrome 快捷方式说明](https://developer.chrome.com/blog/how_chrome_helps_users_install_the_apps_they_value#create-a-shortcut-on-desktop-and-mobile)。

## HTTP 可行性与平台事实

稳定 HTTP 地址、同源资源与 WebSocket 转发、前台核对当前演出和重新加载工程页面，不依赖 HTTPS 或 Service Worker。实现仍需新增跨工程入口与浏览器接入；现有工程端口避让本身不提供这些行为。

| 平台                  | 可评估的 HTTP 路径                           | 尚不能统一承诺的部分                                                        |
| --------------------- | -------------------------------------------- | --------------------------------------------------------------------------- |
| iOS／iPadOS Safari    | 添加主屏幕；26 起任意网站可作为 Web App 打开 | PNDS 的 LAN HTTP 安装、冷启动、存储与换工程仍需实机验证                     |
| macOS Safari          | macOS 14+ 将网页添加到 Dock                  | 旧 macOS 不因此获得 Add to Dock；HTTP 不因此成为安全上下文                  |
| Android Chrome        | 普通网页及主屏幕快捷方式                     | 不保证 HTTP 得到 WebAPK 或独立应用窗口                                      |
| Linux／Windows Chrome | 普通网页及桌面快捷方式                       | Create shortcut 与 Install page as app 不同，不能承诺快捷方式去掉浏览器界面 |
| 其他浏览器            | 普通网页作为候选回退                         | 安装形式及工程具体能力按平台另验                                            |

平台依据：[WebKit Safari 26](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/)、[Apple Mac Web Apps](https://support.apple.com/en-ca/104996)、[Chrome 安装与快捷方式区别](https://developer.chrome.com/blog/how_chrome_helps_users_install_the_apps_they_value)。平台资料支持不等于 PNDS 已通过相应平台验收。

基础 `AudioContext` 不普遍要求安全上下文，但声音启用仍受用户操作与浏览器策略约束；`getUserMedia`、Service Worker 和 AudioWorklet 需要安全上下文。手机访问 Mac 的 LAN HTTP 地址不适用手机自身 localhost 的例外。工程若依赖这些能力，不能因添加了主屏幕图标就视为兼容。

能力依据：[Web Audio 规范](https://webaudio.github.io/web-audio-api/)、[媒体采集](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)、[Service Worker](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API)、[AudioWorklet](https://developer.mozilla.org/en-US/docs/Web/API/AudioWorklet)。

没有 Service Worker 时，已打开页面可以呈现等待或重连状态；池主 App 退出后，从图标冷启动可能直接进入浏览器连接失败页，不能承诺总能显示 PNDS 自定义离线入口。局域网可演奏与失去池主连接后仍可冷启动入口是不同要求。

## 技术验证与实现边界

- 普通浏览器地址、LAN IP、原生池客私有页面来源与公开稳定入口分别表达，不能用“QR IP”代替完整接入网址。浏览器与原生池客共用公开地址已确定，原生页面来源不因此改成公开 origin；协议兼容方式交由实施设计。
- 原生池客已有池主／工程／演出身份核验与每工程页面来源隔离。浏览器没有其本机代理，需要另行设计浏览器可用的接入、HTTP／WebSocket 门禁及存储边界。
- 原生池客当前仅在页面打开或断线状态继续查询池主；观察到结束或换工程后会停止查询，重新进入还需先点重新核对。Q10、Q14 已确认改变这一交互，让新工程自动出现、单击进入，并保留旧页面；当前实现不符合完整新规则，须重做状态和页面归属，不能仅改文案。
- [ADR-0014](../adr/0014-performance-roles.md) 的旧页面销毁规则已由 Q14 与 ADR-0017 的后续规划修订。对新演出的明确确认继续保留；同工程在池主重启后仍是新演出，不可因地址相同自动进入。
- [ADR-0013](../adr/0013-app-owned-performer-qr.md) 的演出独立二维码展示由 ADR-0017 的网络弹层入口取代。创作测试扫码保留；Q19 已确定未适配外部工程的明确提示和人工旧地址回退，Q22 确定既有 13 个维护源必须同步适配。
- Q21 已确定浏览器跨地址不自动迁移数据。Q12 已确定空闲池主可访问，Q13 已确定跨 App 重启允许端口避让，Q18 已确定创作／池客期间入口继续在线但不公开创作测试。App 退出后的冷启动连接失败是 HTTP 方式的既有边界，不承诺自定义离线入口。
- 安装元数据与启动路径归属于池主，不把临时演出身份、工程版本或一次加入凭据写进永久图标入口。公开邀请入口与已经确认的工程资源上下文须分开管理。
- 同一公开地址需要浏览器可使用的接入机制；不能只把原生 Client 依赖的身份请求头交给普通网页。协议须同时覆盖页面、资源、查询、Worker、polling 与 WebSocket，并在旧页面仍存活的条件下阻止其进入新演出。
- 工程能力须显式验证；`supportsPerformerUrl` 不自动代表动态监听、浏览器接入上下文或完整离线能力。具体版本字段、路由及适配接口在技术验证后定稿，再更新公开契约，不凭规划发布未验证的平台字段。

### 沿用的规则与实现约束

- 同一演出失联后恢复时保留原页面，沿用工程自己的重连和重新对齐，不重新导航；ASBS 的自主推进在接入状态检查期间不能被打断。
- 同一个地址返回另一池主身份时，不静默接纳；当前旧页面继续保留。连接其他池主使用另一入口。
- 新演出必须绑定演奏者实际看到并点击的候选身份；检查期间从 B 变 C，只更新候选，不把针对 B 的操作用于进入 C。
- ASBS 必需资源未取得完整前不能宣称已具备断主机后完整演奏能力；按确认的切换失败保页规则处理失败。下载、缓存、窗口解码及就绪核验属于实施设计。
- 原生池客当前工程的手动刷新仍沿用 ADR-0014 的两击确认，放在 App 自身界面；用户没有要求取消防误触规则。浏览器自身刷新依其正常行为执行。

## Q11 后续：演奏页面自主运行与 ASBS 容错

用户没有直接接受此前把停演、持续等待与主动离开一起描述的 Q11，而是先提出两项关键关注：演奏者正常使用时应主要看到工程内容，不希望增加多余信息或离开按钮；ASBS 原本支持主机失联后设备继续演奏，新接入方式不得让电脑故障变成所有设备停止。随后用户明确接受 Q14、Q15、Q16，形成上述页面保留、简洁界面及 ASBS 配套适配规则。

### 实际代码核查

已只读核查本机 `All-Sentient-Being-Sounds` 2.0.1 及 `PNDS-1.6.2-projects/All-Sentient-Being-Sounds` 2.1.1；两份的跟随引擎和分谱会话行为一致：

- `shared/follow-engine.js:93`：最后状态为演奏中且超过 1000ms 没有位置包时进入自主模式；第 81 行继续按本地时间推进谱面。这里是自主滚谱，不是手机程序发声。
- `src/performer/main.tsx:149`：断线时保存结束上报，重连并重新加入后补发；没有断线即清除谱面的处理。
- `src/performer/ScoreStage.tsx:30` 卸载时调用 `session.dispose()`；`score-session.ts:214` 取消动画循环。框架若因入口故障自动卸载页面，会直接破坏这项自主运行能力。
- `score-session.ts:187` 只按窗口预加载和解码图片（lookahead 3 页、保留窗口 7 页），每张图片仍经 fetch 获取；服务端对非 `/assets/` 资源使用 `no-store`。因此自主滚动不等于整部谱面已经预载，主机完全消失后未加载的图片不保证可用。
- 两份工程 performer 仍依据 `location.hostname` 与 `performerPort` 拼接连接地址，未声明完整入口或动态监听能力。接入稳定代理还需工程兼容适配，不能据页面可保留就宣称 ASBS 已兼容。

以 `npm exec -- node --test test/follow-engine.test.js` 验证原工程现有跟随引擎，7 项通过，包括断流自主推进、恢复对齐及工程内暂停。该结果不是完整 App／iPhone 断机验收。

### 资源成本核对

只读 PNG 文件头和文件大小：每份分谱含结束页 28–30 张 PNG，压缩文件合计约 0.508–0.679 MiB；全部解码后的名义 RGBA 量约 165.6–181.0 MiB。预取本人分谱的压缩字节与把所有位图解码常驻是不同方案，不能将后者的内存成本直接套到前者。完整预载还须列入几何数据、脚本、样式和字体；当前工程尚未实现全分谱字节预取。

### 已确认原则与剩余边界

- 连接状态、新演出候选与已经运行的工程页面应分别表达。无响应、心跳缺失、协议错误或 `performance: null` 都不充分证明操作者要求停止设备上的工程；当前 Host 元数据没有关联演出身份的明确停止原因。
- 原生池客现有网络失败分支保留旧页，但元数据拒绝、停演及身份变化分支会销毁页面；根据 Q14，必须修订这些分支，不能直接复用到新浏览器端。自动检查与重连也不能调用会销毁页面的手动刷新。
- 演奏者明确切换、刷新或关闭才能替换页面；工程自己的暂停／结束消息仍由工程处理，不能与 App 接入层的故障判断混同。
- 已确定不在工程区设置常驻离开或网络状态栏，原生退出能力保留在侧栏；Q17 已确定切换失败必须保留原页面实例。同场演出恢复沿用工程自己的重连，不重建页面。
- ASBS 全分谱原始字节预取已纳入配套适配。必需字节未齐不能发布完整断主机演奏的就绪事实；准备失败遵循失败保原页与重试规则。兼容声明及就绪报告细节在技术验证后定稿。
