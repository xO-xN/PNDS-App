# v1.7.0-beta.3 统一演奏入口、工程切换与断线继续演奏规格

状态：2026-11-09 已确认并发布，纳入 v1.7.0-beta.3。跟踪票 [#294](https://github.com/xO-xN/PNDS-App/issues/294)，标记 `ready-for-agent`；规格已定稿，尚未实施。

## Problem Statement

演奏设备需要一个可以长期保存、跟随同一池主切换工程的入口。工程服务端口自动避让后，直接保存某个工程的地址不能保证下一个工程仍在同处。浏览器、主屏幕图标和原生池客目前又使用不同入口或交互，演奏者可能需要重新扫码、填写地址或先重新核对，现场操作繁琐。

连接故障也不等于工程必须停止。ASBS 等工程已设计为位置消息中断后在设备上继续推进谱面；如果 App 因池主失联、停演或发现另一工程而销毁页面，就会破坏这种能力。仅保留地址或重新创建相同页面也无法恢复未保存的本地时间轴。ASBS 当前按窗口加载谱图，还需要配套资源准备才能覆盖主机完全故障后的完整分谱。

不同平台对安装为独立窗口的支持不同，普通主屏幕快捷方式也不等于完整 PWA。现场不应要求配置 HTTPS、互联网打包服务或浏览器安全开关。Host 侧栏运行大卡、独立 QR 按钮及投影覆盖又重复呈现接入信息，占用工程操作空间。

## Solution

由池主提供一条实际绑定、跨工程保持的局域网 HTTP 演奏入口，浏览器和原生 PNDS Client 共用同一公开地址。浏览器直接打开即可参与，演奏者也可选择保存主屏幕、Dock 或桌面入口；独立窗口按平台提供，快捷方式和普通浏览器都是有效路径。首次接入、保存入口、再次打开及换工程均不要求公网。

入口属于池主，不属于单个工程的内部端口。空闲池主也能提供等待页面；切到创作或池客后，入口继续在线但没有公开演出。新工程自动被发现，演奏者点击后才进入。失联、停演或新候选不销毁旧文档；主动切换失败也保留旧实例，新页面成功后才替换。正常演奏只显示工程内容，接入管理留在主动打开的界面中。

Host 下栏网络区统一呈现完整公开地址、复制、QR、入口故障和必要诊断，撤下侧栏“本机演出运行中”卡、演出独立 QR 按钮及投影 QR 覆盖，创作真机测试扫码继续保留。既有 13 个维护工程与 App 对应资源同步适配，ASBS 配套预取本人完整分谱必需资源，保留滑动解码与自主滚谱。

## Implementation Decisions

1. **版本与范围。** 本功能作为 v1.7.0-beta.3 的改动；本规格拥有统一演奏入口、浏览器与原生联动、断线保页、网络区整合、全部维护工程适配及 ASBS 完整分谱预取的范围。规格定稿不代表功能已实现或实机验收完成。
2. **单一公开入口。** 池主提供一条真实绑定的局域网 HTTP 根入口，包含实际主机和端口。浏览器与原生池客使用同一公开地址；公开邀请网址与已确认演出的页面、资源及实时连接上下文分别管理。
3. **不增加现场配置。** 不要求 HTTPS、证书、域名服务、修改浏览器安全开关或公网打包服务。浏览器已安装、池主和所需本地资源已准备、局域网可达是使用前提；不承诺离线生成完整 Android WebAPK。
4. **按池主保存。** 一个保存的入口对应一台稳定池主；节点名、当前工程与本次演出分别表达，不因换工程生成另一个永久安装身份。首版不增加网页内多池主选择器。
5. **入口生命周期。** 节点与局域网准备好后，入口在未加载工程时也可访问，开放入口本身不启动工程或音频。App 进入创作或池客后继续持有入口，只报告无公开演出；创作测试通过独立测试入口提供，不自动公开。
6. **端口权威与真实状态。** 复用现有 App 端口管理、真实监听器、实际服务分配和归属核验。公开地址发布依据真实绑定，不将探测后释放当作保留；工程内部实际端口仍由既有能力契约决定。
7. **稳定范围与冲突。** 同一 App 持续运行且所用 LAN 地址不变时，切工程不改变公开入口。退出重开优先复用上次端口，启动占用时允许避让并明确提示更新保存入口；不结束其他进程。运行中入口不热迁移端口，不用换号掩盖故障。
8. **入口与本地演出独立。** 对外入口不可用不自动停止健康的本地工程、音频或已经加载的客户端文档。未绑定、无公开演出、正在准备、就绪和故障是不同事实，不能由本机 ready 推导对外可加入。
9. **接入确认。** 池主、工程与演出身份分别核验；每次新演出都需明确进入，包括同工程重新开始。保留身份数据不替代当次确认，旧连接或旧确认不能进入新演出。
10. **浏览器接入契约。** 必须支持普通浏览器直接接入，不依赖由测试或浏览器扩展手工注入原生私有请求头。页面、资源、查询、Worker、polling 与 WebSocket 均受同一确认边界约束；协议形式、能力版本和适配接口经首阶段验证后定稿。
11. **旧上下文保护。** 已经运行的旧页面可以继续本地执行，但它的网络访问不能因端口复用、cookie 变化或新候选而流入替代工程。停止旧网络接纳与销毁文档不是同一操作。
12. **已加载文档归属。** 无响应、超时、入口故障、无效或不兼容 metadata、核实停演、工程变化及另一池主身份都不得自动刷新或销毁旧文档。自动检查不调用会重建文档的手动刷新。
13. **同场恢复。** 核验仍为同一演出时，保留原文档、未持久化状态和自主时钟，沿用工程自身重连及对齐。工程的暂停、结束、座位重置和断线策略继续由工程处理，不合成替代性的音乐停止命令。
14. **新候选发现。** 浏览器与原生池客持续发现同一池主的新工程；已有页面时只提供轻量进入提示，没有页面时使用等待或进入界面。正常演奏不新增常驻网络状态栏或 Leave 按钮。
15. **明确进入与异步归属。** 一次进入绑定演奏者实际看到的候选身份。候选 B 已变为 C 时，只更新候选，不把点击 B 用于 C。取消、迟到检查和较旧代次不得加载新页或覆盖更新的状态。
16. **失败保留原实例。** 明确切换时，新页面或必需资源准备失败，原页面实例仍可继续演奏并允许重试；不以重新加载同 URL 冒充恢复。成功后才完成替换并收尾旧页，避免两页同时接收演奏输入。加载成功不自动等同工程已经接纳演奏者。
17. **关闭与管理。** 浏览器通过关闭页面结束该文档；原生退出、换池主及当前工程手动刷新保留在 App 侧栏，沿用现有防误触与确定清理规则。隐藏侧栏、主窗口或管理面板不是退出，不应重建工程文档。
18. **原生池客收益。** 原生池客自动显示新工程并单击进入，不再重填地址或先执行重新核对。统一公开网址不改变其每池主／工程私有页面来源、持久数据、媒体权限及清理归属；参与本身不启动 App 托管的 Host 音频进程。
19. **浏览器数据。** 适配工程按池主／工程区分长期凭据，按工程规则复用，尊重身份重置或拒绝。演出身份用于当次授权，不作为长期恢复键。同源内的命名空间避免功能串用，不宣称浏览器级安全隔离。
20. **数据恢复边界。** 不保证不同浏览器或图标实例共享、同步或迁移。IP 或端口变化后，浏览器首版允许重新选择分谱／身份，不自动跨地址迁移；原地址的数据不因此被删除。该限制不削弱原生既有恢复能力。
21. **网络区整合。** Host 下栏网络按钮显示完整实际公开入口；复制和 QR 使用同一来源。入口故障需可发现，详情与实际端口按需展开；保留诊断地址，但不得将不可用入口继续当作可邀请地址提供。
22. **侧栏与 QR 收敛。** 移除 Host 侧栏“本机演出运行中”信息卡、演出独立 QR 按钮和投影 QR 覆盖；地址、复制、故障及诊断迁入网络区。角色、节点名、工程列表、运行标记和启停门禁保留，创作真机测试扫码继续提供。
23. **运行事实与选择分离。** 选中另一个工程、修改下次配置或打开网络面板，不能改变当前实际入口、端口归属、运行工程、监听器或演奏文档。原卡片相关事实断言迁移到新信息位置，不能随 UI 删除。
24. **全部维护源同步适配。** 采用既有维护清单中的十三个指定源，保留其已有修改及同名旧副本；覆盖 Template、III、IV、ASBS、四个工具、Orbital Fugue、Runes、Splash Ink、Co here-Co hear 和 Template Preact。不能以旧地址回退代替这些维护工程的真实适配。
25. **App 对应资源。** 同步 Blank／Classic 创建来源、冻结模板、四个工具的固定发行来源、随包资源、内容哈希、文案与帮助；使用既有构建打包流程，不用旧副本覆盖当前维护源。
26. **ASBS 完整资源准备。** 为本人选定分谱取得并持有完整必需字节及几何等运行资源，再发布完整断主机演奏的就绪事实。资源应属于同一分谱和工程内容状态；缺失或下载失败不宣称已具备该能力。
27. **ASBS 内存与运行保持。** 预取完整压缩资源不要求全部位图同时解码，保留滑动解码窗口、自主推进、工程暂停与恢复对齐。页面和原运行循环持续存在，不能通过替换成另一副本实现续演。
28. **HTTP 能力上限。** 统一入口适配不使普通 LAN HTTP 成为安全上下文。需要实时摄像头／麦克风、AudioWorklet、Service Worker 等能力的工程或功能保留原要求，不能以安装图标或填写能力字段虚报可用；既有 HTTPS 功能不删除或静默降级。
29. **未适配外部工程。** 新入口明确说明需适配；网络面板提供标明限制的旧 performer 地址供操作者人工应急。旧地址不保证跨工程稳定，不自动跳转或将其伪装成统一入口。
30. **兼容契约。** 完整 performer URL 兼容不自动代表动态监听、浏览器确认上下文或完整离线能力。需要显式验证和版本兼容策略，不只补声明便称工程已适配，也不提前发布未经验证的字段名或线协议。
31. **可访问与本地化。** 复用现有键盘、焦点、语义控件、双语文案与 RTL 模式；错误不能只靠颜色表达，弹层状态与操作必须可访问。正常工程页面及既有页面交互边界继续保持。
32. **实施次序。** 先验证公开入口与上下文契约，再接池主／浏览器和原生文档生命周期，随后整合网络 UI、迁移十三个维护源与 App 资源，最后完成自动化及跨设备验收；未验证契约不得反向改变已确认产品行为。

## Testing Decisions

1. **优先一条最高层主接缝。** 延续本轮已讨论的公开操作驱动真实链路：App 启动／接入操作 → 真实受管 Node → 实际绑定公开入口 → 真实浏览器和独立原生 Client 上下文 → 页面／资源／Worker／polling／WebSocket → 故障、切换与原文档保留。只测外部行为，不锁定私有函数调用次数或状态容器形状。
2. **复用 prior art。** 扩展现有公开项目启动与实际端口测试、Client 公开检查／加入及元数据故障保页测试、自有 Node 与端口夹具、原生页面来源和持久存储机制夹具。Host 与原生 Client 使用两个独立 App 上下文，不绕过单 App 单活动角色门禁。
3. **真实浏览器补齐缺口。** 浏览器直接访问公开网址，不由测试手工添加原生私有身份头。实际运行脚本与 Worker，并分别观察资源查询、Socket.IO polling 和 WebSocket；把路径回显或 Node 额外请求头视为有限证据，不能当作浏览器支持已成立。
4. **验证同一文档。** 断网、超时、元数据畸形／协议不兼容、入口故障、Stop、新候选和同地址另一池主都应保留旧 Document、未保存内存状态与自主时钟。不能仅检查 iframe 节点或 URL 未变，因为它们可能对应已经重新导航的文档。
5. **覆盖跨工程组合。** 至少包括 A→B、A→Stop→B、A→Stop→A、候选 B→C、点击期间身份改变、取消及迟到结果；不点击就不加载或加入 B，点击 B 也不能进入 C。内部端口变化不改变在线公共入口。
6. **旧网络隔离与保页同时成立。** 在旧文档仍运行的情况下，证明旧 HTTP、Worker、polling、WebSocket 和旧确认没有进入 B。观察 B 实际收到的请求和加入行为，保留现有上下文拒绝断言，仅修订把网络退役等同文档销毁的旧条件。
7. **切换与清理。** 新页面／资源失败及取消保留旧实例，成功才替换；重试和 late results 不复活已退休页面。检查输入仅交给当前页面、媒体与自有连接在明确关闭时释放，清理不确定仍保持可恢复归属。
8. **入口生命周期与冲突。** 覆盖空闲入口、模式／角色切换只报告无演出、创作测试不公开、App 重开端口复用及受控占用避让。只创建并清理测试自己的进程／监听器，原占用者继续正常，不使用未知进程作为信号目标，不以隐藏重试掩盖失败。
9. **原生联动。** 验证同地址公开检查／单击进入、候选持续更新、同场恢复不重载，以及每池主／工程私有来源、地址或代理端口变化后的存储恢复。已有原生机制夹具只能证明其机制范围，仍需完整 App 验收。
10. **浏览器数据。** 验证 A→B→A 各自复用已保存凭据、工程重置有效、不用新演出身份重置长期数据。分别验证跨地址／浏览器／图标实例的已声明边界，不模拟无法成立的跨 origin 自动迁移。
11. **ASBS prior art 与主页面集成。** 复用其现有跟随引擎和页面缓存测试验证自主推进、恢复对齐、工程暂停及窗口解码；新增资源准备连接到真实页面，不另写一套跟随引擎来证明原工程行为。
12. **ASBS 真正断主机用例。** 使用维护源真实分谱与必需资源，完整准备后停止受控 Host 或阻断全部 Host 请求，继续滚过此前未解码的中间页直至结束页。只显示已经预热的三页不足以验收；验证资源失败不发布完整就绪，作为切换候选时失败不销毁旧页。
13. **UI 补测仅覆盖用户可见行为。** 统一地址／复制／QR／故障／端口／旧地址回退，撤下侧栏卡与演出覆盖、保留创作 QR，正常无常驻状态或 Leave 栏，新候选轻提示及一次进入。面板开关不启停工程、重绑入口或重建文档；沿用现有真实组件、typed-command、焦点与侧栏交互接缝。
14. **全部维护源与发行资源。** 十三个指定源逐项执行适用检查并核对完整资源／实时连接、既有音乐行为；检查创建模板、冻结来源、工具包、版本与哈希一致，不能把仅 manifest 或只有 App 仓库通过当作全部迁移完成。
15. **无公网与平台验收。** 保留 LAN、断开 WAN，验证首次访问、保存入口、再次打开、扫码和切工程。记录真实 iPhone／iPad、Android、Mac Safari／Chromium、Linux／Windows 的适用浏览器或快捷方式路径；安装形式不同不作为基本浏览器参与的阻断。
16. **原生与能力边界。** 对支持的 macOS 最低版本、arm64／x86_64、签名权限、媒体、真实声音与双机进行适用验收。API 暴露、health、静态页面和单次 WS echo 分别只证明自己的范围，不代替设备采集或完整工程演奏。
17. **完成标准。** App 必须通过 `npm run check:all`，全部维护工程适用检查和资源构建通过；新业务逻辑随改动带测试。开发服务器由用户启动并回报结果，自动化通过与用户实机结果分别记录。

## Out of Scope

- 将 PNDS 原生 Host 移植到 Android、iOS、Linux 或 Windows；这些平台本次扩展的是浏览器参与方式。
- 强制安装或承诺所有平台都生成独立窗口、完整 PWA／WebAPK、同等系统集成。
- 配置 HTTPS、证书或公网安装服务来满足本功能；删除既有 HTTPS 功能或绕过浏览器安全限制。
- 网页内多池主选择、跨互联网远程加入、互联网中继或任意网络下同地址自动发现。
- 运行中迁移公共端口，或保证换网络／IP 后永久保存的网址无需更新。
- 浏览器跨 origin、浏览器或安装实例自动搬迁数据；将同源工程命名空间宣传为安全隔离。
- 因失联或发现新演出自动销毁当前文档、静默加入新演出或自动采用旧地址回退。
- 用接入层替代工程的音乐消息、暂停、结束、座位重置或自主运行规则。
- 为任意工程新建完整离线演奏能力；明确纳入的是 ASBS 已打开且准备完成的本人分谱，不承诺 Host 离线后的图标冷启动。
- 后台或锁屏持续演奏的跨平台保证、完整离线浏览器壳和离线媒体权限。
- 修改历史副本、验收夹具、缓存或旧工程包；将源码适配自动等同提交、打标签或正式发布。

- 采用已讨论的最高层主接缝，不重新开启产品访谈。技术契约首阶段需对普通浏览器、原生上下文、Worker 和实时连接做真实验证；若发现无法兑现产品行为的约束，应报告具体冲突，不静默降级已确认范围。
- ADR-0017 记录本方案；它修订 ADR-0013 的演出 QR 呈现与入口归属，以及 ADR-0014 对核实停演／换工程即销毁页面的旧规则。原有新演出确认、单 App 单活动角色、录制边界与工程自主音乐行为继续保持。公共等待入口在线不表示 App 正在同时运行另一场 Host 演出。
- 基础能力沿用既有池主／池客与自动运行端口管理；不另建一套端口分配权威。13 个维护源的精确来源和输入版本在讨论记录中保留，实施时按既定维护树核对，不能依据同名目录或存在 manifest 就扩大或替换范围。
- 全部维护源为 PNDS Template、Inarticulate III、Inarticulate IV、All Sentient Being Sounds、Multichannel Signal Generator、Local Network Diagnostics、Telematic Network Diagnostics、Mobile Sensor Meter、Orbital Fugue、Runes、Splash Ink、Co here-Co hear、Template Preact。Blank 生成来源、Classic 冻结模板和随包工具是 App 对应同步资源，不额外计成外部维护工程。

- 规划阶段完整 npm 检查已通过；它证明当前基线状态，不证明尚未实现的 beta.3 功能。保留既有失败与重跑记录，后续不能通过跳过测试或隐藏重试取得验收结论。
