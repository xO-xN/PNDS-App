# QR 内置 App 重构方案

2026-10-30，方案已获用户整体确认并进入实现。决定过程见[逐轮讨论](./qr-host-refactor.md)，职责边界见 [ADR-0013](../adr/0013-app-owned-performer-qr.md)。本文件是本次实现与验收的规格，不表示功能已实现或发布。

## 目标与职责

二维码由 App 统一提供，编码当前运行工程本次选定的完整 performer URL。工程的 performer 页可用于演奏、设备控制、网络或传感器测试；进入页面后的业务由工程负责。

App 撤下 QR 标准技术模块的添加入口和分发源码，迁移全部当前维护工程及相应 App 资源，清除工程自己的 QR 界面、路由、专用代码和已无用途的依赖引用。

## 两种模式的入口

| 模式 | 按钮位置                                              | 二维码显示位置                            |
| ---- | ----------------------------------------------------- | ----------------------------------------- |
| 演出 | 共享底栏                                              | 有投影窗口时在投影，否则在主窗口 monitor  |
| 创作 | 右侧演奏者栏标题行；展开 monitor 时放在现有设备弹层内 | 主窗口 monitor 区域，随普通／展开布局适配 |

两种模式使用同一套显示状态和生成结果。单击显示，再次单击隐藏；按钮能表达当前开关状态。二维码覆盖 monitor 时，创作演奏者栏及其按钮仍可操作。

## 显示规则

- 2026-10-30 后续调整：App 以浮动面板在谱面之上显示二维码、工程名和完整网址，默认居中；周围谱面可见且可交互。按后续简化要求，仅保留顶部拖动及四角缩放，显示／隐藏使用原 App 二维码按钮；固定浅色码底不随主题反转。面板始终适配当前显示面边界。
- 底层页面与音频持续运行；隐藏覆盖层后露出当时应有的内容，保持页面运行及连接。
- QR 与投影开演独立，投影处于简介时也可显示；显示或隐藏 QR 保持投影开演状态。
- 显示期间打开投影，二维码迁移到投影；关闭投影，迁回主 monitor。始终只在一个目标显示。
- 最小化的投影窗口仍算存在，显示二维码本身不唤起或新建投影窗口。
- 创作模式的覆盖层只占 monitor 显示面，普通预览与展开布局使用同一显示状态。

## 生命周期

| 条件或操作                             | 二维码行为                 |
| -------------------------------------- | -------------------------- |
| 无运行、启动中、运行未就绪或入口不可用 | 按钮不可用，二维码隐藏     |
| 当前运行就绪且所选入口可用             | 可由用户点击显示           |
| 再次点击                               | 隐藏                       |
| 停止、重启、切换运行工程               | 隐藏，每次新运行默认关闭   |
| 入口发生故障                           | 隐藏；恢复后由用户再次打开 |
| 切换演出／创作模式                     | 隐藏                       |
| 刷新 monitor、缩放、全屏或改变布局     | 保持显示状态并适配尺寸     |
| 投影窗口打开／关闭／最小化             | 按前述唯一显示目标规则处理 |

生成失败应有明确反馈并可重试，保持关闭状态。停止、切工程或隐藏后到达的旧生成结果不能重新显示二维码。

## 地址与共享编码器

- QR、复制地址与工程浏览器配置使用同一个当前运行 performer URL，保留协议、域名、端口、路径和查询等必要部分。
- 地址来自本次实际运行事实；编辑下次启动设置或选中另一工程不改变当前 QR。HTTPS 入口故障按入口不可用处理，保持本次已选地址的语义。
- 普通工程与工具都使用 performer 入口。多轨道测试通过工程适配提供该页面，保持 App 的地址规则统一。
- App 复用现有共享 `qrcode` 的同一份分发文件。Host 使用随包 Node 和已校验共享资源生成图像，主窗与投影共用结果；App 前端只负责展示。
- 生成结果按运行身份及 URL 复用，生成执行设置超时、输出界限和迟到结果保护。工程是否声明使用 `qrcode` 与 App 自身的编码需求分别处理。
- `qrcode` 共享库继续供 App 和有自定义需求的外部工程使用；已迁移工程清除无用引用。根开发依赖与最终 App 分发资产分别检查，确保新增功能复用现有资源。

## 多轨道测试工具适配

`Multichannel-Signal-Generator` 的 performer 提供手机遥控，monitor 保留 App 本机控制。两端复用现有响应式控制台、页面资源、主题／语言脚本、API 和同一个音频引擎。

通道开关、通道音量及总推子由服务器持有权威状态，两端按该状态同步。后加入、刷新和重新连接先恢复服务器状态，保留已运行的音频；交替操作、快速拖动和迟到请求应保持最终显示与服务器一致。

该工具沿用当前同源 HTTP API 即可完成适配，具体同步方式在实现时选取。移除其 QR 页面元素、`/qr` 路由和专用依赖，App 二维码直接打开 performer 遥控页。

## 文档与兼容

- 演出与创作的产品行为同步到 `docs/developer/app-behavior.md`，实现模式同步到状态、共享库及标准模块的对应开发文档。
- 双语帮助、工程 README／维护说明、标准模块清单与相关接线说明同步更新。
- 按 ADR-0003 保留装机 `help/<tree>/modules/qr.md` 路径，改为 App QR 使用与迁移说明，维持旧链接。
- 迁移后的工程由新版 App 提供扫码入口。独立浏览器与旧版 App 按原有页面和音频兼容范围运行，但不再提供工程自己的 QR 按钮；迁移说明标明扫码能力所需 App 版本。
- 未纳入迁移的外部工程仍可使用其已有源码和共享 `qrcode` 引用。

## 验收范围

| 范围           | 必须覆盖                                                                               |
| -------------- | -------------------------------------------------------------------------------------- |
| App 入口与显示 | 两种模式按钮、再次点击隐藏、简介覆盖、显示面适配与底层运行保持                         |
| 投影与生命周期 | 单一显示目标、打开／关闭自动迁移、最小化、模式切换、停止／重启／切工程、入口故障及恢复 |
| 地址与资源     | HTTP／HTTPS 完整地址一致、运行与待应用设置隔离、共享编码器复用、失败重试与迟到结果保护 |
| 工程迁移       | 全部维护源核对、QR 清理、原页面及业务保持、冻结资源与真实包验证                        |
| 多轨道测试     | 两入口真实页面及资源、同一引擎、通道与总推子同步、后加入／刷新／重连及延迟／失败场景   |
| 文档与发行     | 双语文案、稳定帮助路径、工具固定发行来源与哈希、新旧版扫码兼容说明                     |

业务改动随代码提供测试，App 完成条件为 `npm run check:all` 全绿，并执行各工程适用检查。原生窗口、投影、手机实际扫码、多轨道测试真实控制，以及 arm64／x86_64 的安装运行分别记录实机验收证据。开发服务器由用户启动并回报结果；代码提交与正式发布按用户明确指令进行。
