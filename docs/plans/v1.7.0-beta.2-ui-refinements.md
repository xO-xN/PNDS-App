本轮不改变工程运行、设置下次启动生效、问题授权、历史格式或重启接续。设备元数据通过独立只读命令查询，失败回退图标不阻止原有操作。

自动化验收包含多题折叠、待答与重启恢复、提交焦点、展开历史与后续新发送、迟到设备查询、可见窗口刷新及已应用／待应用配置隔离。完整完成条件仍为 `npm run check:all`；实际设备热插拔、窄栏布局和 WebView 动效由原生验收确认。

2026-10-31 用户另要求将[演奏记录与叠加排练](./v1.7.0-beta.2-performance-recording-design.md)纳入 beta.2，当前先评估并逐轮确认。上文五项与“不改变工程运行”等边界仅描述界面细调，不限制新增功能的待定设计，也不表示该功能已经实现。

2026-11-03 用户明确将[池主／池客与自动管理端口、避让冲突](./v1.7.1-performance-roles-spec.md)一并由原 v1.7.1 提前至 beta.2。产品行为及 App 管理端口的职责已收敛，当前使用 HTML 核对整体 UI／UX，完整技术方案与原生验证尚未完成；不据本条开始正式实现或宣称可发行。原五项细调和演奏记录的范围分别保留，链接文件名沿用原评审路径。

后续用户已确认角色 HTML 与四项新增功能范围，并通过 to-spec 发布为 [#257–#260](./v1.7.0-beta.2-spec-index.md)：演奏记录、池主／池客、自动端口管理、待处理文档。正式实施范围以四份规格及跟踪票为准；本轮仅整理规格与建票，不重复实施上文五项已落地的界面细调。
