# v1.7.0-beta.4：简化新建工程、版本历史和 GitHub 工作流

目标版本 **v1.7.0-beta.4**。产品方案和交互原型已确认。跟踪票 [#339](https://github.com/xO-xN/PNDS-App/issues/339) 标记 `ready-for-agent`。打开[已确认的 HTML 原型](https://github.com/xO-xN/PNDS-App/issues/339/artifacts/1)，选择 Preview 试用。

## Problem Statement

创作者新建工程后，需要在浏览器建仓、授权，再回 App 找到仓库并处理首次备份。日常版本页还把分支、版本详情和 GitHub 操作放在同一层。创作者很难一眼看出保存了什么、当前在哪条路线、哪些版本会传到 GitHub。

## Solution

新建表单显示本机位置与 GitHub 目标，默认选择公开仓库。创作者确认后，PNDS 创建本地 Blank，从官方模板建仓，上传初始工程版本并完成绑定。私有和暂不上传放在高级选项。首次上传中断时，本地工程可以继续创作。

工作台在「版本历史」内保存工程版本、查看版本树和文件差异。GitHub 状态收成一行，随当前路线给出下一步。后续版本默认留在本机，创作者可手动备份或按路线开启自动备份。

## User Stories

1. 作为新创作者，我希望从创作首页或工程菜单打开同一张表单，以便直接开始工程。
2. 作为新创作者，我希望只填写工程名称和确认本机位置，以便减少新建时需要决定的内容。
3. 作为使用中文工程名的创作者，我希望分别预览和修改本地文件夹名及 GitHub 仓库名，以便保留原名并解决路径或仓库重名。
4. 作为愿意公开的创作者，我希望提交前看到 GitHub 目标与「公开」，以便用一次明确的操作创建并公开初始版本。
5. 作为希望限制访问的创作者，我希望在高级选项选择私有，以便使用同一套建仓和首次上传流程。
6. 作为离线或尚未准备上传的创作者，我希望选择暂不上传，以便先在本机创建工程和初始版本。
7. 作为第一次连接 GitHub 的创作者，我希望授权后回到填写好的表单，以便核对实际账号、仓库和可见性后再提交。
8. 作为登录后仍需安装或批准权限的创作者，我希望完成授权后继续原流程，或先在本机创建，以便保留已填内容。
9. 作为组织成员，我希望在高级选项选择有权限的组织，以便把仓库建在正确的名下，并在组织限制公开时另选目标。
10. 作为创作者，我希望选择是否填写作者、简介和提交身份，以便控制工程资料和 GitHub 上可见的提交邮箱。
11. 作为从官方模板开始的创作者，我希望工程仓库显示官方模板来源和正确的工程内容，以便确认工程已经可以从 GitHub 获取。
12. 作为公开工程的创作者，我希望单独决定是否加入公开工程目录，以便自行决定何时展示工程。
13. 作为遇到 GitHub 故障的创作者，我希望本地创建完成后进入工作台，以便继续编辑并在方便时恢复首次上传。
14. 作为在中断期间另存版本的创作者，我希望「继续上传」只完成原先确认的初始版本，以便控制后续版本的可见范围。
15. 作为之后才决定上传的创作者，我希望先看到目标、可见性和当前路线的已保存历史，以便核对早先删除的文件和历史提交身份。
16. 作为已经有 GitHub 仓库的创作者，我希望从管理入口绑定符合条件的已有仓库，以便沿用其历史。
17. 作为在编辑器里工作的创作者，我希望按 `⌘S` 保存当前文件或文档，以便在不创建工程版本的情况下保存文件。
18. 作为想记录一个阶段的创作者，我希望在版本历史中保存工程版本，以便继续工作并按需为版本改名。
19. 作为检查变更的创作者，我希望左侧显示比较文件并支持筛选、目录展开和历史删除文件，以便找到关心的差异。
20. 作为回顾工程历史的创作者，我希望上方显示按真实父版本关系绘制的树，以便看清分叉并区分当前版本与正在查看的版本。
21. 作为检查代码的创作者，我希望下方持续显示所选文件的逐行或左右差异，以便切换文件时保留版本树的上下文。
22. 作为需要继续编辑的创作者，我希望从比较区显式打开当前文件，以便回到原草稿。
23. 作为想尝试另一方向的创作者，我希望从旧版本继续并在下次保存时形成新路线，以便保留原路线。
24. 作为切换路线的创作者，我希望得到关于未保存改动、测试运行和助手任务的明确反馈，以便决定如何继续。
25. 作为日常创作的用户，我希望 GitHub 状态只提示当前路线和适用的下一步，以便快速判断是否需要备份或更新。
26. 作为已经公开初始版本的创作者，我希望后续版本默认只保存在本机，以便先完成自己的试验。
27. 作为需要自动备份的创作者，我希望完成某条路线的首次备份后为它单独开启，以便让新实验路线继续留在本机。
28. 作为离线创作者，我希望待备份版本在恢复联网后按原路线和目标继续，以便中断不影响本机保存。
29. 作为从多台设备创作的用户，我希望主动应用 GitHub 上可直接接续的版本，以便保留当前工作区的编辑状态。
30. 作为遇到远端分叉、删除、权限或可见性变化的创作者，我希望状态行给出处理入口，以便核对后再继续备份。
31. 作为需要更换或解除绑定的创作者，我希望在管理中确认操作并保留本机版本，以便旧待传任务随旧目标解除。
32. 作为升级 App 的创作者，我希望保留工程、路线、绑定和待传记录，并为需要的路线重新开启自动备份，以便控制升级后的上传范围。
33. 作为从 GitHub 打开工程的创作者，我希望沿用来源仓库并默认手动备份，以便在决定上传前先在本机检查。

## Implementation Decisions

- **新建表单。** 主表单只要求工程名称和本机位置，记住上次位置并预览目标文件夹。本地文件夹名和仓库名分别推导。GitHub 摘要始终显示可见性和已知目标。默认已连接的个人账号和公开仓库。高级选项含组织、名称、作者、简介、提交身份、私有和暂不上传。CTA 随选择变化。全局个人邮箱不作为新工程的默认提交邮箱。工程可显式选用 GitHub 提供的 `noreply`。
- **授权与本地创建。** 未连接时引导连接。已登录但缺安装或权限时引导继续授权。浏览器返回保留表单，创作者看到实际目标再提交。授权阶段可选择先在本机创建。本地创建成功后才开始远端写入。暂不上传只创建本地工程和初始版本，未创建仓库或待上传任务。
- **模板和首次上传。** 从官方 PNDS GitHub 模板创建普通工程仓库，保留 `Generated from`。延续官方仓库身份、默认分支根提交和正式版本标签的完整文件树核验。首次上传后远端默认分支的内容等于用户确认的本地版本，并保留两段历史及原本地提交。用普通快进推送。使用现有 GitHub App 设备授权，增加模板建仓所需的最小仓库创建权限，保留现有内容写入权限。实际验证「仅选定仓库」的安装能访问和推送自动创建的仓库，以及有权限的组织目标。
- **明确确认。** 新建时「创建并公开到 GitHub」确认所显示的目标和初始工程版本。已有本机工程后来上传时，确认显示当前路线、目标、公开性和会包含的已保存历史，包括已删除文件与原有提交身份。沿用已有空仓或共享历史的绑定边界。模板来源核验和默认分支处理可复用 #329、#330 的实现。继续使用创作者已确认的本地路线，遇到本地路线与远端默认分支名称不同或无法安全映射时，保留已确认路线并提供可继续的反馈。
- **失败与恢复。** 工程本地创建后即可打开工作台。持久记录本次首次上传的原账号、仓库、可见性、路线和已确认版本，以及已知的远端结果。继续时先查明建仓或推送结果。复用核实过的原仓库。同名仓库身份不明确时等待创作者选择。目标或可见性变化时重新确认。远端已改变或核验失败时保留双方历史。期间新保存的版本和草稿留在本机，之后仍能沿原路线正常快进备份。
- **保存与历史。** 「版本历史」位于中栏的「PNDS 创作助手」旁。「保存当前版本」位于版本历史内，先处理工程文件草稿，再按现有收录规则记录工程版本。页面提供默认版本名，保存后留在版本历史。成功提示和历史行可改名。`⌘S` 继续保存当前文件或文档。无可记录改动或存在阻塞冲突时不新增版本。查看、切换和恢复沿用草稿、外部暂存、运行和助手任务保护。
- **比较布局。** 左栏改为「比较文件」，支持变更／全部、路径筛选、目录展开和历史删除。中间上方是版本树，单路线一列，有分叉时按实际父子关系连线。选中和当前状态分别标记。中间下方持续显示所选文件差异，提供逐行／左右布局、父版本到选中版本和选中版本到本机已保存文件。已保存文件比较只读取磁盘状态。选版本或文件只改变查看状态，显式打开当前文件才进入编辑器并保留草稿。
- **路线切换。** 「切换到这条路线」进入其最新版本并沿原路线保存。「从此版本继续」进入旧版本，下次保存创建新路线。遇到未记录修改提供保存后切换、取消和次要入口中的明确放弃。运行中须明确停止后切换，完成后保持停止。
- **GitHub 状态和入口。** 一行状态跟随工作区当前路线，给一个适用动作并保留「管理」。覆盖仅本机、继续首次上传、待备份、已备份、离线、可更新、冲突、授权、远端分支删除、可见性变更及升级暂停。离线的远端信息标为上次检查。仓库链接、可见性、刷新、绑定、解绑、换仓与按路线备份设置在管理。账号位于全局设置。工程选择器负责从 GitHub 打开，沿用来源仓库并默认手动备份。
- **备份与更新。** 普通保存默认本机。手动备份覆盖当前路线已保存的历史。新路线主动完成首次备份后才能开启自动备份。创建时上传初始版本可算作该路线的首次备份。离线队列对应原工程、仓库和路线。解绑与换仓须明确确认，旧队列随原绑定解除。目标、授权或可见性变化时按相应范围暂停并提示。主动更新只在工作区符合既有保护且远端可以直接快进时进行。远端分叉交由外部工具解决。重建被删远端分支须确认。
- **升级。** 保留工程身份、历史、路线、仓库绑定和待传记录。旧工程级开关迁为暂停。创作者按路线重新确认。缺少首次备份凭据时先核对手动备份，远端已包含相应版本时可以确认现状。升级期间没有远端写入。

## Testing Decisions

- **工作台作为主要测试入口。** 沿用现有新建工程、工作台导航、版本页和 GitHub 交互测试，通过创作首页、工程菜单、中栏版本历史和比较文件执行用户操作，在现有原生命令边界提供可控响应。覆盖公开／私有／仅本机、首次授权、创建失败、保存和上传分离、版本树和差异联动、查看与切换分离、编辑草稿保留、状态管理和按路线开启。断言可观察状态和明确副作用，允许内部组件和状态结构变化。
- **原生命令与真实临时 Git 仓库。** 沿用模板核验、首次备份、同步和本地版本测试的做法。用真实对象、引用、文件树及可控 GitHub 响应验证创建与恢复边界。覆盖建仓响应丢失、已有仓库尚未推送、已推送但未落本地状态、重开、远端竞争、原历史可达、仅推已确认版本、后续正常快进、绑定兼容及旧队列迁移。确认无重复建仓、无强推、无意外扩大上传范围。
- **真实环境验收。** 以已确认的 16 个场景为准，在 macOS 核对实际 UI、键盘、浏览器授权返回及编辑保护。使用专用 GitHub 测试仓库验证公开和私有建仓、官方模板来源、默认分支内容、重开绑定、选定仓库安装、新权限批准和组织限制。原型用于核对交互。交付通过 `npm run check:all`。

| 11 切换保护           | 有草稿、未记录修改、运行中或未完成助手任务时分别尝试切换                                                                           | 有修改时可保存后切换、取消或明确放弃。取消保留草稿。运行中的切换先停止，切完仍停止。助手任务及外部暂存按现有保护处理                                                                                                                                 |

| 13 按路线自动备份     | 为已完成首次备份的主路线开启自动备份，断网保存，再从旧版本另开实验路线。联网后切回主路线                                           | 主路线显示待备份，回到原路线后可续传。实验路线默认在本机保存，需手动完成首次备份后才可开启自动备份                                                                                                                                                   |
| 14 可见性和权限变化   | 私有仓有待自动备份的版本，在 GitHub 改为公开。另测公开改私有、退出原账号及撤销写权限                                               | PNDS 发现变更后暂停自动备份，显示新状态。确认新可见性或恢复原目标授权前，待传版本留在本机                                                                                                                                                            |
| 15 更新、冲突和删除   | 分别构造远端单独领先、本机有草稿、双方各有新版本及远端分支被删除                                                                   | 用户主动发起且满足保护条件时才更新。草稿阻止更新并提供处理入口。双方各有新版本时给出外部处理方法。远端分支须明确确认后才重建                                                                                                                         |
| 16 升级、换仓与克隆   | 准备旧自动备份开启且有待传记录的工程、仅本机工程，以及可克隆的公开和私有仓库。升级后测试换仓、解绑和克隆                           | 工程身份、历史、原绑定和待传记录保留。旧自动备份显示暂停，升级过程无自动推送。换仓和解绑须确认，旧队列不转移。克隆沿用来源和可见性，默认手动备份                                                                                                     |

## Out of Scope

- 新模板类型、自动加入公开工程目录、将每个工程仓库标记为可复用模板。
- 在 PNDS 内修改已建仓库的可见性、自动合并远端分叉、批量迁移仓库或回填模板来源。
- 改变外部工具与 Codespaces 初始化、官方模板发行、`.pnds` 打包发行，以及创作助手和工程运行的业务边界。
