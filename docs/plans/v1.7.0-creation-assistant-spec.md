## Problem Statement

创作者需要围绕创作意图深入讨论、完善方案，并把想法同当前工程的实际内容及 PNDS 运行契约联系起来。现有帮助中心可以查阅平台文档，但不能结合工程解释问题；把整个工程直接交给模型会混入依赖、二进制资源和敏感配置，还可能超过模型的上下文容量。

创作者已有外部编程 agent 处理复杂开发。App 需要提供可追溯的咨询、已有单文件代码修改、确定性检查与创作交接；生成大量文件、跨文件修改及复杂任务由外部 agent 接续。不能把“文件齐全”或“一次启动成功”误解为工程完成。模型服务由创作者自行提供；工程内容在创作者知道发送对象和范围后才发送，聊天上下文不能串到其他工程。

完整创作还需要在讨论时明确附上代码片段、顺手调整参数或直接修改非数字代码、观察实际运行、核对外部交接后的整体变化，并保存可以理解和继续修改的本地版本。不同工程的可调内容和生效方式不同，固定参数卡或按画面／声音分类不能代替对工程实际能力的判断。只有独立聊天、文件阅读或未提交 Git 差异，不能贯通这条流程；外部 agent 即使已经提交代码，交接前后的比较也应仍然可用。

## Solution

创作工作区以助手对话为主要入口，支持围绕创作意图多轮讨论和完善方案。文件、代码差异及已有交接任务预览／文档按需打开，右侧保留实时 monitor，控制台沿用现有按需展开的底部 dock。切换阅读内容保留输入、回复、文件草稿与运行页面，用户能返回相关讨论。助手通过创作者配置的 API 地址、模型和密钥连接具有工具调用能力的 OpenAI 兼容服务；PNDS 不提供统一模型服务。

助手优先检索随 App 发布的 PNDS 帮助语料，工程问题再按需搜索和分段读取当前工程文本。首次发送工程内容需要确认；“阅读整个工程”是独立的显式操作，发送前展示实际可读文件范围、排除内容与 token 估算。回答显示实际来源，工程概况展示身份、内容迹象与已知验证结果。

普通聊天用于讨论与拟定方案。助手说明一个已有目标文件和改法，在同一建议卡内提供参数与代码两种编辑方式：可准确绑定的参数由 App 呈现适合其类型的控件，用户也始终可以直接编辑该文件完整的待应用内容，包括文字、条件和函数。输入不写工程、不执行代码；工程支持的参数调节可即时预演，代码修改需用户显式预演，不支持时说明并保留编辑与应用入口。用户点击“应用到工程”授权将当前最终编辑内容写入一个已有文本文件；实际差异在相关回复下只读展示，并提供受保护的撤销入口。从差异进入“当前文件”后可继续编辑工程草稿。“运行检查”独立触发 App／CLI 共用的临时副本服务，提供进度、结果与停止入口；聊天、输入、预演和保存不自动启动完整检查。复杂任务先询问是否交接，用户同意后写创作交接单并提供可复制任务说明。

每个工程保存独立的本机聊天记录，记录位于 App 数据区，不进入工程目录或 `.pnds` 工程包。取消请求、关闭工程、切换工程或模式都不能让旧请求的结果污染新上下文。咨询失败不影响工程运行、编辑、保存与手动测试。

本版同时交付基础编辑器与可调宽布局，选区可作为明确标注来源和保存状态的附件发送。确认交接时记录保存版基线，返回后查看整个工程的变化；文本显示实际差异，二进制资源显示变化摘要。App 为新建工程建立标准本地 Git 仓库并自动记录初始版本，已有无 Git 工程可以主动启用；后续完整文件提交由用户手动触发，历史文本先载入草稿再决定保存。待应用建议、临时预演、工程草稿、磁盘保存版、实际运行、交接基线与 Git 版本分别表达，不因输入、预演、保存、提交或交接而自动刷新／重启。

## User Stories

1. As an 创作者, I want 以助手对话作为创作工作区的主要入口, so that 我能围绕创作意图深入讨论并完善方案。
2. As an 创作者, I want 按需阅读完整文件或已有交接任务并返回相关讨论时保留输入、回复与文件草稿, so that 阅读和局部编辑不会打断创作思路。
3. As an 创作者, I want 阅读代码和交接内容时右侧 monitor 仍保持同一运行页面，控制台按需在下方展开, so that 我能持续观察测试反馈而不丢失页面交互状态。
4. As an 创作者, I want 在未配置模型服务时看见清晰的配置入口, so that 我能知道如何开始对话。
5. As an 创作者, I want 自行填写 API 地址、模型名称和密钥, so that 我能使用自己的模型服务。
6. As an 创作者, I want 保存模型配置并在下次启动继续使用, so that 我不必反复配置。
7. As an 创作者, I want API 密钥存入 macOS 钥匙串且界面只显示已保存状态, so that 密钥不混入工程文件与普通设置文件。
8. As an 创作者, I want 移除已保存的 API 密钥, so that 我能停止使用该凭据。
9. As an 创作者, I want 测试连接时核对指定模型的文本对话与工具调用能力, so that 我能确认服务符合助手要求。
10. As an 创作者, I want 在连接失败、鉴权失败或工具调用不支持时得到不同的可操作提示, so that 我能修改对应配置。
11. As an 创作者, I want 在同一对话中交替询问 PNDS 基本知识和当前工程, so that 我无需为两类问题建立两套聊天。
12. As an 创作者, I want 平台知识问题依据装机版本的 PNDS 文档回答, so that 建议与当前 App 的契约一致。
13. As an 创作者, I want 回答列出实际使用的平台文档小节或工程文件, so that 我能检查建议的依据。
14. As an 创作者, I want 来源入口可以定位帮助文档或当前工程文件, so that 我能继续阅读原文。
15. As an 创作者, I want 助手按问题搜索相关工程文本, so that 我不必默认发送整个工程。
16. As an 创作者, I want 首次发送工程内容前确认工程、模型服务和读取范围, so that 我知道内容将发送到哪里。
17. As an 创作者, I want 取消首次工程内容确认后保留输入且不发出请求, so that 我能重新考虑发送范围。
18. As an 创作者, I want 关闭“读取当前工程”后继续询问 PNDS 文档, so that 我能使用不附带工程内容的咨询方式。
19. As an 创作者, I want 更换工程或模型服务后重新确认工程内容发送, so that 原授权不会自动扩展到新的对象。
20. As an 创作者, I want 依赖、构建目录、二进制媒体和敏感配置被排除在工程文本读取范围外, so that 请求只包含与问题相关的可读内容。

## Implementation Decisions

### 版本与 UI 边界

- v1.7.0 在前序已验收创作工作台上增加助手能力，采用 2026-10-15 确认的对话主入口与按需阅读布局，不再以“第三个标签页”作为验收条件。保留工程选择、模式接续、草稿与运行契约，不重建运行工作流。
- 对话、完整文件、交接预览／文档、交接后的变化与改动／版本之间切换，保留输入、已产生回复、待应用建议和各文件草稿，并提供返回相关讨论的入口；同一有效预演可继续，不因视图切换重建运行页面。
- 阅读代码不遮挡、挤走或重建右侧 monitor；保留同一运行页面及其交互状态，不自动刷新或重启。monitor 的手动展开／还原沿用既有布局与生命周期契约。控制台沿用底栏或快捷键切换的 dock，在同一工作区下方展开，不另建并列标签或第二套日志视图。
- 本版交付可拖动宽度、键盘调整或等价可访问入口及恢复默认布局，按 App 现有偏好机制记忆宽度。默认比例、两侧最小可读宽度和最小窗口下的工具区安排在本版原型与真实窗口验证后确定；拖动与切换不重建 monitor，不将早期 60/40 示意当作固定尺寸。查看代码不自动缩小 monitor，手动展开／还原保持既有运行页面。
- 助手以当前可编辑文件夹工程为工作上下文。无工程时保持创作首页，`.pnds` 工程包与内置工具的只读边界不因助手而改变。
- 工程概况默认是一行标题和新鲜度提示；指针悬浮或键盘聚焦展开，离开或失焦收起。首个工程问题附带可见的简短概况，不在打开对话区时自动发起模型请求。
- 原型中的示例回复、文件量与 token 数仅用于交互演示，不能作为正式读取结果、模型输出或通用容量限制。

### 基础编辑器

- 提供行号、JS／TS、JSON、HTML、CSS、Markdown 与 SuperCollider 源文件的基础语法着色、括号匹配、自动与选区缩进、当前文件查找／替换、跳转行及工程内快速打开文件；其他可编辑文本可回落为纯文本，不能因缺少语言支持而失去编辑入口。复用成熟可维护的编辑能力，选型与 bundle 成本在实施时验证。
- 建议卡的待应用内容、当前工程草稿、磁盘保存版、只读实际差异和历史内容保持清晰区分。建议卡复用基础文本编辑能力，完整文件编辑器继续承担查看上下文与较长编辑。每文件编辑会话的撤销／重做在工作区视图与文件切换后保留；跨 App 重启恢复编辑撤销栈不在本次承诺内。外部改动、助手写入或历史载入不能让旧编辑栈无提示覆盖新内容。
- 保存、磁盘冲突、manifest 等适用校验、中文输入法、选区、原生剪贴板及快捷键沿用既有契约；替换只改当前草稿，保存仍为显式动作。跨文件替换、语言服务器与调试器不属于基础编辑范围。

### 模型服务与请求边界

- 首版支持具有文本对话与工具调用能力的 OpenAI 兼容接口。配置只有当前使用的 API 地址、模型名称和密钥；不增加供应商账号体系、服务市场或多配置切换管理。
- 认证请求与密钥读取由 Rust 侧处理，通过类型安全命令与事件把状态、结果和错误交给 UI。复用现有 HTTP 依赖与代理约定，补齐此功能所需能力；不在 WebView 中持有已保存密钥或直接进行带认证的模型请求。
- 非敏感模型配置走现有序列化设置更新机制；API 密钥走 macOS 钥匙串。读取配置只返回“密钥已保存”等状态，不把密钥值回传用于回填。保存、替换、移除的失败必须可见；钥匙串操作失败时不降级为明文存储。
- 连接测试使用用户当前填写的配置和最小非工程内容请求，验证模型可正常完成文本及工具调用回环。只检查服务可达、列出模型或收到 HTTP 成功码不构成能力验证；测试不读取或发送当前工程。
- 一次对话请求由统一编排入口管理输入、工程身份、来源策略、请求预算、模型配置快照、受限读取与方案生成、结果与取消。UI 不拼装不同请求链；工具次数、返回量与总上下文有明确上限。
- 对话可以检索文档、清单、文本、提出修改方案及通过声明式专用工具请求参数控件。模型提供建议，App 核实绑定并生成界面；工具调用本身不构成预演或写入授权。实际单文件写入与确定性检查分别受“应用到工程”和“运行检查”的具体任务授权控制，复用 v1.6.5 服务；不提供任意 shell、依赖安装或开放文件系统写入能力。
- 每次请求绑定工程与请求标识，模型载荷、工具执行、工具结果回传和最终回复提交均核对同一工程代次与取消状态。停止请求、关闭工程、切换工程、切回演出模式或替换模型配置时取消相应请求；迟到结果不得提交到新的对话。请求进行中避免重复发送，失败由用户手动重试，不无限或隐式重复收费请求。
- 提示词、读取结果和模型回复在协议中保持不同角色。工程文本与返回的工具数据作为资料处理，不能改变允许工具、路径边界、授权或写入规则；模型输出渲染沿用安全的 Markdown 与链接处理，不执行嵌入 HTML 或脚本。

### 帮助语料、读取授权与上下文

- 平台问答优先使用随当前 App 发布的帮助语料，复用现有语料装载、分节、纯函数搜索与文档导航。保持现有中英镜像、稳定文档标识与装机资源路径契约，不另建一份可能与装机版本错位的在线契约副本。
- 纯平台问题仅使用平台资料；工程问题在用户开启工程读取且授权有效后再检索当前工程。模型可以在一次对话中请求多个相关小节或文件片段，由 App 执行确定性的只读工具；v1.7 不设专门的 LLM 阅读子代理。
- 首次向当前模型服务发送当前工程内容前展示工程、服务与范围并确认。取消不发送且保留输入；切换工程身份、扩大已确认读取范围或变更模型服务后原授权失效。正常保存或外部修改工程文件会更新事实与读取结果，不因此反复请求同一范围的发送授权。发送授权不随本机聊天历史恢复为已确认状态。
- 关闭工程读取后，后续请求不继续调用工程工具或重发历史中的工程摘录与工程概况。历史记录仍可本地显示，发给模型的上下文必须符合当次授权与读取开关；不能仅隐藏开关却继续发送旧工程内容。
- 工程访问复用 v1.6 的当前工程目录与只读文件服务边界，在 Rust 侧同时核实请求入口路径和规范化后的实际目标属于当前工程，拒绝路径穿越、工程外绝对路径与逃逸符号链接；即使工程外链接最终指向工程内，也不能作为访问入口。文件清单、搜索、分段读取和来源导航使用一致的边界，不能只在 UI 过滤。
- 工程工具默认只读取已保存的可读文本，排除依赖目录、构建目录、锁文件、压缩后的第三方库、二进制与媒体内容，以及已识别的敏感配置。未保存工程草稿和建议卡待应用内容不隐式作为磁盘源码发送；显式选区附件按下节处理。文件读取有大小、片段、数量和总预算限制，排除或失败原因可追溯。
- “阅读整个工程”先生成当前实际文件范围、排除项与 token 估算，再由用户确认发送。估算明确是容量估计，不冒充模型精确计数；文件发生变化后重新核对范围。超出请求预算时不静默截断并宣称完整阅读，明确提示改用相关文件或分段问题。
- 回答的来源清单由实际采用的工具结果派生，区分文档、小节、工程相对路径与概况事实。不能把模型编造的引用当作已读取来源；文件不存在或文档缺失时明确说明，帮助中心导航复用已有文档与锚点协议。

### 显式代码片段附件

- 用户从当前工程文本或建议卡代码选区触发提问后，输入框显示工程相对路径、行范围、片段内容、选取时版本和来源状态（保存版、未保存工程草稿或待应用建议），发送前可查看或移除。建议内容标注其候选修订，不能冒充磁盘版本。附件捕获选取时内容，随后编辑不静默替换附件；陈旧来源明确标示，用户可重新选取。路径／文本来源由 App 核实，不依赖模型声明。
- 附件包含未保存内容也必须经过当前工程／模型服务发送授权与请求预算，不自动读取其他草稿，不扩大磁盘写入权限。工程切换时旧附件不得进入新工程请求；模型服务变更须重新授权。已识别敏感文件等禁读范围不因“选中”而绕过。
- “读取当前工程”关闭时不发送附件、不重发历史附件；保留输入和附件，提示启用读取或移除附件后继续纯平台问答，不隐式丢附件并发送不完整问题。历史按既有本机隔离保存来源与实际发送内容，恢复不恢复旧授权；模型上下文继续按当次开关和范围过滤。

### 工程概况与历史

- 概况取自 manifest、文件清单、README、依赖声明、创作交接单以及已经得到的预检与实际运行结果。保持“空白骨架／内容迹象”“静态契约”“最近实际测试”独立，不汇总为完成度评分或工程已完成结论。
- 生成概况只读事实，不调用会清理进程等有副作用的完整预检，不自动启动测试。沿用文件变化通知刷新或标记事实过期，在下一次请求读取最新相关内容；文件变化本身不发起 API 请求。
- 本机聊天按规范化实际源目录或等价的稳定本机工程身份隔离，必须区分不同位置的独立工程，即使它们的 manifest 标识相同；同一目录的符号链接别名不形成新的授权对象或重复历史。继续使用同一工程身份可恢复记录；本版不做跨目录搬迁或克隆后的历史自动合并。
- 聊天记录保存到 App 数据区，包含用户与助手消息、实际来源及请求完成、失败或取消状态；不保存 API 密钥，不放进工程、创作交接单或分发包。采用带版本的数据格式和原子写入，清理当前工程记录通过显式动作完成。
- 切换工程解除旧工程的活动请求、临时授权与当前上下文，加载新工程的独立历史；模型服务配置属于 App。原型切换工程时清空内存聊天的演示不能取代正式产品的本机持久化要求。
- 历史是讨论记录，不代表工程文件仍保持当时内容。恢复记录时使用当前工程事实并标明相关事实更新，不把历史里的一次测试成功当作当前运行状态。

### 讨论内参数与代码建议

- 助手根据当前创作意图、实际读取的工程内容和可核实能力决定是否提出参数面板；用户也可以主动要求将某处改动做成可调控件。不预设所有工程都使用原型的固定参数，不以画面／声音、文件语言或工程类型作为是否可以预演的分类。意图含糊或存在多个不同作用目标时先澄清；无法找到可靠绑定时不伪造控件或实时效果。
- 模型通过声明式专用工具提出目标已有文件、读取版本、参数来源与绑定、类型、当前值、建议值、作用说明和建议控件。App 核实工程身份、路径、文件版本、绑定位置、类型与合法性，再呈现数值 fader／输入、开关、选项或颜色等适用控件，不执行模型返回的 UI 脚本。连续数值才适合 fader；非数字改动始终可以通过代码编辑完成，不要求将所有结构硬映射为控件。
- 工程明示的真实约束和模型推测的试调范围分别标注。App 依据实际来源验证枚举、边界、单位与步长；没有依据时不能将建议范围冒充工程硬限制。非法值保持可见错误且不能送入预演或写入；不能靠截断、强制类型转换或无提示钳制掩盖用户输入。
- 同一建议卡的“参数／代码”编辑的是同一份目标单文件待应用内容。代码入口允许修改完整候选文本，包括字符串、条件、函数和其他非数字内容；它不直接编辑磁盘文件、工程文件草稿或已有执行差异。卡片显示目标、来源版本、是否已编辑和生效方式，用户可以进入完整文件查看上下文。
- 参数变化只更新能够准确绑定的候选内容，保留所有其他手写代码；代码变化只在可确定对应关系时反映到控件。表达式、重复匹配、结构重排等导致无法可靠对应时停用受影响控件并解释，保留原始代码及其他有效绑定，不能重新生成整份模型建议覆盖手写修改。恢复 AI 参数同样只作用于仍准确绑定的参数；恢复整份建议或从当前文件重载须明确说明会放弃哪些待应用编辑。
- 切换参数／代码、完整文件和其他工作视图时保留当前待应用内容及编辑状态；编辑操作在本机完成，不因每次拖动或键入发出模型请求。已有目标出现工程草稿、磁盘外部修改、删除或工程身份变化时，保留用户内容并使旧应用和不再有效的预演失效；用户可以核对冲突、复制内容或明确重载。不能用“重载”暗中丢弃修改，也不能自动把建议合并进工程草稿。
- 本机历史可以呈现旧建议，但恢复历史不恢复旧执行授权、参数绑定有效性或预演会话。重新采用旧建议需核对当前工程和保存版，形成当前候选；跨 App 重启自动恢复尚未应用编辑的编辑栈不在本次承诺内。

### 预演能力与生命周期

- “预演”是在当前创作测试中临时体验待应用修改；它不写磁盘、工程草稿或 Git，不创建交接基线，不更新保存版已采用的运行证据。右侧同一 monitor 明确显示预演中、目标与覆盖范围，并区分当前保存版、实际运行基准及待应用内容。预演成功不代表已应用、已保存、已检查或已记录版本。
- 工程具备经过核实的参数接口或适配时，用户调节有效参数可即时预演；用户键入代码时不执行代码，先退出此前预演，点击“预演修改”后才针对当前完整候选尝试预演。App 不通过 `eval`、任意模型代码注入或执行模型自带脚本来模拟支持；具体受限适配协议、版本字段与消息验证在实现设计中沉淀并测试。
- 能否预演由当前工程的实际能力、运行状态和本次全部改动决定。对同一个目标可能分别需要即时参数更新、页面刷新、编译或进程重启，界面说明实际要求；不能因模型声称支持就启动。代码预演无法覆盖全部候选改动时，明确列出不支持部分并说明未完整预演；不得以部分参数或标题变化显示整份代码已成功预演。不支持预演仍可编辑和明确应用，再手动刷新／重启／测试。
- 开始预演前分别绑定工程、目标保存版、候选修订、当前运行身份与实际加载版本、适配能力，记录可恢复的运行基准；不能假设磁盘内容就是正在运行的版本。退出时只恢复对应临时参数状态，不承诺倒回时间、其他独立页面交互或所有运行副作用。适配消息核实发送端、工程与运行归属、候选修订和合法载荷；输入更新、快速拖动和多次请求按当前修订采用，旧回执不得覆盖新内容。没有运行、绑定过期或不能保证可恢复的适配时不进入预演，保留输入并给出原因。
- 结束预演、代码输入、目标或适配失效、停止测试、切换／关闭工程、离开创作模式及退出 App 都结束旧预演；阅读视图切换、布局拖动和 monitor 展开／还原保留同一有效会话。手动刷新或重启先使旧预演失效，之后只采用保存版；预演值不能偷偷进入重启配置。跨 App 重启、聊天历史恢复或回到旧工程均不自动恢复预演及其授权。
- 预演失败、取消、超时、断连或恢复失败均显示真实状态并保留待应用内容。能恢复时恢复基准；不能确认恢复时标明当前状态未确认，禁用继续叠加预演并提供显式恢复／手动测试入口，不能静默宣称已恢复或自动重启。预演不暗中启动、停止或重启测试／音频，不改变已应用的音频模式、设备或外部目标；临时声音参数也须遵守同一能力核实与恢复规则。
- 用户明确应用成功后，只有重新核验原预演绑定仍有效才可保持当前临时预演，不能让保存版自动成为实际运行基准；显式更新候选的保存版本关联，保留开始预演前的运行基准。用户结束预演仍恢复原基准对应参数，或手动刷新／重启采用新的保存内容。外部或未经核验的来源变化使预演失效；写入失败不能被“仍可预演”掩盖。
- 助手可以提出适配方案；能够在一个已有文本文件内完成的改动沿用明确应用及版本校验，不能自动安装或启用。新增文件、跨文件或其他复杂适配经确认写入创作交接单，外部 agent 完成后重新核对实际能力。适配接口可随实现完善，不将当前原型支持的固定参数和文本映射作为通用产品能力。

### 单文件修改与确定性检查

- 一次应用只写一个已有文本文件，允许源码、manifest、README、SCD。目标文件、改法、工程身份和读取版本随方案展示并绑定；读取其他相关文件不扩大写入范围。新建、删除、重命名及跨文件改写交外部 agent，不能自动拆任务绕过限制。
- 用户点击“应用到工程”作为本次授权，取代旧规划中“执行修改”的建议卡按钮名称，不追加重复确认；保存的是此刻参数和代码编辑后的完整最终候选，不是模型最初返回的文本。App 在提交时捕获候选修订并避免重复应用，结果绑定该次修订；应用过程中后续输入不得被旧结果覆盖或误标为已保存。
- 实际写入复用工程身份、路径范围、只读来源、原子保存、适用内容校验与磁盘版本检查；有未保存工程草稿、外部修改、失效目标或不合法内容时阻止写入并保留候选与草稿，不能因按钮授权覆盖冲突。变更工程或版本后旧方案失效；重载属于用户明确放弃对应候选的操作。
- 修改完成显示实际差异与结果，保存修改前内容和修改后版本供撤销。当前磁盘不再匹配本次修改结果时拒绝直接撤销，不覆盖后续外部修改。每次成功应用产生独立不可变记录，后续参数调整、代码输入、再次应用或运行刷新不能改写此前差异。
- 实际差异在相关回复下按需展开，绑定目标文件及修改前后版本；可编辑的待应用建议与实际执行结果分别表达。“本次改动”是只读记录；同一讨论中可另行编辑下一次待应用内容，进入“当前文件”则编辑工程草稿，并保留回到原讨论的入口。手动保存或外部修改不会把旧差异变成当前文件内容，旧撤销仍须通过版本检查。
- 实际差异和撤销沿用 #207 的记录生命周期，不因回复内呈现而新增跨重启长期差异存档；本机聊天持久化不等于重新获得已失效的修改记录或撤销能力。
- 检查使用 v1.6.5 已验收的临时副本服务，复制、预检、运行、超时／取消清理与报告由确定性程序执行；内置助手和外部 agent 使用同一能力。默认 None，未声明支持时说明未执行；Internal 由用户明确选择，External 首版经 App 手动测试。
- App 存在活动运行，包括启动／关停期间，拒绝需要新启动工程的自动检查；静态可继续，不自动停止现有演出。检查报告绑定副本输入版本、模式、依赖和共享库，并记录未覆盖内容；不把成功启动当成画面、触摸或声音已验收。
- 编译产物与报告属于独立检查动作，不是助手额外修改源码。原工程不因副本检查自动采用产物或新共享引用；采用新版由用户决定并写回工程版本。
- 应用、预演、页面刷新、编译、重启、运行检查和记录 Git 版本是独立动作。应用后按真实修改提示待刷新／编译／重启，预演成功不能消除这些提示或代替确定性检查。检查失败保留已修改文件并解释原因，提供撤销或下一次修改方案；再次修改仍需明确应用，不自动连续修复。跨文件任务先询问交接；用户拒绝时保留现状，可继续讨论。

### 交接基线与返回比较

- 用户确认写入具体交接任务时，记录当时已保存的工程内容作为该任务／修订的不可变比较起点。有草稿时列明文件并提供“先保存再交接”和“仅按保存版交接”，默认建议前者；不自动保存，逐文件保存仍遵守冲突和校验。待应用建议与临时预演另行提示未进入保存版；交接不暗中应用建议，任务可描述意图但基线不能将其当作已保存事实。保存失败时不继续交接，已成功保存的文件状态如实保留。
- “仅按保存版交接”遇到交接文档自身有草稿时，只向经版本检查的磁盘内容写入任务，保留原草稿并标记磁盘冲突；不能静默替换草稿，也不能让旧草稿直接覆盖刚写入的任务。
- 基线不使用 Git HEAD 代替，也不创建用户 Git 提交。基线包括已保存但未提交内容；复制同一任务不更新基线，修订任务经新的明确确认产生新基线并保留关联，多任务可选择各自的比较起点。以捕获前后版本检查保证内容一致；并发变化时重新核对，不能将不同时刻的读取拼成已成功冻结的工程。
- 基线和索引保存于 App 本机工程数据区，按可信工程身份、任务和修订隔离，使用带版本格式及可恢复写入。基线中的交接文档对应此次确认写入成功的版本，不能在刚完成交接时就把 App 自己写的任务显示成外部变化。确认写交接单与持久化基线的成功状态协调：任一步失败不显示“可返回比较的交接已完成”；明确已发生的写入、缺失步骤和重试入口，重试幂等且不悄悄用重试时的新内容替换原基线。旧版或外部创建、没有基线的任务说明“无比较起点”，不伪造历史。
- 基线跨 App 重启保留；清理与聊天清理分开，用户可明确删除选定基线并知晓失去该次比较能力，不能悄悄过期或覆盖。保留存储体积提示与有界读取／存储策略，空间或容量不足可取消／清理后重试；不以无限存储作为实现前提，也不将不完整捕获标为完整。
- 工程整体比较覆盖允许的源码、配置、文档和资源清单，任务涉及文件优先。文本提供真实差异，新建／删除给出明确状态；重命名可先显示删除＋新增，不要求推断归因。音频、模型等二进制仅保存识别变化所需的指纹、大小等摘要，不存可恢复副本；不可读、超限、依赖／缓存、Git 内部数据与逃逸路径等排除或失败项列明。大文件指纹计算有进度、取消及并发变化检查。
- 本地比较范围、AI 可读范围和 Git 纳入范围分别定义：锁文件与二进制摘要可供本地比较，不因出现在变化列表而发送给模型。界面称“交接后的变化”，不把所有修改自动归因于外部 agent；外部提交、分支推进或干净工作区不抹去相对基线的变化。比较版本与未保存草稿分开提示，后续磁盘变化使当前报告过期。
- 返回后可从差异进入当前文件、手动测试或独立运行适用检查，由用户核对任务验收。自动检查、外部任务状态或变更数量均不自动宣称工程完成；比较不会恢复文件、重置 Git 或刷新运行画面。

### 本地版本记录与历史

- App 提供 arm64／x86_64 均可离线使用、无需另装 CLT、Xcode、Homebrew 或 Git 的标准 Git 能力。复用已有工程状态／差异入口，实施时验证所选引擎的兼容、分发、许可及写入边界；不改造现有仓库格式，不使用网络账号作为前提。
- Blank 与 Classic 新建流程均在工程成功发布前初始化独立仓库并生成初始提交，不继承模板历史。初始化或初始提交失败不能显示完整创建成功，保留明确原因与重试；不留下误登记工程或覆盖既有目标。打开已有无 Git 工程仍可创作，主动“启用本地版本记录”预览后才初始化并记录初始版本。
- 已有工程初始化成功但初始提交失败时，明确“仓库已建立，初始版本未完成”。重启后重试复用已建立的仓库并重新核对文件与 HEAD，不删除用户目录、不重建仓库或覆盖期间出现的外部提交。
- 初始化只作用于当前工程根；当前目录属于父仓库、嵌套仓库或 worktree 等特殊结构时明确说明并交由外部工具处理，不静默嵌套或写父仓库。已有仓库历史与配置保留，未支持结构仍可使用不写 Git 的创作能力，不伪装成普通可写仓库。
- 新建工程提交署名预填工程创作者名称且可修改，邮箱选填；未填时明确采用本机占位地址，不能借用模板维护者或用户未知身份。工程作者仍可留空，此时展示可编辑的非空本机署名默认值，不推断系统账号。已有仓库沿用可用身份，缺失时首次记录再设置。版本署名与工程作者信息可独立调整，不反向改写 README／package 作者；只设置本工程所需配置，不修改全局 Git 配置。
- 默认纳入代码、配置、文档、锁文件与普通资源，排除依赖、缓存、Git 内部数据和已识别敏感项。大型音频、视频与模型默认排除，预览列明大小、排除原因与历史增长影响，用户可主动纳入；实现前明确并测试统一的大资源判定及容量上限。已有已跟踪资源不因新默认规则被静默取消跟踪；Git 记录不等于完整资源备份。新增忽略规则保留用户已有规则并可预览，不进行无关配置改写。
- 后续“记录版本”由用户手动触发，预览选中完整文件的保存版变化和提交说明；可记录新增、修改、删除，重命名按对应文件变化处理，不提供逐块暂存。未保存草稿、待应用建议和临时预演提示而不自动保存或应用，AI 起草说明不等于提交授权。保存、助手修改、预演、检查和生成交接单不自动提交。
- 提交结果仅包含用户预览并确认的完整文件，不带入其他外部已暂存内容。磁盘、HEAD 或 index 变化使旧预览失效；保留未选择文件的外部暂存状态，选中文件若已有外部暂存内容则本版拒绝该次提交并提示先在外部工具处理，不默默取消暂存或将部分暂存扩大为整个文件。merge／rebase／cherry-pick、冲突、锁占用、权限或空间不足等给出可恢复结果，不自动修复仓库。不得运行仓库自定义 hook、外部 diff 或 filter 程序；依赖未支持 filter／LFS 等处理的写入明确拒绝并引导外部工具。提交成功但状态刷新失败不得误报为未提交而引导重复提交。
- 历史列表显示说明、署名、时间、标识及变化文件，支持选择提交查看文本内容与实际差异，二进制只显示基本信息。仅允许将单个现存文本文件的历史内容载入编辑草稿：已有草稿先处理，保存继续经过磁盘冲突与适用内容校验。不直接改磁盘、HEAD、index、其他文件或运行状态，不恢复删除文件或整工程。
- 标准本地历史可由外部 agent 使用；Git 操作与助手授权、交接比较各自独立。`.pnds` 沿既有规则排除 Git 历史，本机聊天与交接基线也不随包分发。
- 所有本地 Git 操作不隐式联网补对象、不启动外部认证或签名程序；partial clone 缺对象、仓库要求未支持的签名等情况明确拒绝对应操作并引导外部工具，保留配置，不能静默绕过要求。继承已有只读 Git 的进程和资源边界。

## Testing Decisions

用户已确认测试边界：助手请求与模拟模型服务验证读取、取消、工程隔离、声明式控件、建议编辑、单文件应用、独立检查与确认交接；真实文件与持久化复用 Rust 临时目录，运行检查复用 v1.6.5 已验收服务。参数绑定与预演通过确定性适配测试和真实工程／模型评估分别验收，具体清单见 [#172 验收要求](../acceptance/172-v1.7.0-creation-workflows.md)。

- 好测试验证用户可观察的结果与不变式：实际发出的请求、返回的来源、授权前后是否读取、记录能否恢复、确认后写入的文件内容、取消后是否提交结果。避免断言内部函数顺序、组件结构或模型必须生成某一句话；不把原型假回复当作模型质量验收。
- **拟新增的最高业务接缝是一次助手请求的编排入口。** 当前尚无已实现的助手请求服务，使用可控的兼容服务替身与真实或临时工程工具，覆盖文档问题、工程问题、交替提问、多步工具调用、全工程阅读、预算耗尽、来源输出、错误、取消与迟到回复。复用项目已有 flow 模块与类型安全命令替身的测试方式，集中验证完整请求行为，不为每个 UI 小步骤新增服务层。
- **帮助检索复用既有纯函数接缝。** 保留现有语料装载、搜索排序、小节锚点、链接解析、语言镜像和语料规模测试。增加助手实际采用来源能够定位到已装机文档小节的整体验证；需要改进检索时用中文与英文实际契约问题作为行为样例，不复制实现权重做断言。
- **Rust 的命令与文件服务接缝承担真实边界验证。** 用临时工程与 App 数据目录验证范围校验、工程外路径、符号链接逃逸、敏感或二进制排除、不可读文本、大小限制、分段结果、工程变化与来源定位；沿用现有 manifest 路径验证、README 读取和原子设置写入的测试先例。不能仅用前端 mock 声称路径安全。
- 用最小可控 HTTP 服务验证认证配置、指定模型、工具调用回环、无工程内容的连接测试，以及超时、鉴权错误、无工具能力、非法工具参数、重复工具请求、断开的响应与停止请求；用凭据存储替身验证保存失败、移除失败、已保存状态和日志不泄漏。自动化测试不依赖真实 API 密钥或外部付费请求。
- 历史持久化用临时目录验证原子保存、重启恢复、版本解析、失败不损坏旧记录、显式清理，以及同 manifest 标识的不同工程不会共享记录。针对工程 A 的迟到结果在工程 B 打开后不能落入 B；旧发送授权不能从历史中恢复。
- UI 使用已有 Vitest、Testing Library、i18n 包装与全局 Tauri command mock 验证未配置入口、测试反馈、工作区阅读切换、概况悬浮与键盘展开、首次发送确认、关闭读取、全工程范围确认、来源定位、停止与重试、交接确认取消和冲突。切换对话、完整文件及已有交接内容后，输入、回复与草稿保持；monitor 保持同一页面及交互状态，控制台沿用 dock。保持新命令的默认 mock 显式暴露缺失测试配置。
- 单文件应用从最高文件服务接缝验证按钮前不写、已有文件与单目标限制、参数及非数字手写修改后的最终内容／真实差异、只读和路径拒绝、草稿／磁盘冲突、适用校验、撤销版本变化、重复提交、工程切换及迟到结果。应用提交期间再编辑时旧结果不能覆盖新候选；保存失败保留内容，重载前明确放弃范围。通过检查入口验证独立按钮、默认 None、显式 Internal、busy 拒绝、取消清理、副本输入版本与原工程不变；失败后不自动改写或重试。
- 差异呈现验证相关回复与真实执行结果对应、可编辑待应用内容与只读实际差异可区分、只读差异可定位当前文件，以及再次应用、手动调参或外部修改后旧差异仍表示原改动、旧撤销不能覆盖新内容。测试沿用 #207 的记录生命周期，不新增跨重启差异归档要求。
- 声明式参数工具使用真实／临时工程验证来源、工程身份、目标版本、绑定唯一性、类型、当前值、真实约束与建议范围区分；覆盖不存在或过期目标、非法类型／范围、表达式或重复匹配、恶意路径和模型假能力声明。参数改动保留其他手写代码，失去准确映射时只停用对应控件；代码、参数和阅读视图切换不丢内容。仅 UI 出现控件不能证明绑定正确。
- 预演从能力入口验证有效参数即时反馈、代码输入不执行且退出旧预演、代码显式触发、全部改动覆盖判断、无能力／无运行回落，以及候选、保存版和运行身份变化。覆盖快速调节与乱序回执、失败、超时、取消、断连、恢复失败、结束预演、手动刷新／重启、停止测试、工程／模式切换和 App 退出；正确恢复基准或明确未知状态，保留输入且无隐式磁盘、Git、音频或进程副作用。
- 预演成功后应用、继续调参再应用、结束预演和手动刷新／重启组合验证各版本独立：当前候选保存成功不改旧 diff、不自动变成运行证据，后续预演不改已保存文件，刷新只采用保存版。聊天历史恢复不恢复执行／预演授权；显式代码选区之外不默发待应用内容。
- 真实模型验收采用不同工程、不同参数和非数字改动的正例、反例及歧义例：应提供控件时提供且绑定正确，不适合时解释并保留代码入口，含糊意图先澄清；实际工程能力决定预演范围，不能按媒体类型猜测。记录工程版本、服务／模型、输入与实际工具结果和观察，不要求固定措辞；固定演示回复、模型自报或一次示例成功都不能证明质量通过。
- 交接验证先询问、拒绝不写、同意内容正确、已有任务与外部状态保留、版本冲突、重复确认不重复写、旧工程确认失效；新建／删除／重命名、跨文件、任意 shell 和安装不属于可执行单文件工具。
- 附件从真实编辑选区到最高请求入口验证：实际发送内容与来源、未保存标记、移除、后续编辑、工程／服务切换、读取关闭、授权恢复、预算和历史过滤；不能只测附件卡片是否出现。
- 基线与比较用临时工程覆盖未提交保存内容、无 Git、外部提交后干净工作区、多个任务／修订、重启恢复、二进制变化与排除说明、取消、并发变更、空间不足、交接／基线部分失败、幂等重试和显式清理。比较不得修改原工程或用户 Git 历史。
- Git 用真实临时仓库验证新建与主动启用、署名、初始提交失败不发布、整文件提交仅含所选内容、已有 index 保留、并发修改、无全局配置污染、忽略与大资源策略，以及历史载入只改草稿。双架构安装产物在无系统 Git 的环境核对能力，不以开发机已有 Git 的测试替代发行证据。
- 失败恢复验收补充已有工程建仓成功但初始提交失败后的重启重试、保存版交接后交接文档旧草稿保存冲突，以及 partial clone 缺对象、外部签名／过滤器配置下的不联网、不启动辅助程序和明确拒绝。
- 编辑器与布局核对中文输入法、每文件会话撤销／重做、快速切换、建议卡非数字编辑、查找替换与保存、外部冲突、历史载入、快捷键焦点、可调整宽度、1000×700 最小窗口及 monitor 页面状态保留。中英文和 Pond／Sand／Stage／Brutal 四主题覆盖长代码、长对话、错误及预演状态，滑块／数值输入／代码区域和退出预演可全键盘操作，系统减少动态效果仍能理解状态。语法着色不要求完整语言服务器语义。
- macOS 发布验收覆盖 Intel 与 Apple Silicon 的钥匙串保存／恢复／移除，使用已知具有工具调用能力的兼容服务实际核对连接测试与对话；在断网、错误配置和取消场景中核对工程编辑、手动测试与运行不受影响。原型只证明交互方向，不能替代此验收。
- 中英文真实创作流程覆盖：新建自动初始版本／已有工程主动启用 → 围绕创作意图讨论并附加选区 → 同卡调参／直接编辑非数字代码 → 按真实能力预演或说明未支持 → 明确应用最终单文件内容并阅读真实差异 → 手动核对保存版运行效果／适用检查 → 处理草稿并确认交接基线 → 外部 agent 实现并提交 → 返回比较整体变化、核对效果 → 手动记录版本 → 历史文本载入草稿。两个架构均核对键盘、布局、阅读切换及重启后的持久数据；无 Git 工程不启用时也能完成讨论、交接和比较。运行检查仍遵守活动运行拒绝规则；模型质量使用具体创作场景，不要求固定句式，不把自动检查通过当作艺术效果已验收。
- 当前独立原型 30 项交互测试及对话内预览 10 项 jsdom 检查只验证内存演示的状态关系；它们不是生产参数适配、真实模型质量、磁盘写入、音频／运行恢复或双架构窗口验收证据。需求定稿不等于下述发布要求已通过。
