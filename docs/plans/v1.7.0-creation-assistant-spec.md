# v1.7.0：创作助手

状态：依据已定稿 UI 原型与已确认产品决策整理的发布规格，待实现。以 v1.6.0 创作模式为基础；v1.6.0 提供标准模块文件添加与接线交接，v1.6.1 整理模块和外部 Skills；本规格只消费已发布的版本资料，不承担外部 Skills 实现或安装。

GitHub Issue：[\#149](https://github.com/xO-xN/PNDS-App/issues/149)，标签 `ready-for-agent`。

## Problem Statement

创作者需要理解 PNDS 的工程与运行契约，并把自己的创作意图同当前工程的实际内容联系起来。现有帮助中心可以查阅平台文档，但不能结合工程解释问题；把整个工程直接交给模型会混入依赖、二进制资源和敏感配置，还可能超过模型的上下文容量。

创作者已有外部编程 agent 负责代码实现。App 需要提供的是可追溯的咨询、工程事实与创作交接，避免重复建设编程 agent，也避免把“文件齐全”或“一次启动成功”误解为工程已经完成。模型服务由创作者自行提供；工程内容应在创作者知道发送对象和范围后才发送，聊天上下文也不能串到其他工程。

## Solution

在创作模式的编辑区增加第三个标签页“创作助手”，与当前文件、控制台并列。助手通过创作者配置的 API 地址、模型和密钥连接具有工具调用能力的 OpenAI 兼容服务；PNDS 不提供统一模型服务。

助手优先检索随 App 发布的 PNDS 帮助语料，工程问题再按需搜索和分段读取当前工程文本。首次发送工程内容需要确认；“阅读整个工程”是独立的显式操作，发送前展示实际可读文件范围、排除内容与 token 估算。回答显示实际采用的来源，工程概况展示身份、内容迹象与已知验证结果。建议可以经用户确认写入创作交接单，由外部编程 agent 接续；助手不修改工程代码。

每个工程保存独立的本机聊天记录，记录位于 App 数据区，不进入工程目录或 `.pnds` 工程包。取消请求、关闭工程、切换工程或模式都不能让旧请求的结果污染新上下文。咨询失败不影响工程运行、编辑、保存与手动测试。

## User Stories

1. As an 创作者, I want 在创作模式中打开第三个“创作助手”标签页, so that 我能边看工程边讨论创作问题。
2. As an 创作者, I want 在当前文件、控制台与创作助手之间切换时保留文件草稿与聊天, so that 咨询不会打断编辑和测试。
3. As an 创作者, I want 助手保持在编辑区内且不覆盖 monitor, so that 我能同时观察工程的测试反馈。
4. As an 创作者, I want 在未配置模型服务时看见清晰的配置入口, so that 我能知道如何开始对话。
5. As an 创作者, I want 自行填写 API 地址、模型名称和密钥, so that 我能使用自己的模型服务。
6. As an 创作者, I want 保存模型配置并在下次启动继续使用, so that 我不必反复配置。
7. As an 创作者, I want API 密钥存入 macOS 钥匙串且界面只显示已保存状态, so that 密钥不混入工程文件与普通设置文件。
8. As an 创作者, I want 移除已保存的 API 密钥, so that 我能停止使用该凭据。
9. As an 创作者, I want 测试连接时核对指定模型的文本对话与工具调用能力, so that 我能确认服务符合助手要求。
10. As an 创作者, I want 在连接失败、鉴权失败或工具调用不支持时得到不同的可操作提示, so that 我能修改对应配置。
11. As an 创作者, I want 在同一对话中交替询问 PNDS 基本知识和当前工程, so that 我无需为两类问题建立两套聊天。
12. As an 创作者, I want 平台知识问题依据装机版本的 PNDS 文档回答, so that 建议与当前 App 的契约一致。
13. As an 创作者, I want 回答列出实际使用的平台文档小节或工程文件, so that 我能检查建议的依据。
14. As an 创作者, I want 来源入口可以定位帮助文档或当前工程文件, so that 我能继续阅读原文。
15. As an 创作者, I want 助手按问题搜索相关工程文本, so that 我不必默认发送整个工程。
16. As an 创作者, I want 首次发送工程内容前确认工程、模型服务和读取范围, so that 我知道内容将发送到哪里。
17. As an 创作者, I want 取消首次工程内容确认后保留输入且不发出请求, so that 我能重新考虑发送范围。
18. As an 创作者, I want 关闭“读取当前工程”后继续询问 PNDS 文档, so that 我能使用不附带工程内容的咨询方式。
19. As an 创作者, I want 更换工程或模型服务后重新确认工程内容发送, so that 原授权不会自动扩展到新的对象。
20. As an 创作者, I want 依赖、构建目录、二进制媒体和敏感配置被排除在工程文本读取范围外, so that 请求只包含与问题相关的可读内容。
21. As an 创作者, I want 只有当前工程内的文件能够被助手读取, so that 外部路径或逃逸链接不会进入请求。
22. As an 创作者, I want 对超大、不可读或已变化的文件获得明确说明, so that 我不会把不完整读取当作完整分析。
23. As an 创作者, I want 主动选择“阅读整个工程”并先查看文件清单与 token 估算, so that 我能控制全面评议的范围。
24. As an 创作者, I want 范围超过当前请求预算时被明确告知且可以改为针对性提问, so that App 不会静默截断后声称已读完整工程。
25. As an 创作者, I want 工程概况默认保持一行并在悬浮或键盘聚焦时展开, so that 对话区能保留足够空间。
26. As an 创作者, I want 工程概况区分空白骨架、静态契约与最近实际测试结果, so that 我能理解事实与尚未验证的部分。
27. As an 创作者, I want 工程文件变化后看见概况更新状态, so that 我知道旧回答可能依据此前版本。
28. As an 创作者, I want 生成或更新概况时不自动启动工程或调用有副作用的预检, so that 咨询不改变当前运行状态。
29. As an 创作者, I want 请求进行时看到阅读和组织回复的状态并能停止, so that 我能结束不再需要的请求。
30. As an 创作者, I want 请求失败后可以手动重试且输入和已有记录仍保留, so that 临时网络故障不会丢失我的工作。
31. As an 创作者, I want 切换工程后看见该工程自己的聊天记录, so that 其他工程的上下文不会被错误引用。
32. As an 创作者, I want 重新打开同一工程后恢复本机聊天记录, so that 之前的讨论能够继续。
33. As an 创作者, I want 聊天记录位于 App 本机数据区而不进入 `.pnds` 工程包, so that 分发工程不会附带我的私人讨论。
34. As an 创作者, I want 能明确清理当前工程的本机聊天记录, so that 我能管理不再需要的上下文。
35. As an 创作者, I want 旧工程的迟到回复不能出现在新工程中, so that 工程切换始终保持隔离。
36. As an 创作者, I want 助手把需要代码实现的建议交给外部编程 agent, so that App 保持咨询与测试的职责。
37. As an 创作者, I want 先查看拟写任务的意图与验收条件再确认写入, so that 创作交接单只记录我认可的任务。
38. As an 创作者, I want 取消交接写入后保持工程内容不变, so that 咨询建议不会自行变成工程待办。
39. As an 创作者, I want 写入交接单时保留已有任务并检测外部修改冲突, so that 我不会覆盖外部 agent 的工作。
40. As an 创作者, I want 助手不能直接修改源码、manifest、README 或执行工程命令, so that 实现仍由我的外部编程 agent 掌控。
41. As an 创作者, I want 在讨论外部 agent 实现时按需要获得已发布 Skills 的提醒, so that 我能了解可用支持而不被固定安装 UI 占据空间。
42. As an 创作者, I want Skills 资料尚未发布时仍能查阅 PNDS 契约和记录交接任务, so that 助手不依赖未完成的 Skills 清单。
43. As an 创作者, I want 助手支持当前 App 的语言、主题、键盘操作与可访问状态提示, so that 它与其他创作功能保持一致。
44. As an 创作者, I want 助手或模型服务不可用时仍能编辑、保存、运行和测试工程, so that 创作工作台不依赖外部模型在线。

## Implementation Decisions

### 版本与 UI 边界

- v1.7.0 在 v1.6.0 的创作工作台上增加助手能力，沿用已定稿标签页、工程选择、模式切换、文件草稿与测试运行语义。当前文件为第一页、控制台为第二页、助手为第三页；不添加重复的顶部助手按钮或浮动助手面板。
- 助手以当前可编辑文件夹工程为工作上下文。无工程时保持创作首页，`.pnds` 工程包与内置工具的只读边界不因助手而改变。
- 工程概况默认是一行标题和新鲜度提示；指针悬浮或键盘聚焦展开，离开或失焦收起。首个工程问题附带可见的简短概况，不在打开标签页时自动发起模型请求。
- 原型中的示例回复、文件量与 token 数仅用于交互演示，不能作为正式读取结果、模型输出或通用容量限制。

### 模型服务与请求边界

- 首版支持具有文本对话与工具调用能力的 OpenAI 兼容接口。配置只有当前使用的 API 地址、模型名称和密钥；不增加供应商账号体系、服务市场或多配置切换管理。
- 认证请求与密钥读取由 Rust 侧处理，通过类型安全命令与事件把状态、结果和错误交给 UI。复用现有 HTTP 依赖与代理约定，补齐此功能所需能力；不在 WebView 中持有已保存密钥或直接进行带认证的模型请求。
- 非敏感模型配置走现有序列化设置更新机制；API 密钥走 macOS 钥匙串。读取配置只返回“密钥已保存”等状态，不把密钥值回传用于回填。保存、替换、移除的失败必须可见；钥匙串操作失败时不降级为明文存储。
- 连接测试使用用户当前填写的配置和最小非工程内容请求，验证模型可正常完成文本及工具调用回环。只检查服务可达、列出模型或收到 HTTP 成功码不构成能力验证；测试不读取或发送当前工程。
- 一次对话请求由统一的请求编排入口管理：输入、工程身份、来源策略、请求预算、模型配置快照、只读工具循环、结果与取消。UI 不直接拼装多个互不一致的请求链；工具次数、返回量与总上下文有明确上限。
- 只注册平台文档检索、当前工程文件清单、文本搜索和分段读取工具。对话可以提议创作交接任务，但没有直接写文件、运行 shell、安装依赖、编译或启动工程的模型工具。
- 每次请求绑定工程与请求标识，模型载荷、工具执行、工具结果回传和最终回复提交均核对同一工程代次与取消状态。停止请求、关闭工程、切换工程、切回演出模式或替换模型配置时取消相应请求；迟到结果不得提交到新的对话。请求进行中避免重复发送，失败由用户手动重试，不无限或隐式重复收费请求。
- 提示词、读取结果和模型回复在协议中保持不同角色。工程文本与返回的工具数据作为资料处理，不能改变允许工具、路径边界、授权或写入规则；模型输出渲染沿用安全的 Markdown 与链接处理，不执行嵌入 HTML 或脚本。

### 帮助语料、读取授权与上下文

- 平台问答优先使用随当前 App 发布的帮助语料，复用现有语料装载、分节、纯函数搜索与文档导航。保持现有中英镜像、稳定文档标识与装机资源路径契约，不另建一份可能与装机版本错位的在线契约副本。
- 纯平台问题仅使用平台资料；工程问题在用户开启工程读取且授权有效后再检索当前工程。模型可以在一次对话中请求多个相关小节或文件片段，由 App 执行确定性的只读工具；v1.7 不设专门的 LLM 阅读子代理。
- 首次向当前模型服务发送当前工程内容前展示工程、服务与范围并确认。取消不发送且保留输入；切换工程身份、扩大已确认读取范围或变更模型服务后原授权失效。正常保存或外部修改工程文件会更新事实与读取结果，不因此反复请求同一范围的发送授权。发送授权不随本机聊天历史恢复为已确认状态。
- 关闭工程读取后，后续请求不继续调用工程工具或重发历史中的工程摘录与工程概况。历史记录仍可本地显示，发给模型的上下文必须符合当次授权与读取开关；不能仅隐藏开关却继续发送旧工程内容。
- 工程访问复用 v1.6 的当前工程目录与只读文件服务边界，在 Rust 侧同时核实请求入口路径和规范化后的实际目标属于当前工程，拒绝路径穿越、工程外绝对路径与逃逸符号链接；即使工程外链接最终指向工程内，也不能作为访问入口。文件清单、搜索、分段读取和来源导航使用一致的边界，不能只在 UI 过滤。
- 默认只读取已保存的可读文本，排除依赖目录、构建目录、锁文件、压缩后的第三方库、二进制与媒体内容，以及已识别的敏感配置。未保存草稿通过现有状态提示，不隐式作为磁盘源码发送；文件读取有大小、片段、数量和总预算限制，排除或失败原因可追溯。
- “阅读整个工程”先生成当前实际文件范围、排除项与 token 估算，再由用户确认发送。估算明确是容量估计，不冒充模型精确计数；文件发生变化后重新核对范围。超出请求预算时不静默截断并宣称完整阅读，明确提示改用相关文件或分段问题。
- 回答的来源清单由实际采用的工具结果派生，区分文档、小节、工程相对路径与概况事实。不能把模型编造的引用当作已读取来源；文件不存在或文档缺失时明确说明，帮助中心导航复用已有文档与锚点协议。

### 工程概况与历史

- 概况取自 manifest、文件清单、README、依赖声明、创作交接单以及已经得到的预检与实际运行结果。保持“空白骨架／内容迹象”“静态契约”“最近实际测试”独立，不汇总为完成度评分或工程已完成结论。
- 生成概况只读事实，不调用会清理进程等有副作用的完整预检，不自动启动测试。沿用文件变化通知刷新或标记事实过期，在下一次请求读取最新相关内容；文件变化本身不发起 API 请求。
- 本机聊天按规范化实际源目录或等价的稳定本机工程身份隔离，必须区分不同位置的独立工程，即使它们的 manifest 标识相同；同一目录的符号链接别名不形成新的授权对象或重复历史。继续使用同一工程身份可恢复记录；本版不做跨目录搬迁或克隆后的历史自动合并。
- 聊天记录保存到 App 数据区，包含用户与助手消息、实际来源及请求完成、失败或取消状态；不保存 API 密钥，不放进工程、创作交接单或分发包。采用带版本的数据格式和原子写入，清理当前工程记录通过显式动作完成。
- 切换工程解除旧工程的活动请求、临时授权与当前上下文，加载新工程的独立历史；模型服务配置属于 App。原型切换工程时清空内存聊天的演示不能取代正式产品的本机持久化要求。
- 历史是讨论记录，不代表工程文件仍保持当时内容。恢复记录时使用当前工程事实并标明相关事实更新，不把历史里的一次测试成功当作当前运行状态。

### 创作交接与 Skills

- 助手只拟写任务。用户选择“记录为交接任务”后先看到意图、涉及范围、验收条件与状态，再确认写入现有创作交接单；取消不写入。写入走 v1.6 的工程写入边界，检测外部修改冲突，保留已有任务，不覆盖外部 agent 更新的状态。
- 不向模型开放任意工程写入权限。用户确认的是具体任务内容与当前工程，确认后再校验工程身份和文件版本；切换工程或内容变化不能沿用旧确认写入其他对象。
- 标准模块文件添加与接线交接由 v1.6.0 提供；模块接口、文档、兼容整理、可选 hub 模块及外部 Skills 由 v1.6.1 交付。助手可消费随 App 发布的固定版本资料，在相关讨论中说明外部 Skills 的用途、资源入口和安装步骤；安装自愿、按需，由创作者在外部环境主动完成。App 不安装、更新、卸载或执行 Skills，不扫描外部 agent 安装位置，不增加固定 Skills 安装 UI。
- 未发布的 Skills 不作为回答依据或完成本版的前置条件；助手仍可引用 PNDS 契约并记录通用创作交接任务。模块添加不会扩大模型工具权限；助手没有源码写入、安装或自动接线工具。新建、修改和任意来源工程的调查、可行性评估与移植实现由外部 agent 承担，App 不新增移植入口。

### 工程约定

- 组件临时状态留在组件，跨标签页和工程生命周期状态使用 selector 方式消费 store；设置持久化走已有序列化更新入口。Rust 与 UI 的通信使用生成的类型安全命令和生命周期明确的事件订阅。
- 文案进入中英 locale，布局遵循逻辑方向与既有主题；请求、错误、来源与确认支持键盘和可访问状态提示。日志记录请求状态与可定位错误，不记录 API 密钥、完整提示词、完整工程片段或聊天正文。
- 新增模型传输、受限文本工具、历史与钥匙串的开发模式在对应开发文档沉淀。完成标准为完整检查全绿，并完成 macOS 原生凭据与真实兼容服务的发布验收。

## Testing Decisions

用户已确认测试边界：v1.7 以助手请求工作流和模拟模型服务验证读取范围、取消、工程隔离与交接确认；真实文件与持久化复用 Rust 临时目录边界。

- 好测试验证用户可观察的结果与不变式：实际发出的请求、返回的来源、授权前后是否读取、记录能否恢复、确认后写入的文件内容、取消后是否提交结果。避免断言内部函数顺序、组件结构或模型必须生成某一句话；不把原型假回复当作模型质量验收。
- **拟新增的最高业务接缝是一次助手请求的编排入口。** 当前尚无已实现的助手请求服务，使用可控的兼容服务替身与真实或临时工程工具，覆盖文档问题、工程问题、交替提问、多步工具调用、全工程阅读、预算耗尽、来源输出、错误、取消与迟到回复。复用项目已有 flow 模块与类型安全命令替身的测试方式，集中验证完整请求行为，不为每个 UI 小步骤新增服务层。
- **帮助检索复用既有纯函数接缝。** 保留现有语料装载、搜索排序、小节锚点、链接解析、语言镜像和语料规模测试。增加助手实际采用来源能够定位到已装机文档小节的整体验证；需要改进检索时用中文与英文实际契约问题作为行为样例，不复制实现权重做断言。
- **Rust 的命令与文件服务接缝承担真实边界验证。** 用临时工程与 App 数据目录验证范围校验、工程外路径、符号链接逃逸、敏感或二进制排除、不可读文本、大小限制、分段结果、工程变化与来源定位；沿用现有 manifest 路径验证、README 读取和原子设置写入的测试先例。不能仅用前端 mock 声称路径安全。
- 用最小可控 HTTP 服务验证认证配置、指定模型、工具调用回环、无工程内容的连接测试，以及超时、鉴权错误、无工具能力、非法工具参数、重复工具请求、断开的响应与停止请求；用凭据存储替身验证保存失败、移除失败、已保存状态和日志不泄漏。自动化测试不依赖真实 API 密钥或外部付费请求。
- 历史持久化用临时目录验证原子保存、重启恢复、版本解析、失败不损坏旧记录、显式清理，以及同 manifest 标识的不同工程不会共享记录。针对工程 A 的迟到结果在工程 B 打开后不能落入 B；旧发送授权不能从历史中恢复。
- UI 使用已有 Vitest、Testing Library、i18n 包装与全局 Tauri command mock 验证未配置入口、测试反馈、标签页保留、概况悬浮与键盘展开、首次发送确认、关闭读取、全工程范围确认、来源定位、停止与重试、交接确认取消和冲突。保持新命令的默认 mock 显式暴露缺失测试配置。
- 交接写入从最高文件服务接缝验证：无确认不写、确认内容正确、已有任务与外部状态保留、版本冲突可恢复、重复确认不重复写、旧工程确认失效。模型提出其他写入、执行命令或安装动作时，测试确保没有对应可调用工具。
- macOS 发布验收覆盖 Intel 与 Apple Silicon 的钥匙串保存／恢复／移除，使用已知具有工具调用能力的兼容服务实际核对连接测试与对话；在断网、错误配置和取消场景中核对工程编辑、手动测试与运行不受影响。原型只证明交互方向，不能替代此验收。
- 所有新增业务逻辑随实现带测试；本版完成前运行 `npm run check:all`，满足 typecheck、lint、ast-grep、prettier、clippy 与测试门禁。

## Out of Scope

- v1.6.1 的模块接口、文档、兼容整理与外部 Skills 实现；v1.6.0 的确定性模块文件添加不由助手执行。App 移植评估入口、Skills 自动安装、更新、卸载和执行不在本版范围。
- 内置助手直接改写代码、manifest、README，运行 shell、安装依赖、编译音频或自动启动／重启工程；其工程写入仅限用户确认的创作交接任务。
- PNDS 托管模型服务、统一账号、付费或订阅系统、云同步聊天、多供应商原生协议、多个模型配置管理。
- 图片、音频、视频等多模态输入，素材解码或试听、图像生成、联网研究工具、任意 URL 抓取、远程文件系统读取。
- 专门的 LLM 阅读子代理、后台自主任务、无限上下文、自动阅读整个工程、无确认发送工程内容。
- `.pnds` 工程包或内置工具解锁编辑、跨工程检索、目录搬迁与克隆时自动合并聊天。
- 工程完成度评分、自动艺术评价结论，以及以助手替代确定性的预检、编译或运行验收。
