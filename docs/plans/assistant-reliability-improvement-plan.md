# 创作助手可靠性修改计划

日期：2026-10-29。状态：代码已实施，`npm run check:all` 全绿；真实模型语义、原生界面及现场验收尚未完成。

本计划整理 Runes 多轮讨论、逐题问答、声音重构及后续修正中暴露的问题，目标是让创作助手从用户决定、方案承接、实际实施到验证交付保持一致。用户已授权按计划实施 App 改动；保留现有未提交工作，不修改 Runes 工程，不启动 dev server，不提交代码。下文优先级表示本次可靠性工作的先后顺序，不代表已发布的缺陷等级。

首批工作解决三件事：完整方案与操作入口共同交付；完成状态与实际证据一致；实施和测试遵守用户确认的行为及范围。随后补齐任务内自动编译、项目测试、版本关联和用户纠正的继承。已明确要求：涉及 SynthDef 的 Work 任务由助手自动完成必要编译、产物校验及编译错误修复，正常流程不要求用户点击编译按钮。工程概况优化排在后面，本次证据不支持将扩大默认上下文作为主要修复。

## P0 A 讨论收束和操作入口

### 目标与改动

将一个讨论方案定义为可追溯的公开结果：包含完整正文、目标、文件范围、验收、有效用户决定和明确的未验证事项。正文、交接草稿和 Start work 都选取这一份内容。`activity` 继续承载工作过程，不承担唯一的方案存储。

建立明确的讨论完成协议，区分普通回答、等待一个问题答案和方案就绪。优先复用现有 `propose_handoff` 及共享工具清单，使方案就绪结果必须携带完整方案并通过 App 校验；不能只靠最终正文中出现“完整方案”或按钮名称推断就绪。具体类型名称可沿用现有模型，但普通问答不应被强制生成方案卡，也不能以回答题数判断讨论结束。

校验成功后共同发布完整方案和两个操作。工具轮已经给出完整方案时，将其作为正式方案内容发布，避免后续自由文本摘要覆盖；最终正文已有完整方案时，同样必须有有效操作结果。模型宣称方案就绪但缺少必要结果时，进行一次有界协议补齐；补齐失败保留内容并显示准确状态，不承诺不存在的按钮，不循环调用。

统一共享 schema 与实际校验，包括必需字段、空值、路径、长度和数组边界。`knownProblems` 没有实际问题时应有明确的空表示，不能迫使模型编造问题。拒绝回执返回具体原因；只有成功结果才能说操作入口已可用。讨论请求的说明不携带无关的 legacy 模式描述。

App 捕获的模式决定行为。讨论模式收束提供 Write handoff file 和 Start work；工作模式中的问题作答接续原任务，不能虚构讨论入口。上一轮工作结束不自动改变用户选择的模式，也不根据“出现了 grill”猜测模式。

新提交的明确选择，例如 `Start work`、`开始工作`、`直接工作`，与按钮复用同一方案选择及准入路径。只有当前话题存在唯一可选方案、工程和资料版本仍有效时才能开始；缺少方案时进入补齐或重新核对，歧义时说明需要选择哪份方案。不能静默把这类输入当普通讨论发给模型，也不能把引用文字、问题答案或历史消息当成新的执行选择。

记录最小诊断：实际请求模式、终答类别、是否调用方案工具、拒绝原因、方案发布结果及卡片隐藏或失效原因。诊断不保存原始私有源码、凭证或模型私有推理。

### 主要落点

`src-tauri/resources/assistant-tools.json`、`src/lib/assistant-tool-contracts.ts`、`src/lib/assistant-flow.ts`、`src/lib/assistant-handoff.ts`、`src/lib/assistant-workflow.ts`、`src/store/assistant-store.ts`、`src/store/assistant-handoff-store.ts`、`src/components/creation/AssistantWorkflowCard.tsx`、前后端历史 schema。实施后更新 `docs/developer/creation-assistant.md` 和 `handoff-baselines.md`。

### 验收

- 两次逐题问答后，正常调用、遗漏结果、参数拒绝三条路径都有确定终态；未回答问题不生成可开工方案。
- 分别重放完整方案位于工具轮正文、最终正文的情形，真实组件显示完整方案及两个按钮；不只断言 `result.handoff` 有值。
- 两个按钮和明确文字选择携带相同方案正文、数字、范围和答案；不重新设计、不重复询问已定事项。
- 覆盖上轮 Work 完成后继续新设计，从 Discussion 和 Work 两种状态进入；模式、工具权限和文案一致。
- 取消、重复点击、切换工程、资料变更和旧回调不会启动错误任务；补齐卡片本身不写工程文件或自动开工。

## P0 B 完成状态和证据范围

### 目标与改动

将“本轮模型调用已结束”与“用户目标已经完成”分开。按任务实际需要记录源码保存、静态检查、产物生成、运行加载、行为检查和人工验收；纯文档任务不需要音频产物阶段。各项保留输入版本、工具范围、实际结果和未执行原因。

工程 ready 时对旧实例的 health/HTTP 观察继续保持只读，但 `savedChangesVerified: false` 只能支持“当前实例健康、新改动未验证”。模型可以结束本轮并保留待加载或待验证状态，不能由一个顶层 `passed` 推出新功能已完成。缺编译产物属于实施尚未闭合；听感尚待创作者复核属于另一种状态，两者不能混成一句通用免责声明。

接入 E 的自动编译后，“待编译”只能作为执行中、实际受阻或中断状态。编译能力可用且任务仍有效时，Work 必须继续完成必要编译和校验，不能以“源码已保存，请用户编译”结束交付。

能力结果区分工具不可用、尚未探测、实际缺失、执行失败和执行成功。编译器文件存在只说明发现候选编译器；成功编译及输出验证另有证据。静态路径检查、编译产物符号校验、运行实例加载确认分别命名，工具结果不能被扩写成未执行的检查。

最终回复和 App 状态共享同一结果依据：首句说明实际到达的阶段，主要结果列出相关未完成环节及可执行下一步。状态迁移由可信工具回执决定，模型措辞不改变证据。必要实现或检查未完成时，交接记录继续保留对应任务；不要归档为“没有待实施或受阻事项”。

### 主要落点与验收

重点涉及 `src/lib/assistant-task-checks.ts`、`src/lib/assistant-task-lifecycle.ts`、`src/lib/assistant-flow.ts`、`src/store/assistant-store.ts`、任务恢复与历史 schema，以及 `src-tauri/src/project/diagnostics.rs` 和 controlled-checks 回执。更新 `docs/developer/controlled-checks.md`、`creation-assistant.md`、`handoff-baselines.md`。

验收覆盖源码新但产物旧、源码新但旧实例健康、编译失败、测试失败、工具不支持、运行被占用和仅人工听感待验七类结果。分别断言首要结果、任务保留状态及下一步动作；未执行不记通过，运行被占用不反复启动同类检查，必要步骤缺失不宣称目标已验证。

## P0 C 行为验收和决定范围

### 目标与改动

沿用讨论方案，将核心要求写为“触发条件、持续行为、结束条件”，并附用户选择的来源。grill 重点处理会影响实施的矛盾，不增加固定问答题数、成熟度评分或逐项确认表。数值建议区分实测结果、估算和待试听调整，不能把未测的“5 ms 点按可听”作为已经保证的结果。

改变共享参数时，检查依赖该参数的行为。本例 release 同时影响包络长度、控制器提前收尾、尾音占用和测试预期；不能只同步数值。用“持续按住直到元素消失”这样的场景检验旧规则是否仍兼容新要求，真正冲突才提出一个必要问题。

每项决定保留适用范围。元素消失、松手、全曲结束、Pause、Stop、seek、断连和声部抢占是不同触发条件。用户只改变其中一项时，其余沿用已确认行为；若组合后不可实现，应解释冲突后澄清。不能用“这是同一规则”扩张决定。

实施验收先来自用户行为，再由实现满足。修改旧测试前说明旧断言对应的行为是否已经被用户取代；保留仍然有效的回归。允许重构实现和测试，但不能仅因为实现输出变了就把新数字写成正确答案。

### 固定回归场景

使用脱敏的八音色 fixture 和可控时间，不运行真实演出：持续提供触摸与心跳；元素有效期间不提前发 release；松手只触发一次 release；元素到期按最新明确决定开始 release，并播放完整尾音。其余结束条件按各自已确认规则验证，不能从元素到期规则自动继承。

加入一条反例：旧测试与旧实现都通过，但它们在手指未松开时提前 release。评测应发现它不满足新要求。Runes 的 2,820 ms 提前量可作为历史复现依据，测试断言应围绕事件时序，而不是锁死这一数字。

主要落点是 A 的方案内容、讨论和工作策略、相关回放 fixture 与测试。源码流程能确定地检查来源和状态；模型能否发现语义冲突交由 G 的真实模型评测验证，不能靠提示词包含某句话宣布解决。

## P1 D 用户决定与纠正继承

在当前话题内保留原始用户回答、所选选项的含义、出处和适用范围，作为讨论、交接和工作的共同输入。保留来源身份：用户意图、用户提供的环境说明、代码事实和助手推断不能混为同一种“已验证事实”。如用户说明与实际代码冲突，明确指出差异并继续核对。

当前历史筛选可能因某个文件版本变化排除整轮回复。后续应使代码证据失效触发重新读取，而不同时删除用户在该轮提交的决定。跨轮、压缩、重启和选中方案都使用同一投影，且不把旧执行权限一起恢复。

已回答问题的模型输入突出实际答案和有效选择；旧问题中的假设不继续作为事实传播。用户更正覆盖此前助手的推测，保留原始记录供追溯。涉及被纠正解释的授权工作，应同步修正当前生成的注释、报告和交接；历史原文保留，当前文档明确哪项决定已被取代，避免旧误判经源码阅读再次进入新任务。

主要落点：`src/lib/assistant-context.ts`、`assistant-questions.ts`、`assistant-working-context.ts`、`assistant-handoff.ts`、`assistant-history.ts` 及历史/恢复 schema。

验收重点：同一自由文本答案同时表达“采用升八度”和“专业设备出声”，两者均保留；文件变化、上下文压缩和重启后不恢复手机外放前提；交接和工作继承同一选择，未采纳的选项不成为任务。该机制只保存当前话题必要决定，不建立所有 PNDS 事实的永久常驻清单。

## P1 E 编译与工程测试能力

### SynthDef 编译

自动编译是 Work 的必需交付步骤。任务修改了 `supercollider/source/*.scd`，或发现任务所需产物缺失、编译证据已失效时，在保存本批源码后、交付前自动编译当前工程已保存的全部 SynthDef 源码。当前 Work 授权包含这些必要构建步骤，不另问“是否编译”，不要求用户点击工具栏或手动运行命令。

自动触发限于当前已授权 Work 任务所需的构建，不扩展成对所有用户手动编辑的后台自动编译。

由 App 根据任务文件变更和编译证据安排必要编译，不能只增加一个工具后依赖模型记得调用。模型遗漏调用也必须在交付前补齐；编译失败将真实诊断交回同任务，助手修复本任务范围内的源码问题并重新编译。只有遇到无法自行解决的实际环境或版本冲突才保留受阻状态并报告原因；不能把常规编译转交用户，或把源码已保存称为编译完成。

将现有编译服务接入助手任务工具，复用本机编译器发现、临时产物、输入版本复核和符号/文件/manifest 校验。先返回实际能力状态；缺失才报告缺失，执行失败返回可修复诊断。

编译需要当前工作任务归属。生成的二进制纳入任务文件记录、版本冲突检查、取消清理和撤回；不能直接暴露 UI 命令绕过任务管理。输入或产物被外部修改时拒绝覆盖并重新核对，重试与恢复不重复发布不同版本。编译成功不自动重启用户正在使用的演出。

主要复用：`src-tauri/src/commands/creation.rs`、`src-tauri/src/project/creation/compile.rs`、`assistant_tasks` 及共享工具清单。首要验收是用户只提出声音修改要求、完成必要的创作决定后，助手自行修改、编译并校验全部必要产物，期间用户不执行任何编译操作。另覆盖模型遗漏编译调用后的自动补齐、编译错误的同任务修复重试、编译器候选存在但启动失败、缺编译器、输出缺失/符号不符、并发源文件变更、取消、重启恢复和任务撤回。源码或产物再次变化后，旧编译证据不能满足交付条件。

### 工程测试

首批为已识别的 Node 测试入口提供受限执行能力，使用 App 自供 Node 和临时副本，记录实际入口、退出码、失败项与输入版本。优先支持本例的 `node --test`，支持范围以工具契约明确列出；不存在受支持入口时如实说明。项目开发依赖继续遵循仓库 npm 规则，不自动安装依赖，不扩展成任意 shell 执行入口。

测试受任务取消、进程所有权、输出限制和清理机制约束。临时副本不等于操作系统沙箱，测试可能使用硬编码端口或连接现有服务；首批沿用运行互斥，无法确认资源隔离时，工程演出期间拒绝执行并保留待验证状态。只有具备可验证的隔离能力后，才允许并行运行。源码改变使旧测试结果失效，重启接续时重新核对版本。测试失败应进入同任务修复；能运行的检查应实际运行，不能以手算预期代替。

主要复用 controlled-checks 的临时工程、进程和回收基础设施，并通过 `assistant-task-tools.ts` 和共享工具清单接入。验收覆盖真实失败、超时、取消、输出过大、依赖缺失、测试期间输入改变、演出资源冲突时的拒绝，以及临时资源完整清理。

## P1 F 源码产物与运行版本关联

为需要构建的任务关联源码版本、构建输入/结果、产物摘要和运行实例身份。源码改变使构建证据失效；产物改变使先前加载证据失效；观察旧实例只证明旧实例的状态。版本信息由 App/native 服务产生，不要求模型根据文件时间或文档描述猜测。

复用已有 session、检查 receipt、版本指纹及编译报告，按需要扩展，避免另建并行状态系统。实际“重启工程以加载”与退出/重启整个 App 应按现有生命周期区分。重启后重新核对产物和实例；未获授权不为了验证而打断运行中的演出。

声音行为验证增加一个小范围的离线能力：针对已编译的八个 fixture，在持续 gate、松手和结束条件下渲染并分析包络、电平和尾音。检测实际生成的二进制，不以 SCD 字符串或 HTTP 200 代替。先以受控 fixture 建立能力，任意作品的特殊 OSC/合成协议继续由工程定义，不假设 Host 可以自动理解。

客观行为与艺术听感分开。持续 gate 是否提前静音可以自动验证；八种音色是否合意、现场响度和专业设备听感由创作者验收。能量保留、分音衰减等指标需要明确基线、参数采样和测量方法，未建立测量时只能作为待验证目标。

验收覆盖新源码配旧产物、新产物配旧实例、外部修改产物、编译后再次改源码，以及持续型源码实际编译失败/产物仍为敲击包络等情况。只有正确版本的实际行为检查通过，才能将对应行为标为已验证。

## P1 G 真实模型评测与回归

以脱敏场景建立固定输入、实际工具结果和期望行为，覆盖 E1 至 E10。开工前保留当前表现作为基线；A 至 F 每批改动后运行相关确定性测试，再做必要的真实模型评测。

| 层次            | 验证内容                                                       | 不能据此宣称                 |
| --------------- | -------------------------------------------------------------- | ---------------------------- |
| 纯逻辑/契约测试 | schema、状态、版本失效、决定投影、任务准入和错误恢复           | 模型已经理解艺术意图         |
| 流程与组件集成  | 两次问答到真实按钮、同方案转交、失败提示和跨模式承接           | 原生界面和真实服务均已验收   |
| 真实模型回放    | 不复活已纠正前提、不扩张决定、不伪造能力或完成、能发现行为冲突 | 一次成功保证所有模型永远正确 |
| 原生与设备验收  | 编译、重启加载、交互持续、音频与现场听感                       | HTTP 健康检查可以替代演奏    |

真实模型至少覆盖：手机交互与专业设备输出的混合描述；自由文本同时接受方案和纠正原因；源码变化后的决定继承；元素消失与全曲结束的不同边界；新源码配旧运行；两题结束但模型省略/错误调用方案工具；旧测试通过却违背用户行为要求。

自动编译回归覆盖用户只要求修改声音、没有提到编译，以及模型漏调用编译工具的情况。断言 App 仍安排必要编译，失败回到同任务修复，成功产物对应最新源码，全程无需额外编译确认或按钮点击；未进入授权 Work 的手动编辑不触发此流程。

对选定的实际模型配置，每个关键语义场景先重复三次，保留通过次数、失败类别及工具开销。出现虚构执行、纠正丢失或未授权扩展范围时，修正后重测相关场景。三次通过只是本批验收证据，不宣称普遍保证；不自动替用户更换模型，不把未经授权的私有聊天发送给其他服务。

每批功能实施后以 `npm run check:all` 全绿为完成条件；必要时另加编译/运行验收。dev server 由用户启动并回报，受控回放与真实 App/设备结果分别记录。当前计划文档的格式检查不代表这些功能已经实现或通过。

## P2 H 工程概况和按需阅读

明确工程概况是默认导航。当前 native 为 README、manifest、package、handoff 等读取开头片段，发给模型时压缩为最多六份、每份前 200 个 UTF-16 单位。模型仍可通过项目读工具继续读取，单页最多 65,536 个单位；Runes 本次确实读过关键声音代码。

优化方向是让可解析配置提供少量完整结构化元数据，普通文档提供用途、章节/路径和实际摘录范围；不用任意 JSON 前 200 字符代表整个配置。字段来自现有解析器和来源版本，不能由模型猜测。关键技术前提仍需按任务读取相关代码和已安装契约。

不逐条常驻所有 PNDS 知识，不默认发送全工程，不先引入新的 RAG 或大型记忆系统。只有 G 显示存在稳定的检索遗漏，再调整目录入口和任务相关检索。这里不作为 E1 的已证实根因修复。

主要落点：`src/lib/assistant-overview.ts`、`src-tauri/src/project/creation/assistant.rs`、帮助检索/阅读工具与相关预算测试。验收覆盖短配置、长 README、缺文件、无效 manifest、多语言、版本变化及摘录不完整的明确提示。

## P2 I 历史方案与人工步骤接续

保存方案的只读显示快照，让重启后的用户仍能看到完整方案、决定和当时状态。新的明确选择可以将其作为新任务参考；开始前核对当前工程、资料与目标，旧任务授权和旧执行状态不会复活。无法安全恢复的旧格式保留历史正文，不从 `activity` 或私有推理自动拼成已授权方案。

待人工步骤保留为有出处的后续入口，例如确认演出可中断的重启时机、试听反馈。SynthDef 编译由 E 的 Work 自动流程承担，不列为常规人工步骤；真实环境阻碍解除后，由助手接续编译和校验。人工步骤完成后继续原目标的验证，避免要求用户重新描述方案。点击入口只触发其标明的动作；历史方案失效时显示具体原因，不静默消失，也不把任何历史助手建议变成用户已选范围。

此包改善恢复体验；A、B 所需的当前方案与未完成状态应在首批就具备，不等待这里完成。
