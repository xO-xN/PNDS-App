# v1.6.0：演出模式与创作模式

状态：已定稿规格，待实现。GitHub Issue：[\#148](https://github.com/xO-xN/PNDS-App/issues/148)，标签 `ready-for-agent`。

## Problem Statement

PNDS App 已能承担现场演出的工程选择、运行、音频配置与投影，但创作者在准备一个文件夹工程时，需要频繁往返外部编辑器、终端和浏览器才能查看文件、调整工程声明、编辑简介、编译音频产物和测试多个 performer。现场演出与创作测试也缺少清楚的操作边界。

创作者希望 App 提供一个轻量的创作工作台：查看与少量编辑当前工程、理解磁盘内容和运行版本的区别、手动测试和生成 `.pnds` 工程包。完整的代码实现继续交给外部编程 agent。演出操作者则希望保留全窗口 monitor 与自动隐藏的侧栏，不因创作能力增加而承担更多常驻控制。

## Solution

引入「演出模式 / Performance mode」与「创作模式 / Creation mode」。App 每次启动仍进入空闲的演出首页。演出模式保留原有运行体验；创作模式围绕一个可编辑的文件夹工程，提供文件阅读与轻量编辑、manifest 表单、README 可视编辑、控制台、monitor 和多个独立 performer 测试窗口。

采用定稿原型的并排工作台和侧栏底部模式按钮。模式按钮以两次点击在自身区域内完成确认，不弹出模式切换窗口。演出中可编辑的文件夹工程进入创作时直接接续同一工程和当前运行；创作返回演出始终结束测试并回到空闲首页。保存、页面刷新、工程重启和打包都是明确的人工动作。

新增可立即测试的空白工程，并通过创作交接单记录 README 翻译和外部 agent 的实现意图。本版提供首批五项标准模块的文件添加、来源版本记录和外部 agent 接线交接；模块接口、文档与兼容整理、可选 hub 模块和外部 Skills 重构归 v1.6.1。创作助手由 v1.7.0 单独交付。

## User Stories

1. As an 演出操作者, I want 每次启动 App 都看到空闲的演出首页, so that 我能明确选择此次要加载的工程。
2. As an 演出操作者, I want 运行时 monitor 占满主窗口, so that 乐谱画面拥有完整的显示区域。
3. As an 演出操作者, I want 指针进入左边缘或按住 Cmd 时显示覆盖在 monitor 上的侧栏, so that 我能需要时访问控制而保持乐谱尺寸稳定。
4. As an 演出操作者, I want 操作下拉和对话框时侧栏保持显示, so that 控制不会在选择过程中消失。
5. As an 演出操作者, I want 侧栏演出卡只保留音频、网络、增益和单一加载／更改／关闭按钮, so that 我能快速辨认当前可执行的动作。
6. As an 演出操作者, I want 工程选择与正在运行的工程保持独立, so that 浏览其他工程不会中断演出。
7. As an 演出操作者, I want 用下拉选择多个自定义演出文件夹, so that 我能维护不同场景的工程编组。
8. As an 演出操作者, I want 新建更多自定义演出文件夹, so that 编组不受旧的三个文件夹限制。
9. As an 演出操作者, I want 通过独立工具按钮随时进入内置工具, so that 我能快速运行诊断工程。
10. As an 演出操作者, I want 工具激活时看到返回上一个文件夹的入口, so that 我不会把仍显示的下拉误认为当前工具列表的归属。

## Implementation Decisions

- **交付范围与基线**：本版实现定稿原型的两种模式和并排工作台。保留演出加载、错误、Retry、主增益、全屏、投影、退出清理等现有契约。UI 原型的工程、进程、文件和窗口演示必须由真实能力替换，不能把内存演示当成生产实现。
- **启动与状态归属**：App 模式属于界面状态，启动固定为演出模式；用户工程索引、演出文件夹和已有有效偏好继续走现有持久化队列。界面模式不改写工程 manifest。工程选中、正在运行的工程、已应用音频配置和待应用测试配置必须分别表达。
- **模式按钮**：侧栏底部距边缘约 12px 的单一胶囊区域默认仅显示当前模式。悬浮／键盘聚焦显现目标模式；第一次点击显示「再次点击切换」与后果；第二次点击提交。确认后果放在按钮上方，包含停止测试或放弃草稿的实际影响。Esc、区域外点击和窗口失焦取消确认，无模式切换弹窗。
- **过渡与访问性**：斜切上下偏移固定为 56px，只作平移。确认提交后约 300ms 填满目标色块并淡入目标模式名称，期间禁止重复提交。完成时锁定新模式静止样式，直到指针离开再进入；键盘仍有可见聚焦反馈。颜色、边框、圆角和阴影使用已有主题 token；Brutal 与减少动态效果直接完成，保留确认语义。
- **非对称工程接续**：演出到创作优先采用真正运行中的工程身份，而非另一张选中卡片。运行工程是可编辑文件夹时，接续该工程及已应用的音频、LAN、External 目标和运行状态，不停止、不重新启动、不重挂或刷新 monitor，保留其页面导航与运行世代。没有运行但已选择可编辑文件夹时打开该工程且保持未运行。无可编辑目标时进入创作首页；工程包或内置工具的旧运行应结束。启动和关停提交期间禁止模式切换，以防并发接续。
- **返回演出与取消**：创作到演出结束当前测试、关闭 performer 测试窗口并清空当前创作临时状态，回到未加载的演出首页，不自动恢复旧演出。模式确认取消前不停止工程，不关闭窗口，不丢弃草稿。模式离开时关闭投影，避免创作切换遗留场地显示；可编辑工程的主运行接续不因此停止。
- **可编辑身份**：可编辑对象是用户自己的文件夹工程。安装后的 `.pnds` 工程包虽已解压成文件夹，仍按安装来源保持只读；注册表内置工具同样只读。后端命令依据可信来源与规范化工程根验证可编辑身份，不能只靠扩展名、是否为目录、隐藏按钮、文件名、界面分类或前端标记保护；重新打开安装目录或经符号链接访问不能绕过只读边界。此版不提供从只读工程包或工具自动生成可编辑副本的能力。
- **演出侧栏**：运行时侧栏覆盖 monitor，沿用左边缘／Cmd 显示、离开自动收起以及操作期间保持显示的规则。显隐不改变 monitor 尺寸，不重挂、不导航、不改变工程连接。投影、投影开演、简介和刷新入口留在侧栏相应位置，不新增 monitor 上下控制栏。移除侧栏帮助按钮与重复的工程身份／运行行，保留其他既有帮助访问方式。
- **演出卡**：仅保留音频模式、网络、增益与一个满宽加载／更改／关闭操作。操作沿用选中与运行分离、启动门控、替换运行确认、错误 Retry 和重复提交保护；不增加第二个停止／重新载入按钮。
- **演出文件夹**：用可滚动下拉承载自定义编组，解除原三个文件夹总数上限（旧限制包含内置工具文件夹），保留既有成员、排序、命名、导入导出与持久化语义。内置工具使用独立按钮且继续受注册表保护。工具激活时隐藏下拉，显示返回上一个用户文件夹的入口；返回或再次点击工具恢复此前视图。文件夹切换只改变浏览，打开工程加入当前用户编组，当前演出不受影响。
- **创作首页与选择器**：首页提供打开文件夹工程、新建工程与最近创作入口。工作台工程标题在悬浮／聚焦时显示「切换其他工程」，选择器列出可编辑工程并提供新建空白工程；只读条目给出原因。取消选择或表单保留旧工程。确认新目标后再处理未保存修改；只有明确同意放弃时才结束旧测试并切换。
- **工程切换的原子边界**：切换成功后清除旧工程草稿、待刷新／待重启标记、错误、交互与临时交接状态，读取新工程自己的内容。异步文件、预检和窗口返回以工程身份和操作世代校验，旧工程迟到结果不能写入新工程。失败显示可读原因，不把另一个工程的草稿或运行快照当成新工程事实。
- **创作打开与运行验证**：外部 agent 交回的初版在必要文件及结构齐全、符合创作打开要求时可以进入工作台，不要求已有成功启动、声音或演出验收记录。创作打开、编译、完整启动与打包的校验分别执行，不把作品未完成当作禁止创作阅读的理由。
- **空白工程**：通过原生目录选择与工程信息表单创建用户指定的新目录，避免覆盖已有工程。结构满足既有 manifest、health、页面、音频 bus 和关停契约，没有生产依赖，使用固定随包 Node 可立即启动。创建成功进入该工程工作台但不自动启动测试。取消创建保留旧工程；创建失败不显示虚假的成功或可运行状态。
- **空白音频**：默认 Internal，同时声明支持 External 与 None。提供音频代码、SuperCollider 源和对应已编译的技术占位 SynthDef；Internal 只向注入的工程私有 bus 写零信号。External 在未实现工程协议时可启动预览，不发送音乐消息。空白工程不包含作品声音源或完整 PNDS Template 功能；生成基本结构不要求创作者先安装 sclang。
- **空白文档**：初始 README 使用当前 App 语言，另一语言翻译作为交接任务。提供面向外部 agent 的契约与交接入口，继续沿用平台标准的 README 和工程格式，不建立新的工程模板协议。
- **文件工作区**：侧栏分类帮助识别文件职责，实际路径不改动。主区依次为当前选中文件、控制台两个标签；为 v1.7 的第三个助手标签保留布局接入点，本版不出现未实现助手。文件切换保留每个已打开文件的草稿，显示未保存状态；阅读、简单文本编辑、查找和原型保留的重命名能力限定在当前可编辑工程内。
- **精简编辑边界**：工程文件栏只有一个打开工程文件夹的 Finder 按钮，没有任意新建文件／文件夹、导入素材和删除文件控件。标准模块分类中的文件添加是明确的窄例外，不扩展为通用文件创建或素材导入。文件树不展示固定 Skills 安装入口或类别说明区；已有模块文件继续分类和阅读。完整代码实现、接线、文件组织和素材处理由外部编程 agent／Finder 完成。
- **标准模块添加**：模块分类标题提供选择与添加入口，首批为 QR 加入、客户端连接与身份恢复、monitor 主题跟随、monitor 语言跟随、monitor 多窗口视图状态同步。随 App 固定版本提供真实模块源码、必要配套文件、用途、前置条件与接线说明；一个模块可以包含多个文件。添加仅复制文件、记录模块来源与源码版本，并生成外部 agent 接线及验证任务，不自动修改页面、服务器、manifest 或艺术映射，不运行 npm、安装依赖或安装 Skills。
- **模块结果与冲突**：已加入文件归工程所有，可以由作者或外部 agent 修改。来源记录随源工程保留，创作交接说明实际加入文件和剩余接线工作；文件已加入、接线完成和实际验证分别表达。重复添加提示已存在，目标文件冲突时停止并说明，不覆盖作者已有实现；升级、合并和移除交给外部 agent。多文件与记录写入失败不能显示完整成功，保留原有内容并说明实际结果，重试不得重复任务。工程范围、只读来源和磁盘版本保护继续适用，文件树更新不自动重启工程。
- **文件访问与写入**：复用类型安全命令边界，扩展为受工程根约束的目录清单、限量读取、文件版本、保存、重命名和 Finder 定位；规范化后仍限制在工程根内，拒绝路径逃逸和经符号链接读取或写入工程外文件。文件保存使用原子写入并检查读取时的磁盘版本，不能仅依赖 watcher 通知。越界、无法读取、文件消失、体积超限与无写入权限分别给出可理解的反馈。
- **外部修改冲突**：无草稿的文件可按外部磁盘变化重新读取；有草稿时保留内存内容并标明冲突，保存时要求重新读取或明确确认覆盖。确认覆盖仍针对同一工程、同一文件和已展示的磁盘版本；磁盘再次变化需重新确认。重命名不得覆盖现有目标，不自动修正源码引用，给出引用可能需要外部 agent 调整的提示。
- **manifest 表单**：覆盖定稿原型中的工程身份、允许／默认音频模式、输出与 bus、SynthDef 引用、服务器入口／工作目录／端口和可选网络声明。未识别字段原样保留；表单与文本必须使用同一个磁盘文件版本。保存验证可编辑声明的基本格式和约束，允许先保存尚未生成的合法 SynthDef 引用以便后续编译；不能把缺产物当成无法保存的循环依赖。启动对保存版本执行现有完整加载和 preflight，打包执行既有静态可打包校验；保存成功不代表工程已经可运行或可打包。采样率和设备继续由 App 全局音频设置控制。
- **README 编辑**：复用现有 README 语言回落、封面元数据与简介展示。仅对可安全解析的封面字段和首节内容提供可视编辑，保留封面外段落与未识别内容；不安全格式只读预览并解释原因。保存另一语言的更新作为交接任务，不在本版调用翻译模型。普通 README 仍按文本文档显示，允许轻量文本编辑；链接继续遵守现有外部打开与防主窗口导航规则。
- **素材查看**：图片按需预览，首版为 PNG、JPEG、WebP、GIF，读取有体积边界且解码失败可回到文件信息。音频只显示文件名、格式和大小并定位 Finder 中的该文件。其他二进制显示基本信息和 Finder 入口。App 不解码、试听、重采样或路由音频素材，不新增素材播放器依赖。
- **磁盘与运行版本**：草稿、已保存磁盘内容、当前运行内容分别显示。源码／音频声明／产物变化标记待重启，页面变化标记待刷新；这只是行动提示，不能声称运行时自动采用新版本。保存、外部 watcher、编译都不自动刷新或重启。已有自动进程监督和 health 行为继续依契约工作。
- **手动更新动作**：保存只写当前文件。页面刷新从磁盘重新加载 monitor 和已打开的 performer 测试页面，并复用现有导航缓存 nonce 和揭示门控；不重启 Node/scsynth。工程重启沿用共享 session 工作流，使用保存后的工程及待应用测试配置，保留选中工程；启动失败进入现有错误与重试路径。未保存草稿不进入任一运行版本，动作提示应说明这一点。
- **monitor**：工作台持续显示真实工程 monitor，顶栏含「创作模式」、地址与展开入口。展开临时隐藏侧栏、编辑和窗口列表；点击还原或 Esc 恢复。展开／还原只改变布局，不重载页面、不终止运行、不关闭测试窗口。保持工程页面现有 resize 与输入归属契约。
- **performer 测试窗口**：创建多个独立原生窗口，每个承载真实 performer 页面并具备独立客户端生命周期。设备外框提供手机／平板及横／竖向尺寸模拟，不伪造手机浏览器能力。主工作台列表显示编号、方向、已知连接状态、聚焦与关闭操作；关闭一个只影响它自己。测试窗口不是投影窗口，不沿用投影的单实例约束。
- **页面与 Host 边界**：演奏消息直接在 performer、工程服务器和音频目标之间流动，不通过 Rust／React 转发。App 的窗口壳只管理尺寸、导航、生命周期和连接显示；无法从现有公开契约获知的页面内状态不杜撰成真实连接状态。需要握手时只增加窄的 Host 生命周期能力，不要求既有工程重写消息协议；未适配工程仍可直接测试。
- **窗口清理与重启**：关闭工程、离开创作和切换工程时关闭旧 performer 测试窗口。测试重启可保留同一工程的测试窗口壳并重新连接新运行地址，旧导航／连接事件不能更新新运行。实际退出沿用所有子进程和窗口清理；普通主窗口隐藏不等同于结束工程。
- **测试音频**：实时测试标题旁选择 Internal／External／None，只显示保存后的工程声明支持的选项。External 使用 App 自己的测试 OSC 目标，不使用 standaloneTarget；目标按既有格式校验和本机偏好规则处理。修改选择只产生待应用状态，手动重启后才替换已应用配置，不改写默认音频模式。接续演出时以已运行配置初始化测试事实。
- **控制台**：第二个标签集中展示既有工程运行日志与编译结果，保留来源、错误和可复制详情。日志从现有日志服务获取，不在工程内另建运行日志，不新增常驻技术状态面板。控制台切换保留文件草稿，操作错误能进入或定位控制台。
- **SCD 编译**：把现有编译功能移到 SCD 文件工具栏，面向当前工程的标准源码集合，不是只编译当前单一文件。相关 SCD 或 manifest 有未保存草稿时禁止编译；运行中显示忙碌并防重复提交。沿用本机 SuperCollider 的 sclang 查找、执行超时与 SynthDef 注册／产物写入规则，App 不新增随包 sclang。
- **编译输出**：结果进入控制台，列出使用的编译器、产生的产物、全部 manifest 引用核对结果和可读错误。所有声明引用均验证，不因当前测试音频模式跳过。成功后更新文件树并标记待重启；失败不得标为验证通过，也不自动重新启动或替换运行版本。
- **工程包生成**：工作台提供生成 `.pnds`，使用原生保存对话框选择输出位置，默认名称继续沿用当前打包契约，并确认覆盖同名产物。前置条件仍为完整 manifest、必需文件、生产依赖和声明的已编译产物，复用既有静态可打包校验；不能借用带进程清理或启动副作用的运行 preflight。不执行 npm、不联网、不自动编译、不改变源工程或当前演出。未保存草稿明确不入包。无成功测试记录时提示建议，允许确认后继续；运行测试不是硬门槛。
- **打包兼容性**：保持现有容器布局、路径校验、权限、排除、元数据、原子写入与 sha256 输出。README 和演出资产随包，创作交接单、测试资料和 App 本机状态不随包。输出路径参数扩展现有打包命令，不另建第二种打包器。内容变更升工程 version 的契约保持有效。
- **创作交接单**：记录任务意图、涉及文件、验收条件与状态，供外部 agent 接续。可由 README 翻译和明确的手动待办产生；App 不自行完成代码任务或声称外部 agent 已完成。交接写入复用同一工程范围、版本冲突与原子保存边界。新建工程和既有 Template 的 agent 入口指向交接单和平台契约；标准模块添加生成接线与技术验证任务，保留已有任务和外部 agent 更新；Skills 重构与模块接口、文档、兼容整理归 v1.6.1。
- **网络与节点**：设置保留已有全局本地网络、节点名、hub 地址与 token；房间仍按工程与分组规则形成。修改按既有下次启动生效语义提示。token 保持遮罩，不进入状态转储、日志或 URL。网络配置和工程音频模式相互独立，不为创作另建一套节点配置。
- **Ports 调试**：恢复既有设置页，显示目标工程 manifest 的 performer／monitor 端口，无选择时采用既有默认端口。进入查询一次和手动刷新，不后台轮询。区分可用、外部进程占用和 App 当前运行；运行端口显示所属工程并要求先关闭工程，不提供直接释放。目标查询以所选工程为准，运行占用归属以真实运行工程的已应用端口和子进程身份为准；运行 A 而选择 B 时，不能把 B 的不同端口误标成 A 正在运行。
- **端口释放身份**：外部占用显示 PID、名称、完整命令行，释放必须确认此身份。现有释放命令扩展为携带已确认身份并在终止前重新核对；身份变化、占用消失或已成为本 App 运行进程时取消释放并刷新状态，不能仅按端口终止后来占用的另一进程。后端根据真实受管子进程身份再执行保护，不能只相信 UI 对端口的判断。真实终止沿用现有有界优雅退出与强制退出策略。
- **技术与文案**：继续使用 Tauri v2、React、TypeScript 与现有 Zustand／偏好架构。组件按 selector 订阅，事件动作取最新状态，类型安全命令桥承载原生能力。文案进入全部已支持 locale，中文术语遵守领域词汇表；布局使用逻辑方向属性。有限新业务逻辑集中在模式／创作工程工作流与受工程范围约束的文件服务，避免在各组件重复启动、保存或关停规则。

## Testing Decisions

用户已确认测试边界：v1.6 主要复用 AppShell 与演出工作流，验证模式接续、保存冲突和测试窗口；真实文件与进程在 Rust 临时目录／受控进程边界验证。

- **优先最高已有接缝**：主验收接缝是用户动作驱动的 App 工作流与类型安全 Tauri 命令，延伸既有 session-flow、open-project 和 AppShell 测试做法。断言实际页面、运行身份、命令参数／次数、磁盘结果和窗口生命周期，不断言私有函数拆分、内部 CSS 类或与实现逐句镜像的状态细节。
- **模式与运行矩阵**：覆盖启动空闲；可编辑运行工程接续而无 stop／start／monitor 导航或重挂；已选未运行工程接续而无 start；运行 A 且选中 B 时仍接续 A 的已应用配置和 Monitor 世代并关闭投影；安装后已经是目录的只读工程包仍进入创作首页；创作返回演出执行清理且不 autoload；启动／关停中拒绝提交；取消与双提交；停留指针不立即反向悬浮。用现有 session 快照和命令 mock 表达真实生命周期。
- **按钮和演出回归**：React Testing Library 从可访问名称、键盘动作和可见后果验证两次确认与取消。沿用 Sidebar 键盘／选中与运行分离测试，验证侧栏帮助入口移除、单一演出动作、侧栏显隐不导航 monitor、下拉操作保持侧栏和现有加载／错误／Retry 行为。固定角度、过渡和主题风格由真实 macOS 视觉验收，不把 jsdom 几何当成可见效果证据。
- **工程索引与偏好**：延伸 project-store 与 preferences 的在内存磁盘上加载／修改／保存测试，验证超过三个用户文件夹、现有数据迁移无截断、成员独立、工具保护、返回先前文件夹、索引结构提交持久化和并发偏好更新不覆盖其他字段。视图切换不得触发启动、停止或应用测试设置。
- **新建与切换工程**：通过工作流命令 mock 和 Rust 临时目录测试覆盖原生选择取消、表单取消、未保存确认取消、成功创建、目标已存在、权限错误、部分失败和旧异步返回。对空白产物执行真实 manifest／结构校验；检查无生产依赖、三模式声明、源码与占位产物一致、语言 README 和交接入口。
- **文件与冲突**：Rust 临时工程目录经过公开文件操作边界验证读取、保存、重命名和 Finder 目标解析。覆盖范围外路径、工程外符号链接、失效可编辑身份、无效 UTF-8、超大内容、文件消失、不可写、外部修改、第二次版本变化和目标重名。前端从用户操作验证草稿保留、冲突选择、原子切换及迟到结果隔离。
- **文档和表单**：复用现有 project-readme／README 封面解析与渲染测试先例，以完整输入输出夹具验证封面外内容与未知字段保留、未识别格式只读、语言回落、双语交接任务和链接不导航主窗口。manifest 表单保存后以磁盘输出验证声明，再分别通过编译、完整加载／启动与静态打包接缝核对各自门槛，而不是只断言控件值变化。覆盖合法但产物缺失的引用可以保存、随后编译、产物存在后才可启动／打包，及打包不执行清理型运行 preflight。
- **更新与音频配置**：扩展 session-flow 已有重启参数捕获与并发门控测试，覆盖待应用与已应用配置分离、接续继承、External 目标、保存与 watcher 不自动启动、页面刷新只导航页面、重启采用保存版本且保持工程选择、失败 Retry 可用。检查现有私有 bus／master、设备通道能力、gain 和关停测试无回归。
- **原生窗口接缝**：参照 projection-window 与 help-window 的 WebviewWindow 替身测试窗口创建、聚焦、关闭和主题／语言桥；为多 performer 增加窗口管理接缝，覆盖独立编号／身份、单窗口关闭、全部清理、工程世代和迟到连接事件。monitor 展开／还原必须保持同一页面实例与运行，投影继续遵守单实例及简介门控。设备方向和真实触摸／键盘归属需 WKWebView 实测。
- **已有编译和 Ports 服务**：延伸 DeveloperSection／SettingsPanel 的命令驱动测试，将入口位置和未保存门控放在工作区验收。Rust 继续使用现有 SynthDef runner 的替身可执行文件验证产物、引用、缺 sclang、超时与失败；使用可控进程／端口测试验证已确认身份与释放目标一致、本 App 受管子进程保护和占用变更取消，避免结束真实无关进程。专门覆盖运行 A／选中 B 的查询端口与归属判定分离，以及绕过前端直接调用释放命令仍不能结束 A。
- **模块添加与交接**：在创作工作流与 Rust 临时目录文件服务验证五个实际发布模块的文件、来源记录、接线任务、重复添加、文件冲突、部分失败、外部版本变化、只读来源及越界拒绝。验证不改入口、不安装依赖或 Skills、不重启运行，复制结果不能冒充接线或运行验证。原型占位文件不是验收产物。
- **打包与交接**：沿用现有 bundle 临时目录与安装往返测试，增加选择输出位置、取消／覆盖、缺文件／依赖／产物阻止、无成功运行记录可继续、草稿不入包、交接排除、原工程不变、合法符号链接物化及路径逃逸拒绝。交接任务追加、冲突和取消在同一个文件写入接缝验证。
- **真实 macOS 验收**：在可运行的 App 中验证四种主题、减少动态效果、键盘与中英界面，演出全窗口 monitor、模式接续不重连、创作展开、多个 performer 与手机／平板方向、外部 agent 改文件及冲突、真实 Finder、真实 sclang 编译、Ports 查询／受控释放、保存对话框和工程包安装。空白工程与官方工程均完成 Internal／External／None 启动、重启、关闭、退出清理；发行产物按既有 Apple Silicon 与 Intel 干净环境门槛验收。
- **完成标准**：新增业务逻辑随改动带测试，运行 `npm run check:all` 全绿，完成所列真实环境验证并记录结果。开发服务器由用户启动和回报，实施阶段不绕过此约定。无关可逆样式不添加逐行镜像测试；在最高可观察接缝充分验证后停止重复测试。

- 外部 Skills 重构、首批五项之外的模块扩展及接口、文档、兼容整理归 v1.6.1；App 中的移植评估、代码实现、自动接线、模块升级与移除、Skills 安装服务不在本版范围。
- v1.7 的创作助手、模型 API、工程内容授权、AI 上下文与本机聊天记录。
- 完整 IDE、代码补全、调试器、Git 界面、App 内终端执行任意命令，以及自动 npm 安装。
- App 内任意新建／导入／删除工程文件（已明确的标准模块文件添加除外）、批量素材管理、原生音频试听、音频转换、自动声音路由。
- 从 `.pnds` 或内置工具自动复制可编辑工程；工程包和工具的编辑能力。
- 自动热刷新、自动重启、自动编译、AI 直接改写工程代码、自动判定作品完成度。
- 改变 manifest schema、数字乐谱高频消息协议、hub／房间体系、音频 bus／master 或 `.pnds` 容器格式。

- 原型比较用的 A／B／C 切换、演示状态、版本切换、模拟 API／编译／端口操作等实验控件。
