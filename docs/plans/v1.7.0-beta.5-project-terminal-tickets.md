## T1 / #353：验证 Ghostty 真实终端采用资格

### Parent

[#352](https://github.com/xO-xN/PNDS-App/issues/352)

### What to build

在现有 Tauri/WKWebView 宿主中，用真实 Rust PTY 驱动 Ghostty Web 终端，形成可以输入命令、观察输出、调整尺寸和显式结束的最小可验证入口。固定实际依赖与必要局部补丁，证明后续正式工作台可以复用同一终端 surface 和字节通道，无需再造第二套原型。

### Acceptance criteria

- [ ] 固定实际 wrapper/WASM 与相关上游版本，本地加载资源，形成真实 PTY → 有序字节流 → 显示与键盘输入的完整可运行链路；不是只渲染模拟输出或只提供后端命令。
- [ ] 在真实 WKWebView 验证中文 IME、复杂 Unicode、多行/bracketed paste、resize、alternate screen、必要查询、Ctrl-C/Ctrl-D 和目标 CLI TUI；不通过 CI 使用个人登录或付费 Agent。
- [ ] 以真实进程及确定性 fixture 验证双向字节、分片、退出/EOF、实际受管作业结束和重复释放；覆盖复杂 emoji、不同列宽和滚动历史后反复创建/销毁的已知故障情形。
- [ ] 隐藏时保留会话并控制无条件绘制；输出队列和历史有界。证明新会话颜色初始化具备可行路径，含纯黑等已知边界；不实现完整实时换肤或全主题产品映射。
- [ ] 记录当前架构的真实资源开销、生产 WASM/CSP 与双架构构建/验证结果，区分实测、上游报告及未验证项。后续工作台沿用已通过的链路及补丁，避免重复建设。
- [ ] 完成以可采用为前提的技术验收后才放行 T2。若关键问题无法通过局部修补解决，记录不采用原因并保持后续阻断，回到路线评估；不得以完成一次演示或关闭研究记录代替采用资格。
- [ ] 自身实现/验证代码通过适用测试和仓库完整检查，不增加 Node/Bun/HTTP/WS 服务、独立 WebView 或通用 renderer 重写工程。

### Blocked by

无，当前可领取；本轮仅发布规划，未领取实施。

## T2 / #354：在当前工程使用唯一终端

### Parent

[#352](https://github.com/xO-xN/PNDS-App/issues/352)

### What to build

创作者从助手、版本历史所在区域打开当前可编辑工程的唯一真实终端，使用普通 shell 或自行启动的 CLI，并在文件、讨论和历史之间切换。新会话匹配 PNDS 当前主题，能够可靠输入、观察输出和显式结束。

### Acceptance criteria

- [ ] 首次显式打开才加载终端资源并从当前真实工程目录创建会话；正确处理中文/空格路径及 Finder 启动后的 shell 环境。重复打开复用同一会话，不给只读内容、演出或合并候选开放实际工程终端。
- [ ] 与创作助手、版本历史同区切换，不新增底部面板、分屏或 Shell/Agent 双标签。切视图与隐藏窗口保留同一会话，隐藏绘制沿用已验证的受控行为。
- [ ] 普通命令与本机 CLI 可运行，输入、复制粘贴、选区、尺寸调整、滚动和作业控制可用；焦点与 App 快捷键归属正确，不重新设计全局快捷键。
- [ ] 新会话按四套 PNDS 主题初始化默认色、光标、选区及标准 16 色，保持颜色含义与可读性；其他显式扩展色/RGB 保留。切 App 主题不会重启现有终端，完整热换色仍后置。
- [ ] 启动失败、通道错误、EOF 和退出如实反馈，允许用户显式结束和重新打开，不假报运行/结束，也不自动重启 CLI、安装工具或读取凭据。
- [ ] 会话操作具有实际工程与会话归属，过期/迟到数据不会污染替换后的上下文。为后续两票复用真实的打开/聚焦、显式结束与必要状态边界，不先造空壳任务管理接口。
- [ ] CLI 写盘沿用现有 watcher：干净文件采用保存版，脏草稿保留冲突；不自动刷新、编译、检查、保存工程版本或上传。以工作台公开流程及真实 PTY 补测验证，不新增 Work journal、锁定或完成状态。
- [ ] 该切片自身行为测试及完整检查通过；跨工程/版本/模式离开保护由 T3 完成，尚未形成父规格的完整可发布功能。

### Blocked by

[#353](https://github.com/xO-xN/PNDS-App/issues/353)：必须先取得真实宿主中的可采用终端链路。

## T3 / #355：离开工程前正确结束终端

### Parent

[#352](https://github.com/xO-xN/PNDS-App/issues/352)

### What to build

创作者切换工程、替换工程版本、进入合并候选、离开创作或退出 App 时，可以选择结束当前终端再继续，或取消并留在原工作区。结束失败时保留原状态，避免旧工程命令被界面切换掩盖。

### Acceptance criteria

- [ ] 覆盖切工程、替换版本、进入候选、离开创作和退出 App 的真实入口；有活跃会话提供结束并继续/取消，无活跃会话沿用原流程。
- [ ] 取消不结束会话、不切换目标、不丢草稿；结束失败如实报告并阻断原操作，成功确认结束后才继续。现有运行、草稿和版本预览/确认保护不被绕过。
- [ ] 红色关闭按钮继续隐藏窗口并保留会话，切主工作区标签不触发结束，不把现有关闭快捷键重新定义为终端结束。
- [ ] 终端的实际受管 shell/作业清理有界且归属正确，不以 leader 退出冒充作业已清理，不误杀演出，也不承诺结束用户主动脱离托管的任意进程。
- [ ] 成功结束后磁盘修改仍保留，候选期间无指向实际工程的终端；重开 App 不自动重启 CLI，迟到输出不会进入新的工程或会话。
- [ ] 通过工作台可观察操作、失败注入及真实进程测试覆盖取消/失败/成功分支，并通过完整检查。T3 不要求任务记录、编辑权锁、后台多工程或恢复调度。

### Blocked by

[#354](https://github.com/xO-xN/PNDS-App/issues/354)：需要实际工作台会话和明确的打开/结束/状态操作。

## T4 / #356：将当前方案交给终端 Agent

### Parent

[#352](https://github.com/xO-xN/PNDS-App/issues/352)

### What to build

创作者从已确认的 grilling 方案卡选择「交给终端 Agent」，得到仅针对本次方案的静态任务文件和已复制短提示，并进入当前唯一终端。用户在已有 CLI 就绪后自行提交；也可保存并显式调用一个常用启动命令。

### Acceptance criteria

- [ ] 第三个动作只使用当前选定的公开方案与已答决策，生成静态任务文件、复制短提示并打开/聚焦同一终端；不额外调用模型摘要或重新设计，不误带旧交接任务。
- [ ] 内容包含方案范围、验收、工程保存版位置、实际装机文档和现有检查 CLI 用法，不假设命令已在 PATH。可选概况快照标明导出时间，不建立在线 App 查询前置。
- [ ] 不默认导出其他聊天、未保存草稿、未选素材或秘密，不自动保存或丢弃文件。静态文件采用可供本机 CLI 读取的私有落点，核对版本/共享上传/打包排除并保持本次交接可读，不增加任务档案系统。
- [ ] 已有 CLI 不重启、不被自动输入，登录/审批/对话中的时机由用户掌握；路径及短提示通过复制或结构化参数处理，不拼接方案正文为 shell 命令。新 CLI 自动传参不是本票最小验收前置。
- [ ] 可选保存一个常用启动命令并显式调用，沿用偏好机制；其他 CLI 可直接手动运行。没有配置库、登录状态探测、全局 Agent 配置改写或逐家执行器。
- [ ] 既有外部提示词继续承接整份创作交接单，内置「工作」入口继续原有语义。CLI 保存与人工审阅复用既有 watcher、草稿冲突、版本差异与检查，不产生终端任务完成记录。
- [ ] 通过工作台真实方案卡 → 私有文件/剪贴板边界 → 实际终端流程验证准确交接、复制/生成失败、已有 CLI 和草稿保护，并通过完整检查。完整产品交付仍需 T3 离开保护及 T5 联合验收。

### Blocked by

[#354](https://github.com/xO-xN/PNDS-App/issues/354)：需要能实际打开、复用和聚焦的唯一工程终端。T3 的离开流程不阻塞该切片的开发，但两者都必须完成后才能进行联合验收。

## T5 / #357：联合验收真实 CLI 与双架构

### Parent

[#352](https://github.com/xO-xN/PNDS-App/issues/352)

### What to build

使用真实 macOS 发布构建与用户已有 Codex、Claude Code，完成「讨论方案 → 静态交接 → 终端修改 → 文件回流 → 版本审阅/检查/编译/试听 → 正确离开」的完整用户流程，给出 beta.5 可交付证据。

### Acceptance criteria

- [ ] 前序各票已完成自己的业务测试和验收，不把已知输入、清理、主题或交接缺陷推到本票兜底。联合验证完整父规格的 14 组场景及失败保护。
- [ ] 在真实 Codex/Claude Code 中验证 TUI、登录/审批、交接提交及文件修改；CI 仍使用确定性 fixture，不要求个人账号或付费调用，也不建立 Agent 专用适配。
- [ ] 在 arm64/x86_64 发布构建核对本地 WASM/CSP、资源与许可分发、真实输入与重复开关；分别记录构建通过、自动测试、真实宿主验收与未验证项，不以跨架构编译代替运行证据。
- [ ] 对比记录包增量、首次打开、空闲/隐藏 CPU/RSS、高输出输入延迟和有限历史表现；与现有音频/monitor 同时使用时检查稳定性，不宣称未经比较的绝对最轻。
- [ ] 文件保存、实际运行版、Agent 自述及人工验收结果分别表达；CLI 不自动获得 Work 撤销或并发写保护，未实现的后置能力不回流为补做要求。
- [ ] 仓库完整检查全绿，开发文档记录实际形成的接入模式与真实限制；本票只证明交付资格，不自动 commit、发布 App 或操作用户作品。

[#355](https://github.com/xO-xN/PNDS-App/issues/355)、[#356](https://github.com/xO-xN/PNDS-App/issues/356)。T1/T2 已由传递依赖覆盖，不重复增加冗余阻断边。
