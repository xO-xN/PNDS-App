# v1.6.0–v1.7.0：创作基础设施与有限助手

状态：用户已确认的总体发布规格，实施与发行证据分别维护。

GitHub Issue：[190](https://github.com/xO-xN/PNDS-App/issues/190)，标签 `ready-for-agent`。

## Problem Statement

当前创作模式实现只到 #158，后续功能尚未闭合，部分实际 UI 与原型存在差异。创作者希望先完成可靠的创作工作台，再建立共享依赖、工程起点、版本感知和可重复验证，最后让内置助手使用这些能力。把所有候选功能或复杂 agent 任务塞进首版会增加维护和等待，规格与 Issue 的旧只读边界也已不符合新目标。

## Solution

按有限、可验收的版本接续：v1.6.0 完成原功能并末期手动调整 UI/UX；v1.6.1 整理模块和外部 Skills；v1.6.2 提供单一较新共享库并保证三个作品发行时可运行；v1.6.3 提供 Blank／Classic、只读 Git 与上下选卡；v1.6.4 静态诊断；v1.6.5 确定性临时副本检查和单文件恢复；前序全部验收后正式开发 v1.7.0 助手。

助手一次按钮执行只改一个已有文本文件，检查另按按钮，失败后由用户决定；复杂任务先询问，再写交接与复制说明。模型负责理解和方案，App／CLI 负责程序性检查，外部 agent 处理广泛开发，创作者负责真实演奏和艺术判断。

## Implementation Decisions

- 保留 v1.6.0、v1.6.1 原业务范围并修订末期 UI 与后续助手边界；#150–#158 按代码与验收证据维护，不根据 OPEN 或规划确认重做／关闭。
- 版本分工为创作闭合、模块／Skills、共享库、起点／Git／导航、静态诊断、受控检查／恢复、有限助手。各项细节由版本规格承接，避免在父规格复制所有接口。
- 共享库每项一个尽量新的固定发行版本，模型属于工程；正式采用写回工程引用与版本。三作品真实可运行是 v1.6.2 硬门槛。
- 模板复用 Blank，并加入干净 Classic；只读 Git 不增加提交／分支／远程操作。导航只有演出主窗 Cmd+Opt+上下，不自动加载，独立窗口与创作不作用后台选择。
- 静态与运行检查以高层确定性服务复用现有契约和运行／文件 primitives，UI、CLI 与助手都是入口，不各建一套实现。
- 副本检查 None 默认、Internal 显式、External 首版手动；活动运行含启动／关停时拒绝新检查，不自动 Stop。版本证据以实际副本与依赖为依据。
- 助手一次执行只写一个已有文本，编译产物与报告属于独立检查。新建／删除／重命名／跨文件先确认外部交接；失败不自动修复。
- v1.6.0–v1.6.5 各自范围与验收全部完成后正式开发 v1.7.0，方案研究可提前。公开文档、技术依赖与用户自愿安装 Skills 是不同概念。
- 不设未经讨论的发布日期。保持 npm、双架构、i18n、状态与受信命令模式，新业务带测试；用户启动 App 开发服务器，不自动 commit 或发 App 发行包。

## Testing Decisions

- 测试接缝已经在此次讨论确认：最高层是工程用户工作流与类型安全命令，App／CLI 共用诊断／验证服务；模型替身用于助手请求编排，真实文件与进程用于边界。
- prior art 包括 AppShell、工程打开与 session-flow、manifest／bundle、Rust 临时目录原子读写、真实 Node／HTTP、音频与有界关停测试；先延伸既有接缝，必要新接缝位于完整诊断或验证任务。
- 好测试断言实际工程、文件内容、来源、报告、运行身份、取消和清理；不镜像实现、断言组件结构或让原型回复冒充真实能力。
- UI／原生键位、双触点、作品画面、声音、Finder、凭据及双架构发行在真实环境验证，自动报告准确保留未验证部分。
- 三作品 v1.6.2 使用当时已有工具验收，不制造等待 v1.6.5 的循环依赖。v1.7.0 依托先前验证过的副本服务，外部 agent 可先调用 CLI。
- 实施完成需要 `npm run check:all` 全绿及所属发行验收；规格发布、标签和任务创建不构成完成证据。

## Out of Scope

- 此次规格发布直接实现新功能、迁移作品、启动开发服务器、commit 或发布 App。
- 多人自动场景、交互录放、OSC 观测、自动音频分析、通用 agent 引擎及完整 GitHub 协作作为 v1.7.0 前置。
- 模型共享、多旧共享版本、动态 latest、任意 shell、自动安装、后台连续修复及艺术完成度判断。
