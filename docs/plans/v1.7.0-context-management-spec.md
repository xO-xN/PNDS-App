## 当前问题与术语

现有代码有 8 次文档工具、24,000 返回字符、128 KiB 消息及 120 秒请求保护；最近修复仅增加模型可见的剩余预算与固定字段诊断。尚未按模型 token 容量管理长对话。已完成的平台聊天文字不断进入新请求；同一问题的工具结果累积回传，旧工具原文不会自动跨问题保留。本机帮助加载／缓存不等于已发送整套语料。

- **模型上下文容量**：具体服务／模型可处理的窗口，区分可靠能力信息和手填未确认值。
- **有效输入预算**：模型容量扣除输出／推理预留及安全余量，再受 App 使用目标约束；字节、工具次数与返回量安全上限仍独立有效。
- **预计占用与实测用量**：发送前按真实组装结果估算，服务端 usage 返回后校对；缺少计量能力或统计时明确未知，不用固定字符比例冒充精确 token。
- **单次调用与整轮问答**：窗口占用属于当前一次模型调用；一个问题多次调用的累计输入／输出消耗另列，不能当作上下文占用百分比。
- **完整历史与发送上下文**：完整记录保留在本机；近期轮次、摘要和新话题边界决定本次发送范围，整理不等于删除记录或恢复旧授权。

## #232：配置模型容量并统一上下文预算

当前助手仅按消息字节和工具返回量保护请求，无法按具体模型的 token 容量安排历史、资料及输出。增加按模型服务与模型标识隔离的容量配置和统一请求预算，作为上下文显示、长对话与受限读取的共同基础。

- [ ] 设置提供上下文容量、最大输出／预留输出及可用输入预算，明确模型能力、App 目标和独立的字节／工具安全上限。配置只能限制 App 使用量，不能扩大服务端模型能力。推理模型按能力为推理与可见输出留空间。
- [ ] 按规范化服务地址与模型标识隔离配置；有可靠来源的能力标明来源／版本，未知能力允许手填并标明未核验，不根据模型名字猜容量或显示虚假的精确百分比。
- [ ] 非敏感配置复用序列化 preferences；已有 #165 配置可兼容加载。非法、相互矛盾或输出预留不小于容量等值拒绝并保留可修正输入，不影响原密钥保存与本地编辑／测试。
- [ ] 统一预算组装／测量入口计算真实将发送的消息、系统策略、工具定义、当次资料与消费者内容；按模型 tokenizer／受支持计量能力估算，能力缺失明确估算或未知。字符、UTF-8 字节、token 分别计量，不把 128 KiB 当作 128k tokens。
- [ ] 发请求前及工具循环中检查有效输入预算与输出预留，并保留独立的字节、工具次数、返回量及总时限保护。明确是哪类上限，保留输入和已产生内容，不静默丢弃来源或自动收费重试；不靠将各上限无限调大规避问题。
- [ ] 容量／服务／模型变更使旧配置快照和用量失效，取消与迟到回调遵守 #166 所有权；不做填满上下文的收费能力探测，不自动扫描服务或读取工程。
- [ ] 以不同容量、未知能力、中文／英文／代码、长工具定义和预算边界的受控服务验证实际请求范围；新业务逻辑有测试，中英文、四主题、键盘及错误反馈完整，npm run check:all 全绿。App/dev server 由用户启动。

## #233：显示上下文用量并保留模型 usage 统计

聊天输入区显示实际将发送的上下文占用，并随文档工具循环更新。将发送前估算、服务端实测、当前调用占用与整轮累计消耗分开，使创作者能判断历史、资料和输出预留是否接近容量。

- [ ] 输入区显示本次／下一次调用的预计输入、有效容量及输出预留，读资料时动态更新。容量未知或手填未确认时标明状态；缺少可信分母不伪造百分比，不把字符或字节当精确 token。
- [ ] 展开查看系统策略与工具定义、已选历史、本次输入、资料结果的占用；为工程概况／片段／附件提供同一受限消费者契约，未接通或无授权内容不显示为已发送。
- [ ] 计量来自 #232 的同一请求组装结果。显示范围与真实载荷一致，提供来源明确的估算值，不能只数输入框文字或显示全部本机聊天／整套本机文档大小。
- [ ] Rust 保留服务端返回的 usage 并通过类型安全桥带到当前请求／轮次；支持已支持传输的流式末尾统计及普通 JSON。缺失、取消、断流或不支持的统计标明未知／不完整，不记作零，不为补统计自动重发模型请求。
- [ ] 分开显示单次模型调用上下文占用与一个用户问题中多次调用的累计输入／输出消耗；缓存、推理等细项仅按服务实际返回且含义明确时展示，不能相加成虚假的上下文百分比或推算未经确认的费用。
- [ ] 使用 #167 扩展／迁移本机记录所需的用量元数据，历史实测不冒充当前请求估算；不保存密钥、内部请求令牌或完整认证载荷。切换工程／服务／模型及停止后的旧统计不能污染新用量。
- [ ] 受控兼容服务验证已知／未知容量、中文／代码、工具累积、usage 缺失与流式尾块、停止／迟到、模型切换及历史恢复；中英文、键盘、四主题和最小窗口可读，不抢焦点。新增逻辑带测试，npm run check:all 全绿，App/dev server 由用户启动。

## #234：管理长对话上下文并保留完整本机历史

长对话目前会把所有可发送的已完成聊天文字不断加入请求，达到上限后只能报错。分开保存完整本机记录和实际发送上下文，提供近期对话、可核对摘要及新话题边界，使长对话可继续且保留原始证据。

- [ ] 完整聊天按 #167 原有实际目录身份独立保存；本次发送使用近期完整轮次和可追溯摘要。旧消息未进入本次请求时明确提示，不静默删除或把被排除内容说成仍在模型上下文。
- [ ] 接近 #232 的有效预算时提供整理上下文／新话题入口，显示整理范围、预计占用与可能遗漏。整理需要的模型调用由用户明确发起，说明会调用当前服务；不后台收费压缩、不隐藏自动重试或先丢原文再尝试生成摘要。
- [ ] 摘要区分用户决定、助手建议、已验证／未验证事实与待解决问题，保留原消息／来源定位。用户可核对、取消或重做；整理失败保留原记录和输入，超长单条／附件不能偷偷截断后声称完整保留。
- [ ] 新话题仅建立当次发送上下文边界，清楚说明旧记录仍在本机；不清空工程文件、草稿或其他工程聊天。清理整个历史仍走 #167 的明确确认与原子保存语义。
- [ ] 摘要和新话题边界持久化有版本迁移／损坏拒绝与恢复路径；重启可辨认来源，不重放旧请求或恢复旧发送、应用、预演授权。历史成功与旧工程事实保持历史含义。
- [ ] 摘要不升级为系统指令，不用资料中的指示扩大权限。摘要／选入历史继续按当前工程、模型服务、授权和读取范围过滤；工程读取关闭后不能通过摘要、引用或历史附件重新送出旧工程资料。基础阶段用受控消费者覆盖，#168／#225 做真实载荷补验。
- [ ] 停止整理、切换工程／服务／模型或清理时拒绝旧摘要和迟到回调。近期轮次及工具调用／结果保持协议完整，计量与 #233 用量显示一致，不把累计花费当当前窗口占用。
- [ ] 最高请求入口和真实临时存储验证多轮中英文／代码、超长轮次、整理取消与失败、新话题、重启、迁移、目录隔离和关闭读取过滤；原生键盘、焦点、四主题与最小窗口待实机，新增逻辑带测试，npm run check:all 全绿。App/dev server 由用户启动。

## #235：优化本机文档检索与分段读取的上下文占用

当前按小节读取一次可返回 6,000 字符，少数长小节就可能占满 24,000 字符的资料预算；多步模型调用还会重复携带前面的结果。优化现有本机帮助检索和分段读取，以较短相关片段、按需展开和去重降低单次占用与累计消耗。

- [ ] 复用装机帮助 allowlist、现有分节／纯函数搜索和来源导航；不另建在线契约副本或要求 LLM 阅读子代理。语言、文档版本、ID 与 help 资源路径遵守 ADR-0001／0003，不改已分发工程依赖的装机链接。
- [ ] 根据相关性优先返回短摘要／短片段，读取提供有硬上限的页长和明确 offset、total、nextOffset；可继续展开，未读取范围清楚可见。不能静默裁断后声称读完一节或整本文档。
- [ ] 同一请求的相同版本、语言、文档、小节和范围可识别复用与去重，避免无进展重查；缓存的本机复用与进入模型上下文分别计量。缓存命中不宣称 token 占用为零，不重发不必要的重叠原文，也不破坏工具调用／结果配对协议。
- [ ] 仅实际返回的片段构成查阅证据，保留版本、语言、小节和准确定位；资料不足就说明缺口。取消／失败保留已产生来源，不能把搜索命中列表当作全部文档已经读完。
- [ ] 文档／语言／装机版本变化使旧结果失效；服务／工程切换、停止及迟到结果继续受 #166 所有权保护。不跨版本复用内容，不把用户工程、认证数据或私人聊天加入公共检索缓存。
- [ ] 同一请求继续遵守 #232 的模型有效预算及独立工具次数、返回量、上下文字节和时限限制，#233 显示真实片段占用与多次调用消耗；不能只提高限制、强制模型固定回复或隐藏失败样本来完成验收。
- [ ] 固定可复验问题覆盖 outputChannels、internal／external／none 比较、缺失资料和多轮追问；记录实际发送片段、重复量、来源覆盖、输入 token 估算／实测及失败原因，在相同服务／模型与预算下比较改动前后。确定性测试验载荷与边界，真实模型质量另收证据，不要求固定句子。
- [ ] 新业务逻辑带测试，中英文、主题、键盘与展开／返回交互完整，npm run check:all 全绿；App/dev server 由用户启动。后续工程读取、概况、全工程与附件真实集成由消费票和 #172 补验。
