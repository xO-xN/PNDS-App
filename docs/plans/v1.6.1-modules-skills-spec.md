# v1.6.1：标准技术模块与外部 PNDS Skills

状态：用户已确认的发布规格，待实现。前版 v1.6.0 交付模块文件添加与首批五项，本版整理模块并重构外部 Skills。

GitHub Issue：[\#173](https://github.com/xO-xN/PNDS-App/issues/173)，标签 `ready-for-agent`。

## Problem Statement

创作者需要复用扫码加入、客户端身份与恢复、页面主题和语言跟随、monitor 状态同步以及跨现场连接等技术能力。现有 Template 与多个工程已经有这些代码，但接口、示例政策、版本、接线说明和来源记录尚未形成清楚的一套发布资料；复制某个工程的文件容易一并带入它的座位、声源、角色或同步规则。创作者需要的是能解决技术问题的模块，艺术内容仍由作者决定。

现有 PNDS 移植 Skills 主要面向 p5、SuperCollider 与 TouchOSC 三件套，并带有固定音频、拓扑和艺术取舍前提。创作者还需要从零创建、修改已有 PNDS 工程，以及先讨论任意来源工程成为 PNDS 版本的可能性。相关知识缺少可独立使用的基础能力，发布资源还依赖维护者电脑路径和未声明的兄弟工程。

App 应提供阅读、手动测试、确定性的模块文件添加与交接；外部编程 agent 实施代码。创作者还需要区分文件结构已就绪、已接线、实际运行已验证和可分发四种事实，避免被迫安装 Skills、重复打开工程或把初版可打开误认为作品已完成。

## Solution

以 v1.6.0 已批准的标准模块添加工作流为基线，整理首批 QR 加入、客户端连接与身份恢复、monitor 主题跟随、monitor 语言跟随、monitor 多窗口视图状态同步的技术接口、说明和版本兼容，并在 v1.6.1 增加可选的 hub 连接与远程节点状态模块。App 随版本固定提供离线源码和说明，复制到工程后记录来源并产生外部 agent 接线交接；源码由工程维护。已有连续控制过滤作为客户端模块的可选能力整理，不增加限频框架。

重构外部 PNDS Skills：统一创作入口覆盖新建、修改和移植评估，组合五项也可独立使用的基础能力——工程调查、作者讨论与可行性、运行契约适配、模块接入、验证／打包／交接。移植接受任意类型的来源工程，先形成评估与待决定事项，由作者确认实施方案；保留 pnds-cm1 课程入口及教学要求。

外部 agent 准备好必要文件和完整文件结构，能在创作模式打开后即可交回 App 继续。实际启动、声音和演出验证分别记录。普通工作默认交付可编辑源工程及决策、验证、交接记录，明确需要分发时再生成工程包；课程任务交付两者。Skills 自愿按需安装，App 助手只提示用途与步骤；App 不新增移植入口或安装执行能力。

## User Stories

1. As an 创作者, I want 按用途理解六个可复用模块条目, so that 我可以只选择当前工程确实需要的技术能力。
2. As an 创作者, I want 首批五项现有能力有稳定接口和同版本说明, so that 复制的代码与接线文档不会彼此脱节。
3. As an 创作者, I want 没有网络时仍能取得 App 随版本携带的模块源码和说明, so that 排练场的连接条件不会阻碍工程整理。
4. As an 创作者, I want 看清模块版本与适用条件, so that 我能判断当前工程和 App 是否具备必要协议与依赖。
5. As an 创作者, I want App 更新后已加入工程的模块源码保持原样, so that 自己和外部 agent 的改动不会被后台替换。
6. As an 创作者, I want 模块文件成为工程自己的源码, so that 我能阅读、修改、随工程打包并由外部 agent 持续维护。
7. As an 创作者, I want 模块说明分别列出源码、依赖和接线要求, so that 加入文件后仍知道下一步需要做什么。
8. As an 创作者, I want 已加入版本记录与待接线状态明确区分, so that 我不会把文件存在误认为功能已经运行。

11. As an 外部编程 agent, I want 每个模块说明明确输入、输出、事件、回调和生命周期, so that 我无需从某件作品反推出通用技术接口。

## Implementation Decisions

### 版本与技术模块

- **版本职责**：首批五项的 App 添加文件、版本记录与待接线入口归 v1.6.0 基线；v1.6.1 标准化其接口、说明与兼容信息，并新增可选 hub 模块。实现时以先前版本实际交付为依赖，不能把当前 Template 的文件存在视为 App 工作流已经完成。
- **模块单元**：一个模块可以包含配合运行的服务端与浏览器端文件，不以单个文件数定义模块数量。可复用技术接口要有明确用途、前置条件、输入输出、事件交付、生命周期和错误／未就绪行为。
- **工程源码归属**：加入后的源码归工程维护。模块可以修改并随工程分发；App 不作为运行时模块管理器，不自动替换模块内容或监控外部 agent 的实施进度。
- **离线分发与版本**：App 每次发行固定一套模块源码、对应说明及兼容信息；不从网络自动更新目录或模块。兼容信息分别解释模块版本、需要的 Host 协议、运行依赖和作品适配条件，不把 App 版本号当作已加入模块源码版本。
- **添加与接线分开**：文件加入和版本记录不代表依赖已安装、入口已引用、事件已接入或测试已通过。App 不修改工程入口、不运行 npm、不自动布线。记录与交接应明确保留尚需外部 agent 接入的事实。
- **冲突边界**：复用已有工程范围、磁盘版本检查与原子文件操作边界，拒绝覆盖已有目标和改变用户自定义模块文件。冲突交给外部 agent 合并；App 不提供强制模块覆盖、自动升级或自动删除。
- **外部 agent 职责**：确认依赖、完成服务端与页面接线、实施合并／移除／升级、验证作品行为；相关交接利用既有创作交接单工作流。模块说明不授权 App 自己运行这些步骤。
- **QR 加入**：模块接受工程解析后的完整 performer 地址；地址解析继续遵循已有运行契约。二维码输出、显示和生成选项可由作品接入；本版不实现 TLS 网关、证书或新的安全入场流程。
- **客户端连接与身份恢复**：稳定连接、加入确认／拒绝、重连、持久身份恢复、观察者连接与释放接口。事件名、载荷、身份／座位制度和声音恢复适配由工程提供或选择。Template 的独占座位和路由规则作为示例，不能变成所有作品的强制前提。
- **连续控制过滤**：仅整理客户端已存在的重复值与微小变化过滤，作为显式选择的能力；启用方式和阈值按工程提供。离散动作有独立发送路径，不因相同载荷而默认合并。本版不新建限频调度、队列合并或录制系统。
- **monitor 主题跟随**：保留既有 Host 主题消息、首帧信息、幂等应用和未知消息容错；提供 CSS 映射与自定义绘制回调，不固定作品的画面设计。作用范围为 monitor，performer 不自动采用。
- **monitor 语言跟随**：保留既有 Host 语言消息、首帧信息、语言解析、默认回退和回调；作品自行维护字符串表和显示内容。作用范围为 monitor，performer 不自动采用。
- **monitor 多窗口视图同步**：工程 server 保存工程声明的低频视图键，连接和重连取得当前快照，调整经 server 广播到各副本。未声明状态保持局部；状态生命周期止于工程 server 退出。该能力不等同于乐谱进度、音频状态、dataset、跨工程共享或跨演出持久化。
- **快照适用范围**：快照能力限于身份恢复与 monitor 同步需要的交付。本版不增加全工程状态恢复模块。hub 如需发起工程状态交付，由作品适配器提供并采用，模块不内置“更晚进度胜出”等政策。
- **可选 hub 模块**：工程的 score server 使用既有节点、hub、token 与 room 契约连接既有 hub；功能包括配置读取、连接／重连、状态通知、心跳、远端摘要过期清理、事件回调、回声过滤与释放。模块不增加 App 全局节点配置，不重写中央 hub 服务。
- **节点与乐手分开**：hub 在线对象是各远程工程运行节点，通常对应各现场 Mac；本地手机继续连接本现场的 performer 服务。工程可提供本地角色和乐手摘要，远程节点计数与远程乐手摘要条数必须有不同含义，不能沿用示例中座位数量冒充节点数。
- **hub 的作品适配**：事件名称、载荷、需要同步的内容、节点摘要结构、掉线演奏方式、远端快照采用、角色和声音分配由作品决定。模块的心跳与过期设置须可说明和按工程配置，不把某个作品的固定参数升级成公共契约。
- **hub 故障与清理**：连接不可达、鉴权失败、掉线和恢复提供可理解的状态；远程链不会等待后阻塞本地音乐控制链。停止后取消相应连接和计时器；技术层不承诺跨站一致性裁决或声音同步。
- **不固定音频制度**：身份不等于物理输出通道；一个客户端不必对应一个 voice，独占座位不是共同前提。既有 audio-engine、OSC 和输入防护继续依原有工程／Host 契约工作。
- **文档整理边界**：广义页面适配只增加必要用法说明；单一操作者认领暂缓，轻量诊断继续沿用既有工具，音频防护继续沿用现有基础设施。它们不扩展为本版额外可添加模块条目。
- **Skills 的关系**：Skills 由创作者自愿按需安装；模块文件、离线说明及外部 agent 交接不以已安装某项 Skill 为运行条件。具体 Skills 交付工作与提醒入口由总规格的 Skills 部分规定。

### 外部 Skills 与作者工作流

- **工作位置**：主入口及五项基础能力均在外部编程 agent 中运行。App 不提供新的调查、移植评估或代码实现入口。本版不增加由内置助手直接修改工程代码的能力。
- **技能组织**：建立覆盖新建、修改、移植评估的统一外部入口；基础能力分为调查、作者讨论与可行性、运行契约、模块接入、验证／打包／交接。五项能力均有可独立调用的任务说明，主入口按任务组合，避免将单一工作流的所有前置条件强加给独立调用。
- **一般移植模型**：以来源工程的实际材料与作者目标为起点，先形成事实、平台适配限制、候选路线和未决问题，再由作者确认实施方案。通用入口不要求三件套，不固定 Internal／External／None，不固定本地或遥现，不采用预设的声音、画面、互动优先级。
- **艺术决定归属**：声音、画面、互动和时间行为的必要改变必须与作者讨论。确认的改变与原因进入源工程记录；来源不足时保持未决，不能通过技术默认值隐式代替作者决定。
- **既有 Skill 演进**：现有遥现移植工作流中的可复用调查、契约、接入和验证知识进入新的能力组织；保留其适用于对应场景的指导，不将旧 Skill 的固定拓扑与取舍要求视为新通用规则。CM1 保留明确、可发现的教学入口，及其已定义的输入和输出基准。旧的独立 Skill ADR记录的是课程入口与旧遥现入口的组织理由，不构成新通用移植必须采用旧策略的要求。
- **交付阶段**：普通任务默认交付源工程和决策、验证、交接记录；明确分发时生成工程包。课程任务保持源工程与工程包同时交付。工程初版的最低交接条件是必要文件结构完整并能在创作模式打开；运行、声音和演出验收状态分别记录，不把能打开当作已通过演出验收。
- **模块协作**：App 提供标准模块文件、记录来源并生成接线交接；外部 agent 根据工程架构完成依赖检查、配置、接线和组合验证。Skills 对接既有模块提供与创作交接能力，不另造自动运行的模块安装器，不附带艺术内容或未经决定的平台能力。
- **安装与分发**：Skills 自愿、按需安装。App 可提示步骤和资源入口，实际安装由用户在外部环境完成。发布资源可以在其他创作机上发现与读取，不依赖维护者机器路径或未声明的本机兄弟工程。主入口所需的能力资料与辅助资源纳入可分发组织，独立使用时明确所需资源。
- **版本兼容**：运行契约与模块使用资料对应装机 App 的已发布能力；已有本地帮助语料优先和稳定资源接口继续适用。资料缺失或版本不匹配时说明限制并取得适配依据，不能默认为远程最新版能力已在本机可用。
- **环境声明**：以实际可用的 harness 和模型组合记录验证覆盖。zcode、Codex 或配置 DeepSeek 等模型的可用环境可以纳入验证；不强制通过预设 Codex／Claude 支持矩阵，不将“使用某个模型”误报为独立 harness 验证。

### 创作记录、评估与调用边界

- **来源记录与运行声明分工**：来源版本、实际加入文件及接线交接属于随源工程保留的创作记录，使用可演进的数据格式；不把模块来源或创作任务扩成新的 manifest 运行字段。既有来源不明的文件不能仅凭名称推定版本，App 添加不会成为模块升级器。
- **评估结果与阶段门槛**：任意工程均可调查，评估可以得出可行、有条件可行、需要进一步验证或暂不可行；不承诺任意工程都能完成转换。材料不全时说明实际已知与影响决策的缺口，不把缺少三件套直接当作拒绝通用评估的理由。纯评估可以交报告；进入实现的初版只要求必要文件与架构齐全、可在创作模式打开，不附加成功启动、声音或演出完成门槛。启动和打包仍按已有运行与资产契约校验。
- **调用与资料定位**：主入口组合基础能力而不是复制五套流程；独立能力有自己的用途、输入、产出和完成条件。环境具备相应 Skill 调用方式时使用它，其他可用环境按可发现的能力说明和资源继续工作并记录限制。解析器、案例、模块手册与平台适配资料作为支持资源，不因每个文件都存在而各造一个用户入口。
- **艺术保真基线**：默认保持原作声音、视觉、交互与演奏时间行为；技术语言、文件组织和传输方式可以按已确认方案适配。没有通用的声音高于互动或画面的排序，必要的艺术改变由作者决定并记录。新建任务同样先形成作者目标，技术模块不带入固定艺术内容。

## Testing Decisions

测试入口已由用户确认：App 模块添加沿用创作工作流及 Rust 临时目录文件服务，验证实际文件、来源记录、冲突和交接；模块通过接入参考工程验证连接／恢复／同步行为；Skills 在至少一个实际使用的外部 agent harness 中完成完整工作流程并记录覆盖范围。优先使用已有最高业务接缝，只有缺失的公开操作需要扩展，不为每个小工具另立服务。

v1.6.0 的文件添加验收属于前版基线，v1.6.1 检验固定发布模块、接线说明与基线的组合，不能把前版尚待实现的能力写成现有事实。

- **最高测试入口**：从可编辑工程的模块选择与加入工作流验证固定版本的文件、版本记录和待接线交接，再用按发布说明接线的受控工程 fixture 经过真实工程 server 与客户端公开接口验证运行行为。App 文件操作验证与工程运行集成测试覆盖两个实际进程边界；不为每个小工具重新创建独立测试服务。
- **好的测试**：检验用户能够观察的文件结果、冲突反馈、版本与接线状态、连接与身份行为、广播范围和资源释放。测试不依赖私有函数布局、内部容器数量或某个作品的固定画面／声音映射。
- **加入能力的测试边界**：复用 v1.6.0 工程工作流和 Rust 临时目录公开文件操作测试；验证新目录与带自定义实现的目录、只读来源、目标冲突、外部修改、路径逃逸与符号链接边界。拒绝时不覆盖已有工程内容、不声称完成接线。测试确认 App 不启动 npm，不重写入口，不自动重启工程，不通过网络替换模块源码。
- **源码与说明一致性**：对实际随 App 分发的模块版本和元数据进行验证；最小接线 fixture 使用同一发布源码与说明中的公开接口，不能只用手写相似 mock 模块证明其可用。固定版本包缺少源文件或说明时，不能发布为完整可添加条目。
- **客户端与身份**：真实工程集成覆盖新加入、服务端拒绝、断线重连、相同持久身份恢复、观察者不占用身份、释放与工程重启后的声明恢复边界。用不同作品策略 fixture 证明技术接口没有要求独占座位、座位等于通道或一客户端一 voice；不要求这些 fixture 生成真实作品的全部声音。
- **连续值过滤**：在公开发送接口上确认选择启用／不启用、阈值内外、未入场状态，以及重复离散动作仍逐次交付。不通过参数流测试声称新限频或完整离线队列已实现。
- **主题与语言**：从页面消息与可观察的 DOM／绘制适配回调验证首帧、重复投递、切换、缺省、畸形消息和兼容回退；真实工程 HTTP 接口确认模块仅在声明的 monitor 入口暴露与加载，performer 保留工程自己的行为。浏览器／WKWebView 真机冒烟确认所发布脚本可以按说明工作。
- **monitor 同步**：同一真实工程内创建多个 monitor 客户端，验证首份快照、调整广播、晚加入／重连、未知键、生命周期重置和 performer 不接收该通道；不假定某个 App 窗口对象就是唯一数据路径。
- **hub 集成**：优先复用既有本机真实 hub 子进程和工程 server 集成模式，以两个受控工程节点及其本地客户端验证鉴权、room 隔离、外部事件交付、回声过滤、节点摘要、失联／恢复和关闭清理。过期参数用可控时钟或现有 clock 注入细化测试，不把长时间等待作为主要验收方式。外部公网服务不是自动测试的必要条件。
- **hub 本地自治**：工程已按 Host 声明与配置门正常启动后，hub 不可达、拒绝鉴权或运行中关闭时，本地 performer 仍能加入并交付本地控制；外端摘要不会无限保持为在线。standalone 的未配置场景按其适配约定验证，不绕过 App 对声明远程能力工程的既有节点配置门。测试的断网／恢复不把作品的艺术同步政策强行设为公共标准。
- **已有 prior art，非本版已完成证据**：PNDS Template 已有真实 Node score server 与 Socket.IO 客户端集成测试，覆盖入场、控制、重连、重启座位、观察者、多个 monitor 快照／广播／重连及 performer 广播隔离；真实 HTTP 请求覆盖页面与主题／语言脚本的 monitor-only 暴露。其客户端单测使用注入的 socket 与 storage；主题／语言已有消息、DOM／回调、首帧、畸形消息和幂等测试。
- **hub prior art 的层级区别**：co-here 的 HubLeg 测试使用 fake socket 与可控时钟，已有连接快照、回声过滤、在线摘要过期、停止和状态日志断言。Telematic Network Diagnostics 已有真实 hub 子进程、真实工程实例、鉴权／房间 relay、失联与自动重连，以及双工程实例相互可见的集成测试。后者可以作为新的共用 hub 模块最高工作流先例，不能把前者单测描述成完整双节点真机验证。
- **发行回归**：模块源码所在的实际维护仓库执行对应检查；App 的改动满足仓库全量检查。进行离线模块取得、外部 agent 按文档接线后的工程验证与 macOS 冒烟；本 spec 不声称完成手机传感或演出负载测量。

- **最高业务接缝**：以外部 agent 从接收目标、读取 Skill 和资料、产出工程／报告、执行适用验证到交接的完整工作流为主要验证接缝。观察任务决定、工程产物、运行检查与交接记录，不通过提示词逐句快照或内部推理形态判断正确性。
- **真实环境门槛**：至少一个实际可用 harness 跑通完整流程，记录 harness、模型、平台资料版本、输入、作者确认点和结果。实际使用的其他环境按可用条件补充覆盖；没有验证的环境不声称支持已通过。
- **主入口覆盖**：分别验证新建、已有工程修改和任意来源移植评估；移植案例包含非三件套输入，观察报告先出现、作者方案确认前不开始改写、改变声音／画面／互动／时间时保留明确决定。已有工程修改不重置工程身份或重复初始化。
- **独立能力覆盖**：五项基础能力各至少有一个独立任务能读取其资料并产出可检查结果，避免只能从主入口被动使用或依赖维护者机器隐藏资源。
- **创作初版门槛**：新建初版在创作模式实际打开；记录必要结构已完成、声音或运行尚未验证的状态，验证不会因初版未完成演出验收而错误终止交接，也不会误报完整运行成功。
- **模块接入覆盖**：利用标准模块源码和接线交接完成一次真实工程接入，观察来源保持、依赖／配置处理、接线和既有功能的组合结果。不能仅验证文件已复制。
- **CM1 回归**：沿用既有 Node 检查、协议／控制与恢复测试、none 模式 health 烟测、真实浏览器冷打开流程及课程输出基准；继续覆盖 START、有界结束、扫码、编号、移动端双方向和多点触控。实际声音与设备验收保持单独记录。
- **交付范围覆盖**：普通任务在没有分发要求时只交付源工程与记录；明确分发后生成工程包；课程任务交付两者。复用既有打包结构、产物、依赖和 health 检查，不以 Skill 重构改变工程包格式。
- **可移植资源覆盖**：在没有维护者专属目录的环境，从已发布 Skill 资源与对应 App 资料完成查找和工作；覆盖缺资源、缺工具或版本不匹配时给出准确限制。辅助工具继续验证实际输入／输出和失败反馈。
- **沿用已有验证实践**：现有移植 Skills 的源工程记录、Node 测试、真实 health 烟测、冷打开与 SHA256 产物核对是 prior art；App 的工程打开、手动测试、模块复制和交接写入沿用各自已确定的测试接缝。本 Skills 工作不为外部 harness 建新的 App 请求编排层。

- **发版完成条件**：修改实际所属仓库的业务逻辑时随改动补行为测试；App 改动满足 npm run check:all 全绿，模块和 Skills 工具满足所在维护仓库的既有检查。真实 harness 发布记录至少包括一个完整任务，五项独立能力和 CM1 保留验证覆盖；其他 harness 可按条件补测，未测的环境只记录未验证。App 开发服务器由用户启动和回报，不以规格发布冒充本版功能验收。
- **初版与发布门槛分开**：结构齐全且可在创作模式打开可以完成初版交接，实际启动和声音结果不得虚填；需要分发时仍执行现有依赖、音频产物与工程包检查。源工程交接、none 模式烟测、作者真机声音验收和工程包安装往返是不同证据，不互相替代。

## Out of Scope

- App 自动修改工程入口、执行 npm、安装依赖、布线、模块运行时注入、自动合并、自动升级、自动删除或强制覆盖模块文件。
- App 从网络动态更新模块目录或已加入工程的模块；Skills 强制安装或成为模块运行前置条件。
- 新的连续控制限频框架、固定更新频率或对所有音乐动作进行去重合并。
- 多触点与坐标模块；传感输入、摄像头／麦克风采集、HTTPS 网关／证书入场；事件录制与回放。
- 单一操作者认领新模块、独立页面适配框架、独立诊断／压测模块、额外音频资源与参数创作框架。
- 全工程状态快照、作品进度或音频状态统一恢复、跨工程／跨演出状态持久化、跨站艺术政策或一致性裁决。
- 替创作者决定声源组织、乐谱画面、固定控件、角色分配、音乐映射、生成规则或段落引擎。
- 修改既有完整 performer URL 契约或为本版重新实现中央 hub 服务。
