# v1.6.3：多模板、只读 Git 与上下选卡

状态：全部实现已合入 `codex/v1.6.3-integration`，全量检查与复审通过；模板、Git、原生上下选卡及追加 Cmd+Opt+Enter 加载均已通过用户真实 App 验收。实施与验收见 [#192 验收记录](../acceptance/192-v1.6.3-creation-workflow.md)。

## Problem Statement

创作者需要在空白结构和完整参考示例之间选择起点，创建后离线运行，并了解外部 agent 对工程的修改。演出操作者在 monitor 获得键盘焦点后仍需可靠选择工程，现有主页面按键监听不能满足所有焦点场景。

## Solution

创作模式提供 Blank 和 PNDS Classic 两个固定来源模板，生成独立、可编辑的工程，随后由用户手动启动。增加只读 Git 状态与差异，保持草稿、磁盘、提交和运行事实分开。演出主窗口新增 Cmd+Opt+↑／↓ 原生选卡，显示侧栏但不自动加载；用户追加 Cmd+Opt+Enter 显式加载当前选择，左右键不添加功能。

## User Stories

1. As an 创作者, I want 从 Blank 或 Classic 创建工程, so that 我能选择适合当前目标的起点。
2. As an 创作者, I want Blank 保留最小无艺术预设结构, so that 我可以自主设计作品。
3. As an 创作者, I want Classic 保留完整参考示例, so that 我可以从已有网络与声音实现开始。
4. As an 创作者, I want 两个模板离线创建后可手动启动, so that 我不必另外安装运行依赖。
5. As an 创作者, I want 查看模板用途与来源版本, so that 起点和已加入模块不会混淆。
6. As an 创作者, I want 在指定位置建立新工程, so that 源工程由自己维护。
7. As an 创作者, I want 新工程有独立身份和客户端身份, so that 两个新作品不会串用状态。
8. As an 创作者, I want 模板创建排除运行缓存和原 Git 历史, so that 不继承维护者设备记录。
9. As an 创作者, I want 工程元数据、文档与版本一致, so that 外部 agent 不重复初始化已创建工程。
10. As an 创作者, I want 取消创建保持原工程与草稿, so that 试选模板不会丢失工作。
11. As an 创作者, I want 创建失败说明真实结果, so that 半成品不会被标成可运行。
12. As an 创作者, I want 缺共享资源时明确失败, so that 不会暗中改用另一版本。
13. As an 创作者, I want 创建成功进入工作台但不自动运行, so that 我决定何时测试。
14. As an 创作者, I want 已有 Git 工程显示分支与提交状态, so that 我知道外部修改对应的版本。
15. As an 创作者, I want 查看工程范围内的文本差异, so that 能审阅 agent 的实际改动。
16. As an 创作者, I want 没有 Git 时仍正常创作, so that 版本控制不是工程运行前提。
17. As an 创作者, I want 草稿、磁盘、Git HEAD 与运行状态分别表达, so that 提交不会被误当保存或已运行版本。
18. As an 创作者, I want Git 操作留给外部工具, so that App 的工作流保持有限。
19. As an 演出操作者, I want monitor 持焦时也能用 Cmd+Opt+上下选卡, so that 无需先移动鼠标。
20. As an 演出操作者, I want 选卡时显示侧栏和当前选择, so that 我能看到导航结果。
21. As an 演出操作者, I want 上下按当前列表顺序且到边界停止, so that 不意外跳到另一端。
22. As an 演出操作者, I want 快捷选择不自动载入工程, so that 当前演出继续运行。
23. As an 演出操作者, I want 确认弹层和启动／关停期间禁止导航, so that 快捷键不绕过正在处理的动作。
24. As an 创作者, I want 创作及独立窗口保留原键盘操作, so that 演出选卡不会误作用于其他窗口。
25. As an 演出操作者, I want 左右键本版没有新增导航, so that 已有页面和编辑键位保持明确。
26. As an 创作者, I want 两种模板、Git 和快捷导航支持主题、语言与键盘, so that 它们与现有 App 一致。
27. As an 演出操作者, I want monitor 或输入控件持焦时用 Cmd+Opt+Enter 加载已选卡片, so that 原生上下选卡后可稳定提交既有加载流程。

## Implementation Decisions

- 模板创建复用已有空白工程与受信文件创建工作流，选择器扩为固定目录；复用 v1.6.2 共享资源，不另建一套依赖安装器。
- Classic 来自经过验证的干净发行来源，完成身份、元数据、文档与缓存初始化；普通新工程不继承来源 Git 历史。打开已有工程不重置身份或历史。
- 创建、取消、失败与工程切换继续遵守原子边界、草稿确认、只读来源及迟到结果归属；不会把模板变更推送到已创建工程。
- Git 能力仅只读状态与差异，范围属于当前工程；不要求 GitHub 登录，不提供提交、分支切换、合并、推送或仓库发布。
- 原生菜单动作复用现有选卡工作流，限定演出模式主窗口；monitor 获焦也可执行。创作、performer、投影、帮助窗口不操作后台演出选择。
- Cmd+Opt+↑／↓ 按列表顺序选卡到端停止，并唤出侧栏。确认弹层、启动和关停期间让位，选中与运行分离；左右键不添加。
- 用户追加 Cmd+Opt+Enter，限定同一演出主窗，复用所选卡片的 Load／Change 与替换确认。预检或启动条件未就绪不加载旧卡，不跨预检自动排队；运行 A 时加载 B 先确认，当前运行卡没有变更时无动作，不关闭演出。现有 Enter 与 Cmd+Return 投影开演键位保持。
- 侧栏显示不改变 monitor 尺寸、实例或导航；不重建页面焦点恢复与运行流程。

## Testing Decisions

- 最高接缝是创建／取消／切换、查看差异与用户选卡动作。延伸 AppShell、工程打开、创建、草稿与选卡流程测试，断言实际工程和命令结果，不断言组件结构。
- 临时目录创建两份 Classic 与 Blank，检查身份隔离、来源、缓存排除、无 Git 历史继承、失败保护、共享缺失、离线启动及打包安装；已有文件服务和 bundle 测试为 prior art。
- 临时 Git 仓库验证只读状态、差异范围、未提交修改、无 Git 的降级与原工程不变；不以执行命令文本相同代替结果。
- 原生 macOS 验证 monitor／输入控件持焦、全屏、列表边界、弹层与忙碌、独立窗口不影响主窗。已有窗口分派和侧栏键盘测试为 prior art；jsdom 不证明原生 accelerator。
- 原生加载追加复用实际 AppShell／SessionActionButton／菜单和 typed IPC 接缝，验证上下后加载、慢焦点与预检、单次提交、替换确认及取消、Change 与不关闭运行卡；原生夹具检查正文／输入／跨域 guest 的真实 Return 投递和既有窗口／模式门控。
- 新业务逻辑带测试，App 全量检查通过；用户负责 App 开发服务器与真实视觉／操作反馈。

## Out of Scope

- 在线模板市场、第三方模板安装器、从只读工程包解锁用户可编辑副本。
- Git 写操作、GitHub 登录／克隆／PR／Release 操作、自动提交和分支切换。
- 左右导航、创作文件导航快捷键、独立窗口改变后台工程、快捷选卡自动载入。

## Further Notes

Blank 的既有交付仍属于 v1.6.0，不能迁走或重做。当前全局左右导航已经撤销，新的上下加速器必须按本版窗口范围验收。实施不得把原型演示当作实际模板或 Git 能力。

### 实施期间的用户补充（2026-10-14）

- 用户报告作品／文件夹都输入 `Test` 时创建被禁用。文件夹输入的大写英文自动转小写并展示实际目录，作品名称保留原输入；其他无效文件夹名显示具体双语原因，纠正后恢复创建，不放宽既有后端规则。
- 记住上次所选父目录，下次新建与重启后默认该目录。只保存归属仍有效的成功选择，取消／迟到结果不覆盖；启动恢复晚到不替换用户刚选的新目录。失效目录经现有创建错误提示后可重新选择，不自动换位置。

- 后续用户确认父目录记忆正常，并要求作品名称和文件夹名称关闭 macOS 自动纠正／自动大写。输入辅助仅作用于这两个字段；作品名保留输入大小写，既有文件夹小写规则保持。

- 用户已对原生上下选卡、焦点、全屏、边界、门控、独立窗口及运行／页面保持回复「全部通过」，同时报告与 Enter 配合不稳定并明确要求「Cmd+Opt+Enter 是加载」。原验收保留，新增加载按上面的显式提交与既有确认流程实施。
