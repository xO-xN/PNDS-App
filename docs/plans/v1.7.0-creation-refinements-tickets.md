每张子票贯通用户请求或动作、必要的原生能力、可见结果和对应测试，完成后可独立演示或验证。目录能力先补齐，再供资料采用和默认整理共用；资料管理先独立可用，再接入助手阅读。无冲突采用与同名冲突接续分别交付，默认整理与补充规范分别交付。SCD 打开本身已经足够窄，保留一张完整执行子票。

主要自动化入口仍为完整创作工作区到统一助手请求及任务执行；必要原生测试使用真实临时工程或私有资料目录验证权限、隔离、保存版本、接续和撤回。各票须通过 npm run check:all。真实模型、SuperCollider GUI、双架构和作品画面／声音验收汇入 #172，App 与 dev server 由用户启动。

#149 的 28 个直接子项及既有相对顺序保持，#172 仍最后收尾，原有 25 项直接阻塞保留。父规格必须完成全部执行子票及自身完整范围后才可收口；拆出子票不代表父规格已经完成。本轮不修改父 issue 正文、负责人或完成状态，不认领或实施功能，不提交代码。

全局历史编号保留为 1–86，其中第 72–76 项的 #239–#243 现在是父规格，第 77–86 项为新增执行子票。跨版本叶子票由规格发布时的 76 张调整为 81 张（76 − 5 + 10）；统计包含已完成与待完成任务，不作为完成度。
