## Q22：已确认收缩首版

目标为「普通工程终端 + 快速准备交接」。先验证终端承载和真实 CLI 交互；多工程后台、写入锁、任务状态、接续与实时信息服务退出首版。

### 保留的核心

- 工程终端与助手、版本历史同区切换，复用当前工作台。
- 全 App 只有当前工程的一个终端会话，从当前可编辑工程目录启动，提供真实 PTY、正常输入、复制粘贴、尺寸调整和有限滚动历史。普通 shell 与 agent 使用同一个终端；用户可自行启动熟悉的 CLI，可选保存一个常用启动命令。
- 新建终端按当前 PNDS 主题初始化背景、默认文字、光标、选区及标准 16 色，CLI 指定的其余扩展色和 RGB 颜色保留。完整运行中热换肤及历史输出重着色后置，切主题不结束 CLI。
- grilling 方案卡新增第三个动作：整理本次已确认方案和必要参考，生成静态交接文件，复制短提示并切到终端。已有会话不重启，由用户在 CLI 就绪后提交；明确配置的新 CLI 可通过启动参数接收短提示，但自动传参不是首次验证的前置条件。
- 交接文件提供工程保存版位置、装机文档路径和现有 pnds check 用法；可附导出当时的工程/运行概况等明确标时快照。它不代表实时 App 查询接口。
- 文件保存沿用现有外部变化检测和草稿冲突处理，结果由用户通过现有版本/diff、检查、编译及试听操作审阅。交接读取保存版工程，不默认导出未保存草稿或其他聊天，也不自动保存或丢弃草稿。

### 交接与协作边界

第三个动作只承接当前选定方案及已确认决策。现有「给外部 agent 提示词」承接整份当前创作交接单的语义保持，不能直接把它的「执行全部当前任务」提示复用于新动作。任务文件是静态说明，不建立独立任务记录、比较基线、审批流程或完成状态机；它的私有落点及导出排除规则在技术验证时核对。

用户自由运行 Codex、Claude Code 或其他本机 CLI；登录、模型、权限审批、对话与恢复由 CLI 自己管理。启动命令不发展为 Agent 配置库，不自动修改全局 CLI 配置、项目 AGENTS 或用户凭据。短提示与文件路径通过结构化参数或复制交接，不拼接方案正文为 shell 命令，也不向未知状态的终端自动粘贴。

终端保留普通本机执行能力；cwd 不是权限沙箱。CLI 的写盘按外部编辑处理，不自动进入内置 Work 的 journal 或整任务撤销。首版不增加 App 自动只读、写入锁或 Work/CLI 串行调度，创作者自行协调修改；现有冲突检测不等于能阻止所有并发写入。进程退出只表示进程结束，不表示需求完成，实际文件保存也不表示已加载到运行版。

### 会话生命周期

切换助手、历史、文件和终端只切换显示，当前会话继续；红色关闭按钮隐藏窗口时仍保留会话。切换工程、替换当前工程版本、进入合并候选、离开创作或退出 App 时，有活跃会话则选择「结束并继续」或取消原操作；没有活跃会话沿用原流程。结束终端不撤销已保存的修改，也不自动重启 CLI。

合并候选期间不提供指向实际工程的终端。结束失败时保留当前界面并如实显示错误，不能先宣称已结束再继续切换。进程退出、EOF、受管作业清理及输出缓冲仍是必须验证的终端基础能力；不承诺能收回用户主动脱离终端托管的任意后台进程。

### 后置范围与实际取舍

| 后置范围                                 | 首版处理与实际取舍                                                                         |
| ---------------------------------------- | ------------------------------------------------------------------------------------------ |
| 多工程后台与全局配额                     | 仅当前工程一个会话，切工程结束；不能去 B 时继续运行 A                                      |
| Shell/Agent 两类会话及启动配置库         | 只用一个终端，可选一个常用启动命令；可能多一次启动命令与粘贴                               |
| 工程自动只读、执行权锁与自动串行         | CLI 按普通外部编辑器对待；复用已有冲突检测，不承诺自动阻止并发修改                         |
| 独立终端任务状态、交回、待审阅与完成记录 | 只输出静态交接文件，不建立新的任务调度或完成状态机                                         |
| 任务接续、自动归档与自动检查回收         | CLI 自己管理对话；用户操作现有版本和检查功能                                               |
| PNDS 在线只读 CLI/App IPC 与 MCP         | 首版使用交接快照、普通文件及现有检查 CLI；无法自动查询实时 App 日志/状态或动态私有素材语义 |
| 完整实时主题切换                         | 新会话匹配当前主题；已有会话的完整热换色另行验证和排期                                     |

该收缩减少业务状态组合，不降低中文输入、TUI、字节流、反复开关、隐藏绘制开销与进程清理的要求。Ghostty 发布包的已知问题仍需真实验证，不把「少功能」当作底层可靠性的证明。

## 技术验证边界

优先验证 ghostty-web / WASM / Canvas + 现有 WKWebView + Rust PTY，复用类型化控制命令和有序字节通道；不新增 Node/Bun 服务、HTTP/WS 服务或独立 WebView。它是候选路线，不是已验证最省资源的结论。当前第三方发布包存在生命周期、隐藏绘制、粘贴和主题能力缺口，详见[调查](../research/embedded-terminal-agent-evaluation-2026-11-16.md#实际发布包与必要修补)。若关键门槛无法满足，再比较原生完整 Ghostty，而非先自建 renderer。

后续技术验证只回答以下问题，不顺带扩充任务管理：

1. 真正的 shell 与 Codex / Claude Code TUI 能否可靠使用：中文 IME、Unicode、复制与括号粘贴、Ctrl-C/Ctrl-D、作业控制、alternate screen、resize/reflow、字节分片。
2. 四套 PNDS 主题的新会话色板是否可读；颜色来源复用当前主题，保留标准颜色语义。
3. 同区切换、隐藏、反复创建/销毁、EOF、停止与退出是否保留正确的进程归属，输出队列与滚动历史是否有界。
4. 简单交接是否只执行所选方案，能否经文件 watcher、现有检查、版本差异与人工试听回到创作流程。
5. 实际包增量、首次打开、空闲/隐藏 CPU 与 RSS、高输出下输入延迟是否可接受；结果需实测，包含 macOS 双架构及现有音频/monitor 负载场景。

本轮只收束评估文档；没有安装终端依赖、启动 coding agent 或改动产品代码。产品实现另行安排，不能把完成访谈理解为已完成技术验证。
