# 创作模式版本规划与定稿范围

状态：UI 与两个大版本的核心范围已确认（2026-10-03），尚未实现。正式规格为 [v1.6.0](./v1.6.0-creation-mode-spec.md) 与 [v1.7.0](./v1.7.0-creation-assistant-spec.md)；本文保留版本分工和上下文量研究记录。

已发布到项目 Issue tracker：[v1.6.0 #148](https://github.com/xO-xN/PNDS-App/issues/148)、[v1.7.0 #149](https://github.com/xO-xN/PNDS-App/issues/149)，两者均标记 `ready-for-agent`。

## v1.6.0：演出模式与创作模式

- 两种模式按场景命名为「演出模式 / Performance mode」和「创作模式 / Creation mode」。每次启动 App 都进入演出模式的空闲首页。模式按钮在自身内部经两次点击确认，不弹窗。演出→创作直接接续正在运行的可编辑文件夹工程及已应用音频配置；没有运行时打开已选文件夹，但不自动启动测试。工程包与内置工具不进入编辑。创作→演出结束测试并回到空闲首页；进入创作时关闭投影。详见更新后的 ADR-0007。
- 创作模式聚焦单个文件夹工程。已安装的 `.pnds` 与内置工具只读；侧栏显示工程文件，按音频、动画、模块、系统等用途辅助识别，实际路径不因分类改变。
- 文件树提供读取与有限编辑、当前文件重命名，以及在 Finder 中打开工程文件夹；移除新建文件、导入素材和删除文件入口。工程文件的增删与复杂改写交给外部编程 agent。
- 主区按定稿 A 布局提供当前文件与控制台两个标签，以及始终保留的 monitor 和多个独立 performer 测试窗口。预览刷新与工程重启由用户手动触发。外部 agent 改动当前打开的文件后，App 在保存时检测磁盘版本变化，提示用户重新读取或确认覆盖。
- 演出侧栏保留单一加载 / 更改 / 关闭按钮，移除重复工程标题与帮助按钮。演出文件夹使用可扩展下拉，工具独立切换；进入工具时下拉位置改为返回原文件夹。演出中侧栏覆盖 monitor，显隐不改变页面尺寸或重载页面。
- 保留已有 Ports 调试能力并在释放前核对进程身份；SynthDef 编译入口移到 SCD 文件工具栏，结果进入控制台，不自动重启工程。
- 「新建工程」在用户指定位置生成空白文件夹工程，不另造一个 Template。工程没有生产依赖；新建后应能立即启动并预览。包含音频代码、SuperCollider 源文件和已编译产物，但没有作品声音源。默认音频模式为 Internal，同时支持 External 和 None。Internal 的技术占位 SynthDef 只向工程私有 bus 写零信号；External 在作品协议尚未实现时可以启动和预览，但不发送音乐消息。
- 新工程以当前 App 语言写入初始 `README.md`，并在交接单记录另一语言的翻译任务。
- App 在工程的 `docs/creator-handoff.md` 记录留给外部编程 agent 的任务，如另一语言的 README 更新。新建工程的 `AGENTS.md` 指向交接单与平台契约；现有 PNDS Template 也增加交接单入口。

Internal 技术核查：空 `.scd` 不会产出运行所需的 `.scsyndef`，App 的编译入口也要求源码实际注册 SynthDef。本机 SuperCollider 3.14.1 可以编译没有 UGen 的空 SynthDef，但它不会向工程音频 bus 输出信号，不能单凭它满足当前 Internal 运行契约。新工程采用只向私有 bus 写入零信号的技术占位 SynthDef，不生成作品声音源。

### 工程素材的查看边界

- 图片文件在 App 内预览。现有 README 封面图已使用 WKWebView 显示工程图片；通用图片预览复用平台解码，按需读取并限制过大文件。首版目标格式为 PNG、JPEG、WebP、GIF。
- 音频文件在文件树中显示文件名、格式和大小，提供「在 Finder 中显示」按钮，选中的是该文件本身。创作者在 Finder 中决定用什么工具打开和试听。App 不解码、播放、转换采样率或路由音频素材，也不把素材带入安装包。
- 编译产物等其他二进制文件只显示基本信息。Finder 定位动作复用 App 已有的 `tauri-plugin-opener` / `reveal_item_in_dir` 能力，仍验证目标属于当前工程目录。

此取舍撤销了原生音频试听的 8–14 人日估算及其音频依赖、设备并发风险。图片预览和 Finder 定位的安装包增量预期很小，仍以发行构建实测为准；v1.6 无需引入素材播放器。

## v1.6.1：Skills 与 PNDS 工程模块

范围已确认，详见 [v1.6.1 正式规格](./v1.6.1-modules-skills-spec.md)。v1.6.0 先交付模块文件添加、来源版本记录及外部 agent 接线交接，首批为 QR、客户端连接与身份恢复、monitor 主题、语言和多窗口视图同步；v1.6.1 整理接口、说明与版本兼容，增加可选 hub 连接与远程节点状态，并重构外部 PNDS Skills。连续控制过滤归客户端模块，无新增限频。模块只提供技术能力，作品政策由作者决定。

外部 Skills 通过可独立使用的五项基础能力组织新建、修改和任意来源移植；移植先评估并与作者确认，保留 CM1 课程入口。源工程初版达到必要文件结构完整、可在创作模式打开即可，运行与声音验证单独记录；普通任务默认交付源工程，明确分发时再打包，课程交付两者。Skills 自愿按需安装，App 不安装或执行；App 不新增移植入口，助手只提供咨询、交接和相关安装步骤提示。

## v1.7.0：创作助手

- 助手位于创作模式，可读取 PNDS 文档、skill 与当前工程文件，回答创作问题并提出建议。工程文件按问题读取；全面阅读由用户明确触发。
- 助手不承担成熟编程 agent 的代码修改工作；经用户确认后可以在创作交接单中拟写任务。
- 助手复用随 App 发布的 PNDS 文档；v1.6.1 已确认并发布的 skill 可作为固定版本语料读取，与创作者外部 agent 的安装位置无关。模块与外部 Skills 按 v1.6.1 规格交付，安装由创作者在外部环境主动完成。
- 助手连接创作者自行配置的 LLM API 地址、密钥与模型；PNDS 不提供统一模型服务。
- v1.7 首版只承诺具有工具调用能力的 OpenAI 兼容接口，设置中提供连接测试；其他厂商原生协议按后续需求增加。每个工程有自己的本机聊天记录；同一聊天可交替询问 PNDS 基本知识和当前工程，切换工程则打开对应记录，防止上下文串用。记录存在 App 本机数据区，不写进工程或 `.pnds` 包。

### 本地工程文本量抽样（2026-09-28）

对同一开发目录内 10 个带 `manifest.json` 的工程统计。下表的「可读文本」包含源码、测试、文档和配置，排除了 `node_modules`、构建目录、锁文件、压缩后的第三方库和二进制资产。token 是根据字符类别给出的宽范围估算，不等于任何指定模型的计数结果。

| 工程                          | 可读文本 |  估计 token |
| ----------------------------- | -------: | ----------: |
| Multichannel Signal Generator |  143 KiB |   约 29–51k |
| Inarticulate III              |  224 KiB |   约 46–79k |
| PNDS Template                 |  308 KiB |  约 64–108k |
| All Sentient Being Sounds     |  372 KiB |  约 77–134k |
| Telematic Network Diagnostics |  413 KiB |  约 85–143k |
| Orbital Fugue                 |  478 KiB |  约 99–168k |
| Co here Co hear               |  491 KiB | 约 101–169k |
| Splash Ink                    |  616 KiB | 约 127–213k |

另外两个工程：Local Network Diagnostics 为 209 KiB（约 43–74k token），template_preact 为 257 KiB（约 53–88k token）。PNDS 中文帮助语料本身有 23 篇、约 121 KiB。直接读取完整工程文件夹还会混入依赖和资源；这 10 个工程的总磁盘体积为 3.3–109 MiB，不能原样作为纯文本上下文。

已确认的上下文方案：允许助手在当前工程目录内按问题搜索和读取源码，由 App 控制路径、文件大小和每次请求的上下文预算；PNDS 基本知识问题只检索平台文档，工程问题再读取相关文件。对需要全面评议的任务提供显式的「阅读整个工程」动作，并先展示文件范围与 token 估算。v1.7 暂不设专门的 LLM 阅读子代理；本地文件清单、搜索和分段读取由确定性的只读工具完成。用户可在同一对话中交替提出平台和工程问题。

首次对话自动附一份创作者可见的简短工程概况，取自 manifest、文件清单、README、依赖声明、交接单，以及已有的预检和预览结果。概况区分「是否仍是 App 生成的空白骨架」「静态契约是否齐全」「上次是否实际启动成功」；不把这些证据合成为「作品已完成」的单一结论。文件变化后更新概况。App 不为了生成概况自动调用完整 preflight：现有 `preflight_project` 会先清理可确认归属的遗留进程，不能当作纯读取操作。
