当前创作模式实现只到 #158：#150–#157 有实现提交，#158 已进入 HEAD（26eac27），实机验收仍暂缓。#159–#164 的未完成工作继续交付；GitHub OPEN 状态不能作为重做已实现工作的依据。

App 业务改动遵守仓库完成标准：新逻辑随改动带测试，`npm run check:all` 全绿，并完成所属版本的实机与发行验收。前轮记录的 #158 lint／格式问题已在当前 HEAD 解决；本轮允许既有端到端测试夹具本机监听后，npm run check:all 全绿。新规格文档格式与本地链接亦已检查；自动检查通过不代表未来功能或作品兼容已交付。App 开发服务器由用户启动并回报；此次不 commit。

## v1.6.2：共享库及真实作品兼容

正式规格：[本地文档](./v1.6.2-shared-libraries-spec.md) · [#191](https://github.com/xO-xN/PNDS-App/issues/191)。

共享浏览器库与选定 Node 生产依赖在同一个版本交付。每项只提供一个尽量新的发行固定版本；调研候选为 p5、ml5、Express、qrcode、Socket.IO／client、osc-min，最终版本在兼容验证后冻结。包含实际必要的完整生产依赖，不强行把所有内部传递依赖版本抹平。

模型由工程自带。Mobile Sensor Meter 的模型仍随内置工具进入 App；旧含模型、多旧版共享目录的容量测算不作为新方案指标。最终资源与 DMG 容量在真实发行构建中记录，原测量依据见[体积与兼容核查](./shared-packages-size-and-compatibility.md)。

工程建立明确引用，共享库留在 App；工程也可自带依赖。共享 `.pnds` 只携带引用，不物化这些共享库。缺资源给出可读失败，不静默换版本。正式采用新版写回工程引用、更新工程版本；安装新 App 或临时试验不自动改写源工程。旧共享版本共存和自动回退方案已取消。

迁移 Template、内置工具及目标作品需要跨仓库接线与验证。Inarticulate III、Inarticulate IV、ASBS 在本版发行时可运行是硬门槛；失败由用户更新作品后重验，不能以未迁移例外放行。IV 的 Max／Ableton 环境、ASBS 谱面和预编译页面、各作品音频资产仍由工程提供。

验收使用当时已有的 App、工程检查和真实作品测试，不能等待 v1.6.5 CLI。三个作品按各自声明支持的模式验收真实页面、交互、声音链、刷新／关停，以及 `.pnds` 打包安装后的运行。服务启动或 health 成功不能单独放行。

## v1.6.3：创作起点、版本感知与导航

正式规格：[本地文档](./v1.6.3-creation-workflow-spec.md) · [#192](https://github.com/xO-xN/PNDS-App/issues/192)。

首批模板为 Blank 与 PNDS Classic，离线创建后由用户手动启动，无需另外 npm 安装。Blank 复用 v1.6.0；Classic 使用固定、干净、已验证的 Template 来源，生成独立工程与客户端身份，清理运行缓存，更新元数据、README 与外部 agent 指引。

Git 首版提供只读状态与差异查看，工程没有 Git 也可继续创作。Git 提交、分支切换、合并、推送和远程 GitHub 管理由外部工具完成；不将 Git 设为工程格式要求。未保存草稿、磁盘内容、Git HEAD 与正在运行的内容分别表达。

新增 Cmd+Opt+↑／↓ 仅用于演出模式主窗口，按当前列表顺序选卡，到边界停止；monitor 持有焦点时仍可调用并显示侧栏。只改变选择，不自动加载，确认弹层和启动／关停期间禁止导航。创作模式及 performer、投影、帮助窗口保留各自操作；左右键首版不添加功能。复用选中与运行分离的动作，不恢复 #153 已撤销的全局左右切换。

## v1.6.4：工程诊断与静态 CLI

正式规格：[本地文档](./v1.6.4-static-diagnostics-spec.md) · [#193](https://github.com/xO-xN/PNDS-App/issues/193)。

提供可独立使用的静态工程诊断与 `pnds check` 类 CLI：manifest／路径／资源／生产依赖／共享引用等已知契约检查，明确检查项、严重程度、原因与结构化结果。同一确定性能力供 App 和外部 agent 使用。

不启动工程或清理进程；不能直接包装现有会执行 orphan cleanup 的 `preflight_project`。识别静态事实与未验证内容，不声称完整推断动态音乐协议或证明作品完成。真实源码分析、通用 AST 索引和自动依赖安装不作为本版承诺。

## v1.6.5：受控运行检查与可恢复单文件修改

正式规格：[本地文档](./v1.6.5-controlled-checks-spec.md) · [#194](https://github.com/xO-xN/PNDS-App/issues/194)。

确定性的 App／CLI 服务准备临时副本，执行预检、启动、严格 health／HTTP 检查、有界结束和清理，输出与副本输入版本、依赖、共享库、模式和环境对应的报告。外部 agent 可先使用 CLI 验证，v1.7.0 助手调用同一能力。

默认 None，仅在工程声明支持时执行；不支持则说明未执行，不更改声明或自动换模式。Internal 由用户明确选择，证明启动、就绪和关停；External 首版通过 App 手动测试。它不自动证明画面、真实手机、模型推理、声音内容或艺术结果。

任何 App 活动运行，包括启动与关停期间，阻止需要新启动工程的自动检查；静态仍可用，不自动停止已有演出。临时副本不得改写原工程，具备取消、超时、异常退出和迟到结果归属处理。

提供已有单个文本文件的差异、版本保护写入与撤销基础，复用 #154 的工程身份、路径和磁盘冲突保护。外部修改或未保存草稿不能被静默覆盖，撤销不覆盖后来发生的修改。编译产物与报告由独立检查产生，副本检查不自动回写原工程；原工程继续使用已有手动编译入口。具体检查配置、预算和超时在实现时验证，不增加新的产品前置能力。

## v1.7.0：有限代码修改的创作助手

保留[原规格](./v1.7.0-creation-assistant-spec.md)的用户自配兼容 API、钥匙串、本机工程独立聊天、按需文档与文件读取、发送范围授权、来源、预算、取消和工程切换隔离。替换原只读咨询限制，布局遵循末期修订的原型。

普通聊天用于讨论与拟定方案。助手说明目标文件和改法，用户点击“执行修改”授权一次修改，只写一个已有文本文件，可为源码、manifest、README 或 SCD。显示实际变更与撤销入口。“运行检查”是独立按钮，使用 v1.6.5 服务，展示进度、结果和停止入口；聊天、保存不自动启动完整检查。

新建、删除、重命名、跨文件修改或其他复杂任务先说明原因并询问是否交接；同意后写创作交接单，提供可复制的目标、文件、已知问题与验收要求，由创作者交给外部 agent。App 不直接派发外部任务，也不安装／执行 Skills 或开放任意 shell。

保留 #165–#170 的模型、问答、历史与读取工作，修订 #149／#166 的工具边界、#171 的确认交接流程、#172 的真实功能验收；新增单文件执行与检查接入任务，依赖 v1.6.5。检查失败保留已修改文件并说明原因，用户选择撤销或下一次修改方案，再次修改仍需点击执行，不自动连续修复；拒绝交接后保持现状并可继续讨论。
