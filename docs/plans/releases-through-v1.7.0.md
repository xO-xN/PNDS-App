状态：最初规格于 2026-10-12 经用户确认发布；2026-10-15 用户确认扩大 1.7.0 为完整创作流程，并将当前布局、讨论内调参／直接编辑代码／临时预演流程确认为实现基线；真实功能、模型效果和原生窗口视觉仍待验收。当前范围见下文与对应正式规格。总体规格为 [#190](https://github.com/xO-xN/PNDS-App/issues/190)，规划不代表功能完成；实施按对应版本规格与实际任务领取。决定过程见[讨论记录](./pre-v1.7-release-grilling.md)，任务映射见[Issue 变更清单](./pre-v1.7-issue-changes.md)。用户随后批准的 to-tickets 拆分形成最初 58 票基线，扩容后的任务以[最新实施与依赖清单](./pre-v1.7-ticket-breakdown.md)为准。

## 进度与完成标准

最初发布规划时的进度快照（2026-10-12）：创作模式实现到 #158：#150–#157 有实现提交，#158 已进入 HEAD（26eac27），当时实机验收暂缓。后续实现与验收进度应以对应 issue 的最新证据核对；此历史快照不代表当前实现上限，GitHub OPEN 状态也不能作为重做已实现工作的依据。

App 业务改动遵守仓库完成标准：新逻辑随改动带测试，`npm run check:all` 全绿，并完成所属版本的实机与发行验收。每轮检查结果记录在对应任务，历史检查通过不代表当前工作区或未来功能已经验收。App 开发服务器由用户启动并回报；本轮只调整规格与任务；用户随后授权单独提交 1.7.0 规划与验收文档，并行的 1.6.5 实现不纳入该提交。

版本按能力与验收安排，无固定发布日期。App 保持 macOS arm64／x86_64 双架构发布。源码存在、自动检查通过、实机验收与已发布分别记录。v1.6.0–v1.6.5 全部完成各自范围和验收后，才开始 v1.7.0 正式开发；助手方案研究可以提前。

## v1.6.2：共享库及真实作品兼容

正式规格：[本地文档](./v1.6.2-shared-libraries-spec.md) · [#191](https://github.com/xO-xN/PNDS-App/issues/191)。

共享浏览器库与选定 Node 生产依赖在同一个版本交付。每项只提供一个尽量新的发行固定版本；调研候选为 p5、ml5、Express、qrcode、Socket.IO／client、osc-min，最终版本在兼容验证后冻结。包含实际必要的完整生产依赖，不强行把所有内部传递依赖版本抹平。

模型由工程自带。Mobile Sensor Meter 的模型仍随内置工具进入 App；旧含模型、多旧版共享目录的容量测算不作为新方案指标。最终资源与 DMG 容量在真实发行构建中记录，原测量依据见[体积与兼容核查](./shared-packages-size-and-compatibility.md)。

工程建立明确引用，共享库留在 App；工程也可自带依赖。共享 `.pnds` 只携带引用，不物化这些共享库。缺资源给出可读失败，不静默换版本。正式采用新版写回工程引用、更新工程版本；安装新 App 或临时试验不自动改写源工程。旧共享版本共存和自动回退方案已取消。

迁移 Template、内置工具及目标作品需要跨仓库接线与验证。Inarticulate III、Inarticulate IV、ASBS 在本版发行时可运行是硬门槛；失败由用户更新作品后重验，不能以未迁移例外放行。IV 的 Max／Ableton 环境、ASBS 谱面和预编译页面、各作品音频资产仍由工程提供。

验收使用当时已有的 App、工程检查和真实作品测试，不能等待 v1.6.5 CLI。三个作品按各自声明支持的模式验收真实页面、交互、声音链、刷新／关停，以及 `.pnds` 打包安装后的运行。服务启动或 health 成功不能单独放行。

## v1.6.3：创作起点、版本感知与导航

正式规格：[本地文档](./v1.6.3-creation-workflow-spec.md) · [#192](https://github.com/xO-xN/PNDS-App/issues/192)。

首批模板为 Blank 与 PNDS Classic，离线创建后由用户手动启动，无需另外 npm 安装。Blank 复用 v1.6.0；Classic 使用固定、干净、已验证的 Template 来源，生成独立工程与客户端身份，清理运行缓存，更新元数据、README 与外部 agent 指引。

Git 在 v1.6.3 首版提供只读状态与差异查看，工程没有 Git 也可继续创作。该版的 Git 写入仍由外部工具完成；v1.7.0 在此基础上增加本地记录与历史能力，分支切换、合并、推送和远程 GitHub 管理继续交给外部工具。不将 Git 设为所有已有工程的格式要求。未保存草稿、磁盘内容、Git HEAD 与正在运行的内容分别表达。

新增 Cmd+Opt+↑／↓ 仅用于演出模式主窗口，按当前列表顺序选卡，到边界停止；monitor 持有焦点时仍可调用并显示侧栏。只改变选择，不自动加载，确认弹层和启动／关停期间禁止导航。创作模式及 performer、投影、帮助窗口保留各自操作；左右键首版不添加功能。复用选中与运行分离的动作，不恢复 #153 已撤销的全局左右切换。

## v1.6.4：工程诊断与静态 CLI

正式规格：[本地文档](./v1.6.4-static-diagnostics-spec.md) · [#193](https://github.com/xO-xN/PNDS-App/issues/193)。

提供可独立使用的静态工程诊断与 `pnds check` 类 CLI：manifest／路径／资源／生产依赖／共享引用等已知契约检查，明确检查项、严重程度、原因与结构化结果。同一确定性能力供 App 和外部 agent 使用。

不启动工程或清理进程；不能直接包装现有会执行 orphan cleanup 的 `preflight_project`。识别静态事实与未验证内容，不声称完整推断动态音乐协议或证明作品完成。真实源码分析、通用 AST 索引和自动依赖安装不作为本版承诺。

## v1.6.5：受控运行检查与可恢复单文件修改

正式规格：[本地文档](./v1.6.5-controlled-checks-spec.md) · [#194](https://github.com/xO-xN/PNDS-App/issues/194)。

确定性的 App／CLI 服务准备临时副本，执行预检、启动、严格 health／HTTP 检查、有界结束和清理，输出与副本输入版本、依赖、共享库、模式和环境对应的报告。外部 agent 可先使用 CLI 验证，v1.7.0 助手调用同一能力。

默认 None，仅在工程声明支持时执行；不支持则说明未执行，不更改声明或自动换模式。Internal 由用户明确选择，证明启动、就绪和关停；External 首版通过 App 手动测试。它不自动证明画面、真实手机、模型推理、声音内容或艺术结果。

任何 App 活动运行，包括启动与关停期间，阻止需要新启动工程的自动检查；静态仍可用，不自动停止已有演出。临时副本不得改写原工程，具备取消、超时、异常退出和迟到结果归属处理。

提供已有单个文本文件的差异、版本保护写入与撤销基础，复用 #154 的工程身份、路径和磁盘冲突保护。外部修改或未保存草稿不能被静默覆盖，撤销不覆盖后来发生的修改。编译产物与报告由独立检查产生，副本检查不自动回写原工程；原工程继续使用已有手动编译入口。具体检查配置、预算和超时在实现时验证，不增加新的产品前置能力。

## v1.7.0：以 AI 沟通为主的完整创作流程

保留[正式规格](./v1.7.0-creation-assistant-spec.md)的用户自配兼容 API、钥匙串、本机工程独立聊天、按需文档与文件读取、发送范围授权、来源、预算、取消和工程切换隔离。2026-10-15 用户先确认主要布局修订与五类新增能力，随后将讨论内调参、直接编辑代码和临时预演流程一并定稿；[完整范围与决定](./post-v1.7-creation-experience.md)及 [issue 修订记录](./v1.7.0-creator-experience-issue-impact.md)对应当前目标。

助手对话为主要创作入口，围绕创作意图多轮讨论与完善方案；完整文件、交接、比较与版本按需打开。右侧保留同一 monitor 页面，控制台沿用编辑区下方 dock。支持宽度调整、键盘操作和窄窗口使用，默认比例与可读宽度在本版实机验证。切换保留草稿、输入、回复及运行状态，不自动刷新或重启。旧原型中的“第三个助手标签”不再作为最终布局。

基础编辑包括行号、SuperCollider／JavaScript／TypeScript／JSON／HTML／CSS／Markdown 基本着色、括号匹配、缩进、撤销／重做、当前文件查找替换、跳行与工程内快速打开文件。用户可显式附加选区，包括标记清楚的未保存片段；发送前查看来源与内容并可移除。默认工具读取仍是保存版，附件不自动读取其他草稿，不绕过授权、读取开关、预算及历史过滤。读取开关关闭时，附件发送与历史重发均禁止，保留附件和输入并提示启用读取或移除，不提供单次发送例外。

助手按当前意图与真实工程内容，提供适合的参数控件及作用说明；不强制每条回复都有 fader，不按画面／声音或工程类型硬划范围。修改建议卡的“参数／代码”入口共同编辑待应用内容，可直接改非数字文本、条件和函数。只有准确绑定时才双向同步；无法对应的控件停用并说明原因，保留手写代码。待应用建议、文件草稿、保存版、运行、Git 和已执行差异分别表达。

工程适配支持时，参数调节可立即临时预演；代码输入不执行且结束旧预演，明确点击“预演修改”后才尝试当前内容。不支持时解释原因，明确应用后手动测试。预演不注入任意模型生成代码，不暗中启动或重启音频、服务或工程；复杂适配仍进入交接。结束预演恢复临时覆盖前的参数状态；恢复失败明确尚未恢复，不自动重启。

用户点击“应用到工程”授权将当前最终内容写入一个已有文本文件，沿用保存版本、目标身份、已有草稿及适用校验保护。成功后的实际前后差异在相关回复下只读展开；继续修改产生下一条记录，不重写之前的执行结果。“当前文件”入口仍用于完整上下文和文件草稿编辑。差异与撤销复用 #207 的生命周期与版本保护，不额外承诺所有助手差异的永久存档。应用不自动刷新、重启、检查或 Git 提交。检查使用 v1.6.5 独立服务，展示进度、结果和停止入口；失败不自动连续修复或覆盖后来内容。

复杂任务经确认写创作交接单，由用户交给外部 agent；App 不直接派发、不安装或执行 Skills、不开放任意 shell。写入时捕获已保存工程的比较基线，草稿提供“先保存再交接”或“仅按保存版交接”，不自动保存。基线与任务关联，重启后可比较；回来核对整个工程的“交接后的变化”，优先显示任务文件，不自动把所有变化归因于 agent。文本提供实际差异，二进制资源记录指纹、大小等变化摘要而不保存可恢复副本；比较不依赖 Git，Git HEAD 不能代替基线。

App 自供覆盖两个架构的本地 Git 能力；新建工程自动初始化并记录初始版本。已有无 Git 工程提供主动启用入口，用户预览范围后初始化与记录初始版本，单纯打开不自动建仓。新建署名默认工程创作者名称且可修改，邮箱选填并明确本机占位地址；已有仓库保留身份，缺失时再设置，不改全局配置。之后按完整文件由用户手动记录，保存、助手修改与交接不自动提交。历史仅将单个现存文本文件内容载入草稿，核对后显式保存，不回退整个工程。

Git 文件范围先预览。Q18 已确认默认纳入代码、配置、文档和普通资源，排除依赖缓存、已识别敏感项及大音频／视频／模型；大资源可由用户主动纳入，预览显示体积与历史增长影响，不承诺无限制存档。已有已跟踪大资源不静默取消跟踪。交接基线资源摘要与 Git 纳入范围分别定义，具体阈值在实施任务中统一。父仓库、外部暂存和并发修改须防止提交超出预览范围。

保留 #165 的六项前序验收门控，按实际服务关系为新增能力建立独立任务和依赖，汇入 #172 的发行验收，不把所有新增任务都加成 #165 的开工前置。不重建已有模型、历史、读取、交接、检查或只读 Git 服务。1.7.0 内分批实现与实践验证，最终连贯验收“新建 → 讨论 → 调参／改代码 → 临时预演 → 明确应用 → 手动测试 → 交接 → 返回比较 → 记录版本”，包括不支持预演时的明确说明与手动测试路径。验收用例见 [#172 创作工作流验收](../acceptance/172-v1.7.0-creation-workflows.md)，需用真实模型与不同工程验证控件选择和预演适配。功能存在、自动检查通过和真实创作效果分别记录。

八组调试安排已由用户确认：G1 基础编辑、G2 助手对话与主布局、G3 工程理解、G4 参数预演基础、G5 完整讨论内创作、G6 交接比较、G7 本地版本、G8 连续流程与发行验收。具体依赖、操作步骤、通过标准和交付证据见[阶段性调试计划](./v1.7.0-staged-debugging-plan.md)。现有 22 张子任务包含后续批准的 #232～#235 上下文基础，四票在 #168 前完成；不把组号改成串行阻塞。前序开工门控不变，G1／G2／G4／G7 可按实际依赖并行，阶段结果逐组汇入 #172。未接入的后续功能单列待联调，不能用早期阶段通过代替整票完成。

## 收口与范围之外

已讨论的五类扩展均属于 1.7.0，不再保留“后续交付”排期。开发期间发现的本流程缺口与缺陷在本版补齐；后续版本根据实践调整，新的独立能力另行评估。

通用自主编程、完整 IDE／调试器、多文件自主写入、Git 分支切换／合并／远程同步、全工程历史恢复、资源备份、多人自动场景、交互录放、OSC 观测、自动音频分析及 GitHub 协作不纳入本版交付，也不是本版开工前置。
