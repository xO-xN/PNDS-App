## 当前调整目标

保留现有任务编号、#224–#230 与已验收基础；扩写 #149／#190 的定稿范围和 #166、#167、#168、#171、#172、#208、#224、#225、#226、#229 的关联契约。新增 [#231](https://github.com/xO-xN/PNDS-App/issues/231)“工程参数绑定与临时预演能力”基础票，为 #208 的讨论建议卡提供可独立验证的能力；基础编辑、Git 与参数预演不必等待模型配置。新增依赖按实际服务关系建立，汇入 #172 的最终发行验收，不把全部工作塞进旧 UI 任务或引入循环依赖。

完整交付流程为：新建并记录初始版本 → 与助手讨论并按需附加代码片段 → 在同一卡片编辑参数／代码 → 按工程能力临时预演 → 明确应用一个已有文本并查看实际差异 → 手动测试 → 确认交接与保存版基线 → 外部 agent 实现 → 返回比较工程变化 → 手动记录版本。已有工程同样可进入创作流程；无 Git 不阻断讨论、编辑和交接比较。

## 新增任务应覆盖的可验收结果

| 能力               | 必须落实的范围与边界                                                                                                                                                               |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 参数绑定与临时预演 | 连续数值与受支持非数字值按工程能力映射；本地核验真实来源、版本、限制和适配，运行会话／加载版本与保存版分别表达；结束、源变更与失败撤销可观察，不注入任意代码、不自动启停服务及音频 |
| 同卡参数／代码编辑 | 独立待应用候选；准确绑定才双向同步，表达式使无法解析的控件失效；代码输入退出旧预演且不逐键执行，明确请求预演后说明支持范围；仅应用按钮保存，实际差异不可变                         |
| 基础编辑器         | 行号；SuperCollider、JavaScript、TypeScript、JSON、HTML、CSS、Markdown 基本着色；括号、缩进、撤销／重做、查找替换、跳行与快速打开；复用保存与冲突保护                              |
| 显式片段附件       | 保存或未保存选区、来源和未保存标记、发送前移除；遵守授权、预算和历史过滤；读取开关关闭禁止发送和历史重发，保留附件与输入并提示启用或移除；不自动读取其他草稿                       |
| 交接基线           | 确认写交接单时保存磁盘版本基线，草稿明确选择先保存或只交接保存版；任务关联、重启可用、失败不伪装成功；与 Git 提交独立                                                              |
| 整体返回比较       | 全工程变化、任务文件优先；文本实际差异，二进制指纹／大小变化摘要；明确排除和未覆盖项，不自动归因或宣称验收完成                                                                     |
| App 自供 Git       | macOS arm64／x86_64 无额外开发工具可用，标准本地仓库，与外部 agent 兼容；不依赖当前系统 Git 探测作为可用保证                                                                       |
| 新建与启用版本记录 | 新工程初始化与初始提交属于创建成功条件；已有无 Git 工程主动启用并先预览范围；父仓库／嵌套范围明确处理；本地身份不改全局                                                            |
| 手动版本记录       | 后续提交由用户选择完整文件、预览保存版变化并确认说明；草稿不自动保存；防止外部暂存与并发变化导致提交范围不符                                                                       |
| 历史阅读与载入     | 查看历史与差异，仅将单个现存文本的历史内容载入草稿；处理已有草稿并经保存冲突校验，不回退整个工程、不自动刷新或提交                                                                 |

## 参数／代码与预演定稿同步

本轮采用用户确认的“按工程能力判断”原则：助手根据当前讨论和真实工程来源提出控件，App 核验绑定与约束，工程适配决定哪些值可临时生效；不按画面／声音划分范围，不把所有作品强行压成预设参数。文本、条件、表达式或函数可在同卡代码视图编辑；不能准确映射的内容保持代码编辑和显式应用，并明确预演限制。新建／跨文件／复杂适配仍需确认 handoff。
