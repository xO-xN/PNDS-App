2026-11-17 实施调整：用户确认基本测试通过并授权将终端集成合入 main。当前界面采用已确认的 C 配色与 Fira Code，保留单终端／静态交接边界；不再提供独立的常用命令表单、保存偏好或发送桥，命令直接在终端输入。下文可选常用命令条目保留为原始设计记录，以本段与开发文档中的现行行为为准。

## Problem Statement

创作者在 PNDS 创作助手中完成讨论和 grilling 后，可以交给内置「工作」，也可以复制提示词到外部 Agent。后者需要离开 App、定位工程、准备参考资料，再回到 PNDS 查看文件和验证作品。熟悉 Codex、Claude Code 或其他 CLI 的创作者，希望直接在当前工程使用自己的工具。

如果为每个 Agent 接管登录、对话和审批，再加入后台多工程、执行权锁与任务状态，首版会出现大量相互依赖的行为。当前需要先交付可靠的普通终端和清楚的方案交接，让创作者可以完成实际工作，并保留选择 CLI 的自由。

## Solution

在创作助手、版本历史所在的同一主工作区增加「终端」切换入口。全 App 只有当前可编辑工程的一个终端会话，从工程目录启动。用户可以运行普通命令或自己的 Agent CLI，也可选择保存一个常用启动命令。新会话按当前 PNDS 主题初始化配色。

grilling 的已确认方案增加「交给终端 Agent」动作：生成仅含本次方案和必要参考的静态终端任务文件，复制短提示并切到终端。已有终端继续使用，用户在 CLI 就绪后提交。Agent 通过工程保存版、装机文档和现有检查 CLI 工作；修改沿用现有文件变化检测、草稿冲突、版本差异及人工检查流程。

先验证 Ghostty 候选在 PNDS 真实宿主中足够可靠，再接入完整流程。首版没有独立 Agent 任务管理器、自动编辑锁或在线 App 信息服务。

## User Stories

1. 作为创作者，我希望从创作助手和版本历史旁切到终端，以便在同一个工作台使用命令行。
2. 作为编辑当前工程的创作者，我希望终端从实际工程目录启动，以便直接操作保存版工程。
3. 作为使用中文或空格路径的创作者，我希望终端正确处理工程位置，以便不必移动或重命名工程。
4. 作为创作者，我希望重复打开终端仍使用当前唯一会话，以便保留正在进行的命令和对话。
5. 作为熟悉命令行的创作者，我希望运行普通 shell、npm 和 Git 命令，以便使用已有工程工具。
6. 作为 Codex 用户，我希望在终端使用自己安装的 CLI，以便保留熟悉的对话和工作方式。
7. 作为 Claude Code 用户，我希望在终端使用自己安装的 CLI，以便保留熟悉的对话和工作方式。
8. 作为使用其他 Agent 的创作者，我希望自行输入其启动命令，以便不等待 PNDS 增加专用适配。
9. 作为经常使用同一 CLI 的创作者，我希望可选保存一个常用启动命令并显式调用，以便减少重复输入。
10. 作为已有 CLI 用户，我希望登录、模型选择、权限审批和恢复对话仍由 CLI 管理，以便沿用自己的工具设置。
11. 作为使用中文的创作者，我希望输入法组合期间正常选词，以便不会误提交命令或提示词。
12. 作为阅读终端输出的创作者，我希望中文、组合字符和 emoji 正确显示，以便理解命令与 Agent 回复。
13. 作为复制任务和代码的创作者，我希望可以可靠地复制选区和粘贴多行文本，以便保留内容及终端程序的粘贴行为。
14. 作为使用 TUI 的创作者，我希望终端尺寸调整和全屏界面正常工作，以便使用 CLI 的选择器与审批界面。
15. 作为运行命令的创作者，我希望 Ctrl-C、Ctrl-D 和作业控制遵循终端行为，以便控制前台作业。
16. 作为查看长输出的创作者，我希望可以滚动历史且大量输出不拖垮界面，以便继续输入和使用工作台。
17. 作为需要查看文件和版本的创作者，我希望切换工作区视图时终端继续运行，以便在命令与工程之间往返。
18. 作为临时隐藏 App 的创作者，我希望红色关闭按钮隐藏窗口时保留终端，以便返回后继续当前交互。
19. 作为选择 PNDS 主题的创作者，我希望新建终端使用当前主题的背景、文字、光标、选区和标准色，以便在工作台中保持可读性。
20. 作为运行 CLI 的创作者，我希望更换 App 主题不会重启命令，以便不丢失当前会话。
21. 作为已完成 grilling 的创作者，我希望从方案卡直接准备终端交接，以便不再手工整理整段聊天。
22. 作为有多项交接任务的创作者，我希望新动作只带入当前选定方案及已确认决策，以便 Agent 不误执行旧任务。
23. 作为保留草稿和其他聊天的创作者，我希望交接按保存版生成且不自动收录这些内容，以便明确 Agent 的输入来源。
24. 作为需要 PNDS 参考的 Agent 使用者，我希望交接文件提供实际装机文档与检查命令入口，以便工具可以在本机获取必要资料。
25. 作为查看交接概况的创作者，我希望快照标明导出时间，以便不把静态资料误当成实时 App 状态。
26. 作为已有 Agent 对话的创作者，我希望交接后复用终端并复制短提示，以便在合适时提交而不被自动打断。
27. 作为正在登录或等待审批的 CLI 用户，我希望 PNDS 不向未知状态自动输入方案，以便由我决定何时发送。
28. 作为收到 CLI 文件修改的创作者，我希望干净编辑器按现有机制采用磁盘保存版，以便回到 App 检查结果。
29. 作为仍有未保存草稿的创作者，我希望外部修改保留冲突提示及自己的草稿，以便决定采用哪一份内容。
30. 作为审阅成果的创作者，我希望使用现有版本差异、检查、编译和试听，以便按实际结果判断需求是否完成。
31. 作为准备切换工程、版本或模式的创作者，我希望可以取消离开并保留会话，以便完成正在进行的工作。
32. 作为决定离开的创作者，我希望先结束当前终端再继续原操作，以便旧工程命令不会悄然进入新工作区。
33. 作为遇到结束失败的创作者，我希望停留在当前工程并看到真实错误，以便不会误以为进程已经结束。
34. 作为结束终端的创作者，我希望已经保存的修改保留，以便结束进程不会被误作撤销工程。
35. 作为进入合并候选的创作者，我希望不会得到仍指向实际工程的终端，以便候选范围保持清楚。
36. 作为重新打开 App 的创作者，我希望 CLI 不自动重启，以便自己决定是否恢复其对话和工作。
37. 作为遇到启动或 CLI 缺失问题的创作者，我希望看到可处理的失败反馈，以便修正自己的命令而不是让 PNDS 自动安装或重新配置 Agent。
38. 作为使用演出和日志控制台的用户，我希望工程终端保持自己的用途和进程归属，以便现有运行流程继续可靠工作。

## Implementation Decisions

- **版本与交付单位。** 本功能纳入 v1.7.0-beta.5，以一张完整规格票承接最小纵向交付。beta.4 的既有任务和验收继续保留原归属；发布规格不表示 beta.4 已完成，也不自动升级当前 App 版本。交付顺序见 Further Notes。
- **工作台入口。** 在创作助手与版本历史所在区域增加终端，沿用同一主显示区与导航方式。文件、助手、历史与终端轮流显示，不增加底部终端或分屏。首次显式打开时才创建会话和加载终端资源，切视图只改变显示，不结束会话。
- **唯一会话。** 全 App 仅当前可编辑文件夹工程有一个终端会话，普通 shell 与 Agent 共用。从实际工程目录启动，不为演出、只读内容或合并候选提供实际工程终端。只记录必要的会话身份、当前工程归属、进程及连接状态，不建立终端任务状态机。
- **Ghostty 候选。** 优先验证 ghostty-web 的 WASM/Canvas 与现有 WKWebView、Rust PTY 的组合，固定实际发布包及相关上游版本。本轮研究的候选是第三方包装，不等于官方稳定 VT ABI 或 Ghostty.app 完整原生组件。采用前须验证已报告的释放重建、隐藏绘制、粘贴和主题缺口，不能仅以 API 存在判断可用。
- **宿主与传输。** 控制动作沿用类型化原生命令；终端输入输出走有序字节流，明确会话归属、EOF、退出和错误。使用有限队列、分批消费、背压和有限滚动历史，保留跨分片的原始字节，拒绝旧会话迟到数据。终端字节与逐帧绘制不进入 React 状态更新。仅隐藏 DOM 不等于暂停绘制，隐藏时继续消费必要输出并停止无条件绘制循环。
- **进程所有权。** PTY 与工程演出进程分开管理。终端负责自己启动的 shell、前台作业及实际受管进程的有界结束；shell leader 退出不能替代对受管作业的确认。Ctrl-C 交给终端前台作业，不默认结束整个会话。不误杀演出，也不承诺收回用户主动脱离终端托管的任意进程。
- **基础交互。** 提供真实 PTY、键盘输入、中文输入法、Unicode、复制粘贴、选区、尺寸调整、alternate screen 和必要终端查询回写。终端获得焦点时核对键盘归属，沿用现有 App 快捷键约定，不顺带重做全局快捷键或把现有关闭窗口行为改成结束终端。
- **通用 CLI。** 用户自由输入任意已安装 CLI 的命令，首批真实验收 Codex 和 Claude Code。可通过现有偏好机制保存一个常用启动命令，仅由用户显式调用；不建立配置库、逐 Agent 参数适配或登录状态轮询。CLI 自己负责登录、模型、审批和对话恢复，不读取或复制其凭据，不自动写入项目指令或全局配置。
- **主题初始化。** 新会话从 PNDS 当前主题获取实际颜色，覆盖背景、默认文字、光标、选区和标准 16 色。四套主题各自保留颜色含义与可读性，不另建全局主题状态。索引 0–15 即使通过扩展序列选择，仍属于标准色板；其余显式扩展色与 RGB 保留。已有会话完整热换色后置，切 App 主题不重建终端或 CLI。
- **方案交接。** 第三个动作使用当前选定的已确认方案及已答决策，生成静态终端任务文件、复制短提示并切到唯一终端；不额外请求模型重新设计或总结。现有外部提示词继续承接整份当前创作交接单，新动作不能直接复用其中的「完成全部当前任务」语义。
- **静态输入。** 任务文件提供本次方案、范围与验收、工程保存版位置、实际装机文档位置和现有检查 CLI 用法，不假设命令已在 PATH。可附明确标时的导出概况，不以获取实时状态为生成前置。不默认带入其他聊天、未保存文件、未选素材或用户秘密，也不自动保存或丢弃草稿。任务文件需在用户提交给 CLI 后保持可读；采用私有落点，并核对工程版本、共享上传及打包排除边界。
- **发送时机。** 已有终端不重启、不自动输入；由用户在 CLI 就绪后提交已复制的短提示。明确配置的新 CLI 可以通过结构化启动参数接收短提示，但自动传参不是 beta.5 首次可用闭环的前置条件。不拼接方案正文为 shell 命令，不把未知 TUI、登录或审批状态当作就绪信号。
- **修改与验证。** CLI 以用户本机权限直接工作，工程目录只是起点。文件修改按外部编辑处理，沿用现有 watcher、干净文件采用、脏草稿冲突保护和版本差异。用户自行协调手动编辑、内置「工作」与 CLI，首版不自动锁定工程。CLI 改动不自动获得内置 Work journal 或整任务撤销。进程退出不表示需求完成，文件保存不表示运行版已刷新、重启或编译。
- **离开保护。** 切助手、历史、文件视图或隐藏窗口保留当前会话。切换工程、替换工程版本、进入合并候选、离开创作或退出 App 时，活跃会话提供「结束并继续」与取消；无活跃会话沿用原流程。成功结束后才执行原操作，取消或结束失败保持当前归属。保留原有草稿、运行与版本检查，不用新确认绕过旧保护。结束不撤销磁盘修改；重开 App 不自动启动 CLI。
- **保持边界。** 不新增 Node/Bun 服务、HTTP/WS 服务、独立 WebView 或完整终端窗口系统。若 Web 候选无法可靠通过关键门槛，或需要重写 renderer/WASM 内部，回到原生完整 Ghostty 路线比较成本，不静默扩大首版。不以「轻量」替代输入正确性、进程清理或实测证据。

## Testing Decisions

- **一个主要入口。** 通过创作工作台的真实用户操作覆盖「方案卡第三动作 → 静态任务文件与短提示 → 唯一终端 → 文件变化 → 版本审阅与离开保护」。使用真实工作台及现有 store/flow，只在最外层原生命令、剪贴板及终端传输提供可控替身。不 mock 掉被验证的业务流程，不依赖私有 helper、组件拆分或内部状态形状。
- **可观察断言。** 核对当前方案和决策的准确交接、旧任务排除、无额外模型请求、已有会话复用、无自动输入、切视图保留、保存版来源、草稿冲突、无自动刷新/编译/启动、取消离开、结束失败、成功后切换及迟到输出不污染新工程。不得把按钮可点击、进程退出或 Agent 自述当作完整验收。
- **既有测试先例。** 优先扩展现有讨论交接、工作台导航与标签、文件同步和草稿冲突、创作模式切换、版本切换失败保护等行为测试。无需为该功能重建编辑器、交接调度或一套新的测试平台。
- **必要原生接缝：真实 PTY。** 使用临时工程及确定性 fixture，经公开原生命令/会话边界验证 isatty、cwd/env、中文和空格路径、双向字节流及 UTF-8 分片、resize、退出/EOF、受管作业清理和过期会话拒绝。延续现有受管进程的真实进程与有界清理测试原则，但不能把普通 Child 测试当作 PTY 已覆盖。CI 不依赖付费 Agent、个人账号或凭据。
- **必要原生验收：真实 WKWebView/WASM。** 在 macOS 核对中文 IME、复杂 Unicode、复制与 bracketed paste、Codex/Claude Code TUI、终端查询、resize、作业控制、反复创建销毁、隐藏后返回及四主题初始化。检查生产资源/CSP 和双架构打包；jsdom 全局原生 mock 不能证明这些行为。沿用现有原生宿主验证方式，不建设新的通用自动化平台。开发服务器仍由用户启动并回报。
- **轻量证据。** 记录引入前后的包增量、首次打开、空闲及隐藏 CPU/RSS、高输出输入延迟、有限历史和现有音频/monitor 负载表现。区分实际测量、上游报告和未验证项，不宣称已证明全路线中最轻。基础输入、隐藏绘制、释放重建或音频稳定性存在关键未解问题时，不以完成业务按钮放行。
- **交付完成标准。** 新业务逻辑随实现带行为测试，`npm run check:all` 全绿，并完成下列真实场景验收。仅发布规格、实现命令或跑通模拟输出不算 beta.5 已交付。

### 场景验收

| 场景          | 操作                                                                             | 可观察结果                                                                           |
| ------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 01 普通终端   | 在中文/空格路径的可编辑工程打开终端，执行读取、写入与 Git/npm 基础命令           | 实际 cwd 正确，输入输出可用；App 中只有该工程一个终端                                |

| 05 四套主题   | 分别选择四个主题后新建终端，显示默认色、标准色与显式 RGB，再切 App 主题          | 新会话色板清楚可读且保持语义；显式其余颜色保留，运行中 CLI 不被重启                  |
| 06 当前方案   | 预先存在旧交接任务，选择新 grilling 方案并点击第三动作                           | 文件和短提示只承接选定方案与已答决策；无额外模型请求，无独立终端任务记录             |
| 07 输入来源   | 保留未保存草稿、其他聊天和未选素材，再准备交接                                   | 交接明确使用保存版及必要参考，未擅自保存、丢弃或导出其他内容；快照有时间标记         |
| 08 已有 CLI   | CLI 正在登录、等待审批或已有对话时准备另一份交接                                 | 同一终端继续，短提示复制成功但未自动输入，由用户决定何时提交                         |
| 09 文件回流   | CLI 分别修改干净文件和已有脏草稿的文件                                           | 干净文件沿用 watcher 采用，脏草稿保留冲突；不自动刷新、编译或启动运行版              |
| 10 审阅验证   | 查看版本差异，手动运行现有检查、编译及试听                                       | 结果对应实际磁盘与操作；CLI 退出或输出「完成」不会产生 PNDS 任务完成记录             |
| 11 离开与取消 | 活跃终端下切工程、切版、进候选、离开创作和退出；分别取消、成功结束、注入结束失败 | 取消/失败保持原工程与会话；确认结束成功后才继续原操作，原有草稿和版本保护继续生效    |
| 12 终止归属   | 运行前台/受管子作业，测试 Ctrl-C、EOF、会话结束、重开与迟到输出                  | 信号和清理归属正确，不误杀演出；旧输出不进入新会话，磁盘改动保留，重开不自动启动 CLI |
| 13 失败处理   | 模拟 shell 启动失败、CLI 不存在、字节通道中断及发布资源加载失败                  | 如实报告失败，无假运行或假结束；可由用户修正/重新打开，不自动安装 Agent 或写全局配置 |
| 14 真实发行   | 在 arm64/x86_64 发布构建反复开关、长输出、隐藏返回，并同时使用现有音频/monitor   | 本地 WASM/CSP 可用；关键生命周期问题已验证，开销有记录，输入和既有音频流程稳定       |

## Out of Scope

- 多工程后台终端、全局会话配额、分屏、独立终端窗口、Shell/Agent 双标签与启动配置库。
- App 自动只读、执行权锁、Work/CLI 串行调度、操作系统权限沙箱，以及保证阻止所有外部并发修改。
- 独立终端任务记录、比较基线、待审阅/完成状态、结果自动回收、归档、跨重启自动接续、后台任务通知和自动推断 Agent 状态。
- 新 PNDS 在线只读 CLI/App IPC、MCP、动态素材查询、实时 App 日志/状态查询，以及把现有受管 writer 工具直接暴露给 CLI。
- 逐 Agent SDK、App Server/ACP 适配、代管登录/订阅/模型/审批、自动安装 CLI、读取会话数据库或自动选择最近对话。
- 已有会话完整实时换肤、历史重着色、主题市场、完整 256 色自定义，以及通过重启 CLI 达成换肤。
- SSH 管理、图片协议、复杂 shell integration、终端搜索插件和完整终端模拟器产品生态；不得据此暗示候选已具备这些能力。
- 改写现有外部交接单范围、为 CLI 提供 Work 整任务撤销、自动运行检查/编译/试听、自动保存工程版本或自动 GitHub 上传。
- 本次规划期间的产品编码、版本号升级、commit、发布或用户真实 Agent 执行。

## Further Notes

- **阶段 A：验证采用资格。** 固定 Ghostty Web 候选并完成真实 PTY、WKWebView、主题初始化、隐藏/销毁与资源开销验证，记录必要局部补丁和双架构结果。先验证已知关键问题，再决定出货依赖；验证失败不能以业务流程完成替代。
- **阶段 B：接入最小工作台。** 建成当前工程唯一终端、普通 CLI、主题初始化及离开保护，沿用现有文件/草稿/运行边界。通过公开工作流与真实进程测试后，再接入方案交接。
- **阶段 C：完成简单交接。** 接上当前方案静态文件、实际装机资料与检查入口、短提示复制和终端切换，验证旧任务不会误带入、已有 CLI 不被重启或盲贴。
- **阶段 D：联合验收。** 覆盖完整场景、真实 Codex/Claude Code、双架构发布构建与音频/monitor 负载，记录自动化、实机与未验证项。阶段为同一规格内的实施顺序，不新建额外业务任务状态；后续是否拆执行票另按仓库任务流程处理。
- 产品决定来自[收束后的设计访谈](./embedded-terminal-grilling.md#q22已确认收缩首版)和 [ADR-0022](../adr/0022-project-terminal-execution-boundary.md)。现有外部创作交接单语义继续遵循 [ADR-0008](../adr/0008-creator-handoff-as-agent-seam.md)。旧 Q1–Q21 中退出首版的方向不恢复为本版要求。
- 技术事实、上游报告与未实测限制见[Ghostty 与 Agent 评估](../research/embedded-terminal-agent-evaluation-2026-11-16.md)。真实终端是本机执行能力，静态交接暂不提供内置创作助手的全部实时信息能力。
- `ready-for-agent` 表示规格具备后续领取实施的范围，不表示本轮已开始编码或功能已验收。仓库本轮已有完整检查在多项现有 UI 测试失败后中止，不能作为全绿基线；后续实现交付仍须完整检查通过。
