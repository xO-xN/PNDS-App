# v1.7.0-beta.4：创作资源媒体接入与助手文件引用

目标版本 **v1.7.0-beta.4**。设计与 A 版交互已确认。跟踪票 [#333](https://github.com/xO-xN/PNDS-App/issues/333) 标记 `ready-for-agent`，附有[完整 A 版 HTML 原型](https://github.com/xO-xN/PNDS-App/issues/333/artifacts/1)。

## Problem Statement

创作者现在可以把文本放入创作资源。图片与录音仍需在 App 外查看和试听，找到用途后又要手动决定工程位置、复制文件并修改代码。试听与作品测试也容易走不同的输出设备。向创作助手交代任务时，创作者还需要手动写出工程文件路径，才能指明要讨论或修改的代码。

## Solution

将创作资源扩展为当前工程的私有待用区。创作者拖入文本、图片或音频后，在同一个左栏列表找到它们，并通过中栏标签编辑、看图或试听。试听跟随底栏所示的输出设备。工程文件和待用资源都能拖到创作助手输入框，作为可移除的文件引用随消息发送。

创作者在「工作」中交代资源用途。助手结合工程现有代码选择目的地并修改使用资源的代码，App 在本机完成媒体文件复制。接入完成后，一起移出本次使用的待用资源，并留下可从工程菜单打开的恢复记录。

## User Stories

1. 作为创作者，我希望左下「创作资源」保持固定比例，以便空收件箱和大量文件时都能找到投放位置。
2. 作为第一次使用收件箱的创作者，我希望空态有收件箱图标和「拖入资源文件」提示，以便识别拖放区域。
3. 作为偏好用系统文件选择器的创作者，我希望点击标题栏里的收件箱图标多选文件，以便按我的习惯导入。
4. 作为同时使用不同类型素材的创作者，我希望一次放入文本、图片和音频，以便快速备齐本次任务。
5. 作为正在编辑的创作者，我希望导入的文件先出现在左栏，以便继续手上的工作并决定何时打开它们。
6. 作为批量导入的创作者，我希望看到失败的文件名和原因，以便只补救未成功导入的文件。
7. 作为有许多待用资源的创作者，我希望资源列表能独立滚动，以便仍能浏览上方工程文件。
8. 作为搬迁工程的创作者，我希望暂存文件随完整工程目录迁移，以便原件位置改变或重开工程后仍可继续。
9. 作为分发工程的创作者，我希望私有暂存和恢复数据排除于工程版本和默认演出包，以便选择何时让资源进入交付。
10. 作为写代码或记录想法的创作者，我希望在同一个中栏编辑器编辑新建和导入的文本，以便沿用保存键与草稿体验。
11. 作为在多个文件之间切换的创作者，我希望未保存的文本草稿保留，以便稍后继续编辑。
12. 作为正在挑选图片的创作者，我希望图片默认适合窗口，并能缩放到 100%、继续放大、拖动查看和恢复适合窗口，以便看清画面细节。
13. 作为试听录音的创作者，我希望点按播放才发声，并能暂停和定位到较长录音的任意段落，以便核对素材。
14. 作为使用声卡或耳机的创作者，我希望试听跟随底栏显示的输出设备，以便清楚知道声音从哪里出来。
15. 作为 Internal 测试运行中的创作者，我希望试听继续走当前生效设备，以便改选下次启动设备时不会听到两个输出。
16. 作为使用 External、None 或已将工程静音的创作者，我希望仍能主动试听并单独调整试听音量，以便检查素材。
17. 作为拔下所选声卡的创作者，我希望试听停止并说明原因，以便避免声音突然从其他设备播放。
18. 作为在助手输入框编辑消息的创作者，我希望拖入工程保存版文本或待用资源作为文件引用，以便少输入路径。
19. 作为用键盘操作的创作者，我希望通过同一个「添加文件引用」入口选取工程文件和创作资源，以便用另一种方式完成同一个动作。
20. 作为已经写了一部分消息的创作者，我希望添加文件时保留文字、光标位置和讨论／工作模式，以便继续当前草稿。
21. 作为同时引用同名文件的创作者，我希望能看见工程相对路径，并能移除或去重引用，以便确定本次请求的文件。
22. 作为在「讨论」中核对代码或资源的创作者，我希望发送后才提交引用，以便只在我明确发出消息时请求助手。
23. 作为正在编辑工程文件的创作者，我希望文件引用使用保存版，未保存选区仍可通过现有附件流程分享，以便知道助手看到了哪一份内容。
24. 作为将工程文件拖到 Finder 的创作者，我希望继续得到保存版的副本，以便原有导出操作照常可用。
25. 作为把音画交给助手的创作者，我希望它根据当前工程和用途确定位置并改好引用，以便图片真正出现在页面或音频能被使用。
26. 作为把素材用于本地工程的创作者，我希望助手只获得媒体元数据，以便原始图片和录音留在本机。
27. 作为有多个相似候选的创作者，我希望助手先询问具体文件或用途，以便避免选错资源或接到错误入口。
28. 作为把未保存文本加入「工作」的创作者，我希望能保存并继续，或取消回到草稿，以便助手按我确认的保存版本接入。
29. 作为目标位置已有同内容资源的创作者，我希望复用它并更新引用，以便避免存放无用副本。
30. 作为目标位置已有不同内容文件的创作者，我希望看到并存、替换和取消，以便保留对工程文件的决定权。
31. 作为同时接入背景图、采样和说明文档的创作者，我希望整次任务通过核对并可恢复后才一起移出待用列表，以便半成品仍能继续处理。
32. 作为遇到检查失败、取消或过期结果的创作者，我希望暂存原件保留并看见已保存的修改，以便继续修正或撤回。
33. 作为演出正在运行的创作者，我希望在确实无法运行检查时看到已接入及未验证原因，以便知道还要核对什么。
34. 作为撤回接入的创作者，我希望能恢复任务改动和原件，也可以仅恢复原件，以便按当前工程状态选择恢复方式。
35. 作为接入后继续编辑的创作者，我希望恢复保护较新修改和同名暂存文件，以便避免覆盖后续工作。
36. 作为核对助手交付的创作者，我希望看到实际资源位置、变动的代码或引用和验证结果，以便用工程测试核对真实音画。

## Implementation Decisions

- **A 版中栏。** 左侧保留工程文件树和「创作资源」。资源分组固定在左下，评审原型取左栏高度的 34%，空态与有文件时比例一致。标题只有新建文本文件、收件箱两个图标入口。空态只展示收件箱图标和「拖入资源文件」，该区域接受拖放。标题中的收件箱图标打开系统多选文件。导入完成在左栏列出，由创作者点选打开。
- **私有暂存。** 延续 ADR-0012 的工程内私有数据边界。文本保留现有版本、编辑和恢复流程。媒体按原始字节保存，使用适合媒体大小的本地文件操作和元数据列表。发布成功后才显示待用条目。完整工程复制包含暂存与恢复，Git、默认演出包和运行检查排除私有数据。保留外部原件。
- **中栏预览与编辑。** 复用现有待处理文档编辑器、显式保存、`⌘S` 和草稿协调机制。图片按需加载，支持适合窗口、100%、缩放及放大后平移。音频按需打开，提供主动播放、暂停、进度定位和独立音量。切换资源、工程或退出创作模式时停止试听。格式、解码和容量上限由实机验证后确定，覆盖常见图片和 WAV／MP3 以及长录音。
- **试听路由。** 当前工程的 Internal 测试运行时采用底栏显示的已生效设备，其余情况使用底栏当前选择。只有用户选了系统默认才走默认设备。指定设备断开时停止并提示，External、None 和工程静音时仍可主动试听。复用现有设备解析和 macOS 播放能力。试听使用本机输出和独立音量，工程运行继续按其会话音频配置工作。
- **文件引用。** 工程树中的可读保存版文本及创作资源可拖入助手输入框，选择器和拖放共用同一消息草稿。展示可移除的标签，工程文件按完整相对路径区分与去重。拖入时显示明确的接收提示，保留文字和讨论／工作模式，由创作者主动发送。保留现有显式选区附件、对保存版的文件权限和 Finder 的复制拖放。工程文件引用用于本次请求上下文，待用资源由明确的「工作」任务接入。
- **助手接入。** 助手取得文件名、类型、大小及可取得的图片尺寸或音频时长，结合现有代码和任务用途决定存放位置、加载方式和引用。用途清楚且资源唯一可确定时直接继续，多个候选或用途不清楚时先问。App 按资源身份和版本在本机复制媒体原始字节。文本草稿沿用保存并继续和重新读取保存版。
- **目标冲突。** 内容完全相同的工程文件可以复用。不同内容由创作者选择并存、替换或取消，推荐并存。并存更新代码指向另一个文件名。替换核对确认过的目标版本并记录可恢复的原内容。
- **接入完成与验证。** 同一次「工作」采用的文档、图片和音频共同核对目标和引用。持久化恢复记录后才一起移出待用列表。仅查看的候选留在列表。失败、停止或结果过期时保留所有暂存原件，报告已保存的部分修改，可继续或撤回。静态检查通过且运行检查确实不可执行时，记录「已接入，尚未运行验证」及原因。受控检查通过与实机音画验收分别记录。
- **恢复。** 工程菜单「最近一次接入恢复」提供整次撤回和仅恢复原件。整次撤回按任务版本校验所写文件，删除任务新建文件、恢复任务替换前的内容并保留同内容复用文件。受影响的文件已有较新修改时保留修改，可选择仅恢复原件。恢复原件遇同名冲突时保护已有暂存文件。
- **运行资产。** 助手按工程的页面或 SuperCollider 加载方式适配代码。Blank 的页面音频验收包含实际静态文件服务。已接入的媒体使用工程普通路径与现有版本和打包规则。通过真实路径与加载结果核对接入。

## Testing Decisions

- 从三个现有入口观察用户可见结果：创作工作台与助手输入框、带真实临时工程的原生命令与「工作」接入流程、正常工程运行与 macOS 实机试听。以用户动作、可见状态、实际文件、请求范围、运行结果和恢复结果为断言。
- 沿用创作资源、待处理文档编辑器和工作台的组件测试。覆盖空／满分区、空态点按不唤起选择器、标题收件箱多选、混合导入、导入后待用、图片缩放、文本草稿与保存。验证工程文件和创作资源拖入同一消息，提示、去重、删除、键盘选择、保留输入与模式、主动发送及保存版边界。验证媒体正文未进入模型请求。
- 沿用真实临时工程的待处理文档、助手任务、冲突和恢复测试。覆盖私有暂存持久化与工程复制、混合任务全部完成后移出、内容相同复用、三种冲突选择、失败／取消／过期保留、确实不可运行时的标记、恢复记录持久化、整次撤回、仅恢复原件及后续编辑保护。核对源文件、目标原字节与引用，以及私有数据的 Git、打包和运行检查排除。
- 以真实「工作」任务验收三条运行路径：图片作为 performer 背景、音频由页面加载播放、WAV 由 SuperCollider 加载为采样。分别记录选中的路径、代码或引用、静态与受控运行证据，以及创作者实际看到和听到的结果。
- 在 macOS 实机令系统默认输出与 PNDS 底栏设备不同，核对听到的实际设备。覆盖 Internal 运行时改选设备、重启后生效、External／None／工程静音下主动试听、拔出设备、切换工程、长录音进度定位，以及 Finder 复制拖放。记录验证过的格式、容量和硬件配置。
- 新业务逻辑随改动提供测试，正式交付以 `npm run check:all` 全绿为准。浏览器原型交互记录用于评审，原生输出与真实助手任务需要各自的验收结果。

## Out of Scope

- 创作助手分析图片画面、理解录音内容、上传媒体正文、转码或生成波形。
- 新增手动「复制到工程」流程、跨工程全局素材库或媒体同步服务。
- 创作助手 `@` 技能、建议输入、双语 README 制作和相关快捷入口。本票覆盖同一输入栏的文件引用。
- 扩展普通工程文件树的媒体试听范围，以及改动工程音频模式、演出总线和设备偏好协议。
