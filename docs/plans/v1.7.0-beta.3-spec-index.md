## 本版范围

- 同一池主的稳定局域网 HTTP 公开入口，浏览器与原生 PNDS Client 共用；安装可选，首次接入及保存入口不要求公网，独立窗口按平台提供。
- 新工程自动发现、演奏者单击进入；失联、停演及新候选不销毁当前文档，主动切换失败保留原实例，成功后才替换。
- 正常只显示工程内容；原生管理留在 App 侧栏。Host 侧栏运行大卡、演出独立 QR 和投影 QR 覆盖撤下，公开地址／复制／QR／入口故障与诊断统一到下栏网络区，创作测试扫码保留。
- App 空闲、创作或池客期间继续持有公共入口，但不自动公开创作测试；跨重启优先复用旧端口，冲突允许避让并提示更新入口。
- 浏览器按池主／工程复用保存身份，不承诺跨地址、浏览器或图标实例自动迁移；原生私有来源和既有恢复能力保持。
- 九个已确认维护源与工具发行资源继续按原子票适配；ASBS 完整本人分谱资源预取和断主机继续滚谱纳入配套验收。新建起点按 #315 收敛为唯一 Blank，既有 Classic 工程保留兼容。
- 保留既有 HTTPS 路径和浏览器能力上限；未适配外部工程提供明确标注的人工旧地址回退，不静默跳转。

## 与既有规格的边界

- [#258 池主／池客](https://github.com/xO-xN/PNDS-App/issues/258) 与 [#259 运行端口](https://github.com/xO-xN/PNDS-App/issues/259) 是既有基础：继续沿用稳定身份、实际监听器与端口归属，不另建分配权威。新规格明确修订核实停演／换工程就销毁文档的旧行为，不放弃新演出确认或旧上下文隔离。
- [ADR-0017](../adr/0017-stable-browser-performance-entry.md) 记录新决定，并修订 ADR-0013 的演出 QR 呈现及 ADR-0014 的文档生命周期边界。单 App 单活动角色、工程音乐协议、既有录制与音频归属继续保持；被动等待入口在线不等于运行第二场 Host 演出。
- [逐轮讨论](./2026-11-09-browser-participation.md) 保留问答、实际代码核对、维护源精确位置／输入版本和历史检查记录。正式实施与验收以本版规格和跟踪票为准，不把讨论记录或此前基线检查当作新功能已完成的证据。
- 具体接入协议、工程能力字段和就绪机制在实施首阶段通过真实浏览器／原生链路验证后固定，不重新访谈已确认产品范围，也不以未经验证方案静默改变行为。

App 完成标准为 `npm run check:all` 全绿，维护源适用检查与构建通过；原生双架构、最低支持系统、真实手机／平板、媒体、声音及无公网场地另记实机证据。开发服务器由用户启动并回报结果，提交、打标签和发布继续按明确指令执行。
