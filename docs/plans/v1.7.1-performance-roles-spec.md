## 产品范围

功能纳入现有 PNDS App，作为 v1.7.0-beta.2 的一部分，自动管理端口与冲突避让同版交付，暂不发布独立版。此安排取代原 v1.7.1 计划。保留演出／创作两种模式，在演出模式内增加池主／池客角色。每次进入演出模式重新选择角色，不恢复上次角色，也不自动开始或加入演出；全局节点名与最近连接分别保存，不因角色重选而自动清除。

同一 App 同时只承担一种角色。池主运行工程并提供参与入口；池客在 PNDS 主窗口内打开工程的 performer 页面，通过场地局域网参加本地演出。池客不因此成为跨互联网 hub 节点，也不因安装完整 App 而启动池主的工程服务或 scsynth；工程页面自身的媒体能力与业务仍归工程。

池客同时只加入一台池主的一场演出，显示一个演奏页面；换池主须先离开。该限制不改变创作模式已有的多个测试窗口能力。

池主必须显式填写全局节点名，不使用电脑名回退；本地接入不要求填写 hub 地址或 token。最近连接按稳定池主身份组织，节点名只是显示名，同名设备不得合并，改名或换工程不另建同一池主的记录。

## 界面

沿用现有 320px 浮动侧栏、50px 底栏、系统字体与四主题，不增加 App 顶部工具栏。中文角色标签只显示「池主／池客」，英文只显示「PNDS Host／PNDS Client」。

首次角色选择占据左侧栏。进入角色后收拢为斜线按钮：默认显示当前角色，悬停或键盘聚焦提示目标角色；空闲首击提示再次点击，第二击提交。Esc、外部点击或窗口失焦取消未提交的确认；减少动态效果时不等待动画。按钮在确认过程中保留同一 DOM 与焦点。

演出、加载、待接纳、断线重连和退出清理期间拒绝角色切换，在按钮内提示先退出，不弹框、不自动停止演出。确认连接与媒体资源已清理后才解除锁定；清理失败保留失败状态并可重试，不提前宣称退出完成。

池主保留现有工程选择与运行能力；节点名未填写时提供设置入口并阻止开始演出。池客侧栏显示地址、最近池主与当前连接；加入后沿用浮动显隐。池客底栏提供离开、刷新、设置，不显示池主的音频引擎、投影与工程管理操作。传感器控件由工程页面提供。

Q25 已确认：池客刷新首击仅在按钮内提示「再次点击刷新谱面」，第二击才重载当前池客页面。先释放旧页面媒体并核验当前演出；若演出已变化则显示变化通知，仍须明确确认加入。刷新不重启池主，保留网页存储；媒体按工程正常启用流程恢复，不保证未保存的演奏状态。

主动离开后回到池客连接页，保留最近连接与池客角色。池客进入创作前结束本地参与并清理，再进入本机创作首页；池主保留 ADR-0007 已有接续。返回演出模式重新选择角色。

## 连接与演出身份

接入至少区分稳定池主身份、工程信息和本次演出身份。节点名、IP、前端本地 runId、manifest projectId 都不能单独承担这些职责。池主关闭后再次启动，即使工程相同，也属于新的演出；普通网络中断不改变本次演出身份。

最近连接保存的目标身份与地址分别核验。地址返回另一台池主时，保留旧记录并停止直接加入；用户明确选择新池主后，才建立或更新对应池主记录。用户更新原池主地址时，核验身份相符后才替换该记录地址；不通过名称或 IP 猜测设备。

每次真正进入工程前，池客必须持有用户确认的接入上下文。上下文不能因后台探测发现另一工程或另一演出而静默覆盖。Host 在请求／实时连接进入工程之前验证目标仍是该上下文对应的运行；不满足时拒绝转发。仅在旧页面已自动加入后显示提示，不满足本规格。

### 拟定的技术组织，待完整规格总览确认

Host 由 App 提供可查询名称、兼容协议与当前演出信息的入口，并把已确认接入绑定到当前工程运行。入口生命周期与工程启停可分别表达，使客户端能区分“池主在线但演出已结束”与“池主不可达”。不能直接公开含工程绝对路径、日志等本机信息的 SessionSnapshot。

池客启动仅绑定回环接口的入口，内嵌 performer 页面从本机来源获取 HTML、脚本、Worker、模型与 Socket.IO。网络请求由受管转发层进入 Host；HTTP polling 和 WebSocket 均须受接入上下文检查约束。连接门禁不解析或替换作品的音乐事件。

池客填写或粘贴池主显示的完整局域网连接地址即可，复制地址只是输入辅助；首版不增加独立邀请机制。普通使用不要求乐手配置证书、DNS 或手填池客本机代理端口。网络地址需要包含入口的实际端口，不承诺仅输入纯 IP 就能定位可变端口，也不因此加入自动发现。此澄清不把任意旧版工程地址变成兼容接入，不静默改变当前手机二维码或 performer URL 契约。具体公开路径、端口与协议字段在技术验证后固定。

工程页面使用低权限 WebView／frame，不获得创作侧文件写入、模型凭据或其他管理命令。网络转发、运行身份和清理归 Rust，React 显示事实并发送类型安全命令，不读取或解释谱面 DOM 来猜测业务状态。

## 状态与反馈

| 情况                         | 页面、媒体与连接处理                       | 对用户的反馈                                     |
| ---------------------------- | ------------------------------------------ | ------------------------------------------------ |
| 地址无效或池主不可达         | 不建立演奏页面，保留输入，可重试或返回     | 指出地址或连接问题，不宣称已加入。               |
| 池主接入协议不兼容           | 不降级绕过校验，不进入工程                 | 提示池主升级。                                   |
| 最近地址返回不同池主         | 不发送原目标的加入信息，不覆盖原记录       | 展示目标变化，用户明确决定是否加入新池主。       |
| 页面打开且工程已接纳         | 保留当前页面，媒体按工程与用户权限运行     | 显示实际接纳状态。                               |
| 页面打开但工程不报告接纳     | 允许使用兼容页面，不能据 onLoad 推断已加入 | 显示谱面已打开／工程未提供连接状态。             |
| 同次演出短时断线             | 保留同一页面与媒体意图，沿用工程重连逻辑   | 显示连接中断，提供离开，不自动重载。             |
| 核实池主已换工程             | 立即断开、销毁旧演奏页面并释放媒体         | 显示演出已变化；明确确认后才加载新工程。         |
| 池主明确关闭演出             | 结束参与并释放媒体                         | 显示演出已结束；随后同工程重新启动也须明确加入。 |
| 主动离开／切入创作／退出 App | 先清理页面、代理、媒体与异步操作           | 清理完成后再返回、切换或退出；失败可重试。       |

无法确认池主状态时仅表达连接中断，不把无响应猜成演出结束。工程端的名册、座位、采样缓存与音乐状态仍由工程负责；App 不统一保证跨工程或跨服务器重启恢复同一座位号码、推子或声音状态。

## 网页数据保留

Q23 已确认：按池主与工程隔离并保留网页存储，例如 claim token，供退出或重启后下次手动加入。保留数据不等于自动加入，不替代新演出的明确确认，也不保证恢复工程未保存的音乐状态。

网页存储与一次演出的确认是不同职责。在当前 macOS 基线上验证可持续使用的隔离方式，不能通过每次运行换来源破坏既有身份恢复；具体存储分区与稳定工程标识仍须技术验证，不由池主名称或本次演出身份代替。

## 工程兼容范围

Q21 已确认。[具体说明与示例](./v1.7.1-performance-roles-design.md#q21-所指的工程兼容约定)区分现有完整入口／同源资源及实时连接要求，与 App 新增的身份、加入前校验和转发职责。工程不负责实现池主身份服务，也不因使用池客功能更换音乐消息协议。

以声明且实际遵循这些入口约定的工程为首版支持范围；未声明先核对，需适配时给出具体问题，池主原有运行能力保持。不得把 `supportsPerformerUrl` 当成已接纳、提供名册或支持摄像头的证明；缺少声明也不直接证明页面实际不兼容。可选接纳反馈的处理已由 Q20 确认，不是工程准入的必需条件。

## 自动端口管理与职责

Q26 的纳入范围已确认：自动管理端口与冲突避让随池主／池客功能进入 v1.7.0-beta.2。区分 Host 局域网入口、工程 performer／monitor 端口与池客回环端口；入口优先复用、冲突后显示更新地址，运行中不迁移。网页存储稳定性须同时通过 Q23 验证。

用户询问是否由作品选择端口。本轮建议明确职责为：App 统一负责端口策略、分配、避让、实际结果登记与地址发布；已适配工程按 App 提供的运行配置监听并报告成功／失败，App 核验后才发布接入地址。底层操作系统分配及监听器交接属于实施机制，工程不独立挑选或切换已发布的端口。旧工程仍走 manifest 固定端口兼容路径，不静默改端口，也不写回 manifest。

依据与现行限制见[端口冲突分析](./v1.7.1-performance-roles-design.md#端口冲突核对与-q26-建议2026-11-03)。当前冻结契约仍是监听 manifest 端口、冲突失败；更改外部转发端口不能解决工程内部 6868／6869 的冲突。自动分配须增补能力与运行端口协商，更新实际端口快照、preflight、启动、health、monitor、网关与端口归属核验，不能只在界面上改数字。

版本范围及产品行为已确定，端口职责与技术方案纳入最终总览。HTML 已补齐两击刷新、实际地址／端口详情与不同适配问题的内存演示，供用户核对整体 UI／UX。WebView 媒体、持久存储、转发与门禁方案仍通过实机和集成测试验证，不转化为用户需要回答的底层实现问题。整体方案尚待用户核对，不据原型直接开始正式功能实现。

## 实施顺序

1. **技术验证先行**：用两台真实设备，在当前支持的 macOS 基线验证内嵌 WebView 的回环安全上下文、摄像头／麦克风授权、Sensor Meter Worker 与模型、后台恢复和页面销毁释放。验证按池主／工程隔离且可恢复的数据存储方式。未通过前不把 UI 原型升级为可发行功能，也不静默改为外部浏览器或提高系统基线。
2. **Host 接入、运行端口与门禁**：增加稳定池主身份、节点名门禁、协议兼容信息、当前演出身份及受管入口。建立明确的运行端口适配能力，App 以实际绑定结果驱动启动、health、monitor、网关和端口归属核验；旧工程保留 manifest 兼容路径，实施时同步更新双语冻结契约及工程适配说明。保持现有本机音频、手机入口和跨互联网节点职责。使用真实 TCP/HTTP/WS 测试证明旧上下文无法进入新工程，并证明首选端口被占用时适配工程能使用实际分配端口。
3. **Client 连接与资源所有权**：实现加入／取消／离开、受管回环转发、低权限演奏页面、异步结果归属与清理。网络丢失保持当前页面；接入上下文变化先关闭旧页面。
4. **界面与持久化**：接入角色选择与斜线按钮、最近池主、身份冲突、演出变化、未知接纳与升级提示。状态按 Zustand selector、命令桥、i18n 和 CSS 逻辑属性规范实现；持久化只走既有 preferences 更新队列，不持久化演出角色或自动加入意图。
5. **双机与发行验收**：核对当前 Template、Sensor Meter 和其他兼容工程，以及正式签名／打包 App 的权限、生命周期和性能。仓库检查通过后仍由真实设备与声音行为验收决定是否可发行。

## 验收矩阵

| 场景               | 必须满足                                                                                             |
| ------------------ | ---------------------------------------------------------------------------------------------------- |
| 进入／返回演出模式 | 每次重新选择角色，不自动运行或加入。                                                                 |
| 角色按钮           | 中文／英文单独显示；空闲两击；Esc／外部点击取消；运行或清理中拒绝且仅在按钮内提示。                  |
| 命名               | 未命名池主不能开始；不回退电脑名，本地不要求 hub 凭据。                                              |
| 地址与身份         | 改名、换工程不重复记录；同名不同池主不合并；地址复用不把旧身份带入新池主。                           |
| 网络与协议         | HTTP 与 Socket.IO polling/WS 可用；不兼容协议明确拒绝；旧确认不能进入新工程。                        |
| 端口分配与兼容     | 首选端口已被占用时，适配工程使用实际分配端口，health／monitor／转发一致；旧工程冲突明确失败。        |
| 绑定与地址恢复     | 绑定失败有界清理并可重试；不抢占其他进程；新地址如实显示，运行中不迁移，存储恢复仍按池主／工程隔离。 |
| 工程变化与停止     | 同地址、同 manifest.id 的副本替换和同工程重启仍能区分新演出；未确认前不加载新页面或自动 join。       |
| 接纳状态           | 页面加载与工程接纳区分；无名册时状态诚实；不读取谱面 DOM。                                           |
| 媒体               | 首次权限、拒绝、停止、后台恢复、断线与明确退出分别验证；退出后摄像头／麦克风确实释放。               |
| 清理与交错         | 加入中取消、迟到探测／页面载入、快速重试、离开中切角色、Host 替换与退出 App 不恢复旧连接或泄漏资源。 |
| 单场参与与存储     | 同时只有一个演奏页面，换池主先离开；不同池主／工程存储隔离，手动重进可读取既存数据且不自动加入。     |
| 既有能力           | 池主工程运行、音频、投影、创作接续和多测试窗口无回归；覆盖已声明且符合入口约定的工程。               |

新业务逻辑带测试，完成标准为 `npm run check:all` 全绿。仅成功打开浏览器、模拟权限或显示在线，均不替代真实双机接入与媒体验收。当前文件是设计草案，不证明上述功能已实现。
