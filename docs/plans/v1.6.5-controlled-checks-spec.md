# v1.6.5：临时副本检查、版本证据与单文件撤销

状态：用户已确认的发布规格，待实现。

GitHub Issue：[194](https://github.com/xO-xN/PNDS-App/issues/194)，标签 `ready-for-agent`。

## Problem Statement

创作者和外部 agent 需要真实启动反馈、可核对的输入版本和安全恢复单文件修改的能力。把 GUI 启动流程直接包装成自动测试会共享运行状态、偏好和进程归属，可能停止已有演出；直接运行源工程也可能写入作品缓存。文件变化标记不足以证明检查使用了某一份完整输入。

## Solution

App／CLI 共用确定性检查服务：准备临时副本，静态检查、启动、等待 health／HTTP、收集结果并有界清理。默认 None，Internal 明确选择，External 首版留给 App 手动测试；存在 App 活动运行时拒绝新运行检查，静态仍可用。

报告对应实际副本输入、依赖、共享版本、模式与环境，区分自动结果和未验证行为。提供一个已有文本文件的真实差异、版本保护写入和撤销基础，为后续助手复用；程序负责复制、进程与清理，不要求模型自行组织 shell。

## User Stories

1. As an 创作者, I want 主动开始受控运行检查, so that 测试不会伴随聊天或保存自动执行。
2. As an 外部编程 agent, I want 用 CLI 运行同一检查, so that 不必自行搭建另一套 Host。
3. As an 创作者, I want 检查在临时副本运行, so that 正常检查写入的缓存不留在原工程。
4. As an 创作者, I want 准备副本有进度与失败说明, so that 大工程等待可理解。
5. As an 创作者, I want 副本输入范围可核对, so that 报告说明实际检查了什么。
6. As an 创作者, I want 默认 None 检查, so that 不自动打开真实音频设备。
7. As an 创作者, I want 工程不支持 None 时看到未执行原因, so that 声明不会被暗中修改。
8. As an 创作者, I want 明确选择 Internal, so that 我知道检查将使用真实音频环境。
9. As an 创作者, I want External 首版通过 App 手动测试, so that 外部声音目标由我控制。
10. As an 创作者, I want App 已有活动运行时拒绝新自动运行, so that 检查不停止演出。
11. As an 创作者, I want 启动和关停期间也被视作活动运行, so that 状态交错不会绕过门控。
12. As an 创作者, I want 静态检查仍可执行, so that 运行期间可以准备候选工程。
13. As an 创作者, I want 检查真实 Node、health 和页面入口, so that 不只验证文件存在。
14. As an 创作者, I want health 身份与运行配置被核对, so that 别的服务不会被当成本次成功。
15. As an 创作者, I want 超时、提前退出和启动失败有报告, so that 我能定位实际失败阶段。
16. As an 创作者, I want 随时停止检查, so that 不再需要的任务有界结束。
17. As an 创作者, I want 正常、失败和取消都清理所属进程, so that 不留下端口或音频资源。
18. As an 创作者, I want 清理只作用于本次检查, so that 其他演出或应用不被终止。
19. As an 创作者, I want 报告记录实际副本内容和依赖, so that 测试成功对应明确版本。
20. As an 创作者, I want 共享库版本进入输入证据, so that App 库升级不会被遗漏。
21. As an 创作者, I want Git HEAD 与未提交状态分开记录, so that 提交哈希不冒充全部测试内容。
22. As an 创作者, I want 原工程后来变化时结果提示过期, so that 旧报告不会冒充当前通过。
23. As an 创作者, I want 看见未验证的页面、手机、模型与声音内容, so that 不把服务就绪当艺术验收。
24. As an 创作者, I want 编译产物与报告来自独立检查步骤, so that 不扩大助手源码修改范围。
25. As an 创作者, I want 副本产物不自动回写源工程, so that 正式采用由我决定。
26. As an 创作者, I want 查看一个已有文本文件的前后差异, so that 能审阅实际写入。
27. As an 创作者, I want 写入绑定工程和读取版本, so that 不覆盖其他工程或过期内容。
28. As an 创作者, I want 有草稿或外部修改时先解决冲突, so that 我已有工作不会丢失。
29. As an 创作者, I want 本次修改可以撤销, so that 不满意时恢复原文本。
30. As an 创作者, I want 后来又被修改的文件拒绝直接撤销, so that 撤销不会覆盖新工作。
31. As an 创作者, I want 没有 Git 也可使用单文件撤销, so that 恢复能力不依赖版本工具。
32. As an 创作者, I want 检查失败保留源工程与修改结果, so that 下一步由我选择。
33. As an 创作者, I want 迟到结果属于原检查和工程, so that 切换后不会污染新上下文。
34. As an 维护者, I want 用真实受控进程验证生命周期, so that mock 不掩盖资源泄漏。

## Implementation Decisions

- 提议一个高层验证工作流服务，内部复用现有静态校验、Node／音频／health／监督和文件边界，供类型安全命令与 CLI 适配；不复制完整 Host 或以第二个 GUI manager 共用状态冒充隔离。
- 副本包含所需保存版输入，记录实际复制内容与依赖／共享版本；原工程变化不使副本偷偷更新。读取不完整或准备发生变化须准确说明，不声称完整瞬时快照保证。
- 检查有独立运行归属、配置、取消、日志和结果通道，不修改主运行世代。活动门控在后端生效，覆盖 starting、ready、stopping 等实际资源归属。
- 默认 None，遵守工程声明和完整契约，不因模式绕过必需资源。Internal 显式选择且记录设备环境，证明启动／就绪／清理；不自动判断声音或给 External 目标发测试音乐。
- 严格核对 health、HTTP 入口、进程存活、超时及有界关停。取消和异常保留实际结果与清理状态，不提前宣称成功。
- 输入证据以副本内容为依据，Git 是辅助，未提交内容和共享依赖也计入；对原工程的新变化标明过期，不把 watcher revision 当完整内容指纹。
- 单文件写入／撤销复用受信工程身份、现有文本读取、磁盘指纹与原子保存；只对一个已有文本目标操作，保留改前内容及成功改后版本。版本不匹配先解决冲突，不承诺外部编辑器间的操作系统级原子 CAS。
- 编译与报告由独立检查生成，副本检查不自动回写原工程；原工程继续用已有手动编译入口。具体配置和时间预算在实现时验证。

## Testing Decisions

- 最高接缝是一次完整验证任务及一次已有单文件修改／撤销。UI 和 CLI 断言同一报告、磁盘结果和生命周期，不以内部步骤调用次数替代行为。
- 延伸已有真实 Node／HTTP、音频生命周期、子进程有界关停与 Rust 临时目录测试；使用受控进程验证成功、health 不匹配、早退、超时、取消及清理。
- 证明活动 App 不被停止，启动／关停也拒绝新测试，静态仍可用；单纯检查 Node child 存在不足以覆盖完整门控。
- 临时工程测试副本准备、缓存写入、源目录不变、输入指纹、依赖版本、复制期间变化和原工程后来变化；报告明确过期与未覆盖。
- 单文件测试只读／路径／草稿／磁盘冲突、实际差异、成功撤销、后续修改拒绝撤销、切换／取消与迟到结果；复用已有手动保存边界。
- None 自动化不依赖真实声音设备，Internal 另做真实 macOS 音频启动与释放验收；手机、画面、模型推理和作品声音由真实环境补验。
- App 全量检查、双架构工具与真实运行记录通过后才供 v1.7.0 正式接入；用户负责 App 开发服务器和实机反馈。

## Out of Scope

- 与 App 活动演出并行的新自动运行、自动停止演出、任意 shell 或模型自主进程管理。
- 工程代码新建／删除／重命名、多文件回滚、覆盖后续外部修改、自动采用副本产物。
- 多人自动场景、录放、OSC Inspector、自动音频测量、视觉回归及艺术判断。
- Experimental worktree 合并、通用沙箱或完整编程 agent；严格不受任何外部并发影响的全工程原子快照承诺。

## Further Notes

本版服务先供 App／外部 agent 实际验证，v1.7.0 内置助手调用同一能力。临时副本与真实音频不是模型能力承诺；程序行为必须由检查、进程和实机证据证明。
