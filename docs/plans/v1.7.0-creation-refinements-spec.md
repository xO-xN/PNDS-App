# v1.7.0：讨论、逐题回答与创作资料接入

状态：2026-10-20 用户确认产品范围及测试接缝，并要求纳入新的 1.7.0 任务。已发布 #238–#243，全部归入 #149，并安排在收尾验收 #172 之前。本文记录已确认范围，功能状态以执行票及验收证据为准，任务发布不代表完成。MCP 留到后续版本。

## Problem Statement

创作者希望在 App 中推敲数字乐谱的创作意图，但当前 handoff 命名及讨论时直接维护交接单的行为混淆了讨论、实施和交接。一次列出大量问题增加回答负担，也无法根据上一题答案调整下一问。工程事实、创作选择与实施授权需要清楚区分。

已有源码还可能散落在工程之外。创作者拿到 Grid、Pattern 这类文件时，未必知道应放在哪个目录、怎样安排加载顺序和修改引用。仅提供代码选区附件、手动粘贴或复制文件，不能保证实际接线。工程日益杂乱时，也缺少保持作品行为、依据明确规范整理的入口。SCD 虽然可在 App 阅读和编译，仍缺少便捷的本机 SuperCollider 源码调试入口。

## Solution

以“讨论 / 编辑”表达助手的工作方式。讨论读取事实、推敲方案，需要创作者回答时每次展示一张问题卡，提供推荐选项和自由输入，收到答案后再决定下一问。追问只聚焦会改变方案的缺口，在适合时提出最小创作实验，保持普通问答简短自然。

手动交接仅出现在讨论中：默认整理当前话题的已确认方案，先生成可编辑草稿，再由创作者审阅、记录交接及保存版基线。编辑继续实施明确指派的工程任务，沿用多文件修改、检查修复、冲突保护和撤回能力。

创作资料先由 App 按工程保管，跨聊天与重启保留。首版接收代码和文本；明确的编辑任务负责判断放置位置、适配与接线，同名不同内容由创作者逐题决定替换或并存。“整理工程”提供 PNDS 默认规则和用户补充规范。SCD 可用本机 SuperCollider 打开已保存源码，不接入音频环境。

## User Stories

1. As an 创作者, I want 看到“讨论 / 编辑”的工作方式名称, so that 我能理解当前是在推敲方案还是实施工程修改。
2. As an 创作者, I want 普通讨论保持工程只读, so that 交流中的想法不会自行成为文件改动或交接任务。
3. As an 创作者, I want 切换工作方式时保留聊天、输入和文件草稿, so that 我能继续同一创作思路。
4. As an 创作者, I want 编辑只实施当前明确指派的目标, so that 历史讨论与其他待办不会成为新的执行任务。
5. As an 创作者, I want 每次只回答一个当前问题, so that 我不必一次处理长问题清单。
6. As an 创作者, I want 问题卡给出推荐选项和自由输入, so that 我既能快速选择也能表达自己的方案。
7. As an 创作者, I want 提交答案后再生成下一问, so that 讨论能根据我的选择改变方向。
8. As an 创作者, I want 普通说明和最终回答保持聊天正文, so that 问题卡不会把整个交流变成固定问卷。
9. As an 创作者, I want 助手先核对可查到的工程事实, so that 我只需决定创作选择。
10. As an 创作者, I want 追问聚焦演奏者行为、时间变化和可感知反馈, so that 讨论深入到数字乐谱的实际体验。
11. As an 创作者, I want 已明确的需求直接得到回应, so that 简单交流不会被过度采访。
12. As an 创作者, I want 深入讨论时获得反例、建议和最小实验, so that 我能验证想法并保留必要的艺术开放性。
13. As an 创作者, I want 问题及答案保留对应关系, so that 重看讨论时知道哪个选择已经确定。
14. As an 创作者, I want 重复提交、切换和迟到结果不回答另一问题, so that 我的决定不会被错误归属。
15. As an 创作者, I want 暂停或重开后仍能理解尚未回答的问题, so that 讨论与资料接入可以继续。
16. As an 创作者, I want 回答讨论问题不会自动写工程或记录正式交接, so that 决策与执行保持明确。
17. As an 创作者, I want 只在讨论中看到手动交接入口, so that 编辑时不会混淆任务执行者。
18. As an 创作者, I want 交接默认整理当前话题已确认的方案, so that 其他聊天及未接受建议不会被误记为要求。
19. As an 创作者, I want 先修改交接草稿并区分建议和疑问, so that 记录的是我认可的任务。
20. As an 创作者, I want 取消交接草稿时不写入工程, so that 我可以继续讨论。
21. As an 创作者, I want 正式记录交接时处理保存版与草稿并采集比较基线, so that 外部实现有准确起点。
22. As an 创作者, I want 已有交接任务和外部状态保留, so that 新任务不会覆盖其他工作。
23. As an 创作者, I want 交接后的比较沿用现有能力, so that 外部提交和 App 重启不影响核对。
24. As an 创作者, I want 从当前 SCD 操作中用本机 SuperCollider 打开保存源码, so that 我能继续外部调试。
25. As an 创作者, I want 打开源码时保留 App 中的未保存草稿, so that 两边内容不会被隐式覆盖。
26. As an 创作者, I want SuperCollider 缺失或打开失败时获得明确反馈, so that 我知道需要处理什么。
27. As an 创作者, I want 外部保存后由 App 检测文件变化, so that 我能回到工程继续工作。
28. As an 创作者, I want 打开源码不改变当前音频及运行环境, so that 这个入口只承担外部源码编辑。
29. As an 创作者, I want 添加代码和文本创作资料, so that 无需先确定它们在工程中的位置。
30. As an 创作者, I want 先查看资料并在讨论中按需引用, so that 添加文件不等于立即采用。
31. As an 创作者, I want 资料按工程保存在 App 的私有区域, so that 参考资料不会混入运行工程和分发包。
32. As an 创作者, I want 资料跨聊天和重启保留, so that 我能在后续任务中复用。
33. As an 创作者, I want 采用后保留原件并能手动移除资料, so that 我能核对来源并管理资料。
34. As an 创作者, I want 移除参考资料不删除已采用的工程文件, so that 资料管理与工程修改分别进行。
35. As an 创作者, I want 工程切换和读取失败不混入其他资料, so that 模型依据当前工程的实际来源工作。
36. As an 创作者, I want 超限、不可读或不支持的文件得到说明, so that 我不会误以为助手已理解资料。
37. As an 创作者, I want 一条明确的编辑任务完成 Grid 和 Pattern 文件接入, so that 我不必先学习目录和引用规则。
38. As an 创作者, I want 助手依据内容、入口和引用判断文件去向, so that 文件名不会替代真实用途判断。
39. As an 创作者, I want 接入同时完成目录、必要适配、加载顺序和引用接线, so that 文件能由当前工程实际加载。
40. As an 创作者, I want 同名不同内容时看见差异和推荐并选择替换或并存, so that 助手不会自行改变已有功能。
41. As an 创作者, I want 冲突答案接续原来的接入任务, so that 我不必重述目标或重新添加资料。
42. As an 创作者, I want 缺少原作品或关键依赖时被询问具体缺口, so that 助手不会生成替代作品冒充接入完成。
43. As an 创作者, I want 资料采用保护草稿、外部修改及禁改文件, so that 既有工作受到保留。
44. As an 创作者, I want 看见采用位置、适配内容及检查结果并能撤回任务, so that 修改可理解、可核对、可恢复。
45. As an 创作者, I want 有明确的整理工程入口, so that 我能将杂乱工程交给助手按规范维护。
46. As an 创作者, I want 使用 PNDS 默认规则并用文字或文档补充规范, so that 整理适合当前工程。
47. As an 创作者, I want 整理改善结构、命名、引用和冗余, so that 工程更便于继续创作。
48. As an 创作者, I want 整理保留源码算法、声音映射、视觉及演奏交互, so that 维护不会替代艺术设计。
49. As an 创作者, I want 整理不强制采用模板目录, so that 已有工程可保留适合自身的组织。
50. As an 创作者, I want 规范与作品行为冲突时先明确具体选择, so that 行为改变由我决定。
51. As an 创作者, I want 整理沿用工程检查和整任务撤回, so that 不需要另一套执行系统。
52. As an 维护者, I want 六个新任务都在 1.7.0 收尾前完成并联调, so that 新范围成为实际发行门槛。
53. As an 创作者, I want 自动检查与画面、声音及艺术效果分别记录, so that 程序运行成功不会冒充作品验收。
54. As an 创作者, I want 新入口支持中英文、键盘、主题和两架构, so that 创作流程与 App 既有体验一致。

## Implementation Decisions

- 本轮按六个纵向任务交付：逐题问答与 PNDS 极简追问；只读讨论及手动交接；SCD 外部打开；文本创作资料添加、阅读与保留；编辑任务采用资料；依据规范整理工程。每项同时包含界面、命令、状态及必要测试，不另拆纯底层或纯测试票。
- 所有新任务归入既有 1.7.0 父项 #149，带 `ready-for-agent`；收尾 #172 原生依赖全部六项，并在父项中排列于它们之后。既有依赖与已关闭实施票保留，不重开已完成任务，不让旧基础反向依赖新功能。
- 逐题回答复用统一助手请求、聊天归属、任务等待和接续生命周期；当前没有通用问题工具，需要增加受校验的问题与答案契约。问题由当前有效会话管理，历史展示与当前可回答状态分开；回答前不推进依赖该答案的操作。
- 推荐选项和自由文本只作为明确提交的用户答案；模型文字、默认选项及未作答状态均不能代替决定。一个时刻只展示一个当前问题，下一问依据实际答案推进。讨论问题的答案本身不授予工程修改或正式交接权限。
- 逐题 UI 服务整个讨论，也供明确编辑任务中的资料冲突复用；不会将编辑任务变成固定采访。等待、取消、重复提交、工程切换及重启恢复沿用原任务归属与授权重新核验。
- 讨论只读需同时落实工具契约及原生权限，不能仅改模式名称或隐藏按钮。手动交接使用独立的显式审阅记录流程，采集实际保存版基线，保留其他任务及状态；编辑继续按当前直接指令执行，不自动领取交接待办。
- 深入讨论通过短提示规则融入现有策略：核对相关事实，只追问会改变方案的关键缺口，给出建议，在适合时提出最小实验，方案清楚时收束。保持事实说明与问答正文自然，不增加固定阶段。
- SCD 入口复用当前工程文件操作与类型安全命令桥，原生验证工程归属和实际保存源码后交给本机 SuperCollider；未保存草稿、外部修改与运行状态沿用既有契约。打开源码不求值、不编译，不连接或修改 App 音频环境。
- 创作资料是 App 按工程关联的文本副本，与已采用工程文件和选区快照分别表达；添加只保存资料，不改工程或自动发送全部内容。跨聊天和重启保留，采用后保留原件，由用户手动移除；资料存储不进入工程版本或分发包。
- 资料阅读接入已有来源、分页及上下文预算；支持范围由真实文本校验决定，过大、二进制或不可读内容明确拒绝。不得借用户选择一个资料文件扩大为扫描其他工程外文件。
- 资料接入以明确编辑任务为起点，读取资料及实际工程，自行判断合适目录和接线；补足必要目录能力时仍受工程边界与任务撤回保护。正式采用按工程规则管理和打包，不以简单复制作为完成。
- 同名不同内容先展示事实差异和推荐，让创作者选择替换或并存；等待时不覆盖，作答后复核资料、工程版本及草稿，再接续原任务。工程原件保护、已有资源确认、任务检查修复及撤回继续生效。
- 整理工程复用现有编辑任务和检查撤回体系。内置默认规则遵守 PNDS 契约、清晰职责、引用一致及减少无用重复，用户可补充文字、工程文档或创作资料。改变艺术行为或与要求冲突的选择通过现有逐题 UI 澄清。
- 全部任务延续工程、聊天与任务隔离、持久化队列、类型安全命令、国际化、键盘及原生运行所有权规则。实施时更新对应开发文档，当前规格不声称这些新能力已经存在。

## Testing Decisions

以下测试接缝已通过单题 UI 获得用户确认。

- 优先一个最高自动化接缝：通过真实创作工作区的统一助手请求至任务执行器，使用受控模型提交声明式问题、读取资料、产生工程操作和检查结果，断言可观察的完整工作流。复用现有请求回放、资源等待接续、工程保留、检查及撤回先例，避免逐函数镜像实现。
- 只有宿主边界不能由前端替身证明时才补原生测试：真实临时目录中的工程权限、资料隔离与持久化、磁盘版本及任务撤回，以及指定本机应用打开已保存源码的验证。复用既有私有聊天存储、文件操作、交接基线和多文件 journal 测试模式。
- 问答覆盖一次一个问题、推荐与自由回答、未提交不继续、重复提交、取消、切工程和迟到回执、重启后待答与历史只读状态；验证讨论答案不授予工程写入，编辑冲突答案只接续原任务。
- 讨论及交接覆盖模型越权写入被原生拒绝，手动草稿、取消、正式记录、已有任务保留、草稿和磁盘冲突、保存版基线及返回比较；既有多文件编辑与同任务修复不回退为旧单文件候选流程。
- 资料覆盖真实文本添加、阅读来源与预算、跨聊天及重启保留、主动移除、跨工程隔离、不支持和失败反馈。接入以 Grid/Pattern 风格工程验证正确放置、可达资源、引用和加载顺序，冲突逐题等待、过期答案拒绝、检查及整任务撤回，保留资料原件和原作品。
- 整理覆盖默认及补充规范、实际引用变化、重复清理、保持关键算法和艺术参数、冲突澄清及撤回；测试断言保存内容和行为，不以格式化完成或固定回答句式作为成功。
- 真实 App 由用户启动。收尾 #172 在正式 macOS arm64／x86_64 产物中补验中英文、主题、键盘与焦点、最小窗口、真实兼容模型的追问质量、SuperCollider 实际接收文件及外部修改回读，使用不同工程连续走通全部新流程。
- 各业务任务和最终收尾均要求 `npm run check:all` 全绿。自动化、模型质量、桌面交互和音乐／画面效果分别留证；未执行项目不勾为通过，文档及任务发布不替代验收。

## Out of Scope

- 本轮规划直接实现功能、启动 dev server、commit、推送或发布 App。
- MCP、外部 agent 运行控制桥及其协议、工具或具体后续版本设计。
- 图片、PDF、音视频多模态理解，二进制资产接入和通用文件管理平台。
- SuperCollider 音频环境接入、自动求值、完整 IDE 或调试器。
- 通用 Skill 安装管理、任意 shell、联网安装或未经既有确认的依赖采用。
- 整理时艺术重设计、未经指派的性能优化、强制模板目录、自动 Git 提交及自动刷新／重启演出。
