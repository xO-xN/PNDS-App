# 主动保存工程版本，并呈现创作路线

2026-10-19 产品方案已通过七项交互决策确认。创作者不采用每次聊天自动记录代码版本；第一版聚焦本地保存、版本关系图、切换及从旧版本继续分叉，合并与远程协作暂不纳入。本记录是已确认的产品方向，HTML 原型使用示例数据，App 已接入中间栏 Git 页；自动化与实机验收分别记录。

已确认“保存当前版本”先保存全部编辑器草稿，成功后记录符合既有收录规则的工程修改；版本名称可选，留空自动命名。保存冲突继续阻断版本记录，依赖、缓存和敏感文件继续排除。助手任务撤回记录保留其独立职责，不因聊天自动创建 Git 提交。

选择主动保存，是为了让版本对应创作者认为值得保留的状态，控制历史噪声与存储增长；相应地，不承诺任意旧聊天都有精确的提问前代码恢复点。

## 已确认的切换语义

- 已有 A→B→C，切回 A 后保存 D，自动形成 A→D，B/C 保留。用户不必预先创建或命名分支；首次保存新路线时可选填名称。保存的父版本始终是当前工程版本。
- 有未记录修改时，默认提供“保存当前版本并切换”和“取消”。“放弃修改并切换”放在次要入口中，必须明确选择。
- 工程运行中仍可查看与保存版本。真正切换使用“停止运行并切换”；切换完成后保持停止，由用户手动运行目标版本。
- 聊天历史属于工程，不随代码切换删改。存在未完成的助手任务时，用户须明确结束任务后再切换；不把旧任务自动接续到另一代码版本。结束任务保留其已保存代码及独立撤回记录。
- 版本图作为创作模式中间栏的完整切换页，与编辑器、预览平级；左右工程栏、助手独立。单击版本仅查看摘要及文件差异，“切换到此版本”才更改工程。视觉呈树状，数据仍须表达真实父子关系，不能把按时间排列的记录伪装成分叉。

2026-10-19 创作者评审 HTML 后，将原先确认的“底部展开面板”调整为上述中间栏切换页；这一轮只讨论 Git 窗口，原型其余区域不作为 App 整体布局的实现依据。切换工作区页面保留工程与查看状态，不执行版本切换或任务、运行操作。

## 与现有实现的差异

现有“回到此版本”只恢复文件，HEAD、index 和分支关系不移动。A→B→C 后恢复 A 的文件并保存 D，当前实现仍得到 A→B→C→D，不能直接复用该语义实现上述分叉。

实现阶段需要增加多分支历史及父节点信息、当前位置，以及实际的版本切换/分叉事务。既有一次性预览 token、文件新鲜度核对、外部暂存保护、原生运行租约、敏感路径排除及保存后文件同步应保留。Git 改变不会恢复聊天执行授权或替代助手任务撤回。

原型将展示普通保存、选择与当前位置分离、旧版本分叉、带修改切换、运行中切换、未完成助手任务、保存冲突和首次保存等状态；不访问真实 Git、文件或模型服务。

[HTML 原型](../prototypes/creation-git-versions.html)与[评估及验证范围](../prototypes/creation-git-versions.md)随此决策保存。

## 2026-11-15 版本历史精简评审

创作者确认将 [A 方案原型](../prototypes/version-history-study.html)接入 App。
这一轮覆盖前文“保存优先／次要放弃入口”、停止运行专用按钮与版本切换／改名弹窗的呈现决策。
目的是让比较、版本操作和文件差异各有一个稳定位置，减少重复信息与分散控制；原生写入权限与事务边界不变。

- 保留 App 的 226px 文件侧栏与中间工作区页签。左栏只有“此版本改动／与本机比较”、搜索和变更文件列表；删除“变更／全部”、前后版本说明与重复摘要。比较仍是父版本到所选版本，或所选版本到本机已保存文件，不含草稿；当前改动固定比较当前工程版本到保存内容。
- 中间顶部用 32px 工程版本／GitHub 行，下面默认 160px 左横向版本树与右侧 176px 操作栏；需要展示切换后果时可增至 192px。树使用真实父子关系和可复用泳道，节点名称下放时间，当前与选中状态分别表达。仅实际变更或草稿存在时显示虚线当前改动节点。其下直接显示逐行差异。
- 右栏名称旁的铅笔在原位编辑名称，Enter 保存、Esc 取消、有效名称失焦保存；中文选字不提交。主操作下直接显示真实作者、记录时间、标识和父版本。保存当前版本仍通过独立命名窗口执行。
- 版本操作统一“切换到此版本”。无改动时点击直接切换；有需保护的文件或草稿时，首击将同一按钮改为“放弃改动切换”，再次明确点击执行，不再弹出切换窗口，也不自动先保存。要保留当前工作时，用户先单独保存版本。
- 停止测试／结束助手任务的必要后果在按钮旁按实际状态显示。已知后果经点击确认；若准备阶段才发现未知恢复任务，先呈现后果并要求重新点击。目标、改动、任务或运行代际变化会撤销旧确认；Esc、外点、离开焦点与窗口失焦也会撤销。切换后仍由用户手动启动目标工程。

这次调整不修改命名分支与历史位置的底层区别，也不降低工程身份、一次性预览 token、
文件新鲜度、外部暂存、仓库／索引／ref 锁、任务授权或运行租约核对。原生准备与确认仍可拒绝竞争变化；
读取失败不会被当作干净工程。已经完成保存或切换后的刷新失败，只重试同步／读取，不重复写入。
正式行为与验证边界见[本地 Git](../developer/local-git.md#middle-workspace-version-page-2026-10-19)；
本次确认不构成新的原生 App 或 runes-pnds 实机验收证据。

2026-11-15 实测追加：已保存版本的横轴严格按记录时间从左到右排列，
切换到较老的末端版本或查看其他节点均不得将其移到最右侧；同一时间按版本标识稳定排列。
泳道仍按真实父子关系分配，时间与祖先关系冲突时允许连线向左回连，不用移动节点修正时间。
未记录改动尚无提交时间，继续作为当前实际 HEAD 旁的虚线分支显示；排除文件本身不构成工程改动。
