# 主动保存工程版本，并呈现创作路线

2026-10-19 产品方案已通过七项交互决策确认。创作者不采用每次聊天自动记录代码版本；第一版聚焦本地保存、版本关系图、切换及从旧版本继续分叉，合并与远程协作暂不纳入。本记录是已确认的产品方向，HTML 原型使用示例数据，App 已接入中间栏 Git 页；自动化与实机验收分别记录。

已确认“保存当前版本”先保存全部编辑器草稿，成功后记录符合既有收录规则的工程修改；版本名称可选，留空自动命名。保存冲突继续阻断版本记录，依赖、缓存和敏感文件继续排除。助手任务撤回记录保留其独立职责，不因聊天自动创建 Git 提交。

选择主动保存，是为了让版本对应创作者认为值得保留的状态，控制历史噪声与存储增长；相应地，不承诺任意旧聊天都有精确的提问前代码恢复点。

## 已确认的切换语义

- 已有 A→B→C，切回 A 后保存 D，自动形成 A→D，B/C 保留。用户不必预先创建或命名分支；首次保存新路线时可选填名称。保存的父版本始终是当前工程版本。
- 有未记录修改时，默认提供“保存当前版本并切换”和“取消”。“放弃修改并切换”放在次要入口中，必须明确选择。
- 工程运行中仍可查看与保存版本。真正切换使用“停止运行并切换”；切换完成后保持停止，由用户手动运行目标版本。
- 聊天历史属于工程，不随代码切换删改。存在未完成的助手任务时，用户须明确结束任务后再切换；不把旧任务自动接续到另一代码版本。结束任务保留其已保存代码及独立撤回记录。
- 版本图作为创作模式中间栏的完整切换页，与编辑器、预览平级；左右工程栏、助手独立。单击版本仅查看摘要及文件差异，“切换到此版本”才更改工程。视觉呈树状，数据仍须表达真实父子关系，不能把按时间排列的记录伪装成分叉。

2026-10-19 创作者评审 HTML 后，将原先确认的“底部展开面板”调整为上述中间栏切换页；这一轮只讨论 Git 窗口，原型其余区域不作为 App 整体布局的实现依据。切换工作区页面保留工程与查看状态，不执行版本切换或任务、运行操作。

## 与现有实现的差异

现有“回到此版本”只恢复文件，HEAD、index 和分支关系不移动。A→B→C 后恢复 A 的文件并保存 D，当前实现仍得到 A→B→C→D，不能直接复用该语义实现上述分叉。

实现阶段需要增加多分支历史及父节点信息、当前位置，以及实际的版本切换/分叉事务。既有一次性预览 token、文件新鲜度核对、外部暂存保护、原生运行租约、敏感路径排除及保存后文件同步应保留。Git 改变不会恢复聊天执行授权或替代助手任务撤回。

原型将展示普通保存、选择与当前位置分离、旧版本分叉、带修改切换、运行中切换、未完成助手任务、保存冲突和首次保存等状态；不访问真实 Git、文件或模型服务。

[HTML 原型](../prototypes/creation-git-versions.html)与[评估及验证范围](../prototypes/creation-git-versions.md)随此决策保存。

## 实现与验证

中间栏接线、快速保存、多分支分页读取与原生切换现已实现。保存从旧版本开始新路线时创建本地分支；低层历史载入与原有文件恢复命令保留其独立语义。实现边界见[本地 Git](../developer/local-git.md)，验证与 runes-pnds 实机步骤见[验收记录](../acceptance/creator-git-versions.md)。

2026-10-19 工作台 UI 评审追加：工程名右侧显示当前分支与版本，历史位置明确标注。选择命名分支通过共享切换会话附着其本地 ref，选择历史版本仍进入分离 HEAD。预览携带分支名与预期 tip，确认加锁并复核后原子更新符号 HEAD；从该分支继续保存推进该分支。两种入口均保留草稿、外部暂存、运行租约和未完成助手任务保护，详见上述本地 Git 文档。
