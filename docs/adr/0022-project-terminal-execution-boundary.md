# 工程终端保留本机执行边界，以静态交接接入编程 agent

2026-11-16，创作者在[Q22](../plans/embedded-terminal-grilling.md#q22已确认收缩首版)确认首版收缩为「当前工程单终端 + 简单交接」。这一决定替代访谈中曾考虑的多工程后台、自动只读与执行权锁、独立任务状态及在线信息桥；目的是先验证终端与真实 CLI 协作，减少相互耦合的业务状态。设计范围已确认，产品实现尚未开始。

工程终端在创作模式中服务当前可编辑工程，运行用户已有的 shell 与编程 agent，保留普通本机执行能力及 CLI 自身的登录、审批与对话机制。App 不为各家 Agent 维护独立执行器。相较把成熟 CLI 改造成仅使用 PNDS 受控工具的执行器，这保留了通用工程能力，但 App 的原生写入门禁和任务撤销不会覆盖 CLI 直接写盘，也不能把工程目录误作权限沙箱。

grilling 后新增动作只导出当前选定方案和已确认决策的静态终端任务文件，复制短提示并切到终端；已有会话由用户在 CLI 就绪后提交。Agent 通过保存版工程、装机文档路径及现有 `pnds check` 工作，首版不提供实时 App 查询。用户可自行运行 CLI，也可保存一个常用启动命令；自动传参不作为首次验证的前置条件。该接缝避免逐家接管 CLI，但不保证未经配置的任意 CLI 自动接单。

首版将 CLI 写盘按外部修改处理，复用现有文件变化检测、草稿冲突、版本差异与人工检查，不新增任务调度、App 自动只读、比较基线或完成记录。创作者自行协调 Work、CLI 与手动编辑；现有冲突检测不能阻止全部并发修改，进程退出也不代表需求完成。

全 App 仅保留当前工程一个终端会话。同区切换与隐藏窗口保留会话；切换工程、替换工程版本、进入合并候选、离开创作或退出 App 前，结束活跃会话或取消原操作。不在合并候选中提供指向实际工程的终端，不自动重启 CLI，不撤销其实际修改。

新增终端交接只承接所选方案；[ADR-0008](./0008-creator-handoff-as-agent-seam.md) 中现有外部复制提示词承接整份当前创作交接单的语义保留。Ghostty 候选的可靠性与开销仍需技术验证，范围简化不免除中文输入、TUI、主题初始化、隐藏绘制和进程清理等基础要求。
