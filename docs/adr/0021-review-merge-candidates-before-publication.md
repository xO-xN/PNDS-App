# 工程版本合并先在隔离候选中完成审阅

2026-11-15 创作者确认工程版本合并先生成独立候选，合并计算、人工调整与助手工作均不提前应用到实际工程。准备前先保存为工程版本或明确放弃未记录修改，并结束普通助手任务；候选期间实际工程在 App 内只读。统一原生写入门禁与前端状态投影防止普通保存、编译或版本操作旁路改写，最终应用仍需核对外部文件及 Git 基线。相较直接在工作区合并，这增加候选存储与授权边界，但允许真实审阅、取消和恢复。

Git 关系由 App 处理。真正分叉生成承接双方历史的双父版本，即使文件树未变；已包含不操作，可快进则精确采用已有来源提交、不新建版本，快进候选只读。修改结果只用于真正分叉的候选，避免“快进但内容已变”的不一致。来源为当前树中可选的本机提交，包括已手动取回并进入树的 GitHub 提交；首版不负责获取来源或连接无关历史。

助手为可选的候选专属工作：每轮明确启动、固定历史上下文、人工与助手按轮交接，差异可看且最近一轮可按版本保护撤回，后续手改不被覆盖。取消逐文件“标记已解决”，点击测试或完成时由原生统一核对当前结果。冲突、声明格式、路径及身份／基线等必要校验不可跳过；编译、测试或本机环境问题如实报告，允许创作者明确仍然合并，不能用全部静态 error 一刀切地禁止 Git 操作。

创作者后续要求合并前直接启动乐谱服务器，因此初期“只做差异审阅，合并后再试听”的范围已被替代。候选测试可选，使用确定修订的可丢弃运行副本，沿用普通创作测试的音频、页面、设备与工程通信能力，并明确显示未合并来源。修改候选后原运行只代表旧内容，需明确重测；采用编译产物是单独的可见候选修改。复用唯一主运行引擎但新增候选运行归属，明确停止原运行后才测试，结束／失效／离开时确认清理，不把临时路径当作真实工程。运行副本不是操作系统沙箱。

候选和进度独立持久化，离开或重启后重新核对并明确继续，不自动恢复助手、测试或发布。受保护实际输入或目标基线变化使候选失效，只读保留供参考，重新准备不自动移植旧处理。正式应用先固定结果并保存阶段记录，再发布文件、refs 与 index；失败后继续恢复同一结果而不重新合并。外部后续状态不被强制覆盖或回滚，成功后的名称、刷新、同步及备份失败只重试对应步骤；候选隔离不构成跨文件、ref、index 整体原子回滚的承诺。

本决定扩展 [ADR-0011](./0011-creator-git-version-navigation.md) 原先排除通用合并的产品范围。完整已确认流程、验收与实施拆分见[规划](../plans/creation-merge-design.md)。2026-11-15 按 HTML 核对后的方案接入 App；原生候选、发布恢复、助手权限及运行归属见[实现说明](../developer/merge-candidates.md)。自动化检查与实机验收分别记录。
