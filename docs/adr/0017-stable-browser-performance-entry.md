# 池主提供跨工程的浏览器演奏入口

状态：2026-11-09 用户要求以 to-spec 定稿并纳入 v1.7.0-beta.3；[正式规格](../plans/v1.7.0-beta.3-browser-participation-spec.md) 已发布为 [#294](https://github.com/xO-xN/PNDS-App/issues/294)，标记 `ready-for-agent`，尚未实施。技术契约在实施首阶段验证后定稿；逐轮核对与维护源基线保留在[讨论记录](../plans/2026-11-09-browser-participation.md)。

演奏者保存一次入口后应能方便地跟随池主切换工程，入口因此归属于池主，而非某个工程的内部监听端口。采用局域网 HTTP，不要求配置 HTTPS 或修改浏览器安全设置；浏览器可直接参与，添加主屏幕、Dock 或桌面入口是可选便利，独立窗口按平台提供，不要求公网 WebAPK 打包。节点名与局域网准备好后，空闲池主也提供等待演出的入口，开放入口本身不启动工程或音频。App 在线且所用局域网地址不变时，公共入口跨工程保持；退出再打开时优先复用旧端口，占用则允许换号并明确提示更新已保存入口，网络变化的恢复另行决定。

浏览器演奏端自动发现同一池主的新工程并提供进入提示，演奏者点击后才加载新页面，不用手动刷新或重复扫码；声音仍由工程自己的启用流程处理。原生 PNDS Client 保留，并同步采用自动发现新工程、显示名称和单击进入的交互，不再重填地址或先点重新核对，保留其数据隔离与新演出核验。

用户随后明确确认：池主失联、明确停演或换工程，都不自动刷新、卸载或停止设备上已经运行的工程页面；演奏者明确进入其他工程、刷新或关闭时才改变页面。接入层撤销旧演出的网络访问不等于销毁本地页面，旧确认也不得进入新的演出；工程自己的暂停、结束及断线策略仍由工程决定。此规则同时用于浏览器端与原生池客，修订 ADR-0014 原有核实停演或换工程就销毁旧页的规则，以保护 ASBS 等工程的自主继续演奏能力。

正常演奏只显示工程内容，不增加常驻离开按钮或网络状态栏；新工程可进入时提供轻量提示。浏览器以关闭页面离开，原生池客的退出／换池主保留在 App 侧栏。ASBS 完整本人分谱资源预取纳入本轮配套适配，沿用滑动解码窗口，以已打开且准备完成的页面在主机断开后完整滚谱作为验收；这不承诺主机离线时仍可从图标冷启动。

主动切换新工程失败时保留原页面实例继续演奏，新页面成功后才完成替换。App 切到创作模式或 PNDS Client 后，公共入口仍以原地址报告当前没有公开演出，不自动公开创作测试。遇到未适配稳定入口的旧工程，入口明确提示需适配，网络面板提供标明限制的旧 performer 地址供人工应急，不自动把设备转回旧地址。

浏览器与原生池客统一使用同一公开演奏入口，原生池客仍保留自己的私有页面来源与存储恢复。浏览器按池主／工程区分和复用已保存身份，尊重工程重置与接纳规则；不同浏览器或图标实例不保证共享／迁移，IP 或端口变化后首版允许重新选择身份，不做跨地址自动迁移。同源工程的数据命名空间是避免功能串用，不是浏览器级安全隔离。

用户确定所有现有维护工程同步适配，范围沿用 QR 迁移规格的 13 个指定维护源，并同步 App Blank／Classic 与四个随包工具资源；ASBS 的完整本人分谱预取作为配套项。该范围不包含历史副本或验收夹具，亦不将依赖安全上下文的能力强行降级为 HTTP。具体清单、输入基线、实施拆分与验收见规划记录。

演出二维码继续由 App 提供，移除演出底栏独立按钮及演出投影覆盖层，将复制完整入口与首次扫码收进下栏网络弹层。创作真机测试扫码先保留。这修订 [ADR-0013](./0013-app-owned-performer-qr.md) 的演出显示位置及网址归属，保留二维码属于 Host 职责的决定；无需让工程重新接入自己的 QR 功能。

用户随后要求移除 Host 侧栏“本机演出运行中”信息卡，接入地址、复制、QR、入口故障和必要端口诊断统一归入下栏网络区；侧栏沿用角色／节点名与工程列表运行标记。这是展示职责整合，不以删除卡片代替停止入口、隐藏故障或改变运行门禁。

选择这条路线是为了降低现场配置与重复接入成本，接受不同平台安装形式及 HTTP 能力边界；添加图标不授予安全上下文能力。现有 HTTPS 功能与需要相应能力的工程不因此被删除或静默降级，[ADR-0014](./0014-performance-roles.md) 对新演出的明确确认继续保留，已加载页面的销毁边界按本记录的后续决定调整。

## 2026-11-10 后续决定：普通浏览器的等待页与切换确认

用户在[居中留白原型](../prototypes/performer-entry-pond.html)评审后明确要求，将等待页和工程切换一起接入实际演奏者浏览器入口。普通浏览器采用 Pond、指定 PNDS 图标与「PNDS池谱」品牌字样，保存入口收敛为两句说明；该字样是本轮浏览器品牌展示要求，不扩展为全局术语或原生池客 UI 改名。

本决定覆盖上文普通浏览器的轻量提示和点击进入形式：当有可操作、兼容且不同的新候选时，入口用全屏覆盖层虚化旧谱并设为 `inert`，焦点转到圆球；任意方向拖拽并松手反向发射才确认，轻微抖动或普通点按不确认。Enter／Space 与辅助技术激活提供等价的明确确认。这样在切换目标已出现时，演奏者的确认手势不会继续落到旧谱；代价是候选仍可操作时，取消准备或失败后也先回到候选重试界面，旧谱继续保留但暂不接收输入。

旧 Document、自主时钟与工程自己的运行策略仍保留，只有真实资源准备完成且三项身份再次核验后才交接和退役旧页。停止演出、元数据不可用或不兼容候选使可操作覆盖层消失，原页面恢复交互和焦点；它们不自动导航或销毁旧页。真实准备期间仅保留灰色底座内的加载动画，其余内容淡出，Escape 可取消。Safari 缺失首轮指针按下事件时以去重的鼠标事件兼容路径接纳同一手势。

此次只改变普通浏览器入口 UI；原生 PNDS Client 继续使用自己的单击进入界面。公开监听地址、不可变授权 URL、明确确认、资源准备报告、旧页退役与可选保存入口的协议边界保留，全部界面资源由池主局域网入口提供。正式实现与验证边界见[浏览器参与规则](../developer/browser-participation.md)；本轮自动化和显式 WebKit 执行结果待收尾记录，不据原型或旧 GUI 证据宣称签名 App、实体手机或双机验收完成。
