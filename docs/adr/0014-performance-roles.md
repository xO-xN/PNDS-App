# 演出模式内区分池主与池客

状态：已接受的 v1.7.0-beta.2 范围与 HTML A 交互，待实现。池主／池客及自动端口管理已转为 GitHub #258／#259；真实技术验收尚未完成。

桌面演奏端功能纳入现有 PNDS App，暂不发布独立安装包。用户每次进入演出模式时，在左侧栏选择池主（PNDS Host）或池客（PNDS Client）；同一个 App 同时只担任其中一个角色。角色属于演出模式，不增加第三个界面模式，也不等于工程的 performer 页面或座位身份。

这个选择减少首版的安装入口和双角色运行协调，并使每次进入演出时的职责由用户明确决定。池客以地址和最近连接加入通用 PNDS 工程的本地演出，谱面在 PNDS 内显示。最近连接以池主节点名呈现，池主必须显式填写节点名；本地接入不因此要求 hub 地址或 token。不因加入池客角色改变手机浏览器的安全上下文需求，也不据原型宣称内嵌媒体能力已经通过验收。

角色入口采用 A 方案：先选择，进入后收拢为角色按钮。空闲时通过斜线按钮两次点击切换，运行、加载、待接纳、断线重连和退出清理中拒绝切换，在按钮内提示先退出，不弹确认框，也不自动停止演出；明确取消／离开且清理完成后才允许切换。池客进入创作前离开本地演出并进入本机创作首页，返回演出重新选择角色。中文角色标签仅显示「池主／池客」，英文仅显示「PNDS Host／PNDS Client」。

短时网络中断保留谱面，沿用工程自身的重连与媒体逻辑，明确退出演出时释放媒体。核实池主更换工程后，销毁旧演奏页面并释放媒体，池客明确确认后才加载新工程。池主明确关闭演出同样结束池客参与；随后即使同工程再次启动，也须明确重新加入。接入层必须在新工程收到加入之前守住确认条件，不能依赖旧页面连接清理或事后提示。

最近连接按稳定池主身份保存，节点名仅用于显示；改名或换工程不产生另一条池主记录，同名不同设备不合并。最近地址指向不同池主时停止直接加入并保留原记录，用户明确选择后才建立新记录。首版要求池主支持兼容的池客接入协议，旧版提示升级。主动离开后回到池客连接页，保留角色和最近连接。兼容工程未提供接纳反馈时仍可打开，但只显示页面已打开／连接状态未知，不宣称已加入。

池客同时只加入一台池主的一场演出，显示一个演奏页面，换池主须先离开；创作模式已有的多个测试窗口保留。网页存储按池主与工程隔离保存，退出与重启后可供下次手动加入使用，不自动加入，也不保证恢复工程未保存的演奏状态。保留工程的恢复凭据不能代替一次新演出的明确确认。

首版池客支持声明并实际遵循完整 performer URL、同源资源及实时连接约定的工程。未声明先核对，需适配时说明具体问题；接纳名册仍可选。池主身份与演出核验由 App 提供，作品保留既有音乐消息及加入策略，不因桌面接入删除面向普通浏览器的安全上下文需求。

池客主动刷新采用按钮内两次点击确认，首击提示再次点击，第二击才重载当前池客页面；先释放旧页面媒体并核验演出，变化时仍须明确确认加入，不重启池主。网页存储保留，媒体按工程正常启用流程恢复；不保证未保存的演奏状态。该行为于 2026-11-03 确认。

自动管理端口与冲突避让同版交付；实际端口、地址变更与持久网页数据恢复须一并验收。端口职责与新运行契约仍在规格草案中收敛，不能由版本决定推断旧工程已支持动态监听，也不能将 `supportsPerformerUrl` 当作该能力声明。

独立发布、记住上次角色与同 App 并行主持／参与本轮不采用。产品行为已收敛，整体 UI／UX 核对和技术验收按[设计讨论](../plans/v1.7.1-performance-roles-design.md)继续完成；本 ADR 不覆盖 [ADR-0007](./0007-mode-switch-ends-performance.md) 已有的池主创作接续行为。工程兼容范围于 2026-11-02 确认。
