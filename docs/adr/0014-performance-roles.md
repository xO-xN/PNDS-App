# 演出模式内区分池主与池客

状态：已接受的 v1.7.0-beta.2 范围与角色决定。用户在已落地 C 后确认将最终紧凑 E 应用 App：固定身份区的角色／只读节点名改为 18px、字重 600／300、行高 26px，角色最小高 40px，文字内缩 28px；当前文件夹名称作列表标题，底部居中 Home＋动态用户文件夹＋Utilities tabs，不另有工具／返回按钮，保留真实管理、菜单、拖放、持久化与工程选择业务。E 只替换展示，不改角色记忆或原生运行门禁；C／B 留作历史，D 未选。本轮 `check:all`、构建及正式组件静态浏览器核对通过；原生实机验收仍未完成，证据范围见[评审记录](../prototypes/performance-roles-1.7.1-review.md)。

桌面演奏端功能纳入现有 PNDS App，暂不发布独立安装包。用户于 2026-11-03 后续讨论中修订启动规则：首次打开 App 默认池主（PNDS Host），以后每次打开恢复上次成功保存的池主或池客（PNDS Client），无有效记忆时回落池主；同一个 App 同时只担任其中一个角色。角色属于演出模式，不增加第三个界面模式，也不等于工程的 performer 页面或座位身份。

角色记忆在正式 App 中归属 `lastPerformanceRole` 偏好，缺省为池主，写入沿用串行偏好队列。首次偏好装载只填补尚未确定的启动角色，读取失败回落池主；晚到读取不能盖过原生活动或当前显式选择，启动准备期间不展示旧角色卡片。显式切换先更新当前界面与本次会话的最近选择，再保存；保存失败保留当前选择并反馈下次打开可能恢复原先保存的角色，不能把未落盘的选择宣称为已记忆。

这个选择减少首版的安装入口和双角色运行协调，角色记忆则省去重复选择。记忆只决定启动后的角色界面，不自动启动工程、加入演出或启用媒体，也不授予原生运行或接入许可；已有原生活动仍按真实状态恢复和门禁处理。默认池主尚未命名时，仍先经过显式节点命名门禁。池客以地址和最近连接加入通用 PNDS 工程的本地演出，谱面在 PNDS 内显示。最近连接以池主节点名呈现；本地接入不因此要求 hub 地址或 token。不因加入池客角色改变手机浏览器的安全上下文需求，也不据原型宣称内嵌媒体能力已经通过验收。

角色入口沿用小号文字下拉。用户于 2026-11-03 将此前的斜面两击按钮改为该入口：空闲时明确选择另一角色即可切换，当前项仅关闭；运行、加载、待接纳、断线重连和退出清理中仍可查看菜单，但另一项禁用并提示先停止／离开，不弹确认框，也不自动停止演出；明确取消／离开且清理完成后才允许切换。池客进入创作前离开本地演出并进入本机创作首页；本轮不改动原生创作清理事务。成功进入创作后清当前角色与菜单、保留本次会话的最近选择，成功返回演出时使用该选择；若启动的首次偏好读取尚未完成，返回仍保持角色准备状态，等待读取结果而不提前选择暂存的默认池主。即使保存失败，本次往返也仍保留本次选择，不自动启动工程、加入演出或恢复媒体。中文角色标签仅显示「池主／池客」，英文仅显示「PNDS Host／PNDS Client」。池主节点名在同排角色旁、靠逻辑起点显示，使用同字号细体；用户撤回原位编辑提案，名称只读，首次命名与设置页保留编辑能力。

2026-11-03 原决定（当前实现）：短时网络中断保留谱面，沿用工程自身的重连与媒体逻辑，明确退出演出时释放媒体。核实池主更换工程后，销毁旧演奏页面并释放媒体，池客明确确认后才加载新工程。池主明确关闭演出同样结束池客参与；随后即使同工程再次启动，也须明确重新加入。接入层必须在新工程收到加入之前守住确认条件，不能依赖旧页面连接清理或事后提示。

2026-11-09 后续已确认规划（尚未实施）：[ADR-0017](./0017-stable-browser-performance-entry.md) 将已加载页面的生命周期与池主接入状态分开。失联、停演或发现新工程都不自动销毁旧页，以保留 ASBS 等工程的自主继续演奏能力；演奏者明确进入其他工程、刷新或关闭时才改变页面。原生池客与浏览器端均自动发现同一池主的新工程、单击进入，不再先点重新核对；对新演出的明确确认与防止旧连接误入新演出的要求不变。正常演奏不放常驻离开或网络状态栏，原生退出／换池主操作保留在 App 侧栏。

池客侧栏现在按本次 App 启动期间的节点发现和地址核对填充，取代早期保存的最近连接。节点按稳定身份合并，改名、换地址和换工程更新同一条记录，同名不同设备各自显示。在线节点按池主、创作、池客排列，离线节点排在末尾并标注「不在线」。主动离开后保留角色和本次启动期间的节点列表。池主须支持兼容的池客接入协议，旧版提示升级。兼容工程未提供接纳反馈时仍可打开，显示页面已打开／连接状态未知。

池客同时只加入一个节点的一次演出或测试，显示一个演奏页面。2026-11-12 用户确认采用局域网节点列表，池主与已启动的创作测试均可预览 README、明确加入并从当前谱面切换。新谱面准备并核验成功后才交接，原谱面在准备期间仍可使用。所有角色在首次使用时共用一项已保存的本机节点名。网页存储按节点与工程隔离保存，退出与重启后可供下次手动加入使用，不自动加入，也不保证恢复工程未保存的演奏状态。保留工程的恢复凭据不能代替一次新演出的明确确认。[池客页面接续](../developer/native-client-continuity.md)

首版池客支持声明并实际遵循完整 performer URL、同源资源及实时连接约定的工程。未声明先核对，需适配时说明具体问题；接纳名册仍可选。池主身份与演出核验由 App 提供，作品保留既有音乐消息及加入策略，不因桌面接入删除面向普通浏览器的安全上下文需求。

池客主动刷新采用按钮内两次点击确认，首击提示再次点击，第二击才重载当前池客页面；先释放旧页面媒体并核验演出，变化时仍须明确确认加入，不重启池主。网页存储保留，媒体按工程正常启用流程恢复；不保证未保存的演奏状态。该行为于 2026-11-03 确认。

自动管理端口与冲突避让同版交付；实际端口、地址变更与持久网页数据恢复须一并验收。运行契约现以 `scoreServer.runtimePorts: 1` 显式声明，分配与监听器交接见[端口实现规则](../developer/ports.md#managed-runtime-listeners-259)，验收范围见[#259／#260 记录](../acceptance/259-260-runtime-ports-and-pending-documents.md)。旧工程继续固定端口兼容路径，不能由版本决定推断其已支持动态监听，也不能将 `supportsPerformerUrl` 当作该能力声明。

此前「每次进入重新选择、不记住上次角色」的决定已由上述启动与会话内返回规则覆盖；本次正式接入经[实现规则](../developer/performance-participation.md)记录，HTML 演示及旧检查证据不能代替本次 App 检查或原生验收。独立发布与同 App 并行主持／参与仍不采用。整体 UI／UX 核对和技术验收按[设计讨论](../plans/v1.7.1-performance-roles-design.md)继续完成；本 ADR 不覆盖 [ADR-0007](./0007-mode-switch-ends-performance.md) 已有的池主创作接续行为。工程兼容范围于 2026-11-02 确认。
