# 演奏记录在回放时实时生成声音

状态：产品方案与原型已确认，目标为 v1.7.0-beta.2；正式规格与跟踪票为 GitHub #257，尚未实施。

为支持整场演出回放及创作者独自体验各演奏者，App 保存演奏信息，回放时由工程实时生成声音。首版不做音频录制，也不保存纯音频合成内部的随机状态；这项取舍以简洁、可靠和理解作品的大致效果为目标，声音细节不要求与原演出逐样本一致。

叠加录制沿用已有演奏信息并加入当前演奏者的新信息，形成一份合并记录；已有内容不作为现场输入再次追加。新输入引起的乐谱变化可以在当遍发生，不要求冻结前一遍的乐谱，也不引入演出分支。

记录演奏者的身份独立于工程的乐谱选择序号和物理设备：同一序号可有多位独立演奏者，创作者在同一设备上新增叠加一遍也形成新的记录身份。仅明确重录某位时替换该身份，不能按编号或设备自动覆盖已有演奏；回放分别建立独立的工程运行来源，以保留 Runes 等工程的同序号多人语义。

第一轮已确认：影响乐谱的随机生成保留实际生成结果，普通回放恢复对应乐谱；每遍叠加恢复共同时间零点与初始演奏状态。App 提供通用能力，工程通过明确接口适配，以 Inarticulate III 验证叠加互动，以 runes 验证随机乐谱。功能入口、首版控件与其他逐轮决定归[设计讨论](../plans/v1.7.0-beta.2-performance-recording-design.md)，尚未确认的规则不据本 ADR 推断。
