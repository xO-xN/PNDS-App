# 在现有 PNDS Template 仓库发布 Blank 的 GitHub 模板

2026-11-13 定稿，纳入 v1.7.0-beta.4。实施范围与验收见 [规格](../plans/v1.7.0-beta.4-github-template-spec.md) 和 [#327](https://github.com/xO-xN/PNDS-App/issues/327)。

创作者确认复用 [`xO-xN/PNDS-Template`](https://github.com/xO-xN/PNDS-Template) 的仓库身份和入口。默认分支改用由 PNDS App 同一 Blank 生成器导出的模板快照，旧版从新建工程入口退役。App 在本地生成工程身份、工程内容和首次提交，创作者可以离线开始创作。

首版的唯一模板类型是空白工程（Blank）。预接 p5.js 和 sketch 入口的 p5.js Starter 留作后续模板。

旧 `main` 保存在 `legacy`，现有标签和 Release 保留。新版以普通提交更新 `main`。当前创作入口指向 App 和模板仓首页，历史 Release 保留原用途。GitHub 模板来源指向仓库，两代共用同一个来源，因此首次绑定也要核对新版模板快照。

首次备份时，创作者在浏览器从官方 GitHub 模板建仓并选择公开性，再回到 App 绑定。App 核验模板来源和未经修改的远端初始提交，用保留两段历史的合并提交把本地已保存的工程内容快进推送到远端。首次备份在与远端默认分支同名的本地分支完成，后续其他分支按现有规则备份到远端同名分支。该流程在 [ADR-0018](./0018-creator-github-backup.md) 现有绑定规则之外提供专用的首次备份入口，公开仓库的首次备份仍由创作者确认。

由 App 的 Blank 生成且尚未绑定仓库的工程可走这条路径，包括已有多个本地工程版本的情况。已绑定的工程继续备份到原仓库。

本地 Blank 与 GitHub 模板的版本可以不同。核验远端初始提交时采用 GitHub 模板快照的版本。合并提交的工程内容及其来源版本以本地已保存版本为准。

每份正式发布的模板快照保留一个版本标签。首次备份核对官方模板仓库身份、目标默认分支的单一根提交，以及该提交的完整文件树与对应官方标签的文件树是否一致。这样即使模板仓的 `main` 已更新，之前建出的仓库仍可通过核验。目标分支已有额外提交时，App 提示冲突并保留远端历史。

首次备份中断后，创作者可以回到 App 继续。App 保留原目标仓库、分支及待推送的合并提交。若远端已收到该提交，App 补齐本地状态。若远端仍是原模板初始提交，创作者可继续推送同一合并提交。若远端出现其他提交，App 停在冲突状态。本地期间新增的版本保留，公开范围变化时重新确认。

外部创作者可以直接从同一个 GitHub 模板建仓，在本机终端或该仓库的 Codespaces 完成一次工程初始化，再使用外部工具创作。初始化生成独立工程 ID，重复执行保留已有工程身份。后续可在 App 中打开或克隆同一个工程，沿用工程身份和 Git 历史。

GitHub 的模板来源记录可用于核对单个仓库。模板 README 提供公开工程目录入口。首版由创作者在首次公开备份成功或初始化提交推送后自行添加 `pnds-project` topic，已有公开工程也可补标。

后续产品决定见 [ADR-0020](./0020-creator-project-and-versions-experience.md)，其中由 PNDS 代办 App 新建工程的模板建仓、首次上传和绑定。
