# 跨互联网配置为 App 全局而非按工程，房间由工程 id 派生

v1.4.0 T1 原设计（#57 spec 初稿）把 hub 地址 / token / 房间按工程持久化。重新评估后反转：一场演出里乐手与节点是确定的，这些参数跨工程稳定，而 pnds-hub 本身不认识工程——按工程存只会让同一套信息随工程切换反复手填、各自漂移。定稿为：**节点名、hub 地址、token 是 App 全局配置**（设置面板「节点」栏，常显）；**房间不由用户手填**——App 注入 `PNDS_HUB_ROOM = {manifest.id}_{分组号}`（不含版本；分组号 1–3，侧栏「Room」下拉选择、按工程持久、默认 1），同一作品的节点默认同房，开错工程或别的工程闯入从机制上不可能同房，同作品需分房时改分组号；manifest 只保留布尔「跨互联网演奏能力」声明，仅决定注入与「设置节点」强制门（选中声明工程且三项任一为空 → 会话按钮变「设置节点」，门只验齐全不验连通）。

## Consequences

- 同一作品需要分房时用侧栏「Room」分组号（1–3）；两个团开同一作品又用同一分组号仍会撞房——协调编号或另起 hub（换 token）。
- 分组号按工程持久化、崩溃恢复不换组（重置会把崩溃机器静默送进别组的房）；App 界面只显示序号、不显示派生房间全名，完整房间名由工程侧 monitor 显示（排障护栏）。
- 输出设备从侧栏 SettingsCard 迁入设置「音频」栏（与采样率同住，「下次启动生效」）；LAN 地址迁入「节点」栏。侧栏只剩随演奏情况变化的内容（音量、音频模式、OSC 目标）。
- 节点名必须显式设定（占位符提示主机名，不作默认值）；hub 地址填完整 URL，不是裸 IP。
- 生态同步：pnds-hub 同房间同名节点拒绝（握手层，错误码与 invalid token 可区分）；TND（App v1.4.0 前发新版）退场 room 输入框、显示拒绝原因、env 存在时优先于 localStorage；Template 的 monitor 可按需显示节点名 / hub 地址 / 房间（token 永不显示）。

## Considered Options

- 按工程持久化 hub 三项（否决：演出场景参数跨工程稳定；按工程 = 反复手填 + 各工程配置漂移）。
- 房间由用户自定义（否决：手抄拼错即静默分房，人人「已连接」实则各在各的房；错工程串扰只能靠人的自觉防）。
- 房间 = 作品显示名 `name`（否决：不同作品同名显示名会撞房；`id` 是创作者起的机器标识，撞上的概率低得多，且 token 已挡外人）。
- 房间含版本号（否决：同作品不同小版本会静默分房——全团失联，是最坏故障）。
- hub 填裸 IP 由 App 拼 URL（否决：生产 hub 走 TLS 反向代理，协议与端口由部署决定，App 无法猜）。
