# 创作交接单作为 App 与外部编程 agent 的接缝

2026-10-12 修订：v1.7.0 助手一次按钮授权只修改一个已有文本文件（源码、manifest、README、SCD）；新建、删除、重命名、跨文件或其他复杂任务先询问是否交接，用户同意后才写入工程的 `docs/creator-handoff.md`，并提供可复制任务说明。创作交接保留意图、文件、已知问题、验收与状态，新工程和 Template 的 agent 入口指向它；任务留在源工程，根 `docs/` 沿既有规则不进入 `.pnds`。

v1.6.0 提供标准模块文件添加、来源记录与接线交接，v1.6.1 整理模块及外部 Skills；自动多文件接线、复杂重构与安装由外部环境处理。v1.6.5 提供确定性修改／临时副本检查基础，v1.7.0 用“执行修改”和独立“运行检查”按钮调用，不因聊天或保存自动执行。检查失败保留修改，用户选择撤销、再次执行或确认交接，不自动连续修复。通过窄写入范围与成熟外部 agent 分工，避免自建通用编程框架；具体约束见[修订规格](../plans/v1.7.0-creation-assistant-spec.md)。

## Considered Options

- 把任务写入工程 README（否决：README 面向演出准备者与观众，任务不属于作品简介）。
- 把任务写入 manifest（否决：manifest 是运行契约，不承担创作流程状态）。
- 完全只读助手（原方案，已替换：用户需要在 App 完成单文件代码修改与确定性检查）。
- 内置通用自主编程 agent（不采用：广泛文件操作与连续修复增加维护范围，交由成熟外部 agent）。
