# 创作交接单作为 App 与外部编程 agent 的接缝

2026-10-22 交接承接修正：生成交接是把创作者明确选择的方案和已答决策带给实施者的操作，不是重新设计或派发“编写交接文档”的业务任务。现有方案直接准备可编辑交接；历史方案经新的明确选择后作为只读来源，不恢复旧执行权限。真正未决的范围、行为或数值冲突先在讨论澄清，明确延期／排除仍属于已确认范围；未决草稿不得正式记录。复制 prompt 的全部四条规则使用聊天语言（当前为中文／英文），界面切换不改变该交接的语言；App 内 canonical skill 仍是精简英文源文件。此修正保持整份当前交接单的外部实施范围、独立审阅记录和既有权限边界。

2026-10-21 后续修订：外部 agent 接手整份当前交接单，完成全部当前任务，不再按单个 ID／修订选择实施范围；ID／修订继续用于 App 的记录、修订和比较。已确认的极简 `pnds-handoff` skill 随 App 资源分发，复制 prompt 自动附上四行英文正文和实际工程位置，无需从 GitHub 或向外部客户端安装 skill，也不随工程生成 skill。读取工程已有术语和设计文档；完成任务全文与实施／检查报告先归档，再清理完成项，受阻／未完成事项保留。此修订替代下文旧的单任务 prompt 执行范围，App 内置工作仍只实施当前用户指派。内置提示词按讨论／工作／草稿／摘要分开，通用编程细则由工具契约和平台文档承担，摘要请求不提供工具。

2026-10-21 交接生命周期与交互修订：交接单改为当前有效任务清单，同一任务的修订替换旧块，其他未完成任务和未知内容默认保留。创作者可在“管理已有内容”中明确纠正旧错误；替换前将原保存版归档至源工程 `docs/handoff-history/<contenthash>.md`，并核对保存版，避免清理清单时丢失可追溯性。外部 agent 按复制的任务／修订专属 prompt 完成真实实施与检查后，归档最终需求、实际修改、检查和未验证项，再直接移除自己的完成任务，不额外等待创作者批准；受阻或未完成任务保留。App 不从聊天或文件变化猜测完成，也不自动删除错误。私有交接基线仍是最初比较起点，与源工程中的最终执行报告分开。弹窗展示可读任务和实际写入预览，不要求创作者填写初始状态；真正写入后原聊天回复提供可快捷复制的 prompt，草稿不宣称已记录。

普通 grilling 在每个聊天按 Q1、Q2 编号，点选即答，自由回答框常驻并支持 Enter 发送、Shift+Enter 换行及输入法保护；推荐用最右侧描边徽标。取消讨论移至更多菜单，文件替换冲突继续明确确认。移除面向创作者的服务端用量入口与正文加载三点，实际公开处理文字仍可通过淡色“展开思考流程”展开，不展示 provider 私有 reasoning。真实模型、原生视觉与外部工作验收仍独立记录。

2026-10-21 讨论流程补充：借鉴 grilling 与 domain modeling 的简短规则，讨论逐题核对关键选择、原始约束、术语和具体场景，在主回复展示可共同核对的完整方案。同一方案由创作者选择写交接文件或直接开始工作；交接负责可接手的任务与状态、正式记录及比较基线，不重新设计。方案保留在聊天，不默认增加 `creation-plan.md`，避免两份近似方案长期漂移；持久术语与决定按需维护工程已有文档，重要且难以逆转的取舍才单独记录 ADR。既有审阅／记录权限边界不变。

2026-10-21 原型及整体实施已获创作者确认：助手栏为“PNDS 创作助手”，模式为“讨论／工作”（内部 `discussion/edit`）。讨论收束在回复中提供写交接文件或开始工作；前者保留草稿审阅及正式记录，后者以明确选择创建新任务并同步切换模式。用户新发送的明确整理指令也可直接进入工作，普通问题答案与只读工具结果不授予写权限。三个常驻操作从输入框移除，补充规范在对话中表达。

2026-10-20 产品范围修订（#238 / #239 已实现，实机验收归 #172）：将助手的 handoff 工作方式改为“讨论”，讨论只读取、分析和澄清方案，需要回答时通过逐题卡片提供推荐选项及自由输入。交接入口仅放在讨论中，手动生成当前话题的可编辑草稿，审阅并记录后写入交接单和采集比较基线；edit 继续实施明确的工程任务。此选择让讨论、实施和交接各有明确用途，替代下列“默认 handoff 直接维护交接文档”的产品方向。完整决定见[本轮讨论](../plans/creation-mode-refinements-grilling.md)，1.7.0 补充规格及 #238–#243 任务见[发布规划](../plans/v1.7.0-creation-refinements-spec.md)，全部安排在 #172 收尾前；讨论工具和原生写入权限、旧模式只读迁移及当前话题手动交接已按此边界实现；真实模型与发行环境验收见 #172，MCP 留到后续版本。

2026-10-17 用户确认的新修订：新对话默认 handoff，直接维护交接文档并保留其他 agent 的任务与状态；edit 按发送时固定的模式直接实现并保存，支持新建文件、多文件协同、本地共享依赖采用与接线，以及工程检查报错后的同任务修复。修改前持久记录原文，提供整任务及逐文件撤回，拒绝覆盖后续创作者改动；这些记录独立于 Git。工程菜单直接展示“保存当前版本”和“本地历史”。所有依赖来自本地，不提供 CDN 或网络安装替代。此决策替代下列历史修订中的逐候选应用、跨文件写入限制及检查失败后不能连续修复的规定。实现边界见 [creation-assistant](../developer/creation-assistant.md#explicit-creation-modes-2026-10-17)。

2026-10-17 实机修订：工程已保存文本默认可读，无发送内容确认；一次请求可给出最多 8 个不同已有文件的候选，应用按钮仍一次只写一个文件。大文件支持精确局部替换生成完整候选；协同修改须说明逐文件应用顺序与依赖，不增加自动批量写入。新文件可由创作者在 App 手动新建并粘贴助手提供的代码。上述可完成的步骤不强制交接外部 agent，其他复杂实现保留交接接缝。此修订替代下文旧的一次请求仅一候选及所有跨文件需求均交接的限制。

2026-10-12 修订：v1.7.0 助手一次按钮授权只修改一个已有文本文件（源码、manifest、README、SCD）；新建、删除、重命名、跨文件或其他复杂任务先询问是否交接，用户同意后才写入工程的 `docs/creator-handoff.md`，并提供可复制任务说明。创作交接保留意图、文件、已知问题、验收与状态，新工程和 Template 的 agent 入口指向它；任务留在源工程，根 `docs/` 沿既有规则不进入 `.pnds`。

v1.6.0 提供标准模块文件添加、来源记录与接线交接，v1.6.1 整理模块及外部 Skills；自动多文件接线、复杂重构与安装由外部环境处理。v1.6.5 提供确定性修改／临时副本检查基础，v1.7.0 用“执行修改”和独立“运行检查”按钮调用，不因聊天或保存自动执行。检查失败保留修改，用户选择撤销、再次执行或确认交接，不自动连续修复。通过窄写入范围与成熟外部 agent 分工，避免自建通用编程框架；具体约束见[修订规格](../plans/v1.7.0-creation-assistant-spec.md)。

## Considered Options

- 把任务写入工程 README（否决：README 面向演出准备者与观众，任务不属于作品简介）。
- 把任务写入 manifest（否决：manifest 是运行契约，不承担创作流程状态）。
- 完全只读助手（原方案，已替换：用户需要在 App 完成单文件代码修改与确定性检查）。
- 内置通用自主编程 agent（不采用：广泛文件操作与连续修复增加维护范围，交由成熟外部 agent）。
