# 创作交接单作为 App 与外部编程 agent 的接缝

v1.6 的创作模式在工程的 `docs/creator-handoff.md` 记录待办、意图、涉及文件、验收条件与状态；App 新建的空白工程在 `AGENTS.md` 指向它，使外部编程 agent 能发现并接续工作。现有 PNDS Template 的 `AGENTS.md` 也同步增加该入口。App 可为 README 双语同步等动作记录任务；v1.7 的内置 AI 助手也可在用户确认后写入交接单，但工程代码仍由外部编程 agent 修改。交接单放在工程的根 `docs/` 下，沿用该目录不进入 `.pnds` 演出包的现有规则，让创作待办留在源工程。

按后续已确认决策，v1.6.0 提供标准模块文件添加、来源版本记录及接线交接；真实代码接线、升级、合并、移除与验证由外部 agent 完成，文件添加不等于功能已完成。v1.6.1 整理模块接口、文档、兼容并重构外部 Skills，详见[正式规格](../plans/v1.6.1-modules-skills-spec.md)。Skills 安装由创作者自愿在外部环境完成，App 助手仅按需提示步骤；本 ADR 的咨询与交接边界不因此扩大为代码实现或安装执行权限。

## Considered Options

- 把任务写入工程 README（否决：README 面向演出准备者与观众，任务不属于作品简介）。
- 把任务写入 manifest（否决：manifest 是运行契约，不承担创作流程状态）。
- 让内置 AI 直接改写工程代码（否决：创作者已有专门的编程 agent；App 的助手聚焦咨询与交接）。
