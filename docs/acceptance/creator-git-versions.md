# 创作模式 Git 版本页

2026-10-19。产品共识见 [ADR-0011](../adr/0011-creator-git-version-navigation.md)，实现边界见[本地 Git](../developer/local-git.md)。本记录区分代码与自动化结果，以及仍由创作者执行的 dev App 验收。

## 已接入的范围

- 可编辑文件夹工程通过 Git 菜单或中间栏“Git 版本”进入完整页面；原有讨论、编辑器与右侧预览保持其布局。离开页面保留查看版本、文件差异、缩放、名称与已加载历史。控制台在 Git 页隐藏，返回后保留原开关状态。
- 主动保存先按现有冲突校验保存全部草稿，再记录默认符合收录规则的完整文件。名称可空，由本地生成；显示未收录文件，不重复记录无变化状态，不启动模型或运行检查。
- 图来自 HEAD、本地分支与真实提交全部父关系；支持分叉、现有外部合并关系、分批加载和未加载边界。第一版不提供合并、远程或协作命令。
- 从 A→B→C 切回 A 后保存 D，D 的父提交是 A，旧分支仍指向 C。切换使用一次性原生预览，保存内容、索引、HEAD 和引用都重新校验。
- 有修改时主要提供保存后切换与取消；放弃在次要操作中，再明确确认。切换成功前保留草稿，之后也不删除在等待期间产生的新草稿。
- 运行中先停止再切换，保持停止；停止失败、其他运行占用或受控检查租约不允许继续写入。外部暂存、忽略文件冲突、符号链接、受保护来源与 Git 配置校验仍由原生负责。
- 未完成、暂停或重启恢复的助手任务必须先明确结束。保留聊天、已保存代码和任务撤回日志，删除接续 checkpoint 并拒绝原任务迟到发布；文件已手动改动造成恢复失效时也允许明确结束。

## runes-pnds 实机步骤（待创作者）

原生命令有新增，需要重新启动 dev App；dev server 仍由创作者启动。

1. 打开 runes-pnds，通过 Git 菜单或中间栏“Git 版本”进入页面；检查文件栏、右侧预览和原有讨论没有布局变更。
2. 同时修改两个编辑器草稿，留空版本名称保存；核对草稿写盘、版本消息、未收录范围以及图中当前位置。
3. 单击 starting point 查看文件差异，确认工程没有切换；切换工作区页面并返回，核对查看状态、缩放和输入仍保留。
4. 运行工程后选择旧版本切换，核对明确停止并保持停止；手动运行目标版本，确认看到对应代码。
5. 从旧版本修改并保存，核对出现新路线，并能切回之前保存的版本，原路线完整保留。
6. 有草稿时测试取消、保存后切换、次要的放弃流程；制造保存冲突时核对停止切换且草稿保留。
7. 暂停助手任务后尝试切换；取消应保留任务，明确结束后再切换，应保留聊天和任务撤回记录，重启后不自动接续旧任务。

以上实机项尚未由自动化执行，不宣称验收完成。
