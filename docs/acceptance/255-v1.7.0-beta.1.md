## 自动验证范围

最终候选源码执行 `npm run check:all`；每份实际 DMG 执行 `hdiutil verify` 并只读挂载，再核对：

1. App 版本、最低 macOS 13.5、App / CLI / Node / dnsd / scsynth 的目标架构，libsndfile 的 universal slices。
2. App deep / strict codesign；包内 CLI 版本及与构建输入对应的运行时、帮助文档、SynthDef、插件、Skills、许可证、固定共享库和工具目录。
3. 固定共享库 catalog 的每个唯一文件长度与 SHA-256、完整文件集合，以及四工具公开包固定 SHA 与最终工程载荷。
4. 两架构共享载荷一致，安装包名称、字节、SHA-256 与确切候选提交一一对应。

## 实机测试前准备

在 Apple Silicon 和 Intel 各准备一台 macOS 13.5+ 的真实机器，下载或拷贝与本机匹配的最终 DMG，先核对本页记录的 SHA-256。Intel 的运行结果应来自 Intel 机器。

退出现有 PNDS，保留当前安装包，备份 `~/Library/Application Support/com.xo-xn.pnds-app/` 和完整工程目录，包括 `.git`、`.pnds-creation` 等隐藏文件。用副本测试；同一 App 名称与标识会共享数据位置。恢复旧 App 时同时使用测试前的数据副本，保留 beta 期间产生的新内容。

准备一个已有真实工程、一个自己的代码／文本资料、一个可调用工具的真实兼容模型服务及 API key。本页反馈不记录 key。声音测试使用实际目标设备；音量先调至适合测试的水平。

## 第二轮：真实创作连续流程

至少使用一个真实工程完成整轮，并记录实际模型服务与型号、工程和保存版本。

1. 讨论一个创作意图，完成逐题澄清。未提交默认项、取消问题和普通讨论均不应启动编辑或写入文件。
2. 明确指派一个实际多文件编辑任务，观察来源与差异，完成检查／同任务修复。手动运行保存版并判断画面、声音与交互；适用工程再验证参数控件和临时预演的结束恢复。
3. 撤回任务；再制造一次后续人工修改，验证撤回保护不会覆盖它。分别在请求中取消、切换工程，确认迟到结果不写入另一个工程。
4. 回到讨论，手动生成交接草稿，编辑并取消一次，再明确记录。退出重开后查看交接基线；在外部修改工程后返回比较，核对真实变化。
5. 接入自己的文本／源码资料，验证原件保留。同名不同内容时作出替换或并存选择，再让助手按明确规范整理工程；实际运行核对原有画面、声音和演奏交互。
6. 手动记录所选已保存完整文件，查看版本差异，再载入历史文本草稿。打开当前已保存 SCD 到 SuperCollider，确认 App 未保存草稿仍保留，外部保存能按冲突规则回流。
7. 在断网或错误模型配置下继续编辑、保存及手动运行，恢复网络后按界面重试；既有演出不应被编辑或检查意外停止。
