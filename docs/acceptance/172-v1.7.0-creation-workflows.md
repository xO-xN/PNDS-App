## 讨论内调参和直接编辑

- [ ] 助手依据当前意图及实际读到的工程提出参数，通过声明式专用工具请求控件；App 核实来源、目标已有文件、保存版本、绑定、类型与当前值。不能只凭模型文案渲染可执行界面或认定能力存在。
- [ ] 数值 fader／输入、开关、选项或颜色等控件符合参数类型；没有可靠对应时不硬塞控件，代码入口始终可用于已有目标文本。工程真实限制与模型建议试调范围、单位和步长清楚区分。
- [ ] 同一建议卡切换“参数／代码”，能修改完整目标文件的待应用内容。至少验证字符串、条件或函数等非数字改动，输入不写磁盘、不改工程草稿、不运行代码、不请求模型，也不提交 Git。
- [ ] 参数更新只改准确绑定的候选位置，保留其他手写代码；代码改变为表达式、重复目标或不同结构后，只停用无法可靠绑定的控件并说明。无数据丢失、猜测替换或自动重置整份建议。
- [ ] 恢复 AI 参数只恢复有效绑定的参数，保留其他代码。恢复整份建议、从当前文件重载或其他会放弃编辑的操作明确展示影响；取消保持用户内容。
- [ ] 参数／代码、文件、交接、比较、版本等视图切换保留候选与工程草稿，返回相关讨论不丢位置和上下文。完整文件编辑器仍可查看上下文、完成较长编辑。
- [ ] 当前文件存在工程草稿、磁盘外部修改、目标删除或失效时，旧应用及不再有效的预演被阻止，候选和草稿仍可检查、复制或明确重载，不暗中覆盖／合并。
- [ ] 从建议选区提问时，附件明确标注“待应用建议”、候选修订和目标路径；从文件草稿提问则标注未保存。两者都经过发送授权和预算，关闭工程读取后不能发送；普通拖动或编辑不默发新内容。

## 预演能力与恢复

- [ ] 不按画面／声音、语言或固定工程类型认定支持；使用工程的实际适配与当前运行情况判断即时预演、需刷新、需编译或需重启，未支持时保留编辑、明确应用与手动测试入口。
- [ ] 已适配且绑定有效的参数随用户调节反馈；代码键入只更新候选并退出旧预演，必须点击“预演修改”才尝试当前候选。输入中的未完成代码不会执行。
- [ ] 同一 monitor 明示临时预演、目标和覆盖范围。整份候选包含不支持内容时明确哪些尚未预演，不能用标题或少量参数变化宣称整份代码成功。
- [ ] 不通过任意模型 UI 脚本、`eval` 或任意代码注入伪造适配；声明式接口、消息来源、合法值、工程归属、运行归属和修订均经过核实。模型假能力声明、非法载荷、过期和外来消息被拒绝。
- [ ] 保存版本、当前实际加载版本、候选修订和运行身份分别绑定；保存文件尚未加载时也能正确判断。快速调节、重复操作和乱序回执只更新当前有效预演，不回退到旧值。
- [ ] 无运行、适配不支持、来源过期或无法保证对应参数可恢复时不开始预演，不自动启动测试或音频。预演不改变已应用音频模式、设备、外部目标，也不自动停止／重启已有运行。
- [ ] “结束预演”恢复本次临时改动对应的运行基准参数；不宣称倒回时间、所有页面交互或全部运行副作用。磁盘文件、工程草稿、Git 和交接基线保持不变。
- [ ] 代码输入、来源／适配失效、停止测试、切换／关闭工程、离开创作模式或退出 App 结束旧预演；同一工程的阅读视图、布局拖动和 monitor 展开／还原保留同一有效会话。
- [ ] 失败、取消、超时或断连保留编辑并尝试恢复。恢复失败显示“未恢复／状态未确认”，阻止继续叠加预演并提供明确手动处理入口，不显示成功或自动重启掩盖失败。
- [ ] 应用成功后重新核实原预演关联；仍有效时可以继续临时预演，但保存不自动采用为运行基准。结束预演恢复原对应参数，手动刷新／重启才采用保存版；刷新／重启使旧会话和迟到回执失效。
- [ ] 外部或未经核验的源文件变化使预演失效。手动刷新只采用保存版，不采用未应用候选；需要重启或编译的提示不会因页面刷新或预演成功而消失。
- [ ] 聊天历史、App 重启或重开工程不恢复旧执行授权和预演。旧建议重新采用时核对当前事实；旧运行事件不能更新新工程。
- [ ] 无适配时可提出适配方案：一个已有文件内的修改按相同应用规则处理，新增文件／跨文件复杂适配确认后进入 handoff。完成适配后按实际能力重新验证，不能仅看到交接任务完成就认定可预演。

## 明确应用与真实差异

- [ ] “应用到工程”只写一个当前已有文本文件，保存点击时参数和代码编辑后的最终候选；模型最初建议不得覆盖用户最后编辑。目标版本、候选修订、身份、只读限制及适用内容校验均生效。
- [ ] 应用前无磁盘写入；重复点击不重复写入。提交期间再次输入时，旧响应不覆盖新候选或把后续内容误报为已保存。失败保留可继续编辑的候选。
- [ ] 未保存工程草稿、外部修改、路径逃逸、只读来源、删除目标和不合法内容等拒绝应用；通过真实临时文件测试边界，不能仅依赖前端禁用按钮。
- [ ] 每次成功应用产生真实写入前后差异，包含手写的非数字改动。相关回复下只读展示，之后改参数、输入代码或再次应用均不改旧记录。
- [ ] 当前文件入口编辑工程草稿，旧差异仍是历史执行记录。撤销只在磁盘仍匹配该次结果时有效，拒绝覆盖后续人工／外部改动；遵守 #207 生命周期，不借聊天持久化恢复旧撤销权。
- [ ] 应用只保存，预演、刷新、编译、重启、运行检查和 Git 记录分别显式触发。成功保存不等于运行已采用；失败检查不自动修复、撤销或反复收费调用模型。

## 真实工程与模型评估

在实施时建立固定可复验用例集。至少使用两个独立真实工程，覆盖有适配、无适配、实际需要刷新／重启的情况，不能只复制同一原型参数改名。每例记录工程／版本、服务及模型标识、提问、读取来源、工具请求、实际绑定与效果、失败或人工判断；敏感内容和凭据不进入公共记录。

| 类别         | 场景与应观察结果                                                                                                           |
| ------------ | -------------------------------------------------------------------------------------------------------------------------- |
| 应出现控件   | “运动再慢一点”等可定位意图对应工程实际参数；助手选到相关参数，App 验证并可正确调节                                         |
| 用户主动要求 | 要求将某处参数做成滑块；能绑定时提供，不能绑定时解释并保留代码编辑或适配交接                                               |
| 非数字修改   | 修改文字、条件或函数；可直接编辑并应用，按实际能力预演，不能强行转换成 fader                                               |
| 不应出现控件 | 纯概念讨论、无可核实参数或缺少工程读取授权；不虚构可调位置与实时效果                                                       |
| 歧义         | “更有张力”等多种解释；先澄清或明确可选方向，不任意改音量／速度冒充理解                                                     |
| 能力正反例   | 能实时更新的声音参数与必须重载的画面内容分别按能力处理，证明无媒体类别硬编码；没有真实声音适配证据时不得宣称声音预演已通过 |
| 部分可预演   | 候选同时含可映射值和不支持逻辑；明确覆盖缺口，不把局部效果当成整体成功                                                     |
| 过期与恢复   | 外部改动、不同运行版本、断连和失败恢复；正确保留内容并阻止过期操作                                                         |

- [ ] 真实兼容模型完成上述正例、反例与歧义评估；记录判断依据和失败复验，不要求固定句式。单次恰好成功、模型自述或固定回复不构成通过。
- [ ] 确定性测试覆盖每个关键拒绝条件和恢复不变式；模型未选择控件与 App 拒绝不合法绑定分别可定位。质量问题修复后重跑相应用例，不通过隐藏失败样例定稿。
- [ ] 代码和参数调整后的实际效果由创作者核对；自动检查不代替音乐、画面或演奏体验判断。

## 完整工作流与既有能力回归

- [ ] 未配置／断网／错误模型仍能编辑、保存和手动测试；凭据通过钥匙串保存、恢复、移除，未泄漏到工程、日志、普通设置或分发包。连接测试实际核对文本与工具调用，不读取工程。
- [ ] 首次发送、扩大范围及更换工程／服务授权符合规格；关闭读取后不重发历史工程内容。预算、取消、来源导航、分段读取、迟到结果与本机历史隔离有效。
- [ ] 新建 Blank／Classic 在发布前建立独立 Git 和初始版本；已有无 Git 工程只在主动启用后初始化。两个架构无需系统 Git／CLT／Homebrew，身份和邮箱遵守已确认规则，失败不伪装完整成功。
- [ ] 交接先预览并确认，草稿按明确选择处理；未应用建议和预演不写入基线。基线是当次保存版，跨重启和外部提交仍能比较整体变化；二进制只显示摘要，失败／排除范围可见。
- [ ] 手动记录版本只纳入用户预览的完整文件保存版，不自动应用建议、不纳入预演或草稿、不混入未选择的外部暂存；大资源默认排除、主动纳入与历史体积说明可用。
- [ ] 历史只把现存单文本载入草稿；不直接改磁盘、HEAD、index 或运行。已有草稿、并发修改、特殊仓库和不支持 filter／签名等按规格拒绝或保留状态。
- [ ] App 共享包目录、详情、固定版本引用与工程版本保存入口完整；标准技术模块加入文件、来源与接线交接，状态不冒充已接线验证。保留 1.6 的冲突、草稿与固定资源边界。
- [ ] None／Internal／External 手动测试、独立 performer 手机／平板窗口、静态检查及副本运行检查保持既有契约。活动运行时拒绝会新启动工程的检查，不中断现有运行；编译和副本产物不自动采用。
- [ ] 中英文均走通：新建初始版本／已有工程 → 讨论与显式附件 → 参数与非数字代码编辑 → 预演或未支持回落 → 明确应用及 diff → 手动测试／检查 → 确认交接基线 → 外部实现并提交 → 返回比较 → 手动版本记录 → 历史载入草稿。无 Git 工程不主动启用时也能完成非 Git 环节。

## 原生界面与双架构

- [ ] arm64／x86_64 的中英文、Pond／Sand／Stage／Brutal 四主题均核对最小 1000×700 和常用宽窗口，记录实际尺寸与截图。长对话、长代码、错误和长参数名称不遮挡应用／退出预演入口。

- [ ] fader、数值输入、其他适用控件、代码编辑、选区附件、预演／结束预演和应用全程可用键盘完成；焦点不被聊天更新抢走，方向键不与页面／文件列表抢占，状态变化可被辅助技术理解。
- [ ] 中文输入法、原生剪贴板、查找替换、跳行、快速打开、缩进、每文件会话撤销／重做和快捷键焦点有效；减少动态效果下仍能通过文字／数值识别预演状态。
- [ ] 真实运行中验证失败恢复、切换模式、关闭工程和 App 退出清理；声音相关用例记录模式、设备、采样率与观测结果，不把无声模拟当作真实声音验证。
