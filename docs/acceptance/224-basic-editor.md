## 用户启动 App 后的 G1 调试

使用包含 JS/TS、JSON、HTML/CSS、Markdown、SCD、中文、长行和接近 1 MiB
文本的可编辑工程，另备只读 `.pnds` 工程包。记录本票提交、macOS／架构、
输入法和窗口尺寸；运行与否按既有流程手动选择。

1. 文件树／`⌘P` 打开两个文件；用 `⌘F` 查找、单个／全部替换，用 `⌘G`
   跳行，核对语法颜色、行号、选区缩进和长行滚动。非法行号应说明范围。
2. 用中文输入法组合输入、选区、剪贴板和原生编辑菜单；在两个文件间
   切换，分别撤销／重做。未保存时确认磁盘不变；重开同一文件后位置与
   草稿保留。核对 Escape 后 Tab 可以离开编辑器。
3. 保存合法草稿，确认真实磁盘与未保存标记；非法 manifest／README 修改
   应拒绝且保留可修正草稿。确认没有自动刷新／重启／检查／模型请求／提交。
4. 外部修改文件后保存，确认双方内容可核对；取消保留草稿，明确重载后
   显示历史重置且旧撤销不能覆盖新磁盘版本。另核对「撤销已保存修改」
   的独立版本保护。改名后核对新路径、语言模式和原草稿历史。
5. 只读工程包、超限／不可读／二进制文件解释原因；快速打开不能读取
   工程外路径、`.git` 或 `node_modules`。新工程会话不继承旧工程历史。
6. 在 1000×700、窄文件区域及 Pond／Sand／Stage／Brutal 四主题中核对工具栏
   换行、焦点、长行横向滚动、大文本响应、中英文案与错误可读性。
   用同一段代码核对关键字、字符串、数字、类型、函数及属性可轻易区分；
   JSON 键名、HTML 属性与 CSS 属性应有着色。普通行、当前行、选区及查找
   命中中的文字均应清晰，切换主题应即时更新且不改变草稿与撤销历史。
7. 在运行 monitor 中留下可识别交互状态，切换文件／控制台、展开／还原
   monitor；核对页面实例与状态保持、无刷新／重启。焦点转入工程页面后
   其键位继续按页面契约处理。实际声音由用户验证。
