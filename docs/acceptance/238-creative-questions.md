## 2026-10-21 · 简短讨论规则与同一方案承接

本轮保留逐题卡片，以简短的 grilling / domain modeling 提示检查关键决定的依赖、术语、具体演奏场景及原始约束，不引入题数或就绪分数。方案完整放在主回复；讨论保存在聊天，默认不新增 `creation-plan.md`。

- `assistant-task-flow.test.ts` 的双题回放验证：固定音高选择作答后，仍可在原任务中澄清另一个未决选择；明确排除自主底声后，完整主回复保留音高表、微小调音约束、排除项与验收。待答时不调用模型，不重复旧题，不写文件或运行检查。
- `CreationAssistant.test.tsx` / `CreationDiscussionHandoff.test.tsx` 验证：完整主回复中未出现在摘要卡片里的细节，仍进入新工作任务或交接审阅；只接纳当前明确选中的方案，其他助手建议继续分开标明，过程文字与私有 reasoning 不进入方案。
- `assistant-material-replay.test.ts` 验证：所选方案继承材料 ID／版本，交接与工作在重试、重启前继续校验；材料移除或版本改变后不再调用模型。

最终 `env RUST_TEST_THREADS=1 npm run check:all` 退出码 0：前端 2,446 项通过、1 项既有跳过；Rust 主套件 697 项通过、7 项既有忽略，其余工作区与文档测试通过。并发 Rust 运行曾遇到临时端口占用，按既有串行方式复跑通过，未修改该运行测试。

真实模型复测应包含“四色固定基频，仅加速度作微小音高偏移，讨论乐器设计”的创作场景。核对助手是否主动发现会改变方案的缺口、尊重固定音高约束，并区分建议与已确认选择；不以问了几题判断完成。选择交接后应整理同一方案，只有解释清楚的新关键冲突才重新提问。以上受控回放证明信息接续，不证明模型已具备这些设计判断；真实兼容模型复测仍待 #172。

## 2026-10-21 · 提问卡与过程入口调整

本轮调整取代上文首轮卡片的“选择后提交”交互：普通创作问题按当前聊天编号，点击选项或以键盘激活即提交；不预选推荐项。常驻“我的回答”输入框支持 Enter 发送、Shift+Enter 换行，输入法组合期间不发送；提交失败保留文字并允许重试。推荐文字放在选项最右侧的圆角描边标记中。取消待答轮次移到更多菜单，不在卡片底部显示“结束任务”。资料覆盖冲突仍保留独立的明确确认。
