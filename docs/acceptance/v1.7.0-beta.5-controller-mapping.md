# beta.5 MIDI／OSC 控制器映射验收

范围为 [#358](https://github.com/xO-xN/PNDS-App/issues/358) 及其子工单。下面的安装包实机项目由用户在 Apple Silicon 和 Intel Mac 上分别验证。每种架构独立回报。

## 自动化

- 池主运行 `npm run native:app-shell:verify -- --controller-mapping`，从实际 AppShell 载入 monitor 测试工程，在设置启用本机 UDP 和虚拟 Core MIDI 输入。观察工程已有的按钮、开关、推子和自绘回调的实际结果。
- 池客运行 `npm run native:app-shell:verify -- --client-controller-mapping`，从真实公开演出入口用 AppShell 加入受控工程。观察同一 performer 在停演、发现候选、失联及接续时的工程动作，验证刷新、主动切换和离开。
- 两项夹具使用各自真实 AppKit 窗口，分别执行失焦、隐藏和最小化。每段记录两次原生窗口状态采样、原有工程处理器实际记录的动作时间、状态与页面身份。夹具恢复窗口后读取结果，并检查动作时间位于恢复前的原生状态区间。失焦由独立的临时 AppKit 进程取得前台，并核对前台进程 PID。池客后台场景在池主停止后、到池主的连接失联期间进行。
- 夹具在后台通过 UDP 捕获一个已归属旧页的输入，延迟它进入主线程。池主刷新原页面并恢复同一地址的映射。池客显式换页后给新页学习同一地址。放行旧输入后，两种角色的新页动作数都只随新输入增加。
- 原生夹具输出的 `Native entry evidence directory` 指向该次运行的 `result.json`。启动脚本同时输出静态前端来源及改动清单。记录用于复验的集成提交、macOS 版本、架构、两份报告和 `npm run check:all` 结果。

## 实体设备与安装包

使用对应架构的候选 DMG、真实 MIDI 控制器和同局域网的独立 OSC 发送设备。为池客准备另一台运行可加入工程的池主。保留包名、SHA-256、候选提交、App 版本、`sw_vers` 和 `uname -m`。

验收产物中的 Controller Acceptance 工程在 monitor 和 performer 两页均有 Test button、Test switch、Test fader，以及自绘目标 Canvas pulse、Wet mix 和 Latch。旧工程可另用 Runes 的演奏模式按钮和 Nameless Nightmare 的推子。
