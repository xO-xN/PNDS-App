# #258 池主／池客实机验收

状态：代码与自动化接入已在本轮实施；签名／打包 App、双机、媒体、模型和网页持久化尚待用户实机验收。本文不是发行通过证明。

## 准备

- 两台同一局域网的 Mac，分别安装待验收 App。记录 macOS、CPU 架构、App 构建及两机地址。
- 池主明确填写节点名，用支持完整 performer URL 与同源资源的工程启动。使用侧栏“池客连接地址”，不要用普通手机二维码的 HTTPS 地址或裸 IP 替代。
- 准备 Sensor Meter（摄像头／模型／Worker）及至少一个普通 Socket.IO polling/WS 工程。保持既有手机 HTTPS 流程可单独验证。

## 角色与演出身份

1. 每次从创作返回演出都重新选择角色。中文只显示池主／池客，英文只显示 PNDS Host／PNDS Client。
2. 空闲角色按钮首击不切换，Escape／外部点击／失焦取消；次击切换。键盘焦点保持，减少动态效果不增加等待。
3. 池客核对池主名称与工程后明确参与。谱面打开只显示未知接纳，不冒充工程已接受该设备。
4. 演出中、断线、加入中、清理中点击角色按钮只提示先退出；池客底栏没有本机音频、工程启动和投影控制，原生菜单与对应快捷键也不能绕过。
5. 主动离开回到池客连接页。同工程重启和工程副本替换都要求再次核对、明确加入；旧页不能通过 HTTP polling 或 WS 自动进入新演出。
6. 普通断网保持当前页面及工程自身的重连策略；恢复同一演出后继续。确认池主 Stop 时页面及媒体释放。记录两类行为，不能把无响应当成 Stop。

## 媒体与真实网络

1. 首次摄像头／麦克风授权分别验证允许、拒绝和系统设置后重试；确认系统提示采用 macOS 语言，App 内状态不把页面加载当成媒体成功。
2. Sensor Meter 验证同源模型、Worker、首个推理、首个真实输入，以及后台／最小化后恢复。
3. 分别验证 polling、WebSocket 升级和持续连接；重复刷新不重启池主工程或音频进程。
4. 刷新首击和取消保持同一页及媒体。次击释放旧页，再核对同一演出并重载；刷新期间 Host 变化必须先释放并再次确认。
5. 离开、切入创作、实际退出 App 后，核实摄像头指示灯、麦克风、Worker、连接和本机监听均释放。切入创作打开本机首页，不载入旧远端工程。
6. 主窗口隐藏与面板收拢不等于离开。创作模式的多演奏端测试窗口及池主的既有创作接续正常。

## 网页数据与近期连接

1. 在工程自己提供的恢复流程中取得可验证网页数据／身份。手动离开、App 重启后再次明确加入同一 Host/工程，核对数据可恢复；不要要求恢复服务器未保存的触点或推子。
2. 更换 Host 的 LAN IP 或接入端口，再明确核验同一 Host：本机派生 localhost 主机名和端口保持，工程网页数据仍可用。
3. 同名的另一台 Host、同一 Host 的另一工程使用不同来源，不能收到前一工程的 localStorage/IndexedDB 或 host-only cookie。
4. 最近列表按稳定 Host 分开；同一 Host 改名／换工程不新建重复记录。旧地址被另一 Host 使用时保留原记录，经明确确认后另存新 Host。
5. 故意占用已保存的本机来源端口，观察真实失败及恢复步骤；不得自动换来源并宣称旧数据仍在。近期列表保存失败不应显示已保存。
