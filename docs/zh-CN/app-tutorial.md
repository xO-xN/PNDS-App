# PNDS App 使用教程

演出模式中，**池主**运行本地工程，**池客**加入另一台池主。创作模式提供编辑、讨论和测试。

## 1. 首次启动与权限授予

首次启动默认为池主，以后恢复上次选择的角色。通过演出界面的角色按钮切换池主和池客，通过右下角模式按钮进入创作。

若 macOS 阻止打开 App，可到「系统设置 → 隐私与安全性」选择「仍要打开」。系统请求访问工程所在目录时，允许后即可读取工程。

## 2. 工程管理与组织（左侧栏）

- 使用「导入工程」或 `⌘O` 打开工程。工程加入当前编组，未选编组时加入「主页」。
- 用侧栏下拉菜单新建或切换演出文件夹。右键菜单提供重命名、移动、导出和删除。删除编组保留工程文件。
- 拖动工程卡片排序，或拖到其他编组。每个列表最多新增 30 个工程。
- 侧栏「工具」打开内置工具列表，「返回」回到之前的编组。

## 3. 音频与通信配置

底栏提供音频、网络和设置入口。设置的「节点」页包含 External OSC target 与跨互联网演奏的 Room 配置。

- 演出使用工程声明的默认音频模式。创作测试可选保存版允许的 Internal、External 或 None。见[音频模式](./reference/audio-modes.md)。
- 在底栏选择音频输出设备、采样率或 LAN 地址，启动或「重新加载」时应用。
- 底栏音量和 `⌘M` 控制当前运行工程的 Internal 单／双通道输出。Internal 多通道固定 0 dB，External／None 禁用增益。

## 4. 内置工具

从侧栏「工具」选择并加载。

| 工具                  | 用途                                                                                         |
| --------------------- | -------------------------------------------------------------------------------------------- |
| Multichannel Gen      | 逐通道输出信号，核对 16 通道接线。                                                           |
| Local Diagnostics     | 用手机测量到池主的局域网延迟、抖动和丢包。                                                   |
| Telematic Diagnostics | 测量各站点到公网 hub 的连接。                                                                |
| Sensor Meter          | 查看手机运动传感器数据。按手机提示授权，所需安全上下文见[可信 HTTPS](./reference/https.md)。 |

## 5. 加载工程与多端联演流程

1. 把池主与参与设备接入同一局域网。在池主选择工程并点击「加载」。
2. 就绪后在底栏网络弹层复制完整演奏入口或显示二维码。手机浏览器打开后核对池主与工程，再确认进入。
3. 另一台 Mac 可选择「池客」，输入同一地址或选择最近池主，核对后加入。参与期间切换角色需先退出参与。

可在浏览器中保存池主入口到主屏幕、Dock 或书签。入口空闲时显示等待，地址变化后更新保存的网址。停演或换工程后，下一场仍需明确进入。未适配的工程会提示可用的兼容地址。

## 6. 跨互联网演奏（多站点）

1. 准备可用的 hub 地址和共享 token。部署步骤见 [pnds-hub](https://github.com/xO-xN/pnds-hub)。
2. 在各站点的「设置 → 节点」填写节点名、完整 `wss://` 地址和 token。加载 Telematic Diagnostics 核对连接。
3. 加载支持跨互联网演奏的同一工程，各站点选相同的 Room。演奏者加入本站点，站点间实时音频另行配置。见[演出组网](./reference/network.md)。

## 7. 演出实时控制与侧边栏呼出

- 移到窗口左边缘或按住 `⌘` 呼出侧栏。选择另一工程后再次点击加载，才替换当前演出。启动失败可在错误页重试。
- 更改网络、输出设备、采样率或 External OSC target 后，点击「重新加载」应用。刷新按钮只重载乐谱页面。
- 底栏投影按钮先打开场地窗口，再用同一按钮切换简介与演出内容。
- 使用窗口菜单、绿色窗口按钮或 `⌃⌘F` 切换全屏。其余操作见[快捷键速查](#快捷键速查)。

## 8. 创作工作台

点击右下角模式按钮，核对目标后再点击确认。Esc 取消。可[新建 Blank](./template-guide.md#新建-blank-工程)，也可用「打开文件夹工程」或「最近创作」打开源目录。安装工程包和内置工具可只读查看。

运行中的文件夹工程进入创作时保留 monitor 与运行，关闭投影。返回演出会结束测试。从另一张工程卡片选择「开始创作」时，按提示确认结束当前运行。

使用文件栏打开文件，中间区域在讨论、Git 版本和文件页之间切换。打开后的测试与打包入口见[实时测试](#实时测试与-performer-窗口)和[创作指南](./template-guide.md#4-打包与发布)。

## 携带与恢复演奏记录

演奏记录保存演奏信息，回放由兼容工程生成声音。运行后打开底栏「演奏记录」。

- 选择「新建录制」，演奏后点击「停止并保存本轮」。打开完成的记录可从头回放。
- 创作模式可「叠加新一轮」或在「录制轮次」中选择「整轮重录」。一轮可含多人。工程内容变化时，叠加或重录需确认。
- 「导出」生成 `.pndsrecord`，「打开记录」可导入该格式或旧 `.json`，保留外部原件。

可编辑工程的记录存于 `.pnds-creation/recordings/`。停止工程后复制完整目录，包含隐藏文件。Git 和默认 `.pnds` 不携带记录。安装工程与工具的记录在本机 App 数据目录。

原路径首次读取会迁入旧本机记录。已搬迁时，从「设置 → 关于 → 打开数据目录」下的 `recordings` 找到旧 `.json`，再在新位置的工程中「打开记录」。未完成的记录不能回放或续录。

## 工程版本与历史

从工程名旁打开「Git 版本」。Blank 自带初始版本。已有文件夹可选择「启用本地版本记录」，核对文件范围和署名后确认。

- 「保存当前版本」先保存草稿，再记录符合规则的文件。先解决草稿冲突。依赖、构建产物、私有资料及已识别密钥排除在外，大型媒体默认不选。
- 选择历史版本可查看文件差异。对当前仍可编辑的文本可「核对载入草稿」，核对后再保存。用版本旁的改名按钮修改显示名称。
- 工程版本用于恢复文件。交接基线只用于[比较交接后的变化](#比较交接后的变化)。

## 切换与恢复工程版本

先结束未完成的助手任务并停止工程。在 Git 版本页选中目标版本，确认「切换到此版本」或「恢复此版本内容」。有改动时可先保存版本、取消，或再确认丢弃允许范围内的修改。完成后手动启动测试。

## GitHub 同步

在创作模式中，Git 版本页可将当前分支的已提交文件和历史备份到 GitHub 同名分支。若工程还没有 Git 版本，先[启用本地版本记录](#工程版本与历史)。「保存当前版本」默认只在本机记录版本，离线时也可继续创作。

### 连接 GitHub 并绑定仓库

1. 打开「设置 → GitHub 账号」，点击「登录 GitHub」，复制授权代码。点击「前往 GitHub 授权」，在浏览器输入代码并授权 PNDS。
2. 打开工程的「Git 版本」，点击「绑定仓库」。从「管理 GitHub 授权」进入 GitHub，安装 PNDS GitHub App 并选择要使用的仓库。备份需要你的账号对仓库有写权限。返回 PNDS 后点击「刷新仓库列表」。需要新仓库时，可先用「在 GitHub 上创建仓库」创建空仓库。 [PNDS GitHub App 安装页](https://github.com/apps/pnds-app/installations/new)
3. 选择空仓库或与当前工程共享 Git 历史的仓库，确认绑定。若 App 提示已有 GitHub `origin`，核对后再确认。在「备份设置」中可更换仓库或解除绑定。这两项操作会取消旧仓库的待备份任务，并保留本地版本。

### 为首次备份核验官方模板仓库

1. 在已有保存版本、尚未绑定仓库的 Blank 工程中，打开「Git 版本 → 从模板进行首次备份…」，点击「在 GitHub 上使用官方模板建仓」。在 GitHub 选择仓库归属、名称和公开性，仅使用默认分支。
2. 将新仓库授权给 PNDS GitHub App。返回 PNDS，点击「刷新仓库列表」，选中新仓库并核验。
3. 查看所选仓库和默认分支的核验结果。如果 PNDS 提示切换分支，先切到同名本地分支，再核验。核验保留本地版本和 GitHub 仓库原有内容。
4. 点击「查看首次备份」，核对仓库、分支和保存版本后确认。目标为公开仓库时，本次确认包含截至所示版本的已提交文件和历史。
5. 如果首次备份中断，重新打开工程并点击「继续首次备份…」。后来在本机保存的新版本会保留，本次继续备份原先确认的版本。若 GitHub 已收到该版本，App 检查状态时会完成绑定。

### 备份与更新分支

- **备份。** 保存版本后点击「备份到 GitHub」。新分支首次备份时，会在 GitHub 建立同名分支。停在历史版本时，先切回分支或保存成新分支。首次备份到公开仓库时，核对仓库、分支及将公开的已提交文件和历史。曾备份的远端分支被删除后，需确认才会重建。
- **自动备份。** 在「备份设置」中开启「保存版本后自动备份」。离线时可查看上次已知状态，待备份版本会保留。恢复联网且自动备份仍开启时，打开原工程与分支即可继续。
- **更新。** 保存或清理草稿和本地改动，结束未完成的助手任务并停止工程，再点击「从 GitHub 更新」。当前分支须能快进到远端同名分支。若两边的历史已分叉，先在外部 Git 工具中处理，再回到 PNDS 点击「检查 GitHub 状态」。

### 在另一台 Mac 打开 GitHub 工程

在创作模式打开「切换其他工程」菜单，选择「从 GitHub 克隆」。登录后从「已授权仓库」选择私有仓库。公开仓库可输入 `所有者/仓库名`，点击「读取分支」。选好分支、父目录和新文件夹名称后，点击「克隆并打开」。打开后已绑定来源仓库，默认手动备份。运行依赖和 SynthDef 会在手动测试时检查。

需要迁移演奏录制时，按[携带与恢复演奏记录](#携带与恢复演奏记录)单独操作。

## 配置模型服务

在「设置 → 模型服务」填入支持文本和工具调用的 OpenAI 兼容 API 基础地址、模型名及密钥。远程地址使用 HTTPS，本机回环地址可用 HTTP。

配置自动保存，密钥存入 macOS 钥匙串。「测试连接」检查文本回复和工具调用。失败后按提示修正配置再试。

## 讨论与工作

- **讨论**用于提问、澄清选择与拟定方案。回答选项或输入自己的答案。需要结束时，选择「取消本轮讨论」。
- **工作**执行明确的修改任务。核对讨论方案后选择「开始工作」，或切到工作模式并发送任务。助手按任务保存、检查及编译所需 SynthDef。
- 要交给外部 agent，选择「写交接文件」。查看实际帮助来源可点击回复的来源按钮。助手读取工程的范围见[讨论工程保存版文本](#讨论工程保存版文本)。

## 记录交接与外部接续

选择「写交接文件」，审阅任务及保存范围，再点击「记录交接」。可先保存草稿或仅按保存版交接。完成后在原回复点击「复制 prompt」，交给外部 agent。

任务写入 `docs/creator-handoff.md`，基线用于比较保存版变化。基线采集失败可在基线列表重试。

## 恢复与清理工程聊天

重新打开工程即可恢复已保存聊天。搬迁时复制完整工程及隐藏目录 `.pnds-creation/`，在目标 Mac 单独配置模型服务。旧本机聊天可在原路径首次打开工程时迁入，再搬迁。

讨论工具栏支持重试保存、重载或确认清理当前工程聊天。清理保留工程文件与创作资源中的文件。

## 查询与释放端口

打开「设置 → 端口」，查看所选工程保存版声明的端口。未选工程时使用 6868／6869。点击「刷新」更新。

释放外部进程前核对显示的进程身份并确认。App 托管的端口通过关闭对应工程释放。启动失败页也可用「释放并重试」。

## 静态工程诊断

助手工作任务和 CLI 可检查保存版声明、依赖及产物。静态诊断可在演出期间运行。

```sh
/Applications/PNDS.app/Contents/MacOS/pnds check /path/to/project --json
```

## 临时副本运行检查

助手工作任务和 CLI 可在临时副本上核对 health 和页面 HTTP。默认使用工程允许的 None，可明确选择 Internal。资源被当前运行占用时，先等待释放。实际音画仍通过实时测试核对。

```sh
/Applications/PNDS.app/Contents/MacOS/pnds check /path/to/project --run --json
```

可加 `--mode internal`，用 Ctrl-C 取消并等待清理。完整参数见 `pnds check --help`。

## 单文件差异与撤销

修改文本后选择「审阅修改」，查看差异并点击「保存已审阅修改」。可用「撤销已保存修改」还原当前工程最近一次记录。遇到后续修改或未解决草稿时，先处理冲突。

## 编辑工程文本

从文件树或「快速打开文件」（`⌘P`）打开文本。用 `⌘F` 查找或替换当前文件，用 `⌘G` 跳到行。

`⌘S` 保存当前文件，`⌘Z`／`⇧⌘Z` 撤销／重做草稿。保存冲突的处理见[草稿、保存版与运行内容](#草稿保存版与运行内容)。

## 讨论工程保存版文本

助手会把所需的保存版文本发送给配置的模型服务。草稿需在编辑器选中文字并点击「附加选区并讨论」，发送前可核对或移除快照。

聊天上下文详情的「阅读整个工程」会准备允许读取的保存版文本并发送，超出预算时提示缩小范围。

## 比较交接后的变化

打开「交接后的变化」，选择任务和基线。文本显示与当前保存版的差异，资源显示指纹和大小。结果过期时刷新，可用「打开当前文件」继续编辑。基线用于比较，恢复文件请用[工程版本](#工程版本与历史)。

## 修改建议与临时预演

在建议卡切换「参数／代码」并调整候选。当前工程适配预演时，可临时试听或查看参数效果。结束预演会尝试恢复参数原值，恢复失败时在实时测试中核对。

选择「应用到工程」才写入候选。发现文件变化或已有草稿时，先处理冲突。保存后的采用步骤见[草稿、保存版与运行内容](#草稿保存版与运行内容)。

## 文件与目录操作

在文件栏点击「新建」添加文件或目录，或在目标目录的右键菜单操作。已有同名项会阻止创建。用 F2 重命名，引用路径需随之更新。拖出到 Finder 会复制保存版。

## 草稿、保存版与运行内容

草稿是编辑器中的未保存内容，保存版是磁盘文件，运行内容是本次启动或页面加载实际采用的版本。

保存页面文件后用 `⌘⇧R` 刷新。服务器改动需重启测试，修改 SCD 后先编译 SynthDef 再重启。有草稿时遇到外部写入，先比较后选择保留草稿或采用磁盘内容。

## 创作资源

在创作模式左侧栏，点击「新建文本文件」，命名后在编辑器中输入或粘贴文本，再保存。也可以把文本文件拖入「创作资源」，或点击「收件箱」选择一个或多个文件。导入的副本先显示在这里，点击文件名即可打开。每份上限 1 MiB，最多 64 份，合计 8 MiB。支持重命名、在 Finder 中显示和确认删除。

发送工作任务可指定需接入的文档。与工程现有内容冲突时，先确认替换、并存或取消。接入成功后移出原文，失败时保留。从标题栏的工程菜单打开「最近一次接入恢复」，即可核对或撤回。

## 在 SuperCollider 中打开保存版

本机安装 SuperCollider 后，打开工程的 SCD 文件，在「文件操作」选择「在 SuperCollider 中打开保存版」。需要采用声音改动时，回到 App 编译并重启测试。

## 多聊天与历史问题

用聊天选择器切换，或在「更多 → 新建聊天」开始独立话题。聊天列表可删除单个聊天。编辑并重新发送历史问题会建立分支，保留原聊天。

## 长对话与上下文

在聊天上下文详情查看预计用量。需要缩小范围时，选择「整理旧聊天」，核对轮次并生成摘要。采用摘要后，它将用于后续请求。

## 暂停、继续与本地资源确认

用停止按钮暂停，保留已保存改动。点击「继续」接续同一任务，遇到文件或配置变化时按提示处理。

需要模块或共享包时，确认卡列出资源和影响。选择「添加并继续」、替代方案或「结束任务」。

## 移交整场演出

在演出文件夹的右键菜单导出 setlist，将包含 `set.json` 与工程包的完整目录交给接收方。接收方在演出模式用 `⌘O` 打开该目录。

导入成功后替换用户工程列表和编组，保留原工程文件。音频设备、采样率、节点和密钥在接收方配置。

## 实时测试与 performer 窗口

在「实时测试」区选择保存版允许的音频模式并启动。错误原因见控制台，修正后重试。关闭测试保留草稿。

- 手机测试使用底栏网络弹层的 performer 测试地址或二维码。
- 「添加 performer」打开独立测试窗口，可选择手机或平板尺寸。鼠标单点触摸模拟默认开启，可在窗口中切换。
- 需要媒体时，通过工程页面选择设备并按系统提示授权。拒绝后核对权限并重试。用真实设备核对多点触控与采集。见[原生媒体](./reference/native-media.md)。

### 用 USB 连接 iPhone 或 iPad 测试作品

1. 用数据线连接设备和 Mac，解锁设备并点「信任」。关闭设备的 Wi‑Fi 和蜂窝数据（如有）。
2. 在 Mac 的「系统设置 → 网络」查看 USB 接口的 IPv4 地址。若没有地址，可在「通用 → 共享 → 互联网共享」选择设备的 USB 接口作为输出，再查看。
3. 在 PNDS 创作模式底栏的网络菜单选择这个地址，启动测试。在设备上用 Safari 打开底栏显示的完整演奏者地址，触摸页面确认 Mac 有反馈。

## 添加模块与共享包

在文件栏选择「添加资源」。本地模块加入工程源码，共享包在 manifest 引用 App 内的指定版本。Blank 已接好演奏者身份恢复。核对依赖及冲突后添加，模块的接线任务写入交接单。接线后用实时测试确认效果。见[模块手册](./modules/README.md)。
