# PNDS App 使用教程

本文档将介绍 PNDS App 的核心功能界面、工程组织方式、音频/通信配置，以及现场演出的多端协同流程。

---

## 1. 首次启动与权限授予

- **打开应用**：启动 PNDS App 进入欢迎界面。
- **首次打开（macOS 安全确认）**：当前版本使用 ad-hoc 签名、未经 Apple 公证，首次打开会被系统拦截并提示无法验证开发者。在「应用程序」中右键点击 PNDS，选择 **打开**，再在弹窗中确认 **打开**；或前往 **系统设置 → 隐私与安全性**，点击 **仍要打开**。此后不再提示。
- **文件访问权限**：首次运行时，系统会弹出本地文件系统访问请求，请选择 **“允许 / Allow”**，以确保 App 能够正常读取、加载与管理本地乐谱工程。

---

## 2. 工程管理与组织（左侧栏）

App 的**左侧侧边栏**为主要工作区，负责整个演出工程的生命周期与层级管理：

- **导入工程**：点击工程列表末尾的 **`+ 导入工程`** 按钮，或使用快捷键 `⌘ O`，将 `.pnds` 文件导入当前用户编组；未选择编组时加入「主页」。
- **文件夹整理**：通过侧栏下拉选择自定义演出文件夹，数量不限，下拉可滚动。新建入口位于下拉及右键菜单；重命名、上移／下移、导出和删除位于当前编组的右键菜单。删除只解除编组，工程文件仍保留。
- **自由排序**：按住工程卡片拖动可调整成员顺序；拖动时显示临时编组列表，放到用户文件夹则加入末尾，放到主页则回到未分组。打开新工程加入当前用户编组；每个列表的新增上限仍为 30 个工程。
- **独立工具入口**：按「工具」按钮查看内置工具，用户下拉暂时改为「返回…」。再次按工具或点击返回恢复原视图；原编组已删除时回到主页。浏览编组与工具不会停止演出或应用待修改音频。从工具视图打开用户工程，会先返回之前的用户编组。

## 3. 音频与通信配置

单击侧栏卡片只选择、预检工程，不自动开始。加载、刷新、主音量、音频设备与采样率、网络、投影和设置集中在窗口底栏；设置以分类导航进入音频、节点、HTTPS、DNS、端口等现有能力。

- **演出音频模式**：按工程 manifest 声明的默认模式加载，演出界面不提供模式选择。创作测试区仍可选择保存版工程允许的 Internal／External／None，三种模式的区别见[音频模式](../reference/audio-modes.md)。
- **本地网络**：底栏网络面板选择全局 LAN 地址，与设置「节点」同步。运行卡选中时，新地址标记「更改」，手动重启后应用；选中其他工程时只是预配置。面板分别显示运行中已应用的地址与下次启动的选择，monitor 不会立即换地址。
- **音频设备与采样率**：底栏音频面板和设置「音频」使用同一套全局偏好。运行事实显示已应用的设备与实际采样率，修改只供下次启动／手动重启使用，不自动重启。
- **主音量**：底栏喇叭与推子实时控制正在运行的工程；运行 A、浏览 B 时仍控制 A。Internal 单／双通道可衰减至静音，多通道固定 100%／0 dB，External／None 禁用增益。`⌘ M` 静音／恢复；新运行回到原有默认值。
- **OSC 与 Room**：默认 External 工程的 OSC target、声明跨互联网能力工程的 Room 仍在底栏网络面板，按原有偏好和下次启动规则应用。节点 token 保持遮罩。

## 4. 内置工具

侧栏独立「**工具**」按钮提供即开即用的验证工程，覆盖演出链路的三层检查（顺序固定）：

- **Multichannel Gen**（[Multichannel-Signal-Generator](https://github.com/xO-xN/Multichannel-Signal-Generator)）：16 通道信号发生器。什么时候用——验证本机音频接口的通道映射、接线与扩声配置，尤其在多通道输出的工程上场前。加载后 monitor 提供 16 个垂直推子，逐通道确认「声音去了该去的地方」。
- **Local Diagnostics**（[Local-Network-Diagnostics](https://github.com/xO-xN/Local-Network-Diagnostics)）：本地网络诊断。什么时候用——演出前检查演奏者设备到 Host 的 Wi-Fi 链路质量（延迟 / 抖动 / 丢包），手机扫码即测。
- **Telematic Diagnostics**（[Telematic-Network-Diagnostics](https://github.com/xO-xN/Telematic-Network-Diagnostics)）：跨互联网诊断。什么时候用——多站点演出前对 hub 星型网络做 go / no-go 判定（见[跨互联网演奏](#6-跨互联网演奏多站点)一节）；每个站点的 monitor 呈现同一张「花视图」，绿则可演，红则标注问题站点与问题链路。

工具与普通工程一样从侧栏加载运行；细节与判定阈值见各工具仓库。

## 5. 加载工程与多端联演流程

开始前，将运行 PNDS App 的 Host 电脑与所有演奏者设备接入同一本地网络；Host 建议使用有线连接，演奏者设备（手机 / 平板）连接同一 Wi-Fi。

确认配置无误后，点击 **“加载 / Load”** 按钮启动工程：

1. **服务初始化**：App 将按预设参数同时启动该工程内置的**数字乐谱本地服务器**与 **DSP 音频引擎**（如果使用 Internal 内置合成器模式）。
2. **进入指挥界面 (Conductor View)**：工程加载成功后，左侧栏将自动向左收起，主视窗切换为全屏「指挥界面」。
3. **演奏者多端接入**：
   - **扫码加入**：部分工程支持使用移动端扫描指挥界面上的 **二维码** 进入「演奏者界面」。
   - **浏览器访问**：在任意设备的现代浏览器中直接输入 Host 电脑的局域网地址与演奏者页面端口，接入系统。

## 6. 跨互联网演奏（多站点）

PNDS 池谱，寓意「多池相连」：多个城市 / 站点各自运行一台 Mac + 本地演奏系统，经由一台公网中继（hub）相连，即可跨互联网合演同一部作品。标准组网是**星型 hub 中继**，操作流程如下（组网原理与房间 / token 语义见[演出组网](../reference/network.md)）：

1. **部署 hub**：在一台公网 VPS 上部署 [pnds-hub](https://github.com/xO-xN/pnds-hub)（跨互联网演奏中继服务器），按其仓库的部署指南安装（systemd 服务 + TLS 反向代理，安装时生成共享 token）。hub 只中转站点间的控制消息，各站点始终是**出站连接**，无需在演出场地开放任何入站端口。
2. **各站点配置节点**：在每台站点 Mac 上打开设置面板（`⌘ ,`）的「**节点**」栏，填写三项——**节点名**（这台 Mac 在星型图里的名字，如 `site-a`）、**hub 地址**（完整 `wss://` 地址）、**token**（遮蔽显示）。三项是本机全局配置，填一次所有工程共用；修改在下次启动工程时生效。
3. **网络验证（go / no-go）**：各站点加载内置的 **Telematic Diagnostics**（见[内置工具](#4-内置工具)一节）——App 注入的节点配置就是它的连接配置，自动连接、无需在表单手抄；节点三项没填齐时，加载按钮会变为「**设置节点**」提示先完成配置。各站点的 monitor 将呈现同一张「花视图」星型图，横幅绿 / 红给出可演 / 不可演判定，并标注问题站点与链路。
4. **正式演出**：加载正式工程（工程在 manifest 声明跨互联网能力并实现 hub 协议，Telematic Diagnostics 即参考实现）。App 自动按工程派生房间——同一作品、同一 Room 分组（底栏网络面板的 Room 下拉，1–3）的站点进入同一房间，开错工程互不可见；演奏者照常扫码接入**本站点**，站点之间的实时音频由 JackTrip 等外部方案承载。

## 7. 演出实时控制与侧边栏呼出

在演出或排练过程中，如需临时调整音频输出设备、音量或检查连接状态：

- **边缘悬停**：将鼠标指针移至窗口最左侧边缘，左侧设置栏将平滑滑出。
- **快捷唤出**：按住键盘 `⌘` 键显示侧栏；松开且指针离开后自动收起。下拉菜单、对话框、模式确认与启动／关停操作期间保持显示，全部结束后自动收起。侧栏覆盖满窗口 monitor，显隐不改变页面尺寸、不重载。
- **单一演出动作**：底部只显示加载／更改／关闭中的一个动作。选中其他工程不打断演出；点击加载后确认替换运行。修改网络、音频设备／采样率或 External 目标后，用「更改」手动重启工程并应用修改；错误页仍提供 Retry。
- **原生选卡**：`⌘ ⌥ ↑`／`⌘ ⌥ ↓` 选择上一个／下一个可见工程并显示侧栏，monitor 或文本输入持焦时仍有效。仅演出主窗口执行，按当前列表到端停止、不自动加载。确认弹层、App 弹出层、启动／关停及其待提交操作期间阻挡；创作、performer、投影和帮助窗口保留自身键位。左右键无新增导航。
- **投影与简介**：底栏有一个投影按钮：先打开场地窗口，随后同一个按钮切换简介／演出内容，撤回后恢复简介。刷新按钮只刷新 monitor 页面，菜单与 `⌘⏎` 保留投影控制。帮助仍可通过帮助菜单和 `⌘ ?` 访问。
- **全屏演出**：`⌃⌘ F`、窗口菜单或原生绿色窗口按钮进入全屏，monitor 页面自动适配尺寸。

## 8. 创作阅读工作台

右下角持续显示同一个模式按钮，悬浮或聚焦提示目标模式。第一次点击进入原位确认，再次点击提交；只有丢弃未保存内容时在按钮上方提示实际后果。按钮聚焦时，Enter 或空格执行同样的两次确认。Esc、点击其他位置或窗口失焦可取消。用「打开文件夹工程」选择自己的工程，或从「最近创作」继续。创作模式中的 `⌘ O` 同样选择文件夹；不自动启动工程。

打开可编辑源工程后，点击创作顶栏右侧「Generate .pnds」打开保存版打包面板；工程标题下拉可切换／新建工程、记录或查看创作交接单、刷新清单和打开 Finder。选择器说明文件夹工程可在外部编辑、安装的 `.pnds` 工程包与内置工具只读的原因。取消原生选择或选择器保留当前工程。重新打开安装目录或经符号链接访问不会使其成为可编辑源工程。

manifest 与本地化 README 置顶，其余按运行与依赖、页面、声音源码、编译产物、模块、资源和工程支持分组；搜索和文件按钮保留实际路径。选择文本文件可阅读，并在当前文件中查找。PNG、JPEG、WebP、GIF 在选中后预览；解码失败仍可查看信息并在 Finder 中定位。音频和其他二进制只显示名称、类型和大小，交给外部应用处理。文件栏的单一 Finder 按钮打开工程文件夹，文件工具栏的「文件操作」菜单可重新读取磁盘、定位当前文件及重命名；manifest 禁止重命名。

文本上限为 1 MiB、图片为 4 MiB，文件清单最多 4,096 项、32 层；`.git` 与 `node_modules` 不列出。文件消失、权限不足、无效 UTF-8、超过上限、工程身份失效或路径越界会分别提示。需要更新清单时点击刷新文件清单。创作打开只检查基本声明与入口结构，尚未安装依赖或编译声音产物的初版仍可阅读；运行和打包保留各自检查。

从工程标题菜单打开「Git 状态与差异」，查看当前工程的分支、Git HEAD 和未提交文件。工程位于较大仓库中时，仍只显示本工程路径。分别选择「已暂存：HEAD → 暂存区」「未暂存：暂存区 → 磁盘」，或查看未跟踪文件的磁盘保存版预览。二进制、不可读及过大文件会说明无法显示文本的原因；缺少 Git 或仓库不会阻碍创作。此面板只读，无需登录；提交、切换分支、合并和推送仍在外部工具中操作。

Partial clone（部分克隆）仓库可能缺少所需对象，面板会明确说明无法检查。请先在外部 Git 工具中补齐仓库；App 不会下载缺失对象或修改 Git 对象库。

未保存草稿、磁盘保存版、Git HEAD 和运行内容各自独立。查看 Git 不会保存草稿、刷新页面、重启测试，也不能证明正在运行哪个内容版本。磁盘变化、从外部工具返回以及快照打开超过 30 秒时会标记可能过期；点击「刷新 Git」重新读取。切换工程或关闭面板会清除本次查看，迟到结果不会出现在另一个工程中。

胶囊按钮使用固定斜切色块和 300ms 名称过渡；完成后保持新模式静止样式，指针移开再进入才恢复悬浮提示。四主题均保留该过渡，系统启用减少动态效果时直接完成，启动／关停期间禁止切换。运行中的可编辑文件夹优先于另一张选中卡片，进入创作时不重启、不重载 monitor；已选但未运行的文件夹不自动启动。工程包、工具和不可编辑目标结束旧运行并进入创作首页。进入创作关闭投影；返回演出结束测试，清空选择与临时状态，回到空闲首页而不自动载入。

可编辑源工程沿用手动保存、草稿与磁盘冲突保护。SCD 工具栏编译整个标准源码集合，结果进入控制台；底栏启动／重启／关闭测试和刷新保存版页面，右侧保留测试音频、同一个 monitor 与独立 performer 窗口管理。控制台默认关闭，只在创作底栏和 `⌘ + 反引号` 提供切换；展开 monitor 只改变布局，Esc 还原。可编辑工程的「模块」分类标题旁提供「添加 PNDS 模块」，离线提供 QR 加入、客户端连接与身份恢复、monitor 主题跟随、monitor 语言跟随、monitor 多窗口视图同步，以及可选 hub 连接六项。选择后列出真实文件、源码版本和前置依赖；明确加入后写入 `modules/pnds-<id>/`，来源记录位于其中的 `pnds-module.json`，接线任务追加到 `docs/creator-handoff.md`。文件已加入不代表接线或演出验证完成，App 不改入口／manifest、不安装依赖或 Skills、不启动工程。已有目标不覆盖；交接写入失败会列出已经加入的文件，处理错误并重新读取状态后可补记交接。模块升级、合并及移除交给外部 agent。

### 查询与释放端口

打开设置（`⌘ ,`）的「端口」栏，查看所选工程 manifest 的演奏端与监视端端口；创作模式读取当前工作台已保存的 manifest，草稿不会改变查询目标。没有选择时使用 6868／6869。进入时查询一次，需要更新时点击「刷新」，不会后台轮询。

外部占用显示 PID、进程名称与完整命令行。点击「释放」后确认显示的身份；App 在发送退出信号前会再次核对同一进程，先等待优雅退出，必要时有界强制退出。占用消失、身份变化或变成本 App 的受管进程时会取消并刷新，需要重新确认。启动错误页的「释放并重试」也先确认身份，只有成功释放且端口可用才重试。

本 App 运行的端口显示真实所属工程并要求先关闭工程，不提供直接释放。运行 A 时选择 B，只查询 B 的端口；归属依据 A 启动时已应用的端口和真实子进程，不会把 B 的不同端口标成 A 正在运行。

## 静态工程诊断

在创作工作台点击「静态 Doctor」，主动检查工程的已保存文件。未保存草稿
不会进入报告，也不会被自动保存。诊断在演出启动、运行及关停期间仍可
使用，不启动工程、不清理进程、不占用端口，也不联网安装依赖。

报告显示工程和版本、检查范围、阻断问题、提示、跳过原因及未验证内容。
点击工程内的文件位置可返回对应文件；修正并保存后主动重检。工程磁盘
变化后旧结果显示过期。静态通过仅说明列出的静态项通过，页面行为、
运行就绪与真实声音仍需要单独测试。

外部 agent 可使用 App 随附的命令行工具：

```sh
/Applications/PNDS.app/Contents/MacOS/pnds check /path/to/project --json
```

它与 App 使用同一静态规则，默认提供可读报告；`--json` 输出机器可读
报告。具体参数与退出含义可运行 `pnds --help` 查看。工具读取本机资源，
不执行工程源码或修改工程。

## 临时副本运行检查

在创作工作台点击「受控检查」，再主动开始。检查只复制已保存输入；
未保存草稿会保留，不会自动保存。默认 None，且工程必须声明支持；
需要真实音频时明确选择 Internal。External 继续使用 App 原有手动测试。
可明确请求在副本编译 SynthDef；缺少本机编译器或必需资源会如实失败。

进度包含副本准备、静态检查、启动、health／HTTP 和清理。结果记录任务、
实际副本内容指纹、依赖与共享版本、模式、设备环境、退出及清理情况。
Git HEAD 仅是辅助信息，不代表全部输入。原工程后来变化会使报告过期，
请主动重检。临时副本中的缓存与编译产物不会自动回写。
在同一创作工程内关闭再打开对话框，报告与错误仍会保留，直到主动重新检查。
点击「复制报告」可复制完整 JSON，包含错误和清理情况，便于反馈问题。

App 正在启动、演出、关停，或另一个检查仍占有资源时，新的 App／CLI
运行检查会被拒绝，不会停止已有演出；静态 Doctor 仍可使用。停止检查、
关闭检查对话框、切换工程或退出 App 会取消所属任务并清理资源。
如果上次检查的资源清理未确认，关闭前台后仍会阻止新的 App／CLI 运行；
确认资源已释放后重试会恢复。若提示归属记录不完整，先重启 Mac 再重试。
静态诊断仍可使用。
服务就绪不代表画面、手机、模型推理、真实声音或艺术效果已经验收。

```sh
/Applications/PNDS.app/Contents/MacOS/pnds check /path/to/project --run --json
/Applications/PNDS.app/Contents/MacOS/pnds check /path/to/project --run --mode internal
```

命令使用随 App 的 Node／音频／共享资源。Ctrl-C 或 SIGTERM 会取消并
等待清理；退出码 0 表示检查和清理通过，1 为失败或未执行，130 为取消，
2 为参数或输出错误。独立复制命令时可用 `--app-root /path/to/PNDS.app`
指定完整资源来源；不回落全局 Node。副本按保存文件依次读取，不承诺
全工程瞬时原子快照，也不是限制任意工程代码的系统沙箱。

## 单文件差异与撤销

编辑一个已有文本文件后，选择「审阅修改」查看改前与拟保存文本的真实
差异。取消会保留草稿；「保存已审阅修改」成功后显示实际保存记录，
可选择「撤销已保存修改」恢复原文，不需要 Git。

撤销只适用于当前工程最近一次已记录的单文件修改。文件后来又被手动／
外部保存、改名、删除，或存在未解决草稿时，旧操作会被拒绝，不覆盖
后续工作。切换或关闭工程会撤销旧身份的权限；记录不跨 App 重启保存。
检查失败不会自动撤销文件，也不会自动采用副本产物。
