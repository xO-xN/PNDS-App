# PNDS App 使用教程

本文档将介绍 PNDS App 的核心功能界面、工程组织方式、音频/通信配置，以及现场演出的多端协同流程。

---

## 1. 首次启动与权限授予

- **打开应用**：启动 PNDS App 进入欢迎界面。
- **首次打开（macOS 安全确认）**：当前版本使用 ad-hoc 签名、未经 Apple 公证，首次打开会被系统拦截并提示无法验证开发者。在「应用程序」中右键点击 PNDS，选择 **打开**，再在弹窗中确认 **打开**；或前往 **系统设置 → 隐私与安全性**，点击 **仍要打开**。此后不再提示。
- **文件访问权限**：首次运行时，系统会弹出本地文件系统访问请求，请选择 **“允许 / Allow”**，以确保 App 能够正常读取、加载与管理本地乐谱工程。

---

## 2. 工程管理与组织（左侧栏）

App 的**左侧侧边栏**为主要工作区，负责整个演出工程的生命周期与层级管理：

- **导入工程**：点击工程列表末尾的 **`+ 导入工程`** 按钮，或使用快捷键 `⌘ O`，将 `.pnds` 文件导入当前用户编组；未选择编组时加入「主页」。
- **文件夹整理**：通过侧栏下拉选择自定义演出文件夹，数量不限，下拉可滚动。新建入口位于下拉及右键菜单；重命名、上移／下移、导出和删除位于当前编组的右键菜单。删除只解除编组，工程文件仍保留。
- **自由排序**：按住工程卡片拖动可调整成员顺序；拖动时显示临时编组列表，放到用户文件夹则加入末尾，放到主页则回到未分组。打开新工程加入当前用户编组；每个列表的新增上限仍为 30 个工程。
- **独立工具入口**：按「工具」按钮查看内置工具，用户下拉暂时改为「返回…」。再次按工具或点击返回恢复原视图；原编组已删除时回到主页。浏览编组与工具不会停止演出或应用待修改音频。从工具视图打开用户工程，会先返回之前的用户编组。

## 3. 音频与通信配置

单击侧栏卡片只选择、预检工程，不自动开始。加载、刷新、主音量、音频设备与采样率、网络、投影和设置集中在窗口底栏；设置以分类导航进入音频、节点、HTTPS、DNS、端口等现有能力。

- **演出音频模式**：按工程 manifest 声明的默认模式加载，演出界面不提供模式选择。创作测试区仍可选择保存版工程允许的 Internal／External／None，三种模式的区别见[音频模式](../reference/audio-modes.md)。
- **本地网络**：底栏网络面板选择全局 LAN 地址，与设置「节点」同步。运行卡选中时，新地址标记「更改」，手动重启后应用；选中其他工程时只是预配置。面板分别显示运行中已应用的地址与下次启动的选择，monitor 不会立即换地址。
- **音频设备与采样率**：底栏音频面板和设置「音频」使用同一套全局偏好。运行事实显示已应用的设备与实际采样率，修改只供下次启动／手动重启使用，不自动重启。
- **主音量**：底栏喇叭与推子实时控制正在运行的工程；运行 A、浏览 B 时仍控制 A。Internal 单／双通道可衰减至静音，多通道固定 100%／0 dB，External／None 禁用增益。`⌘ M` 静音／恢复；新运行回到原有默认值。
- **OSC 与 Room**：默认 External 工程的 OSC target、声明跨互联网能力工程的 Room 仍在底栏网络面板，按原有偏好和下次启动规则应用。节点 token 保持遮罩。

## 4. 内置工具

侧栏独立「**工具**」按钮提供即开即用的验证工程，覆盖音频、网络与手机传感器验证：

- **Multichannel Gen**（[Multichannel-Signal-Generator](https://github.com/xO-xN/Multichannel-Signal-Generator)）：16 通道信号发生器。什么时候用——验证本机音频接口的通道映射、接线与扩声配置，尤其在多通道输出的工程上场前。加载后 monitor 提供 16 个垂直推子，逐通道确认「声音去了该去的地方」。
- **Local Diagnostics**（[Local-Network-Diagnostics](https://github.com/xO-xN/Local-Network-Diagnostics)）：本地网络诊断。什么时候用——演出前检查演奏者设备到 Host 的 Wi-Fi 链路质量（延迟 / 抖动 / 丢包），手机扫码即测。
- **Telematic Diagnostics**（[Telematic-Network-Diagnostics](https://github.com/xO-xN/Telematic-Network-Diagnostics)）：跨互联网诊断。什么时候用——多站点演出前对 hub 星型网络做 go / no-go 判定（见[跨互联网演奏](#6-跨互联网演奏多站点)一节）；每个站点的 monitor 呈现同一张「花视图」，绿则可演，红则标注问题站点与问题链路。

- **Sensor Meter**：查看手机运动传感器数据，用于核对设备权限与采样行为。通过工具页面指引连接手机；需要安全上下文的传感器 API 按[可信 HTTPS](./reference/https.md)准备，并在手机授予权限。桌面模拟不能代替真实手机传感器。

工具与普通工程一样从侧栏加载运行；细节与判定阈值见各工具仓库。

## 5. 加载工程与多端联演流程

开始前，将运行 PNDS App 的 Host 电脑与所有演奏者设备接入同一本地网络；Host 建议使用有线连接，演奏者设备（手机 / 平板）连接同一 Wi-Fi。

确认配置无误后，点击 **“加载 / Load”** 按钮启动工程：

1. **服务初始化**：App 将按预设参数同时启动该工程内置的**数字乐谱本地服务器**与 **DSP 音频引擎**（如果使用 Internal 内置合成器模式）。
2. **进入指挥界面 (Conductor View)**：工程加载成功后，左侧栏将自动向左收起，主视窗切换为全屏「指挥界面」。
3. **演奏者多端接入**：
   - **扫码加入**：点击底栏的「演奏端二维码」，手机扫码进入当前工程。存在投影窗口时在投影显示，否则覆盖主 monitor；再次点击隐藏。
   - **浏览器访问**：在任意设备的现代浏览器中直接输入 Host 电脑的局域网地址与演奏者页面端口，接入系统。

## 6. 跨互联网演奏（多站点）

PNDS 池谱，寓意「多池相连」：多个城市 / 站点各自运行一台 Mac + 本地演奏系统，经由一台公网中继（hub）相连，即可跨互联网合演同一部作品。标准组网是**星型 hub 中继**，操作流程如下（组网原理与房间 / token 语义见[演出组网](../reference/network.md)）：

1. **部署 hub**：在一台公网 VPS 上部署 [pnds-hub](https://github.com/xO-xN/pnds-hub)（跨互联网演奏中继服务器），按其仓库的部署指南安装（systemd 服务 + TLS 反向代理，安装时生成共享 token）。hub 只中转站点间的控制消息，各站点始终是**出站连接**，无需在演出场地开放任何入站端口。
2. **各站点配置节点**：在每台站点 Mac 上打开设置面板（`⌘ ,`）的「**节点**」栏，填写三项——**节点名**（这台 Mac 在星型图里的名字，如 `site-a`）、**hub 地址**（完整 `wss://` 地址）、**token**（遮蔽显示）。三项是本机全局配置，填一次所有工程共用；修改在下次启动工程时生效。
3. **网络验证（go / no-go）**：各站点加载内置的 **Telematic Diagnostics**（见[内置工具](#4-内置工具)一节）——App 注入的节点配置就是它的连接配置，自动连接、无需在表单手抄；节点三项没填齐时，加载按钮会变为「**设置节点**」提示先完成配置。各站点的 monitor 将呈现同一张「花视图」星型图，横幅绿 / 红给出可演 / 不可演判定，并标注问题站点与链路。
4. **正式演出**：加载正式工程（工程在 manifest 声明跨互联网能力并实现 hub 协议，Telematic Diagnostics 即参考实现）。App 自动按工程派生房间——同一作品、同一 Room 分组（底栏网络面板的 Room 下拉，1–3）的站点进入同一房间，开错工程互不可见；演奏者照常扫码接入**本站点**，站点之间的实时音频由 JackTrip 等外部方案承载。

## 7. 演出实时控制与侧边栏呼出

在演出或排练过程中，如需临时调整音频输出设备、音量或检查连接状态：

- **边缘悬停**：将鼠标指针移至窗口最左侧边缘，左侧设置栏将平滑滑出。
- **快捷唤出**：按住键盘 `⌘` 键显示侧栏；松开且指针离开后自动收起。下拉菜单、对话框、模式确认与启动／关停操作期间保持显示，全部结束后自动收起。侧栏覆盖满窗口 monitor，显隐不改变页面尺寸、不重载。
- **单一演出动作**：底部只显示加载／更改／关闭中的一个动作。选中其他工程不打断演出；点击加载后确认替换运行。修改网络、音频设备／采样率或 External 目标后，用「更改」手动重启工程并应用修改；错误页仍提供 Retry。
- **原生选卡**：`⌘ ⌥ ↑`／`⌘ ⌥ ↓` 选择上一个／下一个可见工程并显示侧栏，monitor 或文本输入持焦时仍有效。仅演出主窗口执行，按当前列表到端停止、不自动加载。确认弹层、App 弹出层、启动／关停及其待提交操作期间阻挡；创作、performer、投影和帮助窗口保留自身键位。左右键无新增导航。
- **投影与简介**：底栏有一个投影按钮：先打开场地窗口，随后同一个按钮切换简介／演出内容，撤回后恢复简介。刷新按钮只刷新 monitor 页面，菜单与 `⌘⏎` 保留投影控制。帮助仍可通过帮助菜单和 `⌘ ?` 访问。
- **全屏演出**：`⌃⌘ F`、窗口菜单或原生绿色窗口按钮进入全屏，monitor 页面自动适配尺寸。

## 8. 创作阅读工作台

右下角持续显示同一个模式按钮，悬浮或聚焦提示目标模式。第一次点击进入原位确认，再次点击提交；只有丢弃未保存内容时在按钮上方提示实际后果。按钮聚焦时，Enter 或空格执行同样的两次确认。Esc、点击其他位置或窗口失焦可取消。用「打开文件夹工程」选择自己的工程，或从「最近创作」继续。创作模式中的 `⌘ O` 同样选择文件夹；不自动启动工程。

打开可编辑源工程后，顶栏右侧“生成 .pnds”打包磁盘保存版；工程选择器用于切换或新建工程。中间工作区有固定的“讨论／Git 版本”和一个可关闭文件页。点击文件树的创作交接单可按普通 Markdown 阅读或编辑；关闭文件页返回讨论。安装的 `.pnds` 与内置工具只读，重新打开安装目录或符号链接不会使其可编辑。取消选择保留当前工程。

默认直观视图将工程设置、作品简介和创作交接置顶；已知文件同时显示用途名称与真实文件名，例如“指挥界面｜monitor.html”“演奏者界面｜performer.html”。工具配置和编译产物默认收在“技术文件”，有未保存修改或冲突时仍显示提示，搜索会展开匹配项。“依赖”汇总已保存的依赖声明，不显示第三方库的内部文件。点击文件栏的“全部文件”可切到真实目录和文件名，再点“直观视图”返回；切换保留选中项、编辑器草稿和运行状态。搜索及快速打开同时支持中文／英文用途名称和路径。选择文本文件可阅读，并在当前文件中查找。PNG、JPEG、WebP、GIF 在选中后预览；解码失败仍可查看信息并在 Finder 中定位。音频和其他二进制只显示名称、类型和大小，交给外部应用处理。文件栏“更多”菜单打开工程文件夹或刷新清单，文件工具栏的「文件操作」菜单可重新读取磁盘、定位当前文件及重命名；manifest 禁止重命名。

文本上限为 1 MiB、图片为 4 MiB，文件清单最多 4,096 项、32 层；`.git` 与 `node_modules` 不列出。文件消失、权限不足、无效 UTF-8、超过上限、工程身份失效或路径越界会分别提示。需要更新清单时点击刷新文件清单。创作打开只检查基本声明与入口结构，尚未安装依赖或编译声音产物的初版仍可阅读；运行和打包保留各自检查。

进入“Git 版本”查看和保存工程版本；“Git 状态与差异”保留已暂存、未暂存及未跟踪文件的高级查看。详细操作及边界见[工程版本与历史](#工程版本与历史)。

Partial clone（部分克隆）仓库可能缺少所需对象，面板会明确说明无法检查。请先在外部 Git 工具中补齐仓库；App 不会下载缺失对象或修改 Git 对象库。

未保存草稿、磁盘保存版、Git HEAD 和运行内容各自独立。查看 Git 不会保存草稿、刷新页面、重启测试，也不能证明正在运行哪个内容版本。磁盘变化、从外部工具返回以及快照打开超过 30 秒时会标记可能过期；点击「刷新 Git」重新读取。切换工程或关闭面板会清除本次查看，迟到结果不会出现在另一个工程中。

运行中的可编辑文件夹优先于另一张选中卡片，进入创作时保留运行与 monitor；已选但未运行的文件夹不自动启动。工程包、工具和不可编辑目标结束旧运行并进入创作首页。进入创作关闭投影；返回演出结束测试并回到空闲首页。也可在演出工程卡的右键菜单选择“开始创作”，直接打开该卡片对应的可编辑工程；需要结束另一个运行时先确认。

SCD 工具栏编译标准源码集合，结果进入控制台；实时测试区选择保存版允许的音频模式并手动启动、重启或关闭。页面刷新位于“窗口 → 刷新乐谱页面”（`⌘⇧R`）。控制台从底栏或 `⌘ + 反引号` 展开；monitor 可展开并用 Esc 还原，页面与运行保持同一实例。文件栏“添加资源”提供本地模块和共享包，核对版本、目标文件及依赖后明确添加。模块文件、来源与接线边界见[模块手册](./modules/README.md#v161-离线标准模块)，复制文件本身不代表接线完成。

## 工程版本与历史

工程名右侧的 Git 入口打开 **Git 版本**页，可保存当前版本、查看版本关系与文件差异，显式切换到历史版本后继续创作。选择一个版本只改变查看内容；“统一 / 并排”分段按钮只切换差异布局。原 **Git 状态与差异**及逐文件历史入口继续提供高级查看。
App 在 Apple Silicon 和 Intel 自供本地 Git，这些操作无需系统 Git 或远程登录，
不运行工程 hook、外部 diff、filter 或网络辅助程序。

Blank 与 Classic 在创建完整成功前生成独立初始版本。请在新建表单中核对版本署名：
未单独编辑时跟随工程创作者，创作者为空时默认 `PNDS Creator`。邮箱选填，留空时采用
已说明的本机占位地址 `creator@pnds.local`。版本署名独立于工程创作者，只作用当前仓库。

打开已有文件夹不会自动启用 Git。主动选择**启用本地版本记录**，核对文件范围、署名与
初始说明后再确认。仓库已建立但初始记录失败时，请保留目录，重新预览并补齐缺失步骤。
已有历史不会被重建。父仓库、嵌套仓库、linked worktree 等不支持的写入结构请使用外部
工具；支持的只读查看仍可使用。

Git 版本页的“保存当前版本”先保存全部编辑器草稿，再记录符合收录规则的文件；草稿冲突会阻止记录。
默认沿当前工程版本的名称系列续号，例如“呼吸 → 呼吸 1 → 呼吸 2”，从旧版本继续时跳过已用名称。
查看某个历史版本不会改变下一版的命名起点。版本保存后，可用名称旁的改名按钮修改任一本地版本的显示名称；只改选中版本，当前版本改为“流动”后，下次默认“流动 1”。
改名不改变提交标识、工程内容或版本关系。名称保存在本地仓库配置中，不随普通 Git push／clone 或 `.pnds` 包传递。

高级记录窗口仍可选择完整文件、填写提交说明并审阅确认；在该窗口中未保存草稿、待应用建议和临时预演
单独提示，不自动保存或纳入。选中文件存在外部暂存内容时，必须先在外部 Git 工具处理；
未选文件的暂存条目保留。预览后文件、HEAD 或 index 变化时须重新预览，不生成空提交，
不自动 reset 或修复。成功显示真实提交标识；此后 index／配置更新警告不表示需要重复提交。

遵守已有忽略规则，排除依赖、缓存、构建产物、App 数据、`.env` 与已识别密钥。
达到 10 MiB 的音频／视频／模型默认不选，可主动纳入；已跟踪资源仍显示变化。
单文件上限 64 MiB，采集上限 256 MiB，清单上限 4,096 项／32 层。纳入资源会增加
历史占用，Git 记录不等于完整资源备份。依赖 filter／LFS 的写入、必须签名、锁／冲突、
partial clone 和缺对象等情况请使用外部 Git 工具；PNDS 池谱不会联网补对象。

历史最多显示最近 30 条涉及当前工程的提交，沿 HEAD 的第一父提交链最多检查 300 条，并提示尚有历史
或已达上限。选择提交和路径，分别核对历史文本、当前保存版与独立草稿。
**核对载入草稿**只支持单个当前存在、可编辑的文本文件。已有草稿可以保留、取消，
或明确替换。载入仅改变草稿，随后打开核对、明确保存并手动测试；以当前磁盘版本作为
保存冲突起点。不会恢复删除文件；二进制、目录、不支持的文本、越界链接和不可达历史
均拒绝载入，文本上限 1 MiB。保存仍校验内容并拒绝覆盖未核对的磁盘变化。
记录与载入均不刷新或重启运行工程，也不代表声音验收通过。Git 历史、本机 App 数据
及工程内 `.pnds-creation/` 私有聊天和创作资料均不进入默认演出 `.pnds` 工程包。
搬迁创作环境请复制完整工程目录并包含隐藏文件；工程副本之后的记录各自独立。

## 切换与恢复工程版本

在 Git 版本页选择历史版本只查看内容；确认“切换到此版本”才改变磁盘。已有修改时选择先保存版本、取消，或经过第二次确认后丢弃允许范围内的修改。恢复当前版本内容也走相同保护；被忽略及排除文件不会被当作可丢弃内容处理。

例如 A → B → C，切回 A 后继续创作并保存 D，会产生新的本地支线，B、C 仍可查看。分支选择器用于查看和切换已有本地分支。显示名称与分支名称分别维护；合并与远程同步继续使用外部 Git 工具。

切版前需明确结束未完成的助手任务，并停止本工程运行；任务目标、聊天与保存修改不会凭切版自动重放。停止失败或其他工程占用运行时，切换会被阻止。取消保留文件和草稿；成功切换后需手动启动和测试，不沿用先前运行结果。

## 配置模型服务

打开设置（`⌘ ,`）的「模型服务」，填写支持文本对话和工具调用的 OpenAI 兼容 API 地址、模型名称和密钥。API 地址填写服务提供的基础地址（例如包含 `/v1` 的地址），模型名称必须与该服务一致。远程服务使用 HTTPS；本机回环服务可使用 HTTP。

保存后，地址与模型留在本机设置，密钥保存在 macOS 钥匙串。重新打开设置只显示密钥是否已保存，不回填密钥；输入新密钥可替换，也可以明确移除。保存或钥匙串操作失败会显示原因，失败不会改用明文保存。

「测试连接」使用当前填写的内容，未保存的修改也会参与测试；密钥输入为空时使用已保存的密钥。测试实际验证文本回复和一次受控工具调用，不读取或发送当前工程。鉴权、网络、超时、协议或工具调用不支持会分别提示，修正后手动再试。测试通过只说明这次配置具备连接能力，不代表工程已经测试或运行通过。模型未配置或服务不可用时，本地编辑、保存和手动测试仍可使用。

## 使用装机文档问答

打开可编辑工程后，工作区默认显示创作讨论。配置模型服务后输入问题，点击发送或按 Enter；Shift+Enter 换行。助手会查阅与当前 App 对应的本机帮助资料，也会将工程概况和按需读取的已保存文本发送给你配置的模型服务；未保存内容仅通过你主动附加的选区发送。“已查阅资料”按文档计数，小节链接合并同节分页；展开可核对原始返回范围。来源按钮来自实际检索的小节，点击后打开对应语言的帮助原文；回复未采用本机来源时会明确标记，模型文字中的引用不作为已验证来源。

默认在 **PNDS 创作助手**的“讨论”模式中商量想法与实现方式。助手先查阅可获得的工程事实，逐题追问影响方案的关键选择并给出建议；含糊术语会结合具体演奏场景澄清。每次回答后继续核对原始要求和后续选择，不以问题数量判断讨论是否完成。普通问答直接回答；讨论不会修改文件、执行检查或写交接单。

问题按当前聊天显示为 Q1、Q2……，点击选项就会发送回答；“推荐”徽标在选项最右侧。也可直接在常驻的“我的回答”框输入，按 Enter 或发送箭头发送，Shift+Enter 换行；输入法选字不会发送。需要结束这一轮时，在聊天的更多菜单选择“取消本轮讨论”。文件替换冲突另有明确确认，不随普通选项点选直接覆盖。

关键选择已解决，或经你明确同意排除／延后后，助手在主回复中展示完整方案，包括目标、范围、已确认的选择、验收，以及未采用建议和延后事项。核对这份方案后，可选择：

1. **写交接文件**：沿用这份方案生成可编辑任务草稿，预览并核对后点击“记录交接”，才更新 `docs/creator-handoff.md` 并采集比较基线。所选方案和已答决策继续作为实施任务，“写交接”只是操作，不会替换原目标。关键未决问题应在选择路线前解决；若发现新的关键冲突，会先返回澄清，再准备可记录的草稿。
2. **开始工作**：确认采用这份方案，立即创建新的实施任务，同时将输入框下方模式切到“工作”，保存修改并自动检查；不必先生成交接文件。方案和已提交回答随任务带入，未采用建议与延后事项不自动成为实施要求。

## 记录交接与外部接续

交接弹窗先展示可读任务，需要修改时用“编辑任务”，无需填写初始状态。“预览交接单”展示将写入的完整有效清单；同一任务的新修订替换旧块，其他未完成任务和未知内容默认保留。发现旧错误或已作废内容时，可展开“管理已有内容”明确纠正，再重新预览；修改前的保存版会归档到 `docs/handoff-history/<contenthash>.md`。App 不凭聊天推断完成，也不自动删除旧错误。

真正写入后，原聊天回复会显示“复制 prompt”，其中已附上实际工程位置和 App 内置的四条交接规则，整段随聊天使用中文或英文，不受界面语言切换影响，无需安装 skill 或从 GitHub 下载。粘贴给外部编程智能体，即可接续当前交接单中的全部任务；App 不自动派发。智能体读取工程已有术语和设计文档，实施并检查后，先将完整旧交接单、实际修改、检查结果及未验证项归档到 `docs/handoff-history/`，再移除完成项或替换失效规则，无需再次批准。仅待创作者听感、视觉或设备复核的内容记录在历史中，不单独阻止已实施且完成检查的任务归档；当前清单只保留未实施或受阻事项及原因，已有历史保持不变。App 每份交接基线仍是对应记录的初始比较起点，和最终执行报告分别保存。

讨论方案随工程内的聊天保存，不默认新建 `creation-plan.md`。需要长期保留的术语和设计决定，可在获准记录或实施时按需写入工程已有的合适文档；重要且难以逆转的取舍才单独记录 ADR。

也可以直接切到“工作”并发送明确任务；仅切换模式不会开始工作。输入“帮我整理一下工程代码库”会直接进入工作，按 PNDS 默认规则整理结构、命名、引用和有依据的重复代码，保留原有声音、视觉、算法和演奏交互。可在消息中补充规范或指定工程文档／创作资料，例如“帮我按 docs/rules.md 的规范整理工程”。助手主动建议整理时，等你选择后才执行。需要交接时，也可直接说“帮我写交接文件”。

工作中的检查失败会在同一任务内继续诊断和修复，遇到阻碍会明确报告；运行被占用时只做允许的静态检查，不停止现有演出。实现后仍需核对实际音画、设备与演奏交互。

输入框右侧箭头用于发送；回复和工作中显示动态加载环，点击中央停止按钮可暂停当前任务。新输入草稿保留，已保存修改不因暂停而撤回。聊天不展示服务端用量或正文加载三点；有公开处理文字时才显示淡色“展开思考流程”，其中不包含模型私有推理。同步和上下文详情仍可按需查看，超限和失败继续明确显示。

阅读与组织回复期间可以停止，输入、已产生回复和来源保留。错误后修正原因并手动重试；切换工程、返回演出模式或修改模型配置会取消当前请求，迟到回复不进入新上下文。工具次数、资料量和上下文超过资源上限时会明确报告。

点击文件打开完整编辑视图，再返回讨论继续；输入、回复和各文件草稿分别保持。交接文档沿已有入口阅读。右侧 monitor 保持同一页面，打开代码不自动刷新或重启。拖动分隔线调整讨论／阅读与 monitor 宽度，也可 Tab 聚焦分隔线后使用左右方向键；Home 或双击恢复默认。宽度在本机记忆，窄窗口按可读宽度限制调整范围。控制台仍从底栏或原有快捷键展开在当前工作区下方。

## 恢复与清理工程聊天

聊天和创作资料保存在工程的隐藏目录 `.pnds-creation/`。复制、搬迁或重命名完整工程
目录时，保留该目录即可携带记录；关闭重开工程或重启 App 后恢复消息与真实来源。
工程副本之后的聊天、清理和资料变更互不影响；同一实际目录的符号链接共用记录，
相同 manifest 标识不会把不同工程的聊天合并。默认演出 `.pnds` 和 Git 版本均不携带
这些私有创作数据，迁移创作环境请复制完整源文件夹并包含隐藏文件。

旧版工程首次在原路径打开时，会自动迁入现有本机记录，保留原记录作备份；已存在的
工程内记录不会被旧记录覆盖或合并。请先在原路径打开一次再搬迁；若已提前搬迁，
需恢复原路径一次完成迁移。任务执行接续和撤回日志仍留在本机，搬迁聊天不会继续
执行旧任务；模型设置和密钥也需要在目标机器单独配置。

旧待完成回复显示为已取消。历史附件与建议展示当时保存的文本、来源和版本，
不重新读取当前文件，不覆盖草稿、不发送工程内容、不应用或重新预演。
过去的测试结果只代表过去，不构成当前运行事实。

讨论工具栏显示保存进度和失败，可主动重试保存。恢复失败或格式不支持时，
可重载，或确认清理；历史版本过期需确认重载或清理。重载会停止旧请求并替换
内存消息，保留输入与文件草稿。清理仅作用于当前工程聊天，保留输入和文件，
并停止活动请求；取消确认则保留记录。清理失败保留原记录，成功后迟到回复不能
补回旧内容。使用 Tab 和 Enter 操作按钮，Escape 取消确认。

## 查询与释放端口

打开设置（`⌘ ,`）的「端口」栏，查看所选工程 manifest 的演奏端与监视端端口；创作模式读取当前工作台已保存的 manifest，草稿不会改变查询目标。没有选择时使用 6868／6869。进入时查询一次，需要更新时点击「刷新」，不会后台轮询。

外部占用显示 PID、进程名称与完整命令行。点击「释放」后确认显示的身份；App 在发送退出信号前会再次核对同一进程，先等待优雅退出，必要时有界强制退出。占用消失、身份变化或变成本 App 的受管进程时会取消并刷新，需要重新确认。启动错误页的「释放并重试」也先确认身份，只有成功释放且端口可用才重试。

本 App 运行的端口显示真实所属工程并要求先关闭工程，不提供直接释放。运行 A 时选择 B，只查询 B 的端口；归属依据 A 启动时已应用的端口和真实子进程，不会把 B 的不同端口标成 A 正在运行。

## 静态工程诊断

助手和随 App 提供的 CLI 使用同一保存版静态检查服务；当前工作台没有手动“静态 Doctor”按钮或报告面板。工作模式会按任务调用检查；手动测试仍通过实时测试区操作。

```sh
/Applications/PNDS.app/Contents/MacOS/pnds check /path/to/project --json
```

静态检查不保存草稿、不运行源码、不占用端口或安装依赖，演出期间仍可使用。报告区分阻断问题、提示、跳过和未验证项；保存版变化后旧结果过期。静态通过不能证明页面、运行或声音正确。运行 `pnds --help` 查看参数。

## 临时副本运行检查

助手工作任务和 CLI 可检查保存版临时副本；当前工作台没有手动“受控检查”菜单或对话框。None 是默认模式且需工程支持，Internal 需明确选择；External 用原有手动测试。修改编辑器草稿或手动保存不会自动发起检查。

```sh
/Applications/PNDS.app/Contents/MacOS/pnds check /path/to/project --run --json
/Applications/PNDS.app/Contents/MacOS/pnds check /path/to/project --run --mode internal
```

检查记录实际输入、依赖、版本指纹、health／HTTP、结果与清理；副本产物不回写。App 正在启动、运行、关停或其他检查占用资源时拒绝新的运行检查，不停止已有演出。工作任务会处理可修复失败；实际画面、手机、设备和声音仍需人工验证。

Ctrl-C／SIGTERM 取消 CLI 并等待清理；退出码 0 为检查及清理通过，1 为失败或未执行，130 为取消，2 为参数或输出错误。`--app-root /path/to/PNDS.app` 指定完整本机资源，不回落全局 Node。清理未确认时阻止新运行；资源释放后重试，归属记录不完整则按提示重启 Mac。逐文件复制不是瞬时原子快照，也不是执行任意代码的系统沙箱。

## 单文件差异与撤销

编辑一个已有文本文件后，选择「审阅修改」查看改前与拟保存文本的真实
差异。取消会保留草稿；「保存已审阅修改」成功后显示实际保存记录，
可选择「撤销已保存修改」恢复原文，不需要 Git。

撤销只适用于当前工程最近一次已记录的单文件修改。文件后来又被手动／
外部保存、改名、删除，或存在未解决草稿时，旧操作会被拒绝，不覆盖
后续工作。切换或关闭工程会撤销旧身份的权限；记录不跨 App 重启保存。
检查失败不会自动撤销文件，也不会自动采用副本产物。

## 编辑工程文本

从文件树打开文本，或在创作工作台使用「快速打开文件」（`⌘P`）。搜索只
使用当前工程文件清单，方向键选择，Enter 打开。超大、不可读和二进制
内容会解释原因，不会被当成可编辑文本。

编辑器提供行号和 JavaScript、TypeScript、JSON、HTML、CSS、Markdown、
SCD 语法着色；其他已有可读文本保持纯文本模式。颜色不代表校验或编译
通过。「查找与替换」（`⌘F`）只针对当前文件，替换先修改草稿且可撤销；
「跳转到行」（`⌘G`）用于定位。Tab／Shift+Tab 缩进／反缩进选区，先按
Escape 再按 Tab 可离开编辑器。在本次工程会话中，切换文件或布局后，
`⌘Z`／`⇧⌘Z` 或工具栏仍撤销／重做各自文件的草稿。

「保存」或 `⌘S` 仍是显式写入，保留 manifest／README 校验和磁盘版本冲突
保护，不自动刷新页面或重启工程。取消冲突选择会保留草稿；明确采用磁盘
版本会重置草稿撤销／重做并提示边界。重启 App 后不恢复编辑历史。
「撤销已保存修改」是另一个针对已记录磁盘写入、受版本保护的操作。

## 讨论工程保存版文本

在可编辑工程中发送问题时，默认提供简短工程事实并允许按需读取保存版文本；无需开启读取开关或首次范围确认。文件草稿、敏感配置、依赖、构建、锁文件和媒体不被隐式读取。来源显示实际版本及范围，局部阅读不代表整工程分析。模型服务接收实际读取内容，请在发送前核对服务配置。

在文件文本编辑器或待应用建议中选择代码，点击「附加选区并讨论」，即可将固定
快照加入输入区。展开后可核对路径、行号、版本及保存版／草稿／待应用状态，
发送前可移除。后续编辑不会替换快照，附件仅包含主动选择的片段；发送不会保存、
应用、预演或运行。附件只发送本次明确选择的快照；后续保存不改变该快照。

聊天上下文详情中的「阅读整个工程」会准备允许的保存版文本并发送，不再弹出第二次发送确认。未保存草稿仍需主动附加片段。超过允许预算会明确拒绝，不会静默截断后宣称读完。工程概况在请求中按需组装，当前没有独立悬浮概况控件；旧聊天不能成为当前测试事实。

讨论收束后，可选择交给内置“工作”模式，或通过“写交接文件”交给外部编程智能体。审阅目标、相对文件、
已知问题和验收后，明确确认才正式记录任务。有草稿时选择「先保存草稿再交接」或
「仅按保存版交接」；此选择不应用待采用建议或临时预演。交接单自身的草稿会保留，
并可能与新写入的任务形成冲突。任务写入和比较基线完成分别反馈；不完整交接可从
基线列表重试，已采集起点不会被替换。正式写入后，在原聊天回复中点击“复制 prompt”并交给
选定的外部 agent；App 不派发任务。最终执行记录由 agent 归档在源工程的 `docs/handoff-history/`，
与 App 私有的初始比较基线分别保留。

## 比较交接后的变化

打开「交接后的变化」，选择任务／修订基线，比较当前保存版文件；无 Git 或外部已提交
后均可使用。文本显示实际差异，资源只显示 SHA-256 与大小，不保留可恢复副本。草稿和
排除范围单独提示，结果过期时请明确刷新。「打开当前文件」进入原有编辑流程；删除
文件只能查看差异。可返回本次比较或讨论，继续使用同一 monitor 手动验收效果。比较不
向 AI 发送内容，不保存、恢复、启动或刷新运行，不提交或标记任务完成。基线保存在
App 数据区，重启和清理聊天后仍保留；可查看占用并主动删除所选基线。它不能恢复工程或资源。

本地比较包含锁文件，但不因此授权助手读取。大资源指纹显示逐文件字节进度，读取时可取消；已确认任务进入正式写入阶段后，请等待真实结果。

## 修改建议与临时预演

已有建议卡中的「参数／代码」共用候选 buffer，与文件草稿分开。表达式或定位变化停用受影响控件，
代码仍可编辑。恢复单个参数建议值保留无关编辑；恢复整份建议或重载磁盘前，需确认放弃整份候选。

临时预演要求明确适配且匹配的当前运行工程。受限接口只发送已声明的值，绝不注入代码。
键入代码结束旧预演；明确点击预演才重新核验映射。局部效果和实际回读不等于整份代码验证。
结束预演只恢复运行参数基准，不撤回时间或已发生效果；恢复未确认时，请核对工程并使用
既有手动运行入口。适配契约见[运行契约](./reference/runtime-contract.md)。

「应用到工程」授权当前可见候选的一次具体写入。已有草稿、外部变化或版本冲突会停止
应用并保留编辑。无法预演或当前未运行，不阻止合法候选明确应用。实际差异固定写入前后
版本，仅在仍有效时提供受保护撤销。采用保存代码仍需手动刷新／重启。建议卡的操作
与「工作」模式的直接写入各自独立。恢复聊天历史只展示快照，不恢复旧应用或预演授权。

## 文件与目录操作

文件栏的「新建」加号可创建代码／文本文件或目录；目录右键菜单可指定创建位置。输入相对路径前先建立父目录，确认显示的实际位置后创建。同名目标不会被覆盖，取消保留原有文件和草稿。

选中文件后按 F2，或从文件操作菜单重命名；根 manifest 禁止改名。改名不会自动修复代码中的 import、页面引用或资源路径，请核对并手动测试。将文件拖到 Finder 或其他应用会复制磁盘保存版，不移动原文件，也不保存草稿。文件栏「更多」提供快速打开、刷新清单和在 Finder 打开工程。

## 草稿、保存版与运行内容

草稿是编辑器中尚未保存的内容；保存版是磁盘文件；运行内容是本次启动和页面加载实际采用的版本。保存不自动刷新、重启或编译。页面改动用「窗口 → 刷新乐谱页面」（`⌘⇧R`）；服务器或音频产物变化需要重启测试；修改 SCD 后先编译，再重启采用产物。刷新清单只更新文件列表。

外部修改会自动更新未编辑的文件；已有草稿会保留并提示磁盘冲突。先核对两个版本，再明确选择保存或采用磁盘内容。运行就绪只代表本次运行事实，不能证明后来保存的改动已经生效。

## 创作资料

点击文件栏的「创作资料」，选择「添加资料」接收代码或文本。App 保存私有副本；支持的文本类型和拒绝原因会明确反馈。每份上限 1 MiB，最多 64 份，总量 8 MiB。图片、音频、压缩包等二进制暂不作为文本资料接收。

选择条目可阅读内容，较长资料按页继续查看。添加不会修改工程，也不会自动把全部资料发送给模型；讨论和工作会按问题读取需要的范围，来源显示实际资料版本。资料跨聊天与 App 重启保留。移除只删除私有副本，不删除原文件或已采用到工程的文件。

要接入源码，在“工作”中明确说明采用哪份资料及目标效果。助手核对入口、引用和加载顺序后实施；同名不同内容会展示实际差异及替换／并存选择，明确作答前不覆盖，作答后仍会复核磁盘版本。资料复制完成不代表接线、声音或视觉已经验证；完成后手动测试。资料搬迁见[恢复与清理工程聊天](#恢复与清理工程聊天)。

## 在 SuperCollider 中打开保存版

打开工程的 SCD 文件，从「文件操作」选择「在 SuperCollider 中打开保存版」。本机需要安装 SuperCollider；缺失或打开失败时，按提示处理后重试。

打开的是磁盘保存版，App 中的未保存草稿仍保留。该操作不求值、不编译、不连接或改变 App 的音频运行。外部保存后，干净编辑器更新为新内容；已有草稿则提示冲突。需要采用声音变化时，回到 App 编译并手动重启测试。

## 多聊天与历史问题

聊天选择器切换当前工程的聊天；「更多 → 新建聊天」开始独立话题，各聊天保留自己的输入。切换聊天不启动旧任务。聊天列表中的删除按钮只删除所选聊天；清空整个工程聊天是另一项需要确认的操作，不删除工程文件或创作资料。

编辑旧的用户问题后重新发送，会建立新的聊天分支并保留原聊天后续内容。历史建议、来源及测试结果保留当时的含义，不恢复旧的写入或预演权限。

## 长对话与上下文

输入区的上下文圆环和详情反映当前请求的预计占用；百分比需要已知容量。估算不等于服务端实际用量或费用，未知容量时不显示虚假的百分比。

在聊天的上下文详情中选择「整理旧聊天」，核对轮次范围，明确调用当前模型生成摘要，再查看来源并采用、重做或丢弃。只有采用后摘要才参与后续请求；原消息仍保留。新话题边界改变后续发送范围，不删除聊天记录。

模型服务的高级设置默认为自动管理；可填写容量供显示，只有明确选择手动预算才按输入预算限制。地址、模型和密钥已足够开始；容量不明时按未知处理，不根据模型名称推测。超限时减少本次范围或整理上下文，保留具体错误供重试。

## 暂停、继续与本地资源确认

回复或工作中的停止按钮暂停当前任务，保留输入和已保存修改。出现“继续”时点击可按原目标接续；正常恢复本机任务后也等待你主动继续，不自动调用模型。工程内容、模型配置或任务条件变化可能阻止接续，先按错误提示核对。复制工程聊天到另一台机器不会携带本机执行权限。

工作需要标准模块或 App 共享包时，确认卡列出真实资源、版本、影响和可用替代方案。核对后选择“添加并继续”、明确采用替代方案或“结束任务”；等待期间不会自行完成采用。此确认与普通创作问答、文件替换冲突分别处理，恢复任务后待决定内容仍需明确选择。

## 移交整场演出

演出文件夹的整套移交称为 setlist 导入／导出。在演出文件夹的右键菜单选择导出，将生成的完整目录交给另一台 Mac，保留 `set.json`、各 `.pnds` 和 README。接收方在演出模式用 `⌘O` 打开该目录，或将目录拖入窗口。

导入成功会重建用户工程列表和编组，恢复导出顺序、显示名称、简介及有效的 External OSC 目标；不是向现有列表简单追加，原工程文件仍保留。先确认当前列表是否需要另行导出。缺包或安装失败会报错，工程索引在安装完成前不替换。音频设备、采样率、节点、密钥和其他机器偏好需在接收方重新配置。

## 实时测试与 performer 窗口

在创作工作台的「实时测试」区选择保存版声明允许的音频模式，手动启动或重启。External 使用 App 的测试 OSC 目标；设备与采样率仍在全局设置中选择。修改选择只产生待应用状态，只有 ready 运行事实才能显示已应用；关闭测试保留工程和草稿，隐藏主窗口不结束测试。预检失败不会关掉已有测试，启动失败可查看原因后重试。

monitor 顶栏显示实际地址，可展开查看，并通过还原按钮或主窗口中的 Esc 返回原编辑布局，页面与运行保持同一实例。控制台标签展示已有日志服务的最近 Node／scsynth 输出与错误，可复制测试详情；返回文件标签不丢失草稿。刷新保存版测试页面只重新载入页面，不重启进程。通过「添加 performer」创建多个独立原生测试窗口，逐个选择手机／平板及横／竖向；列表提供聚焦与单独关闭。这里只模拟页面尺寸，真实触屏、传感器与移动浏览器能力仍需实机验证。页面导航状态与「连接未知」分别显示，不把加载事件当作连接成功。各窗口使用独立临时浏览器存储，直接与工程服务器通信。页面刷新覆盖已打开的测试页，同工程重启保留窗口壳并使用当前运行地址。关闭测试、切换工程或离开创作会关闭旧窗口；取消操作或隐藏主窗口则保留。

performer 测试窗口可保留页面的编号选择等 JavaScript 弹窗；“鼠标模拟单点触摸”默认开启，按住左键拖动即可模拟，关闭后恢复页面鼠标行为，切换不重载。真实多点触控和传感器仍需手机验证，事件边界见[performer 页](./reference/page-interaction.md#performer-页)。

## 添加模块与共享包

文件栏“添加资源”区分本地模块和共享包。模块提供身份恢复、主题／语言／视图跟随或 hub 接线源码；加入后由工程维护。共享包在 manifest 建立对 App 固定版本依赖的引用，资源仍保存在 App。两者都不是新工程模板。

手动添加前核对目标文件、版本、依赖和工程版本。有冲突时保留已有内容，修正后重新核对。模块接线任务写入创作交接单；共享包还需正确导入或提供同源浏览器路由。不要把“已加入”当作“已接线／已测试”。助手工作的资源确认见[暂停、继续与本地资源确认](#暂停继续与本地资源确认)。
