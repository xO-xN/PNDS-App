# PNDS Template 创作指南

本文档将引导你基于 PNDS Template 从零开始创建、开发并发布一个 PNDS 池谱作品。

---

## 在 App 中从 Blank 或 PNDS Classic 新建工程

创作首页与「切换其他工程」选择器均提供**新建工程**。选择起点模板，填写工程名称、新文件夹名称、可选创作者与简介，再用原生目录选择器选择已有父目录。App 创建新的可编辑文件夹，已有文件或目录不会被覆盖。

- **Blank**：原 PNDS App v1.6.0 的最小可运行结构，没有艺术预设或生产依赖。Internal 只向私有 bus 写零信号，External 尚无作品协议时不发音乐消息；带有 SCD 源和一致的预编译 SynthDef。
- **PNDS Classic**：经过验证的固定 PNDS Template 0.7.0 源码快照，保留完整双推子参考示例，包括网络、座位与重连、monitor、主题／语言跟随及每位客户端的正弦声音、16 通道输出。包含源码、实现手册和回归测试；使用 App 的确切共享版本：Express 5.3.0、Socket.IO 4.8.4、osc-min 2.1.2、qrcode 1.5.4、p5 2.3.4。起点模板与「加入模块」分别表达。

两种起点均可离线创建，无需 npm 安装或本地 sclang。Classic 缺确切共享资源或校验失败时明确失败，不改用其他版本。创建后请**手动测试** Internal、External 或 None；真实手机、设备与声音仍由你验收。

每次创建均生成独立工程 ID，即使在不同父目录使用相同文件夹名；Classic 的客户端存储键也独立。manifest、package／lock、Classic 双语 README 与 agent 指引以新身份及版本 0.1.0 初始化，不继承来源 Git 历史、座位或设备缓存。来源记录在 `docs/template-source.json`。打开已有工程不改变身份和历史，模板升级不改写已创建工程。**App 创建的工程已经初始化**；外部 agent 从 AGENTS 与创作交接单接续，不重新执行 `docs/start.md` 的初始化。

Blank 的初始 README 使用创建时的 App 语言，另一语言的待办记录在 `docs/creator-handoff.md`。根 AGENTS 指向交接单及装机 App 契约。交接单与来源记录留在源工程，根 docs 不进入 `.pnds`。改动 SCD 后，再用 App 编译工具并按提示准备本机 SuperCollider。

取消目录、表单或放弃草稿确认会保留旧工程、草稿与运行。目录冲突、权限或部分创建失败不会发布残缺工程；完整目录已创建但工作台采用失败时，错误显示位置，可稍后重新打开。成功进入工作台**不自动启动**，并以工程名称登记演出 Home 列表首位；切回演出后手动选卡和加载，登记列表会跨 App 重启保留。

## 准备工作

在开始之前，请确保本地已具备以下环境：

- **PNDS App 最新版**：已安装并可正常运行
- **Node.js 24**：开发期基线（演出机上无需安装，App 自带 Node 运行时）
- **SuperCollider**（仅 Internal 模式需要）：用于编译 SynthDef，标准安装到 `/Applications/SuperCollider.app`
- **Git 与编辑器**：已配置 Git 环境，并安装惯用的 IDE（如 VS Code、Zed 等）
- **AI-Coding Agent**：建议配合 DeepSeek Harness、ZCode (GLM) 等 AI-Coding Agent 使用

## 1. 创建与初始化工程

1. **基于模板创建仓库**  
   访问 GitHub 上的 [PNDS Template](https://github.com/xO-xN/PNDS-Template) 仓库，点击右上角的 **Use this template** → **Create a new repository** 生成专属项目仓库。

2. **克隆工程到本地**  
   在新仓库中复制 Git 地址，通过终端或 IDE 将工程克隆至本地：

   ```bash
   git clone <your-repo-url>
   ```

3. **查阅工程文档**  
   用编辑器打开项目：根目录 `README.md` 是概览；`docs/implementation.md`（实现手册）讲模板示例作品的行为规格与「创作时改哪里」；`AGENTS.md` 是 AI-Coding Agent 的入口——agent 会自动读取它，并经它按问题索引平台契约文档（优先读取装机 App 自带的本地帮助语料）。端口在 `manifest.json` 中声明，惯例与选择建议见[参考手册 · manifest](../reference/manifest.md)的「端口」一节。

**第二路径：从既有作品移植**  
不从模板起步也行：已有 OpenProcessing（p5.js）+ SuperCollider + TouchOSC 形式的作品，可以交给 AI agent 用 [pnds-agent-skills](https://github.com/xO-xN/pnds-agent-skills) 中的 **pnds-port** 技能整体移植为 PNDS 工程——一次生成完整的工程目录与 `.pnds` 包，随后回到上面的工作流迭代。

## 2. 创作与迭代工作流

PNDS 推荐采用 **「AI 辅助生成/修改 + PNDS App 手动更新测试」** 的双轨循环迭代模式：

- **AI 驱动开发**  
  将工程目录导入你的 AI-Coding Agent，通过对话引导 AI 理解乐谱的交互逻辑、音频/视觉渲染规则以及通信协议，快速编写或重构代码。工程自带的 `AGENTS.md` 会替 agent 取读平台契约与模块手册，无需手动投喂文档。对在 App 外克隆且尚未初始化的模板工程，对 agent 说规范开始语即可——中文**「开始新作品」**、英文 **“start a new piece”**，说哪句 agent 就用哪种语言工作——它会按工程内置的 `docs/start.md` 完成初始化（作品名 / 作者 / 简介就位、版本归零、安装与测试跑绿）。
- **实时加载与预览**  
  在创作过程中，随时在 PNDS App 中载入本地工程目录，即时测试交互响应、音画表现与多端同步机制；左侧栏右上角的「在默认浏览器打开」与「刷新 monitor 界面」两个按钮可辅助开发调试。
- **持续验证与微调**  
  遵循小步迭代原则，在修改后立即于 App 内验证效果，确保各模块表现符合预期。

### 为作品选择连接协议

创作 agent 在新增或修改手机交互、QR 或浏览器连接时，先读取 [manifest.md](./reference/manifest.md) 的两项声明与 [runtime-contract.md](./reference/runtime-contract.md) §15，并检查实际使用的浏览器 API：

1. 普通触摸、手机参与和扫码使用 HTTP；`supportsPerformerUrl: true` 只保留读取 Host 完整网址的能力。
2. 只有作品实际需要运动传感器、摄像头、麦克风等安全上下文 API 时，才声明 `scoreServer.needsHttps: true`，并记录所用 API 与原因。Host 在能力已适配、全局开关打开且材料有效时选择 HTTPS。
3. QR、复制地址与浏览器配置读取同一个 Host 选择的网址，已注入的 `PNDS_PERFORMER_URL` 优先；页面脚本与 Socket.IO 使用当前 performer origin。
4. 在创作交接中记录需求判断、声明值、实际网址及 QR／连接验证结果。普通工程验证 HTTP；需要安全上下文的工程另由作者验证可信 HTTPS、浏览器权限与真实设备能力。尚未完成的实机验证明确保留为待验收。

创作工作台会自动更新外部 agent 增删或修改的文件。未修改的文本可重新读取；未保存草稿会保留，并在磁盘变化时显示冲突，外部删除文件后草稿仍可打开。保存或外部修改不会自动刷新页面、重启工程或编译，也不会改变当前运行的 health 状态。

页面变化提示「待刷新」，源码、音频声明或产物变化提示「待重启」，SuperCollider 源码另提示「待编译」。手动刷新、重启与编译使用已保存的磁盘内容，未保存草稿不会进入测试版本。monitor 成功刷新后清除所更新版本的页面提示；重启失败保留提示，编译成功仍需手动重启以采用新产物。操作期间又发生的修改会继续提示待更新。

## 3. 试运行自检

在创作工作台的「实时测试」区选择保存版声明允许的音频模式，手动启动或重启。External 使用 App 的测试 OSC 目标；设备与采样率仍在全局设置中选择。修改选择只产生待应用状态，只有 ready 运行事实才能显示已应用；关闭测试保留工程和草稿，隐藏主窗口不结束测试。预检失败不会关掉已有测试，启动失败可查看原因后重试。

monitor 顶栏显示实际地址，可展开查看，并通过还原按钮或主窗口中的 Esc 返回原编辑布局，页面与运行保持同一实例。控制台标签展示已有日志服务的最近 Node／scsynth 输出与错误，可复制测试详情；返回文件标签不丢失草稿。刷新保存版测试页面只重新载入页面，不重启进程。通过「添加 performer」创建多个独立原生测试窗口，逐个选择手机／平板及横／竖向；列表提供聚焦与单独关闭。这里只模拟页面尺寸，真实触屏、传感器与移动浏览器能力仍需实机验证。页面导航状态与「连接未知」分别显示，不把加载事件当作连接成功。各窗口使用独立临时浏览器存储，直接与工程服务器通信。页面刷新覆盖已打开的测试页，同工程重启保留窗口壳并使用当前运行地址。关闭测试、切换工程或离开创作会关闭旧窗口；取消操作或隐藏主窗口则保留。

打包前必须完成一次真实运行——App 的打包校验是静态的（结构、产物、依赖齐全），它证明不了工程行为正确：

1. 在 App 中打开工程目录（`⌘ O`、侧栏 `+` 或把目录拖进窗口）；
2. 确认 preflight 通过、session 启动、health 变为 ready；
3. 用手机连入同一局域网扫码进入 performer 页面，确认交互与声音正常；确认 monitor 页面在 App 窗口内正确嵌入、随窗口缩放；
4. 走一遍关闭流程，确认工程释放自己创建的资源。

任一步失败，先修工程再回来打包。

## 4. 打包与发布

当完成一个阶段性版本后，通过以下步骤完成作品交付：

1. **导出 `.pnds` 工程包**  
   打开 App 的 **设置 (Settings)** → **开发者工具 (Developer Tools)**，将当前工程打包导出为 `.pnds` 分发文件。
2. **自动化发布**  
   将本地改动提交并推送到 GitHub 仓库（或创建 Release Tag），触发 Template 内置的 **GitHub Actions** 自动化工作流，完成作品的构建与在线分发。

发布前检查清单：

1. `manifest.json` 通过 App 完整校验（id / name / version 就位，端口、模式、bus 容量合法）；
2. SynthDef 已用开发者工具重新编译，manifest 引用全部验证通过；
3. 工程刚在 App 里完整跑通过一次（health ready、performer 可演奏、monitor 正常、关闭干净）；
4. `npm install` 已完成，`node_modules/` 完整在场；
5. `version` 相对上一次分发的包已递增（内容变更必须升版本，原因见[参考手册 · .pnds 工程包](../reference/pnds-bundle.md)）；
6. 打包成功，记下产物路径与 sha256，连同文件一起分发。

performer 测试窗口支持工程原有的 JavaScript 弹窗，包括演奏者编号选择。「鼠标模拟单点触摸」在新测试窗口中明确显示为开启：按住鼠标左键拖动模拟一个触点，关闭后使用页面原有的鼠标行为。切换不重载页面。模拟事件不是可信硬件触摸，原生文本／表单控件仍可使用；真实多点触控、压力、传感器与移动浏览器行为仍需实机验证。

## 外部 PNDS Skills

Skills 是自愿安装的创作辅助。资源入口：[pnds-agent-skills](https://github.com/xO-xN/pnds-agent-skills)。按资源目录的说明选择统一创作入口或所需独立能力，在你的外部编程 agent 环境安装完整目录，保留它声明的支持资源；App 不执行安装。通用入口支持新建、修改及任意来源移植评估，移植方案先由作者确认；CM1 仍为明确选择的课程入口。资料优先使用装机 App 的本地参考手册，不能用远程最新版代替本机能力。

普通任务默认交付可编辑源工程、决定、验证和创作交接记录，明确需要分发再打包；课程任务交两者。结构就绪、接线完成、实际运行、声音与设备、可分发分别记录。缺少 Skill 不影响 App 阅读、编辑、添加模块或手动测试。
