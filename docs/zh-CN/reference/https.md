# 可信 HTTPS 入口准备

面向操作者：如何为本地演出准备「手机扫码即用、免装证书」的可信 HTTPS 入口。本页只讲 Host 侧的配置、导入、校验与场地准备；入口与工程的运行契约见[运行契约](./runtime-contract.md) §15。

## 为什么需要它

iOS Safari 的运动、摄像头、麦克风等能力只在**可信安全上下文**（secure context）里开放。现有局域网 HTTP 入口不能可靠满足这一条件，而要求每位乐手安装根证书、进系统设置开启信任或安装 VPN，会让临场入场变得复杂。

目标是：乐手连接演出 Wi-Fi → 扫码 → 按作品需要确认浏览器权限。**不安装证书、不用 VPN、不改手机 DNS，也不接受证书错误警告作为正常入场步骤。**

## 准备清单

| 材料                  | 说明                                                                                                                                |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 真实 DNS 域名         | 你拥有并能控制解析的域名（如 `show.example.org`）。不能用 IP 地址、`.local` 名称或内网主机名——公有 CA 不会为它们签发。              |
| 公有 CA 证书          | 由公有 CA（手机系统默认信任的机构，如 Let's Encrypt）签发的证书与匹配私钥。自签证书、自建根 CA **不是**成功路径——手机不会信任它们。 |
| 支持本地 DNS 的路由器 | 演出场地的可控路由器，能把域名解析到所选 Mac 的局域网地址。                                                                         |

## 第一步：域名

在「设置 → 可信 HTTPS」中填写域名。要求是真实 DNS 域名：小写字母、数字与连字符，不能是 IP 地址、`.local`、带协议或端口的完整 URL。通配符写在证书里，不写在配置里——入口地址需要具体主机名。

## 第二步：取得公有证书

用你已有的域名 / ACME 流程取得证书。要点：

- **DNS-01 验证**可以让签发过程完全不需要公网服务器（详见 [Let's Encrypt challenge types](https://letsencrypt.org/docs/challenge-types/)）；首次签发与续期可以联网完成，演出本身不依赖公网。
- 交付形态是两个文件：**证书链**（leaf + 中间证书，即 `fullchain.pem`）与**匹配私钥**（`privkey.pem`）。只导出 leaf 而缺中间证书是最常见的错误——App 会按「证书链不完整」拒绝。
- 续期走你现有的流程即可；App 不代管 ACME，也不存放 DNS 全域凭据。

## 第三步：在 App 中导入

「设置 → 可信 HTTPS」中导入证书链与私钥。导入时 App 会依次校验：

1. 文件是可解析的 PEM 证书链与私钥；
2. 证书**尚未过期**、**已生效**（以本机时间为准）；
3. **私钥与证书匹配**；
4. 证书链完整，且能追溯到**公有信任的根**（Mozilla 根集合）；
5. 证书的 **SAN 覆盖你配置的域名**（含单层通配符匹配）。

任何一步失败都会给出明确的错误与细节（证书实际覆盖的域名、实际到期时间等），**新材料不会写入**——原有的已导入材料保持不变。只有全部通过，替换才会原子地落盘。

两点必须分清：

- **「文件合法」≠「手机实际可用」**：App 的校验证明材料格式正确、链与域匹配、受公有信任。手机最终能否信任与到达，还取决于下面的第四步（本地 DNS）与真机实测——离线正式验收以可控路由器为前置条件。
- **受保护保存**：证书链与私钥由 App 后端保存在本机数据目录的受限权限文件中（仅当前用户可读），**不进入**设置偏好回传、工程目录、manifest、`.pnds` 工程包或日志。乐手侧永远不需要接收或安装任何证书。

## 第四步：路由器本地 DNS

在演出路由器的**本地 DNS**中，把域名解析（A 记录）指向所选 Mac 的局域网地址（「设置 → 节点」中选择的网络地址，App 会在 HTTPS 区提示当前值）。乐手按正常 Wi-Fi 配置获得解析能力，**不需要修改任何手机设置**。

注意：

- App 提供域名、目标地址与操作说明，但**不会自动修改路由器或手机**——场地网络需要操作者可控。
- 公开 DNS 指向私有 IP 可以作为已有部署的选择，但不能据此承诺任意 Wi-Fi 或离线冷启动可用。
- 证书有效、完整链、正确的设备时间与本地 DNS，是离线准备的四个条件。

## 到期与更换

- 设置区显示证书的**实际到期时间**，并按 30 天窗口提前提醒（到期前 30 天内状态变为「即将到期」，附剩余天数）。提醒基于真实到期时间，不假设证书寿命。
- **更换**：导入新证书同样先校验、后替换；失败保留旧材料。运行中的演出沿用启动时的材料——**演奏中改动的域名、端口或证书都在下次启动工程时生效**。
- **座位与 origin**：协议、域名或端口任一变化就是不同的浏览器 origin，乐手在新 origin 下按新加入处理（座位 token 按 origin 隔离，不跨 origin 迁移）。从 HTTP 切换到 HTTPS 同样改变 origin——这是预期行为，不是故障。

## 常见错误

| 状态 / 错误              | 含义与解法                                                            |
| ------------------------ | --------------------------------------------------------------------- |
| 证书不覆盖当前配置的域名 | 证书 SAN 与域名不符（错误会列出证书实际覆盖的域名）。改域名或换证书。 |
| 证书已过期               | 到期时间已过。续期后重新导入。                                        |
| 证书尚未生效             | 签发机器时钟有偏差，或证书还未到生效时间。                            |
| 证书链不完整             | 缺中间证书。导入 fullchain（leaf + 中间证书），而不是只导 leaf。      |
| 证书不受公有信任         | 自签或私有 CA 签发。手机不信任它们；改用公有 CA 证书。                |
| 私钥与证书不匹配         | key 不是与这份证书一起签发的那个。检查是否拿错了文件。                |

## 入口生命周期（#140 起）

证书材料就绪后，打开设置「可信 HTTPS」顶部的**启用开关**，入口即随演出启动：

- **启动**：声明了 `supportsPerformerUrl: true` 的工程在下次启动时，App 在所选 LAN 接口、配置的端口上开启 TLS 网关，把手机请求原样转发到本机 performer 服务（页面、静态资源、Socket.IO polling 与 WebSocket 都走这一条入口）；完整 URL（`https://域名:端口/`）在启动时固定并注入 `PNDS_PERFORMER_URL`——工程二维码、菜单「复制地址」与侧栏入口行显示的是同一个字符串。
- **就绪判定**：工程 health ready 后，App 自己经入口发起一次 TLS/HTTP 探测（以域名校验证书、经隧道取 health），成功才把入口标为**就绪**。这只证明本机隧道可用，不等于「所有手机都能连」——手机的 DNS 与信任仍以真机扫码验收为准。
- **状态展示**：侧栏设置卡（运行卡选中时）的「入口」行显示 准备中 / 就绪 / 故障 与 URL（点击复制）；窗口菜单的 Performer 地址项在入口生效时同样复制入口 URL。
- **运行中故障**：入口故障（如网口变动导致 listener 失效）只报告为入口故障——本地音频与服务继续运行，不会自动改发 HTTP 二维码；恢复由操作者显式重启演出完成。
- **停止**：Stop、重启、切换工程与退出都会关闭入口（listener、活动连接一并释放）；下一个演出重新开启。演奏中改开关 / 域名 / 端口 / 证书都从下次启动生效。
- **未声明的工程**：开关开着但工程未声明适配时，设置卡有醒目提示，按「启动」会弹确认——操作者显式选择「使用 HTTP 启动」才继续，取消则什么都不发生；不会静默降级。

## 与工程的关系

工程通过 `scoreServer.supportsPerformerUrl: true` 声明自己会读取 Host 提供的完整 performer URL 并在同源下建立连接（[manifest.md](./manifest.md)）；未声明的旧工程不受影响，沿用 HTTP 流程。Host 侧的配置、导入、校验与受保护存储随 #139 交付，TLS 入口网关随 #140 交付——材料就绪后无需再为入口重新准备。
