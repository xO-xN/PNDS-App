# 页面交互：键盘、指针与触摸

本篇面向**工程创作者**，把「工程页面在 App 里能依赖哪些交互事件」写成精确承诺——monitor 页能收到哪些键、指针与右键归谁、performer 页的触屏能力边界。演出场景下键位冲突是事故源，为页面选交互键位前先读这里的两张表。App **使用者**的快捷键速查不在本篇——见[使用教程](../app-tutorial.md)的附录。

## 总则：嵌入模型与键位两层

- **monitor 页**在 App 主窗口内以 iframe 嵌入，占据除侧栏与顶部标题条之外的整个主区域。App 不读取、注入或调用跨 origin 页面 DOM（[runtime-contract.md](./runtime-contract.md) §10），页面接收标准 web 输入事件。下文明确标注的 performer 鼠标模拟是窄的原生输入例外，不读取谱面 DOM 或转发音乐消息。
- **performer 页**通常由演奏者设备的浏览器直接访问工程自己的 server。创作模式也能在多个独立原生测试窗口内嵌入真实 performer 页，消息仍直接经工程服务器传递。
- 键盘输入经过**两层**才轮到页面：**原生菜单加速器层**（macOS 菜单栏，App 全局生效，永不让位）与 **App web 层**（App 自身界面的 ⌘ 快捷键层，页面交互期间让位）。一张键位属于哪一层，决定页面永远收不到它、还是交互期间可以用它——见下节两张表。

## monitor 页键盘

### 表 A：原生层永久保留——页面永远收不到

| 键位          | App 行为                             |
| ------------- | ------------------------------------ |
| `⌘ W`         | 关闭窗口（运行中有确认流）           |
| `⌘ Q`         | 退出 App（运行中有确认流）           |
| `⌘ M`         | 主输出静音 / 恢复                    |
| `⌘ O`         | 导入工程                             |
| `⌘ R`         | 重命名选中的工程 / 文件夹            |
| `⌘ ,`         | 打开 / 关闭设置面板                  |
| `⌘ ?`（⇧⌘/）  | 打开帮助中心                         |
| `⌘ 0`         | monitor 缩放：实际大小（按聚焦窗口） |
| `⌘ =` / `⌘ -` | monitor 放大 / 缩小（按聚焦窗口）    |
| `⌘ ⇧ R`       | 重载两个窗口的 monitor 页            |
| `⌃ ⌘ F`       | 聚焦窗口进入 / 退出全屏              |

这些是 macOS 菜单栏加速器：按键在到达页面前就被 App 消费，**页面交互期间照常工作**。作品键位规划必须绕开它们。

v1.5.0（#131）起 monitor 页可能出现在**两个窗口**——主窗口与投影窗口（副屏演出显示）。加速器仍是 App 全局的，但作用按**聚焦窗口**分派：`⌘ 0`/`⌘ =`/`⌘ -` 只调聚焦窗口自己的 monitor 缩放（两窗口各持独立值、互不牵动；投影窗口的缩放同时作用于其简介页，且经 preferences 记忆）；`⌃ ⌘ F` 只切聚焦窗口的全屏；`⌘ ⇧ R` 例外——一个和弦**同时**重载两个窗口的 monitor 页。对页面而言表 A 的语义不变：这些键位在两个窗口里页面都收不到。**#135 例外**：投影副本页面经 §14 握手声明 `zoom:"page"` 后，`⌘ 0`/`⌘ =`/`⌘ -` 对该窗口为无操作——App 不再应用自己的缩放（归属声明方式见[运行契约 §14](./runtime-contract.md)）。

### 表 B：条件可用——页面交互期间属于页面

| 键位          | 平时（页面未交互）的 App 行为 |
| ------------- | ----------------------------- |
| `⌘ 1`–`⌘ 9`   | 选择第 N 个可见工程           |
| `⌘ ↓` / `⌘ ↑` | 下一个 / 上一个工程           |
| `⌘ ←` / `⌘ →` | 切换文件夹视图（两端回绕）    |
| `Enter`       | 加载工程 / 变更后重启         |

**「页面交互期间」**指：页面内任何元素持有键盘焦点（body / html 除外），或指针位于 monitor 区域内（兜住不产生焦点事件的自制控件，如无 tabindex 的 div 菜单）。此间 App 的 web ⌘ 层让位、不夺回键盘，上表键位由页面自行处置；交互结束（焦点落回页面 body、指针离开区域）后键盘即时归还 App。

v1.5.0（#131）两点修订：

- **表 B 只存在于主窗口**——投影窗口没有 App web 层（无侧栏、无 ⌘ 徽标层），非加速器键位在投影窗口全部属于页面。
- **演出与投影 monitor 中的 `Esc` 归页面**（plain-Esc 关闭工程别名已退役，关闭工程的确认流走 `⌘ W`）。v1.6 创作模式的窄例外：主窗口 monitor 临时展开、主窗口聚焦且没有 App 弹层或提交时，plain `Esc` 由 App 用于还原编辑工作台；它不结束运行、不导航页面、不关闭测试窗口。未展开及其他窗口保持原有归属。

特例注（`⌘ ←` / `⌘ →`）：WKWebView 原生层默认把「⌘ + 左右方向键」当作自己的后退 / 前进等价键吞掉，keydown 根本到不了任何页面——App 已在原生层把这一组合改道回普通 keyDown 路径，页面才能监听到它；文本输入元素内仍保留系统「行首 / 行尾」编辑行为。

## 指针与右键

- 指针事件（移动 / 按下 / 抬起 / 滚轮 / 拖拽）**全量透传**给 monitor 页——App 不截留、不解读。
- **右键属于页面作者**：App 抑制了 WKWebView 的原生 web 菜单（Reload / Open Frame in New Window / Back 等；可编辑字段保留系统复制粘贴菜单），且抑制只 `preventDefault`、不拦截事件传播——工程在 monitor 页监听 `contextmenu` 实现的自定义右键菜单与它天然共存，无需任何接线。
- App 自身界面（侧栏等）的右键属于 App 设计的菜单；设备浏览器中的 performer 页右键完全由工程自理；App 测试窗口沿用原生菜单抑制，页面自己的 contextmenu 事件仍归工程。

## 顶部标题条避让区

App 在窗口**顶部中央**悬浮一条标题条（显示当前工程名），它同时是窗口拖动区：会盖住页面顶部中央的对应区域，并在那里吞掉指针事件。monitor 页不要把关键交互（按钮、菜单、状态读数）放进这条顶部中央带——把它留给标题与拖动。

## performer 页

performer 页通常由演奏者设备的浏览器直接打开，输入能力等同普通移动网页：**触屏、多点触控、横竖屏自适应**全部可用，完全由工程自理——用标准 viewport 与响应式布局适配横竖屏和不同尺寸；持续交互状态建议存相对 / 归一化坐标，避免尺寸变化后固化在旧像素坐标（与 monitor 页的 resize 要求同一条纪律，[runtime-contract.md](./runtime-contract.md) §10）。

创作模式的 performer 测试窗口使用独立临时浏览器存储，各自保有客户端身份。手机为 390 × 844、平板为 820 × 1180 的 CSS 页面视口，横向交换宽高；外框缩放以适应桌面窗口，不改变页面视口。尺寸切换保持同一页面，页面需响应 resize。这里只模拟尺寸，不能据此认定真实触屏、多点触控、传感器或移动浏览器 API 已通过验证。

测试窗口没有 App web 快捷键层；原生菜单与 macOS 保留的组合仍被保留。普通键、Esc、指针和页面 contextmenu 归 performer 页；主窗口展开还原的 Esc 例外不扩展到测试窗口。⌘W 只关闭聚焦的测试窗口，⌃⌘F 只改变该窗口的原生全屏，monitor 缩放组合不改变 performer 视口。App 只从自身导航生命周期得知页面加载情况：load 事件也可能来自浏览器错误文档，不等于服务连接成功。现有公开协议没有 performer 连接状态上报，列表明确显示「连接未知」，工程不必接入新消息协议才能测试。

## 键位安全区建议

为 monitor 页挑选交互键位时：

- **安全区**：普通字符 / 数字键、`⇧` 组合、`⌥` 组合、`F1`–`F12`。
- **不可依赖**：macOS 系统级组合——`⌘ Tab`、`⌘ Space`、截屏（`⌘ ⇧ 3` / `4` / `5`）等——任何网页都截不住，WKWebView 里的页面也不例外。
- **`⌘` 系建议整体回避**：除了上表 A 的菜单加速器与系统级组合，未来 App 版本还可能新增 `⌘` 加速器。普通键 + `⇧` / `⌥` 足够绝大多数演出交互，键位冲突的代价远大于组合的美感。
- 表 B 键位可用，但要接受让位语义：页面持有焦点（或指针在 monitor 区域内）时键位归页面，否则归 App——把演出关键操作押在条件键位上时，务必保证「焦点在页面内」是作品的稳定状态（例如让页面开场即聚焦一个元素）。

performer 测试窗口支持工程原有的 JavaScript 弹窗，包括演奏者编号选择。「鼠标模拟单点触摸」在新测试窗口中明确显示为开启：按住鼠标左键拖动模拟一个触点，关闭后使用页面原有的鼠标行为。切换不重载页面。模拟事件不是可信硬件触摸，原生文本／表单控件仍可使用；真实多点触控、压力、传感器与移动浏览器行为仍需实机验证。
