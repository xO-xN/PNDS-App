# .pnds 工程包

## 定位

`.pnds` 将一个可运行的[目录工程](./structure.md)与包元数据封装为单文件。App 解包后运行工程。

## 文件格式

ZIP（deflate）的顶层由唯一工程目录和 `pnds-bundle.json` 组成。归档使用相对路径和正斜杠，保留 Unix 权限。绝对路径、目录逃逸和归档内符号链接均非法。

| 元数据           | 值                |
| ---------------- | ----------------- |
| `formatVersion`  | 整数 `1`          |
| `packedWith`     | 打包 App 版本     |
| `packedAt`       | RFC 3339 UTC 时间 |
| `sourcePlatform` | 打包平台标识      |

## 打包

在**创作工作台 → 作品菜单 → 生成 .pnds**选择输出路径。打包读取磁盘保存版，有草稿或工作台尚无成功测试记录时会提示确认。静态校验涵盖 manifest、入口、所有声明的 SynthDef、生产依赖和确切共享资源。

包保留 README、封面和其他工程文件。任意深度的 `.DS_Store`、`.git*`、`.pnds-creation`，以及根目录的 `docs/`、`test/`、`tests/` 均排除。可用的工程内符号链接物化为文件，越界链接和私有目录别名跳过。

默认文件名为清洗后的 `<name>-<version>.pnds`。输出须位于源工程之外，覆盖需确认。成功后显示路径与 SHA-256。打包只复制并校验保存文件。

## 安装

双击、拖入 App 或用 `⌘O` 打开。App 校验格式与完整工程后发布到 `bundles/<id>-<version>/`，再按目录工程加载。替换运行占用中的槽位前须停止，安装失败保留原文件。从列表移除安装工程时回收解包目录。

## 版本号语义：内容变更必须升 version

内容变更须递增 manifest 的 `version`。同一 `id` 和 `version` 共用安装槽位，重装会替换内容。两者各为一个路径段，禁止斜杠、反斜杠和 `..`。

## 分发

分发 `.pnds` 文件，可提供 SHA-256 供接收方用 `shasum -a 256` 核对。App 安装不强制校验该摘要。

## 共享引用的分发

共享包只携带 [manifest 的确切引用](./manifest.md#app-共享包能力与-schemaversion-2)。接收端 App 须提供确切版本及完整文件。工程的模型、页面、谱面与声音资产随包分发。

## 创作机与演出机

演出机使用 App 内置 Node 与 scsynth。要携带聊天、待处理文档或演奏记录，请复制含隐藏目录的[完整源工程](./structure.md#工程内的私有创作数据)。

## 内置工具的形态

App 从 `Contents/Resources/utilities/<id>/` 运行内置工具。操作入口在 Utilities 文件夹。

## 合规清单

交付前确认归档结构、运行资产与共享引用完整，并在接收端 App 安装和启动。
