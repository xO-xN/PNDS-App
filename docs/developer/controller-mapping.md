# 控制器映射

设置的「演出 → MIDI／OSC 控制」管理 MIDI、OSC 输入和映射。默认 OSC 接收地址是 IPv4 回环。演出底栏的控制器按钮在当前演出页就绪时可用。进入映射模式后点选标准按钮并发送无参数 OSC，画面会标出地址。退出按钮或 Esc 结束学习，已完成的映射继续调用控件原有 click 处理器。

## OSC 来源与数值

OSC 开关开启后先绑定本机 IPv4 回环。显式启用「局域网输入」时，App 同时在演出可用的局域网 IPv4 地址上接收，只学习或投递发送方名单中的消息。名单按设备的发送 IPv4 地址区分，同一 OSC 地址可以在不同来源重复使用。切换接收范围沿用仍符合配置的套接字，绑定失败时保留当前端口和来源设置。

设置允许为连续量独立编辑输入区间、目标区间和反向。单数值 OSC 的输入区间默认 0–1，目标区间默认采用推子完整范围。换算先将输入限制在配置区间，再按比例变换至目标区间，最后选取其中最接近的合法步进值。网页推子收到原有的 `input` 和 `change` 事件。开关收到零时关闭，收到正值时开启，网页已有状态符合要求时保留原状态。零以下的值也视为关闭。

## 归属与保存

池主映射由运行工程的规范绝对路径索引。持久化记录只包含可在同一路径页面重新定位的控件。标准控件以唯一的 DOM id 或 name 定位。匹配歧义或消失时，设置标记待重新绑定，对应输入停止投递。无法得到唯一身份的控件可以按当前元素实例学习，控件替换或文档退出后清除。

原生映射状态在实际项目 WKWebView 完成加载后取得文档令牌。文档导航、销毁和运行归属切换令旧令牌失效。一条输入在原生接收时取得当前文档令牌，主线程处理与文档内投递各自重新核对。标签、点选与控件调用通过独立 WKContentWorld 工作。

AppShell 订阅控制器快照，收到保存版本变化后沿现有偏好队列保存。完整映射存于 App 本地偏好。持久化中的更新重试使用最新快照。原生收包与控制路径独立于 AppShell 的焦点与绘制状态。

## MIDI 输入

设置通过 Core MIDI 列出可用输入端口。启用状态按 Core MIDI 端口的唯一 ID 保存。系统设备变动时原生层重新核对已启用端口，设置显示这些端口的最近消息。已启用端口暂不可用时可继续保留选择，或在设置中取消。

MIDI Note 按端口、通道和音符编号匹配。Note On 的速度大于零时识别按下。Note Off 和零速度 Note On 释放当前按键。标准按钮、原生复选框和页面声明的 `role="switch"` 通过控件的 click 处理器操作。

7 位绝对 CC 按端口、通道和控制号匹配。连续量的输入区间固定为 0–127，映射设置可编辑目标区间和方向。软接管读取推子的实际值，换算后接近或经过当前值时开始投递。当前值超出区间时，要先到达最近的合法端点。重新打开页面、改绑、更换输入连接或从页面独立改变目标值后，实体推子需要重新接管。

用于按钮或开关时，CC 64–127 表示按下，0–63 表示释放。每次按下只调用一次原控件动作，释放后可以再次触发。

## 自动化入口

`npm run native:app-shell:verify -- --controller-mapping` 静态构建现有 AppShell，通过正常设置配置本机 UDP 端口，使用本机回环数据报和原生 monitor 页验证点选、临时映射、控件歧义、Esc、恢复和删除。夹具及同一设备入口也验证了数值步进、范围编辑、局域网端口冲突保留回环和按来源区分的开关投递。运行夹具需要 macOS 图形会话。

同一夹具使用两个临时 Core MIDI 虚拟输入端口在原生 monitor 测试端口枚举、端口与通道隔离、按下和释放、开关的原有处理器和重开恢复。虚拟端口发送标准 MIDI 1.0 事件，经过实际 Core MIDI 输入回调。
