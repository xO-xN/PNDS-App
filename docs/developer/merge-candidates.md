# 工程版本合并候选

产品决定见 [ADR-0021](../adr/0021-review-merge-candidates-before-publication.md)，流程与验收见[合并规划](../plans/creation-merge-design.md)。版本页继续使用窄文件栏、横向时间树与树右操作区。

## 原生边界

`project/creation/git_merge` 负责关系判定、独立对象库、候选记录、三方结果、冲突、修订与最终发布；`commands/git_merge` 只接受已签发的工程身份。只读 probe 先判定已包含，准备时再核对当前目标，不能沿用悬停预览作为写入授权。

候选记录和对象放在工程的私有创作数据中。实际工作树、index 和 HEAD 在准备、编辑、检查及助手工作中保持独立。`CreationAccess` 的统一写入门禁及主运行入口同时检查候选占用，不能只依赖版本页按钮禁用。普通工程文件保存、版本切换、模块与编译产物发布等写入沿用该门禁。

所有修改接受候选 ID、修订及文件内容版本。人工结果由原生 libgit2 差异与文件读取接口展示，不在 WebView 中重新实现合并。文本冲突通过保存后统一核对；二进制和删除／修改冲突需明确选择整份结果。快进候选只读，最终精确采用已有来源提交。

发布固定作者、时间、结果提交与文件／index／ref 的预期内容，再保存阶段记录并逐项发布。恢复复用同一结果；外部后续变化阻断恢复，不能强行覆盖。完成收据独立于界面刷新与 GitHub 备份；同步失败不能重新执行合并。

发布和恢复成功后，编辑器同步先退休本次变更路径的旧工程副本，再读取新磁盘状态。定时扫描提前观察到删除或非文本替换时，同样退休由原干净副本产生的不可用状态，避免将已保存内容恢复成未保存草稿；等待发布回复期间产生的较新输入继续保留。

## 前端所有权

`creation-merge-store` 持有候选投影、文本缓冲和串行修改队列；原生记录是权威。异步读取核对工程、候选和修订，旧工程的回复不能更新新工程。相同修订的状态刷新保留内容缓存与编辑器缓冲，内容版本变化才淘汰干净缓冲；手工未保存输入仍保留供错误恢复。

候选存在时，左侧始终显示候选的变更和冲突，助手与检查复用现有中间页签。树中只出现真实历史；悬停合并按钮的淡线预览与正式边线共用 `gitVersionEdgePath`，候选不伪装成未记录版本。

树右栏只保留名称、单行方向、状态与操作，使用 8px 内边距、24px 按钮及 4px 间距。长错误和可选检查说明放在树下方的全宽信息条；右栏不使用独立滚动或翻页。

保存快捷键由私有参与者消费，只保存候选。离开、退出分别通过 lifecycle 的 cleanup／prepareQuit 保存私有草稿并停止其任务；不会借此保存用户选择放弃的普通工程草稿。重开候选须重新核对并明确继续，不能自动重启助手或测试。

## 助手轮次

`git_merge/assistant` 与 `merge-assistant-store` 使用候选专属任务和工具目录。模型没有实际工程、Git、发布或任意 Shell 写入工具。每轮先保存手工结果，原生建立检查点并持有写入权；停止先撤销新工具准入，取消并等待在途检查，最后交还人工编辑。

差异来自检查点的实际内容。撤回核对每个触及路径的当前版本，后续手改使整次撤回拒绝；未触及文件不受影响。持久化的 request ID 允许 WebView 重载后取消旧模型请求，迟到工具回复仍须通过原生任务所有权核对。

## 候选测试与媒体

`project/merge_runtime` 为主运行引擎标记工程、候选、修订、执行副本和运行代次。运行副本保留已安装依赖并应用真实删除，不成为最近工程。停止只接受已审阅的代次；停止候选不会停止另一份仍在运行的原工程。修改候选后现有运行仍代表旧修订，必须明确重测。

检查报告绑定候选修订与输入指纹。结构、路径、声明和基线是必要条件；静态诊断、编译及已有 Node 测试分别报告，失败时保留明确“仍然合并”的操作。编译检查不暗中改结果，采用编译产物是另一项可见的候选修改；快进候选不允许采用。

图片使用有上限的原生内容读取。声音沿用原生试听和所选输出设备，只把元数据与真实可用波形传入 WebView，不创建音频字节 URL。换文件、修订、输出及离开会退休试听令牌；原生再次核对发出的副本与候选归属。

原生退出先关闭新候选操作准入，取消并等待检查，等待已开始的发布完成，再持久化暂停并清理主运行。清理失败保留 App 和所有权供重试，并恢复准入；不能声称退出已完成。
