# Writing Developer Documentation

- Cover the current entry, required inputs, defaults and recovery. Keep examples to the smallest form needed to use the interface.
- Put App operations in the bilingual tutorial, creation steps in the creator guide, Host and project contracts in the reference manual, capability integration in the module manual, and maintenance constraints here.
- Keep each rule in one place. Link to it from other topics. Archive superseded decisions and verification evidence.
- Check the actual entry and implementation before documenting behavior. Match conditions, limits and failures in both language trees.
- Preserve shipped paths and document IDs. Map removed heading IDs in `src/lib/help-section-aliases.ts`. See the [help center](./help-center.md) for registration and checks.
